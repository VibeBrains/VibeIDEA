# Каталог возможностей VibeIDEA

Версионно-независимый каталог «что умеет продукт». Одна исчерпывающая запись на возможность; расширили — переписываем пункт, не дописываем второй. Чистые баг-фиксы сюда не идут.

## 🧩 Платформа

*(наследуемое от intellij-community описывается только там, где мы меняем поведение)*

- **Собственный дистрибутив VibeIDEA** — продукт собирается из исходников в неподписанный dmg/sit (macOS arm64): свой product code `VI`, `VibeIDEA.app`, своё лого «терминал + искра ИИ» (промпт `>`, строка ввода и четырёхлучевая искра, неон циан→фиолет→маджента) — в приложении (About/welcome, SVG) и в macOS Dock (`.icns`); вендорные mcpserver и featuresTrainer из комплекта исключены. Сборка: `./vibeidea-installers.cmd -Dintellij.build.target.os=current`.

## 🌐 Языки

- **TypeScript/JavaScript через LSP (vtsls)** — completion, диагностика, навигация, hover, форматирование для `*.ts/tsx/js/jsx/mts/cts/mjs/cjs`; сервер vtsls (MIT) подключён через бандленный LSP4IJ, подсветка — TextMate. Сервер ставится пользователем один раз ([мануал](manuals/languageServers.md)); IDE ищет его в PATH и типовых местах установки — GUI-приложениям macOS shell-PATH не достаётся, поэтому известные каталоги проверяются явно.
- **PHP через LSP (Phpactor)** — то же для `*.php`; Phpactor (MIT). Intelephense не поставляется (его EULA запрещает редистрибуцию) — задокументирован путь самостоятельной установки как «премиум»-вариант.

- **Доктор языковых серверов** — Tools → «VibeIDEA: языковые серверы» отвечает, установлены ли vtsls (TypeScript) и Phpactor (PHP), показывает путь найденного и однострочную команду установки для недостающего. Серверы не вкомпилированы в IDE осознанно: они распространяются через npm и composer, и бандлить их значило бы тащить чужой рантайм и лицензию. Чтобы отсутствие сервера не выглядело поломкой IDE, при открытии `.ts` или `.php` без сервера приходит уведомление с командой установки и кнопкой «скопировать» — один раз на сервер и проект, с кнопкой «больше не напоминать». После установки нужен перезапуск: PATH читается при старте процесса.

## 🖥 Дев-стек

- **Vibe Server (`.vibe/servers.json`)** — декларативный дев-стек: сервисы и task-и с `dependsOn`, волны запуска (зависимые ждут ГОТОВНОСТИ — TCP-порт / HTTP не-5xx / regex по логу / exit 0 / spawn), `skipIf`-пробы («уже сделано» — пропуск), `pathPrepend`-пин тулчейна, `envFile`, `stopCommand` best-effort. Тулвиндоу внизу IDE: Запустить/Остановить всё, запуск выбранного с транзитивными зависимостями; исключённые записи (неизвестная зависимость, цикл) видны с причиной — ничего не стартует втихую. Спека: [manuals/serversSpec.md](manuals/serversSpec.md).

## 🎯 Дизайн-контекст

- **Дизайн-память проекта (`.vibe/design/`)** — 4 markdown-файла (uiKit / components / design / product, с fallback на корневые файлы чужих дизайн-скиллов); при наличии панель Vibe Agent подмешивает агенту пути к ним с правильным порядком подачи (uiKit первым) и разобранные именованные правила + осознанные отклонения. Формат правил `**Имя.** тело` и дрейф-строк `- rule-id — причина` разбирается автоматически. Спека: [manuals/designSpec.md](manuals/designSpec.md). Браузерный движок замера (81 детектор) — в очереди.

- **`/watch <ссылка|путь> [вопрос]` — модель смотрит видео и слушает аудио** — команда перехватывается в композере ДО отправки модели: проба источника, субтитры, скачивание, кадры **по сменам сцен** (а не через равные промежутки — это ключевые моменты, а не выборка), прогресс по стадиям и работающий Стоп. Кадры уходят вложениями, субтитры — транскриптом **с тайм-кодами**, чтобы ответ «на 4:12 показывают график» можно было проверить. Аудио-вход (подкаст, голосовое) идёт без кадров и **не требует vision-модели**; vision-гейт стоит ДО пайплайна (чтобы не качать лекцию ради отказа) и повторно ПОСЛЕ — переименованный в `.mp3` видеофайл иначе упёрся бы при отправке. Нет субтитров — честное «разбор пойдёт только по кадрам»; аудио без субтитров — отказ с причиной, потому что отправлять нечего. Настройки: порог сцен, максимум кадров, высота кадра, языки субтитров. **Инструменты берутся из системы** (`yt-dlp`, `ffmpeg`): не найдены — сообщение с точной командой установки; бинари не бандлятся (GPL-сборки пришлось бы подписывать и обновлять вместе с IDE).
- **Дизайн-детектор: замер живой страницы в двух вьюпортах** — тулвиндоу «Дизайн»: адрес, «Открыть», «Замерить». Страница читается **как её вычислил браузер** (стили говорят, что написано, снимок — что победило) и проверяется 29 детерминированными правилами без модели и без ключа, сразу в двух вьюпортах, причём мобильный **физически сужает** превью до 390 px — иначе медиа-запросы не срабатывают и находится не то. Правила делятся на **пол качества** (контраст WCAG с отдельным порогом для крупного текста, мелкий кегль, зоны нажатия, обрезанное содержимое, текст под непрозрачным слоем, страница шире окна, битая картинка, снятая обводка фокуса, выключенное выглядит рабочим, пропуск уровня заголовка, кнопка-иконка без имени, плейсхолдер вместо подписи, отсутствующий `alt`, ошибка без привязки к полю, обязательность звёздочкой) и **вкус** (14 примет сгенерированного вида и русская типографика по измеренной разбивке строк). Каждая находка приходит с селектором и **измеренным значением** — её оспаривают числом, а не мнением; замер ничего на странице не меняет. Находки **видно на самой странице**: рамка с подписью правила, клик по подписи кладёт находку в композер (решение, что с ней делать, остаётся за человеком), кнопка «⚑ разметка» её убирает. Проект может объявить вкусовую находку своей идентичностью — правилом с причиной в `.vibe/design/`; **пол качества принять нельзя**: нечитаемый текст не бывает фирменным стилем. **Замер запускается сам** после хода, менявшего файлы интерфейса (Settings → Tools → VibeIDEA → Агент → «Дизайн-гейт»): `notify` — сводка в ленте, `enforceFloor` — агент возвращается к работе, пока остаются нарушения пола; вкус не блокирует никогда. Панель закрыта — гейт скажет об этом словами, а не промолчит: молчание читалось бы как «страница в порядке».
- **Граф проекта (`.vibe/codeGraph.json`)** — Tools → «Vibe: экспорт графа проекта»: файлы, объявленные символы и импорты (UAST — JVM-языки), TODO/FIXME, **связи в обе стороны** («кто импортирует этот файл» — вопрос, на который сам файл не отвечает) и кратчайшая цепочка между двумя файлами. У каждой связи проставлено **происхождение**: `факт` — строка импорта совпала с объявленным полным именем, `догадка` — совпал только последний сегмент; при неоднозначном простом имени (два `Utils` в разных пакетах) связи не будет вовсе. Различение нужно затем, что модель без пометок обращается с догадкой как с фактом. Экспорт **инкрементальный**: файлы с неизменившимися размером и временем берутся из прошлого графа (уведомление говорит, сколько разобрано заново). Агент читает файл сам — ему даются пути и структура, а не пересказ содержимого. Спека: [manuals/codeGraphSpec.md](manuals/codeGraphSpec.md).

## 📚 Документация

- **Гейт графа доков** — `vibe-tools/docsGraphCheck.py` (stdlib-python, без зависимостей): dead links, wikilinks, записи knowledge без строки в индексе, недостижимость от `docs/vibe/README.md`; exit 1 на любой дефект. Перенос контракта `docs-graph-check` VibeIDE.

## 🎨 Оформление

- **Тема Vibe Neon Dark** — фирменная тёмная тема с неоновыми акцентами (циан/маджента/пурпур): своя палитра UI (фокус, ссылки, прогресс, вкладки) и схема редактора (наследует Darcula, неоновый курсор и синтаксические акценты). Выбирается в Settings → Appearance; новая UI (`targetUi=new`).

- **Правила проекта, папки-справочники и `.vibe/ignore`** — три границы, задаваемые самим репозиторием. **Правила** живут в `.cursor/rules/*.mdc` (формат Cursor: репозиторий коллеги уже несёт свои правила, и агент обязан их видеть) и подмешиваются в ход по одному из трёх признаков: `alwaysApply` — всегда, `globs` — когда ход трогает подходящий файл, иначе — по имени `@правило`; ссылка `@имя` внутри тела подтягивает другое правило один раз и без зацикливания, почта ссылкой не считается; старый `.cursorrules` подхватывается как «всегда». Тело правила проходит тот же контроль, что любой файл с диска — «правила проекта» ровно та вывеска, которую хотела бы носить подсунутая инструкция. **`.vibe/ignore`** (подмножество gitignore: `dist/`, `*.min.js`, `docs/**/*.png`, `!исключение`) убирает из чтения и поиска то, что съедает контекст молча — один минифицированный бандл это строка в 400 000 символов; игнорируемое не предлагается и в `@`-меню. **Папки-справочники** («VibeIDEA: добавить папку-справочник для агента») и `sourceFolders` внутри проекта дают чтение без записи: «прочитай мои заметки, но не редактируй» становится правилом, а не надеждой. Решение принимается ДО действия: запрещённый файл не читается вовсе. Формат и таблица доступа — [manuals/projectContextSpec.md](manuals/projectContextSpec.md).

- **Булавка и ветка разговора** — у каждого своего сообщения в ленте две кнопки. **Булавка** (📌) вынимает сообщение из-под обрезки истории: когда переписка перерастает потолок, закреплённое переносится вперёд хвоста, а счётчик «история обрезана» считает только реально уничтоженное — иначе он врал бы про спасённое. **Ветка** (⑂) создаёт копию разговора до этого места и открывает её отдельным чатом; исходный остаётся нетронутым — ветка нужна, чтобы попробовать другой путь, а не переписать пройденный. Точка среза отъезжает назад через служебные строки: ветка, кончающаяся на «ход отменён», дала бы модели разговор, который нечем продолжить.

- **Страж окна контекста и лимит токенов на чат** — переполненное окно не объявляет о себе: оно заставляет модель забыть начало разговора, и человек делает вывод, что модель поглупела. Поэтому заполнение называется вслух: на 75% — предупреждение, на 90% — строка о том, что ответ уже формируется тем, что выпало (и совет уйти веткой или в новый чат). Каждый порог произносится один раз за чат, а не на каждом кадре. Отдельно от окна работает **лимит токенов на чат** (Settings → Tools → VibeIDEA → Чат, по умолчанию 0 — выключен): окно отвечает за «поместится ли», лимит — за деньги, и проверяется он ДО хода, потому что отчёт об уже потраченном — это чек, а не защита.
- **Сжатие вывода команд, обратимое** — длинный вывод сжимается ПЕРЕД отправкой модели: первые 30 и последние 20 строк, между ними строка с числом убранных строк и меткой. Прогон тестов говорит главное в начале и в конце, середина — это скроллбэк, стоящий столько же токенов, сколько код, который модели ещё читать. Молчаливое усечение недопустимо: именно так модель делает вывод, что упавшие тесты прошли. Полный текст возвращает команда `/output <метка>` (хранятся последние 20 выводов сеанса).

- **`/git` — состояние репозитория фактом, а не терминальной сессией** — команда собирает ветку с upstream и расхождением, изменённые файлы с размером правки (+/− строк, двоичные помечены, неотслеживаемые названы новыми) и последние коммиты. Без вопроса — показывает сворачиваемой карточкой; с вопросом (`/git почему упал билд?`) уходит ходом, где состояние приложено отдельным контекстным блоком, а вопрос остаётся вопросом. Зачем: без этого модель идёт в терминал — платит за `git status`, потом за `git diff`, потом перечитывает наполовину забытый diff; три обхода и стена вывода ради четырёх строк ответа, а большой diff вдобавок заполняет окно и вытесняет саму задачу. Список сортируется по размеру правки, а не по алфавиту («что тут произошло» отвечают три самых больших файла), обрезается на 25 файлах и говорит, сколько осталось. Переименование показывается тем именем, которое у файла сейчас: отправить агента читать старый путь — значит отправить его к несуществующему файлу.

- **Правка агента не затирает чужие изменения** — перед записью содержимое файла сверяется с тем, что агент читал. Случай обыденный, а ущерб молчаливый: агент прочитал файл, думал минуту, человек за это время правил тот же файл в редакторе — и агент пишет текст, собранный из СТАРОГО содержимого. Ничего не падает, работа человека просто исчезает, причём выглядит это как правка агента и находится сильно позже. Теперь расхождение называется строкой в ленте прямо перед diff-превью. Сравнивается содержимое, а не время: сохранение, не изменившее ни байта (форматирование при сохранении), конфликтом не считается, а правка внутри той же миллисекунды — считается.
- **Ошибки, которые редактор чинит сам, агент не оплачивает** — после записи файла платформа применяет свои быстрые исправления: недостающий импорт добавляет IDE, а не оплаченный ход модели. Гейт узкий и намеренно: только исправления-импорты (единственный класс, добавляющий строку и не меняющий поведение), только однозначные (два кандидата на импорт — это решение, какой библиотекой пользуется проект, и оно авторское), не больше пяти на файл (правка, которой нужно пятнадцать, — это правка, пошедшая не туда, и тихо латать её значит прятать проблему). Применённое называется строкой в ленте: молча исправленный код, который компилируется по невидимой причине, стоит доверия ко всему пути правок.

- **Детектор петель и страховка молчания** — две половины одной страховки: агент, который делает слишком много, и агент, который перестал делать что-либо. **Петля** ловится по форме последовательности вызовов: четыре одинаковых вызова подряд — это уже не повтор после сетевой ошибки, а «прочитал A → правил B → прочитал A → правил B» наивная проверка «как в прошлый раз» вообще не видит, хотя именно эта форма крутится часами. Найденная петля не просто отменяет ход, а взводит предохранитель: агент, отпущенный обратно в тот же круг, продолжил бы его. **Молчание** измеряется от последнего признака жизни, а не от начала хода: ход, который час стримил и замер, — замерший, сколько бы он ни работал. На отметке (Settings → Tools → VibeIDEA → Агент, по умолчанию 5 минут, 0 — выключено) чат говорит, что признаков жизни нет, на удвоенной — останавливает ход. Сказать и остановить одновременно значило бы отнять единственный шанс сказать «подожди, оно думает».

- **Планы переживают перезапуск IDE** — план, который агент проговаривает в начале длинной задачи, хранится данными, а не строкой, уплывающей вверх по ленте: чек-лист со статусами показывается сворачиваемой карточкой и обновляется каждым `plan`-обновлением, а сам план лежит в `.vibe/plans.json` рядом с проектом. Перезапуск посреди задачи (а перезапускают именно тогда — ставят обновление) больше не стирает контекст: при открытии чата IDE говорит, что план не закончен, сколько шагов сделано и какой шаг следующий, — иначе остаётся переписка, обрывающаяся на полуслове, и слово «продолжай», которое ничего не значит. Незнакомый статус шага считается невыполненным: ошибка в эту сторону теряет работу, потому что законченный план никто не возобновляет. Законченные планы из файла удаляются — они не отвечают ни на один вопрос, который задают позже.

- **Права на роль: ревьюер не правит то, что проверяет** — роли пайплайна получили не только преамбулу, но и полномочия, и они принуждаются механизмом, а не просьбой в промпте. Роль, чей продукт — суждение (`code-reviewer`, `security`, `qa`, `explore`, `planner`), запись файлов не получает: ревьюер, которому сказано «только отчёт», слушается в большинстве прогонов, и это ровно проблема — тот единственный прогон, где он «заодно починил» найденное, делает ревью и правку одним актом, а правку никто не ревьюил. Прогнать сборку и увидеть падение ревьюеру и QA можно (это часть отчёта), разведчику `explore` — нет. Роль живёт ровно свой шаг: обычный чат, унаследовавший права ревьюера, был бы ограничением, взявшимся ниоткуда, а это хуже отсутствия ограничения. Неизвестная роль и её отсутствие сохраняют полные права по той же причине.

- **Расход по ролям и суточный лимит на роль** — команда «VibeIDEA: расход по ролям» показывает, куда ушли токены за сутки и за неделю, отдельными строками по ролям и по целям (агент или модель), отсортированными по расходу: общая сумма говорит лишь, что месяц стоил денег, а разбивка — что ревьюер зачем-то работал на дорогой модели, и с этим уже можно что-то сделать. Деньги показываются только там, где их назвал сам провайдер, а сумма долларов с рублями не выводится вовсе — вместо неё честное «в разных валютах». Суточный лимит на роль (Settings → Tools → VibeIDEA → Агент, 0 — выключен) проверяется ПЕРЕД шагом пайплайна: на 80% чат предупреждает, на 100% шаг пропускается. Лимит именно суточный и именно на роль, потому что разорительный случай — не один дорогой ход, а ревьюер, которого сорок раз перезапустила незамеченная петля. Учёт живёт в системном каталоге IDE, а не в `.vibe`: расход — дело человека, а не репозитория, и в diff ему не место.

- **Лимит провайдера пережидается, а не превращается в ошибку** — 429 это не сбой, а очередь: провайдер сказал «через тридцать секунд», и превращать это в красную строку значит выбросить ход, который человек уже составил. Ожидание идёт по заголовку `Retry-After` самого провайдера (он знает своё окно; угадать короче — получить отказ снова, длиннее — простоять зря), а без заголовка — удвоением 2→4→8 с потолком в минуту. Столь же важно, что НЕ повторяется: неверный ключ (401/403), кривой запрос (400) и неизвестная модель (404) фатальны — три попытки лишь втрое удлинили бы путь до честного сообщения, а повтор на неизвестной ошибке это способ задолбить чужой сервер. Ожидание называется строкой в ленте: молчаливая пауза неотличима от зависания, и человек жмёт «стоп» ровно тогда, когда провайдер уже готов пустить обратно. «Стоп» во время ожидания срабатывает сразу, а не после паузы, и остановка пользователя никогда не считается сетевым сбоем.

- **Совет моделей (`/council <вопрос>`)** — один вопрос нескольким РАЗНЫМ моделям, каждая отвечает не видя чужих ответов, затем обычный ход сводит мнения: в чём согласны (это опора), в чём расходятся (это и есть открытый вопрос) и что проверить фактом. Разные модели принципиальны: одна и та же, спрошенная дважды, соглашается сама с собой, и второй ответ выглядит подтверждением, не будучи им, — поэтому дубликаты отбрасываются, а совет из одного советника не запускается вовсе и честно говорит об этом. Ответы нумеруются, а не подписываются именем модели: судья, знающий, какой ответ от знаменитой модели, соглашается со знаменитой моделью. Советники опрашиваются параллельно (совет в четыре последовательных обхода никто не использует), сломавшийся советник не роняет остальных. Настройка — «Советники» на странице «Агент», пусто = выключено.
- **Библиотекарь: агент начинает, зная, что уже записано** — перед ходом запрос сверяется с индексом базы знаний проекта (`docs/vibe/knowledge/README.md` и ещё три привычных места), и две-три подходящие записи называются агенту. Проекты копят выстраданные заметки («этот гейт нельзя чинить так», «здесь мы уже пробовали»), а агент, который их не читает, выводит их заново, хуже и за полную цену; вспомнить нужную заметку в нужный момент не успевает никто. В промпт идут ПУТИ, а не содержимое: заметка бывает на страницу, три таких стоят дороже самой задачи, и агент читает то, что счёл нужным, — так же, как человек пользуется указателем. Ничего похожего не нашлось — библиотекарь молчит: назвать «ближайшую» запись на пустом месте значит отучить читать его подсказки.

- **Чек-лист «проверь глазами» вместо слова «сделал»** — когда ход тронул то, что можно увидеть (`.tsx`, `.vue`, стили, файлы с `component`/`panel`/`screen` в имени), он заканчивается коротким списком: что открыть и на что посмотреть. Модель не видит экрана — она может быть уверена, что кнопка по центру, и ошибаться, а платит за это тот, кто открыл приложение, ожидая готовой работы. В списке отдельно названы три состояния, которые модель никогда не отрисовывает в голове: пустое, ошибочное и узкий экран. Тест компонента к осмотру не предлагается: посмотреть глазами на тест нельзя, для этого надо открыть приложение.
- **Хендофф: работа передаётся формой, а не «на словах»** — команда `/handoff` собирает передачу из состояния чата: задача, сделанные и оставшиеся шаги плана, затронутые файлы, команда проверки. Дорого терять не написанный код — он в diff, — а то, что было ВЫЯСНЕНО: какой подход уже пробовали и почему он не сработал; именно этой секции в переписке никогда нет, поэтому форма просит её отдельно. Незаполненные секции называются вслух: половинчатая форма выглядит передачей, ничего не передавая. Пустые секции помечаются, а не выбрасываются — исчезнувшая секция читается как «граблей не было», а это другое утверждение.

- **Трейс хода (`/trace`)** — что ход сделал по шагам: инструменты с длительностями, провалы, повторы. Лента показывает историю, которую агент рассказывает о себе; трейс показывает события, и расходятся они ровно там, где это важно — инструмент, который трижды переспросили, гейт, вернувший ход назад, файл, прочитанный дважды. Ничего этого в прозе не видно, а без этого честный ответ на «почему так долго и почему так дорого» — догадка. Отдельной строкой называется работа, сделанная дважды: это первое место, куда стоит смотреть. Шаг, длительность которого никто не измерял, не считается мгновенным — «не измеряли» и «ноль» это разные утверждения.
- **Чистка вывода инструментов до попадания в контекст** — полоса прогресса, перерисованная четыреста раз, одно и то же предупреждение на каждый файл, стена пустых строк: этот шум не просто велик, он учит модель, что повтор и есть суть вывода, и выталкивает настоящую ошибку из окна. Режим `auto` (по умолчанию) схлопывает повторы, оставляя первый — «то же самое ещё раз» это информация, четырёхсотый повтор нет, — и убирает строки-пустышки; `aggregate` оставляет только форму (какая строка сколько раз встретилась); `raw` и `off` не трогают ничего. Чистка идёт ДО сжатия головы-хвоста, поэтому уцелевшие строки несут смысл, а не перерисованный индикатор, и количество убранных строк называется вслух — молчаливая чистка неотличима от пустого вывода.

- **Команды проекта `.vibe/commands.json`** — описанные один раз, они едут в репозитории: коллега, склонировавший проект, получает те же «поднять окружение» и «прогнать гейты», ничего не спрашивая. Файл — это код, который кто-то другой мог написать, а исполняется он на вашей машине, поэтому команды с метасимволами оболочки и невидимыми символами отклоняются ЦЕЛИКОМ, а не экранируются: такая строка либо атака, либо ошибка, и гадать какая именно не наше дело. Первый запуск спрашивает разрешение и запоминает его для ЭТОГО текста — любая правка команды, хоть человеком, хоть пулл-реквестом, отзывает разрешение автоматически. Секреты только по имени (`${secret:GH_TOKEN}`), значение подставляется при запуске из `.vibe/.env` или окружения и в журнал не попадает; секрет не найден — команда не запускается, а недостающие имена называются, потому что пустая подстановка превратила бы команду в запрос, падающий непонятно почему. Формат — [manuals/commandsSpec.md](manuals/commandsSpec.md).
- **Config Guard: проверка конфигов при открытии проекта** — `.vibe/providers.json`, `servers.json`, `hooks.json`, `acp.json` и `commands.json` читаются один раз при открытии и проверяются на то, что обычно замечают поздно: ключ, вписанный в файл открытым текстом (файл поедет в репозиторий вместе с ним), незашифрованный endpoint наружу, логин с паролем прямо в URL, сырой IP вместо имени. Локальный `http://localhost` не ругается — локальной модели нечего шифровать от самой себя, а ложное срабатывание приучает не читать предупреждения. Предупреждение о пароле не пересказывает пароль. Нашлось пусто — IDE молчит.

- **Свой прокси для моделей и запасные цели** — прокси для запросов к моделям задаётся ОТДЕЛЬНО от системного и от прокси IDE (`http://proxy.local:3128`, `socks5://127.0.0.1:9050`, порт можно опустить): дойти до репозитория плагинов и дойти до провайдера моделей — разные задачи, и людям регулярно нужно одно без другого. Опечатка в адресе не молчит: она пишется в лог, а не оставляет человека уверенным, что туннель работает. **Failover** — это не повтор: повтор пережидает ТОТ ЖЕ провайдер, потому что тот попросил подождать, а failover уходит к другому. Поэтому переход случается только после исчерпания попыток ожидания и никогда — на неверном ключе: ключ неверен и у следующего провайдера, а переход спрятал бы настоящее сообщение за посторонним сбоем. Одна цель дважды в ходу не пробуется.

- **Автодетект локальных моделей** — команда «VibeIDEA: найти локальные модели» (и разовое предложение при открытии проекта) опрашивает привычные порты: Ollama (11434), LM Studio (1234), llama.cpp (8080), Jan (1337). Найденный сервер сам называет свои модели, и IDE показывает готовую запись для `providers.json` — ту самую, которую иначе набирают руками, хотя endpoint у всех одинаковый, протокол всегда тот же, а список моделей сервер отдаёт по первому запросу. Запись **предлагается, а не применяется**: провайдер, появившийся в конфиге потому, что что-то ответило на порту, неотличим от ошибки конфигурации, и после первого такого случая конфигу перестают верить. Сервер, который отвечает, но не отдал ни одной модели, не предлагается — провайдер с пустым списком бесполезен. Уже описанный сервер второй раз не предлагается, причём совпадение ищется по хосту и порту, а не по имени записи (`localhost` и `127.0.0.1` — одна и та же машина). Предложение можно выключить кнопкой «больше не предлагать».

- **Справка о самой VibeIDEA внутри сборки (`/help <вопрос>`)** — документация продукта едет вместе с плагином, поэтому агент отвечает по реальному тексту той версии, в которой работает, а не по памяти модели о каком-то другом продукте. `/help` без вопроса перечисляет всё, что есть; с вопросом — подмешивает в ход два-три подходящих документа целыми файлами. Копия синхронизируется скриптом `vibe-plugins/tools/syncHelp.sh`, а расхождение копии с источником валит тест `HelpBundleTest`: он и есть гейт этой синхронизации — иначе агент однажды сослался бы на файл, которого в сборке нет.
- **Дневная сводка** — в назначенное время (Settings → Tools → VibeIDEA → Агент, `ЧЧ:ММ`, пусто = выключено) IDE присылает короткую сводку: сколько прогонов, сколько файлов затронуто, что упало и сколько потрачено, с именем роли, потратившей больше всех. Осиротевшие прогоны считаются отдельно от упавших: прогон, чьё окно умерло, — это не прогон, который пошёл не так, и слияние прячет и то, и другое. Сводка отвечает на три вопроса и не больше — та, что пытается рассказать всё, превращается в отчёт, а отчёт не читают. Если IDE была закрыта, сводка придёт при открытии, но только в течение двух часов после назначенного времени: вчерашняя сводка в полдень это шум.

- **Панель «Документы»: связность вместо списка файлов** — папка отвечает на вопрос «какие файлы есть», а спрашивают обычно другое. Панель (и команда «VibeIDEA: связность документации») читает markdown проекта как ГРАФ и показывает два факта, которых в проводнике не видно: какие документы **недостижимы** от входной точки (`README.md`) — на них никто не ссылается, и их никто не найдёт, какими бы они ни были, — и какие ссылки ведут **в никуда**: переименованный файл оставляет за собой след мёртвых ссылок, на который ни один компилятор не ругается. Внешние ссылки и якоря рёбрами не считаются, якорь на существующий файл ссылкой считается, цикл обхода не зацикливает, а проект без `README.md` начинает обход с первого документа — иначе «недостижимо» оказалось бы всё, и отчёт стал бы бесполезен. Чтение идёт вне EDT и один раз на открытие: зрелая документация — это сотни файлов.

- **Правка на месте (Ctrl+K)** — выделите код, нажмите Ctrl+K и скажите, что с ним сделать: командой `/doc`, `/refactor`, `/tests`, `/explain`, `/fix` (понимаются и русские написания) или своими словами. Чат для маленькой правки — неверная форма: объяснить, какая функция, вставить её, дождаться прозы вокруг ответа и скопировать результат обратно стоит больше внимания, чем сама правка, — поэтому её в итоге пишут руками. Здесь выделение и есть вопрос, а ответ занимает его место. **`/explain` никогда не заменяет код**, а показывается отдельно: объяснение, вставленное поверх кода, — ровно тот провал, ради которого всё это разделение и сделано. Ответ, не похожий на код, отклоняется целиком — заменить работающий код извинением модели не прощают; распознаётся это по форме ответа, а не по ключевым словам, потому что слова у каждого языка свои. Правка применяется через тот же diff-превью, что и запись агента: то, что вы попросили её одной строкой, не делает результат достойным доверия невидимым. В промпт подмешиваются постоянные правила проекта — инлайн-правка, их игнорирующая, даёт код, который завернёт ближайшее ревью.

- **Поиск по смыслу (`/index`, `/find <запрос>`)** — третий способ спросить о коде рядом с grep и графом: grep отвечает «где написано ровно это», граф — «что с чем связано», и ни один не отвечает «где мы делаем то же самое другими словами», а именно этот вопрос возникает в незнакомом проекте. Файлы режутся окнами по 60 строк с перекрытием (перекрытие и есть причина, по которой совпадение на границе не рвётся пополам), пустые окна из скобок не эмбеддятся, а вендоренные деревья и бинарники не индексируются вовсе. Индекс **инкрементальный** по размеру и времени изменения файла: переэмбеддинг репозитория на каждый вопрос стоит реальных денег. Хранится в системном каталоге IDE, а не в репозитории — векторы регенерируемы, объёмны и принадлежат тому, кто за них заплатил. Слабые совпадения отбрасываются порогом: уверенный ответ, собранный из пяти наименее нерелевантных кусков, хуже честного «не нашёл». Из одного файла в выдачу попадает один кусок — иначе пять окон одного файла вытесняют всё остальное.

- **Превью: размеры экрана, живая перезагрузка, адрес для телефона и ошибки в чат** — в панели «Дизайн» появились кнопки «телефон / планшет / десктоп», и ширина меняется у САМОГО компонента, а не подделкой viewport в JS: медиазапросы тогда срабатывают по-настоящему, ради чего на телефонную ширину и смотрят. Тумблер «обновлять при сохранении» убирает цикл «правка → alt-tab → F5», от которого отказываются после десятка повторений. «Адрес для телефона» подбирает адрес машины в локальной сети и кладёт его в буфер: loopback, docker-мосты, link-local и диапазоны VPN отсеиваются — они существуют на этой машине и недостижимы с телефона, а наивная проверка «не 127.0.0.1» выдала бы адрес, который молча не работает. «Ошибки в чат» собирает ошибки страницы и необработанные отказы и кладёт их в поле ввода: скриншот сломанной страницы говорит «сломалось», а консоль — ЧТО именно. Сборщик ставится при открытии страницы, до того как та успеет упасть: иначе первая ошибка — обычно самая интересная — оказалась бы незамеченной.

- **Дисциплина минимализма и делит-лист (`/simplify`)** — предоставленная себе модель пишет больше, чем нужно задаче: обёртку вокруг одного вызова, флаг, который никто не выставляет, комментарий, повторяющий строку под собой, абстракцию ради второго случая, которого нет. Каждое добавление защитимо по отдельности, а вместе они — причина, по которой код, написанный с агентом, перестаёт читаться быстрее написанного руками. Режим (Settings → Tools → VibeIDEA → Агент): `off` / `light` («сначала переиспользуй существующее») / `full` (плюс запрет обёрток, флагов-пустышек и комментариев-повторов) / `ultra` (каждая строка обязана быть необходимой). Это лестница, а не переключатель: прототип и платёжный путь хотят разной дисциплины. Команда **`/simplify`** читает текущий diff и возвращает делит-лист строками «файл:строка — что убрать — почему»: ревью спрашивает «правильно ли это», а делит-лист — «что отсюда можно убрать, ничего не потеряв», и этот вопрос не задаёт никто, потому что час назад каждая строка казалась нужной. Ответ не в формате называется непрочитанным, а не выбрасывается: делит-лист, тихо потерявший половину пунктов, хуже отсутствующего.

- **Spec-First: панель спек** — существенная фича описывается до кода двумя файлами в `docs/specs/<id>/`. `PRODUCT.md` говорит, что должно быть ПРАВДОЙ для человека, нумерованными инвариантами: спор о поведении через месяц становится ссылкой на номер, а не спором о воспоминаниях. `TECH.md` говорит, как это сделано, с ссылками на реальные файлы — спека, не назвавшая ни одного файла, это пожелание, и она протухает за неделю, потому что с существующим кодом её ничто не связывает. Команда «VibeIDEA: спеки проекта» показывает, что есть, сколько в каждой инвариантов и чего не хватает, и заводит новую спеку из шаблона. Отсутствующий файл — ошибка, слабый файл — предупреждение: на черновик не кричат, иначе черновик начнут писать не здесь. Существующие файлы никогда не перезаписываются.
- **Оптимизация под метрику (`/measure <команда>`)** — для задач, у которых нет порога «правильно»: ускорить, урезать размер сборки, поднять покрытие. Модель, работающая над такой задачей, объявляет победу прилагательным («стало заметно быстрее»), а честный ответ — измерение до и измерение после. Первый запуск становится базой, каждый следующий сравнивается с ней и говорит, стало лучше или хуже и на сколько процентов. Из вывода берётся ПОСЛЕДНЕЕ совпадение шаблона: сборка печатает числа по дороге, а сводку, которую читают, — в конце. Направление («меньше лучше» или «больше лучше») задаётся настройкой и решается ДО работы: решать после — способ назвать регрессию успехом. Числа не нашлось — так и говорится, а не подставляется ноль: ноль превратил бы отсутствие измерения в отличный результат.

- **Мост в Telegram** — поставить задачу, следить за длинным прогоном и получить ответ, не сидя за компьютером. Бот **ваш собственный** (минута у @BotFather), токен живёт в защищённом хранилище ОС, наш сервер в переписке не участвует вовсе. Первое сообщение от неизвестного чата не выполняется: IDE показывает владельцу запрос «разрешить этот чат», а чужому отвечает одной строкой — без имени машины, без списка проектов, без намёка на то, что здесь есть. Команды: обычный текст — задача агенту, `/projects` — какие окна открыты, `/use` — куда слать, `/digest` — сводка за сутки, `/menu` — то же кнопками, `/stop`. Прогресс **редактирует одно сообщение**, а не шлёт поток: сорок уведомлений о прогоне — это телефон с выключенными уведомлениями, а вместе с ними и пропущенный ответ. Прокси для Telegram задаётся отдельно от прокси моделей — блокируются они в разных местах. Как поднять: [manuals/telegramBridge.md](manuals/telegramBridge.md).

- **Обучение с накоплением прогресса (`/learn <навык>`)** — обычный чат учит плохо по двум структурным причинам: он начинает каждый урок с нуля, поэтому десятый повторяет первый, и он ничего не спрашивает заранее, поэтому учит среднего человека средней версии темы — ровно тому, что интернет и так отдаёт бесплатно. Отсюда две вещи. **Миссия — гейт, а не анкета**: пока не отвечено, зачем навык нужен именно сейчас, что ученик уже умеет сам и как выглядит реальный результат, урока нет; вопросы задаются по одному в чате, потому что форму закрывают. **Сложность выбирает не модель, а результат**: две сильные попытки подряд поднимают планку, две слабые опускают — по одной не считается, потому что один плохой раз это плохой день, а один хороший — везение. Прогресс лежит в `.vibe/learning/<навык>.json` рядом с проектом: навык обычно учат ДЛЯ этого проекта, и коллеге, взявшему ветку, полезно видеть, что уже пройдено. Учит агент **по источникам из `RESOURCES.md`, а не по памяти**: нужного там нет — он обязан сказать это и спросить, где взять, потому что пробел ученика дороже гладкого ответа.

- **План выкатки (`/deploy`)** — что нужно сделать, чтобы проект вышел из ноутбука. Тип проекта определяется по файлам (Dockerfile побеждает догадки — это уже ответ автора на вопрос «как собирать»), а план строится в единственном работающем порядке: сперва всё локальное и обратимое, и только потом внешнее — чтобы внешняя часть начиналась из состояния, которое уже собирается. Шаги «наружу» (реестр, хост, домен, сертификат) помечены отдельно: они стоят денег, создают ресурсы на чьё-то имя и не отменяются, поэтому каждый выполняется только после отдельного «да». Отдельно называются вещи, которые замечают поздно: `.env` в корне (секрет в репозитории станет секретом в образе, а образ копируют куда охотнее репозитория) и отсутствие `.dockerignore` (в образ уедет всё, включая `.git`). Интеграции с конкретным облаком нет — эти шаги делает человек или агент по его команде.

- **Проверка дизайн-контура и карта построенного** — «VibeIDEA: проверка дизайн-контура» отвечает на вопрос, который иначе выясняется опытным путём: написан ли дизайн-контекст и где, достижима ли страница для замера и почему нет, сколько правил активно (пол качества и вкусовые — и их сумма СХОДИТСЯ с общим числом: арифметика, которая не сходится, — быстрый способ потерять доверие ко всему отчёту), не опечатан ли id в осознанных отклонениях. Опечатка там не выключает ничего, а проект считает, что выключила, — и это молчаливое расхождение живёт месяцами. «VibeIDEA: снять карту построенного» пишет `.vibe/design/uiKit.md` по коду: объявленные токены, классы и экспортированные компоненты. Замер отвечает «что победило на этом экране», карта — «что вообще объявлено в проекте», и только вторая мешает написать десятую слегка другую кнопку, не зная о девятой. Карта — черновик: разбор синтаксический, что-то попадёт зря, чего-то не хватит, и существующий файл не перезаписывается без спроса — свежий скан затёр бы ровно те правки, ради которых карту и держат.

- **Находимость страницы — десятая категория проверок** — тот же замер отвечает на вопрос, невидимый и на скриншоте, и в превью: найдут ли эту страницу. Проверяется то, что считается на самой странице, без внешних сервисов и без похода в сеть: есть ли `<title>` и не обрежется ли он, один ли на странице `<h1>`, заполнено ли описание, объявлен ли язык, есть ли `viewport` и не запрещает ли он масштабирование, задан ли канонический адрес и не относительный ли он, не осталось ли `noindex` от стенда, кодировка, иконка вкладки, `og:title`. Часть из них — пол качества, а не вкус: страница без заголовка, без языка или с запрещённым зумом сломана для человека, а не немодна. Правила молчат, если сборщик метаданные не собирал: «не смотрели» и «пусто» — разные утверждения, и обвинять страницу в отсутствии заголовка, о котором её не спрашивали, нельзя.

- **Отладка TypeScript и PHP** — клиент отладки поставляется с IDE (LSP4IJ умеет Debug Adapter Protocol), сам адаптер ставится снаружи, как и языковой сервер: `js-debug-adapter` из npm, `vscode-php-debug` из composer. Доктор языковых серверов проверяет и их, отдельной секцией — отсутствие отладчика ломает не переход к определению, а точки останова, и общий список отправлял бы ставить не тот пакет. Подключение — через настройки LSP4IJ. Почему не «из коробки»: вкомпилировать адаптер значит везти чужой рантайм, принять его лицензию за пользователя и вырасти на десятки мегабайт ради того, что нужно не каждому; взамен отсутствие сделано видимым. Как поставить: [manuals/debugging.md](manuals/debugging.md).

- **Офлайн-режим и кеширование промпта** — тумблер «офлайн» останавливает всё, что уходит наружу: запросы к облачным моделям и эмбеддинги (а они отправляют содержимое файлов). Локальные провайдеры продолжают работать. Проверка стоит в ЕДИНСТВЕННОЙ двери наружу, а не в интерфейсе: проверка в интерфейсе — это напоминание, а обещание «содержимое файлов не покинет машину» должно исполняться механизмом. **Кеширование промпта**: большая неизменная преамбула (правила проекта, приложенные файлы) помечается как кешируемая, и повторяющаяся плата превращается в разовую. Помечается только то, что действительно велико: запись в кэш сама по себе не бесплатна, и кешировать две строки — убыток.

- **Глубина рассуждений на языке каждого провайдера** — один ползунок (off / low / medium / high) переводится в диалект вендора: Anthropic получает бюджет токенов, OpenAI — слово, Gemini — свой бюджет. Это принципиально: `reasoning_effort`, отправленный Anthropic, не делает ничего и молча, и человек справедливо решает, что настройка декоративная. Бюджет всегда оставляет место самому ответу — бюджет вровень с `max_tokens` API отклоняет, и выглядит это как «модель молчит». Поля рассуждений подмешиваются ДО пользовательских `extraBody`, чтобы модель со своим написанием могла их переопределить.

- **Идемпотентность запуска и территориальные блокировки** — `POST /run` принимает `idempotencyKey`: пока прогон с этим ключом идёт, повторный запрос не начинает второй, а возвращает тот же `sessionId`. Вебхук, доставленный дважды, — случай обычный, а не экзотический, и без ключа это два агента в одних файлах, где второй побеждает, потеряв половину правок первого. Поиск идёт по всем открытым окнам: вебхук не знает, какой проект открыт. Рядом — **территория прогона**: набор путей, который прогон занимает на время работы; пересечение считается по префиксам с поправкой на то, что `src` включает `src/ui`, а `src/ui` и `src/uikit` — разные углы (ловушка голого `startsWith`), и что «весь проект» пересекается со всем, иначе он был бы способом проскочить проверку.

- **Снимок превью в чат и фоновые команды** — кнопка «снимок в чат» в панели «Дизайн» прикладывает картинку превью к сообщению: описывать вёрстку словами дороже, чем показать её, и именно в описании берутся ошибки — «кнопка съехала» ничего не значит без экрана. Картинка **прикладывается, а не отправляется**: о чём спрашивать, решает человек. Команда **`/bg <команда>`** запускает долгое (сборку, тесты, watcher) вне хода: ход не ждёт, а о завершении приходит строка со временем работы и хвостом вывода — «упало» без последних двадцати строк всё равно отправляет в терминал.

- **Занятый порт и никаких зомби** — перед стартом сервера порт проверяется, и если он занят, IDE говорит об этом с номерами процессов-владельцев. Причина в том, что фреймворк, найдя порт занятым, обычно молча уезжает на соседний: конфигурация проекта называет один порт, деплой ждёт его же, а сервер работает на другом — и это оборачивается днём вопросов «почему на телефоне ничего нет». При остановке гасятся сначала потомки процесса, потом он сам: dev-сервер обычно это оболочка, породившая node, и убийство одной оболочки оставляет node держать порт — тот самый зомби, которого встречают на втором запуске. Вежливая остановка ждёт три секунды, потом становится невежливой.

- **Повтор прогона и сравнение** — в диспетчерской у завершённого прогона есть «повторить задачу»: слова берутся из записи, а не набираются заново, поэтому сравниваются модели, а не формулировки. Рядом со строкой прогона появляется вывод сравнения: кто оказался быстрее и совпал ли исход. Сравнивается намеренно узкое — время, шаги, файлы: «качество» не число, и делать вид, что число, значит выдать вердикт, который начнут цитировать не проверяя. Незаконченный прогон не сравнивается вовсе — уверенный вывод из половины данных хуже отсутствия вывода.

- **Схемы конфигов, диагностика, `/undo` и `/blame`** — четыре вещи, которые убирают самый частый источник «почему не работает». **JSON-схемы** для `.vibe/commands.json`, `pipelines.json`, `hooks.json`, `servers.json` и `providers.json` дают автодополнение и подсветку прямо в редакторе: неизвестная роль, опечатка в имени события или в `readyCheck` подсвечиваются до сохранения, а не всплывают предупреждением в чате через час. Списки значений в схемах сверяются тестами с кодом — схема, разошедшаяся с парсером, подсказывала бы то, что он отвергнет. **«VibeIDEA: диагностика»** собирает в один отчёт то, о чём иначе расспрашивают: сборка, провайдеры (сколько с ключом, сколько локальных), конфиги с находками Config Guard, офлайн-режим, аудит, поиск по смыслу, правила проекта и база знаний; проблемы идут первыми, отчёт копируется кнопкой. **`/undo`** возвращает рабочую папку к последнему чекпоинту и прямо называет, что именно откатывает — молчаливый откат боятся использовать. **`/blame <файл>`** показывает коммиты, тронувшие файл, и просит объяснить по ним, почему код такой: модель, читающая только текущий файл, видит «что написано» и додумывает «почему», а история говорит это прямо — и уберегает от уверенного переписывания решения, принятого осознанно.

## 🤖 Агентская обвязка

- **FIM-автокомплит из реестра провайдеров** — серый инлайн-текст при наборе: модель с `fim: true` (openai-протокол; напр. qwen2.5-coder в Ollama, codestral) получает legacy `/completions`-запрос с prefix/suffix полями API (спец-токены — дело сервера). **Форма запроса зависит от места курсора**: пустая строка — однострочное дополнение; курсор внутри набранной строки — заполнение середины; хвост строки в 1–3 символа (`)`, `;`) — модель ПЕРЕПИСЫВАЕТ строку целиком, а не дописывает к скобке ещё одну; сразу после принятой подсказки — многострочное продолжение со следующей строки (факт принятия выводится по документу: курсор там, где кончился наш текст, и текст этот позади него). Курсор в начале строки, справа от которой чужой код, — **запрос не отправляется вовсе**: такая подсказка всё равно была бы мусором. Контекст 25 строк, для локальной модели 12 (у неё каждый токен стоит времени); строки длиннее 500 символов пропускаются; max_tokens 300 (облако) / 96 (localhost). Ответ чистится: строки-пояснения (почти целиком не-ASCII и без пунктуации кода) выбрасываются, CJK-комментарий после кода срезается вместе с комментарием — но легальный юникод (русский комментарий, строковый литерал, эмодзи в имени теста) остаётся нетронутым. Кэш подсказок по ключу (файл, строка, колонка, нормализованный префикс — отступы и лишние переводы строк не считаются изменением, иначе кэш не попадал бы никогда), LRU с настраиваемым размером. Метрики: попадания кэша, отказы «не предсказываем», задержка модели p50/p95 — действие «VibeIDEA: метрики автодополнения». Настройки: Settings → Tools → VibeIDEA → Агент → «Автодополнение (FIM)».
- **Пайплайны (`.vibe/pipelines.json`)** — линейные цепочки шагов-ролей поверх ACP-агента (кнопка «Пайплайн…»): роли из закрытого списка (неизвестная — ошибка со списком доступных), шагу передаются пути затронутых файлов (накапливаются) и резюме последнего шага (не содержимое!), провал останавливает хвост со статусом «пропущен», `continueOnFailure`/`ignorePreviousArtifacts` — по спеке VibeIDE; битая запись не роняет файл, предупреждения — до списка. Спека: [manuals/pipelinesSpec.md](manuals/pipelinesSpec.md).
- **Каталог LLM-провайдеров (`.vibe/providers/` + `providers.json`)** — прямой стриминговый чат с любым openai/anthropic/gemini-совместимым endpoint без ACP-агента: записи `LLM: провайдер · модель` в той же панели. Реестр собирается из четырёх слоёв (слабый → сильный): глобальный каталог `~/.vibe/providers/*.jsonc` → засеянный проектный каталог (по файлу на провайдера; OpenCode Go/Zen, OpenRouter, MiniMax, Z.AI, Kimi, DeepSeek активны из коробки, OpenAI/Anthropic/Alibaba Coding Plan/Meta Muse/Ollama/vLLM лежат выключенными; внутри каталога — наложение по алфавиту файлов) → глобальный `providers.json` → проектный `providers.json` (перекрытие по `id` по-полево, мерж моделей по id) — каталог играет роль встроенных провайдеров и не может заглушить пользовательский файл. Тумблер `active` на провайдере и модели: неактивные участвуют в слиянии (их можно `extends`-ить и включать переопределением `{"id":…,"active":true}` в своём `providers.json`), но не видны в списках; запись без `active` считается активной. Провайдер, для которого ключ не найден нигде (хранилище → `.vibe/.env` → `~/.vibe/.env` → env ОС), **в сеть не опрашивается и в пилюлю «Модель ▾» не попадает**: строка, падающая на первом же запросе, хуже отсутствующей. Итог опроса каталогов — одна строка в чате вместо строки на провайдера, и состояния в ней различаются по смыслу: «обновлено», «без ключа» (с адресом настроек), «ключ отклонён» (401/403 — ключ есть, но не принят), «локальный сервер не запущен» (ollama/vLLM), «не ответили» с причиной. Изменения подхватываются без рестарта: ключ из настроек — сразу, правки файлов (`providers.json`, каталог `providers/`, `.vibe/.env` обоих уровней) ловит VFS-вотчер с дебаунсом, открытая панель перечитывает реестр и каталоги моделей сама; модели каталога включаются на странице «Модели» (по умолчанию скрыты — curated-список). Вшитых моделей нет — список подтягивается с каталога провайдера (`models.fetch`); **каталоги кэшируются**: на старте пилюля «Модель ▾» сразу полна списком из прошлого сеанса (в чат уходит строка с возрастом кэша), а сеть опрашивается фоном и **параллельно** по всем провайдерам — раньше список наполнялся одним пакетом в конце последовательного обхода и ждал таймаута каждого мёртвого endpoint. В кэш пишется только успешный ответ: 401 или таймаут оставляют вчерашний каталог в силе, а смена `baseURL`/`models.fetch.url` его обесценивает (кэш — регенерируемый файл в системном каталоге IDE, не в `.vibe`); кастомная модель в `models.static` (фикс-параметры, `extraBody`-квирки, `vision:false`, `fim`) помечается в списке бейджем «кастом» — если перестала отвечать, возможно, у провайдера её больше нет. JSONC, битая запись/файл не роняет реестр, `extends`-клоны (в т.ч. поперёк файлов и от неактивных записей), `order`. Ключи — только `apiKeyRef` (хранилище ОС; общий ref = один ключ на несколько провайдеров, как у OpenCode Go/Zen) / `apiKeyEnv` + `.vibe/.env` (файлы можно коммитить); localhost-провайдер помечается «локальная модель»; реестр сканируется Config Guard (не-HTTPS, сырой IP, секрет в headers/query — предупреждения в чате). Спека: [manuals/providersSpec.md](manuals/providersSpec.md).
- **Чекпоинты на каждое сообщение** — git-снимок всей рабочей папки перед каждым сообщением агенту (временный индекс: HEAD и ваш индекс не трогаются; снимок — dangling-коммит в `.vibe/checkpoints.jsonl`); строка чекпоинта в ленте кликабельна (паттерн VibeIDE): клик → подтверждение → откат (файлы, созданные после снимка, не удаляются); правки мимо чата входят в снимок. Не-git-проект — честное «недоступны».
- **Diff-превью перед каждой записью агента** — контракт VibeIDE: любой `fs/write` показывает диалог «Было → Станет» (настоящий диффер платформы) с кнопками Применить/Отклонить ДО записи на диск; закрытый диалог = отказ; запись без изменений применяется молча.
- **Чат по дизайн-системе VibeIDE (и лучше)** — пузырь (радиус 8, токен темы) только у ваших сообщений, прижат вправо; ответ агента — полной шириной без рамки, с капом ширины строки для читаемости в широкой панели (у оригинала капа не было); tool-calls — тихие карточки (радиус 4); чекпоинты — центрированные строки-призраки; таймстампы 11px нейтральные; длительность ответа в мете по завершении; DnD файлов из дерева — чипами контекста. Все цвета — токены `Vibe.Chat.*` / `Vibe.Composer.*`.
- **Композер (паритет с VibeIDE)** — скруглённый блок с полем «План, @ для контекста» (автовысота 60–500 px, дальше скролл; Enter — отправить, Shift+Enter — перенос, Esc — стоп при генерации, Backspace в пустом поле снимает последний чип, Cmd/Ctrl+Backspace — все чипы; клик по пустому месту возвращает фокус). В пустом чате композер стоит **сверху** и под ним чипы «Файл <активный>» / «Модель Провайдер:модель» и — пока в истории один тред — 4 «Подсказки» (клик отправляет); когда тредов больше, вместо подсказок блок «Прошлые чаты». После первого сообщения композер переезжает **под ленту**. Ряд иконок справа: скрепка (изображения png/jpg/webp/gif — выбор, вставка из буфера, перетаскивание), ▷ «продолжи» (текст настраивается: Settings → Tools → VibeIDEA → Чат), Отправить ↔ Стоп. Ряд пилюль: «Режим ▾» (режимы сессии ACP-агента — Plan/Accept Edits/… — переключение через `session/set_mode`; у прямого LLM скрыта), «Модель ▾» (один список с поиском: агенты ACP + модели провайдеров, ✓ у текущей, метка «кастом» у рукописных static-моделей; выбор запоминается на проект; без единой цели — «Нужен ключ провайдера» → настройки), иконки «Пайплайн…» и «Настройки». Slash-меню: `/` в начале сообщения — «Команды чата» (`/commit` — уходит тексту модели, `/skill:` — переключает в список скиллов), `/skill:` в любом месте — скиллы из `.vibe/skills/<id>/SKILL.md` (id = папка, описание из frontmatter `description:` или первой строки; Enter/Tab вставляет `/skill:имя `; пустые состояния по спеке; `/watch` и `/shot` появятся вместе со своими пайплайнами). Один ход за раз: во время генерации Enter ставит текст и вложения в **очередь** (жёлтая полоса «📌 В очереди … (N)» с × у каждой заметки), очередь сливается в следующий ход. Картинка + модель с `vision: false` — блокирующая ошибка; агент без `promptCapabilities.image` — уведомление, картинки не уходят.
- **История чатов** — каждый разговор — персистный тред в глобальном сторе IDE (JSON в конфиг-каталоге, запись с дебаунсом 1,5 с; треды переживают перезапуск и видны из всех проектов). Тред штампуется проектом создания; треды «без проекта» видны везде. Три поверхности: блок «Прошлые чаты» на лендинге (первые 3 + «Ещё N…»/«Свернуть»), выпадашка «история ▾» в ряду пилюль (поиск «Фильтр…» с автофокусом) и правая рейка «История» 280px (кнопка в строке вкладок; по умолчанию свёрнута; группировка «Сегодня/Вчера/Последние 7 дней/Последние 30 дней/Ранее»). Скоуп «Этот проект / Все проекты +N» (виден только при чужих тредах; «Этот проект» = свои + без проекта; выбор синхронен во всех поверхностях). Строка треда: заголовок = первое сообщение пользователя, бейдж проекта у чужих, пилюля «N · Сегодня/Вчера/23 авг»; на ховере — переместить в этот проект / дублировать / удалить (двухшаговое ✕/✓ без диалога). Кап 500 сообщений на тред (настраивается) с маркером обрезки (при повторных обрезках счётчик накопительный). Картинки в LLM-историю уходят только из последних 4 сообщений пользователя (стоимость и защита от «отравленного» запроса; при отказе провайдера картинки из последнего сообщения убираются автоматически).
- **Поиск по истории** — лексический офлайн-движок по всему транскрипту (веса: первое сообщение ×12, ваше ×6, ответ ×2, служебное ×1; бонус за все термины; сатурация 3 вхождения), порядок выдачи — по свежести; под заголовком строка-цитата «Вы:/Ответ:/В переписке:», клик по ней открывает тред **на этом сообщении** (скролл + подсветка, гаснущая через 2,6 с); в скоупе «Этот проект» совпадения чужих проектов не теряются — кнопка «Найдено ещё N в других проектах — показать».
- **Вкладки чатов** — строка 34px над лентой: ярлык = первые 22 символа первого сообщения («Новый чат» у пустого), полный текст в тултипе, × на ховере (тред остаётся в истории), «+» (пустой текущий тред переиспользуется), лимит открытых вкладок (дефолт 5, настройка) с тихим выселением старейшей; набор и активная вкладка переживают перезапуск (на проект). Черновик композера и выбранная модель/режим — свои у каждого треда (черновики — до перезапуска, осознанно). Возобновление треда LLM-провайдера продолжает разговор с полным контекстом; возобновление ACP-треда открывает новую сессию агента (транскрипт виден, контекст процесса не восстановим).
- **Команды палитры (VibeIDEA)** — «История чата» (открыть выпадашку), «Экспортировать историю текущего проекта» (Markdown-стенограмма или JSON), «Удалить историю текущего проекта» (только свои треды, с предупреждением), «Привязать историю без проекта к текущему».
- **@-контекст** — `@` в поле открывает меню под полем (фокус остаётся в поле): Выделение / Недавние / Воркспейс / Файлы / Папки; набор текста в корне ищет файлы и папки сразу (subsequence-матч, ≤100, дебаунс 300 мс); клавиатура: ↑/↓ циклично, Alt±10, Cmd/Ctrl — края, →/Enter — выбрать/провалиться, ← — назад, Backspace — символ фильтра / уровень вверх / закрыть и стереть `@`, Esc. Выбор — чип над полем (иконка + имя, для выделения `имя (N1-N2)`, × — убрать, клик открывает файл/диапазон/папку). При отправке дополнительно разбираются набранные вручную `@"путь с пробелами"`, `@путь`, `@selection`, `@workspace`, `@recent`, `@agent` (AGENTS.md + .vibe/rules.md), `@sym:Имя`, `@folder:путь`; неразрешённое не блокирует отправку — предупреждение в ленте. На проводе: ACP — блоки `resource` (текст файла/выделения; >100k символов — `resource_link`) и `image`; прямой LLM — блоки `<context ref="путь#L…">` после текста и image-части (OpenAI/Anthropic/Gemini).
- **Ключи провайдеров в защищённом хранилище** — Settings → Tools → VibeIDEA → Провайдеры: поле ключа на каждого активного провайдера реестра (подсказка карточки называет источник записи: глобальная `~/.vibe`, проектная `<проект>/.vibe` или «глобальная + проектное переопределение»), значение уходит в PasswordSafe (Keychain) под `apiKeyRef` или id провайдера (общий `apiKeyRef` = один ключ на несколько карточек: близнецы обновляются сразу, пустая карточка-близнец ключ не стирает). Кнопка **«Проверить и сохранить»** запрашивает каталог моделей введённым ключом и, если провайдер его принял, кладёт ключ в хранилище и обновляет модели без рестарта (у endpoint без авторизации так и написано — «ключ этому endpoint не нужен», ложного «действителен» не будет); ключ, набранный поверх во время запроса, не затирается. Apply тоже перечитывает реестр открытой панели. Приоритет резолва: хранилище → `.vibe/.env` проекта → `~/.vibe/.env` → env ОС. В файлах ключи не живут никогда.
- **Диспетчерская агентов** — тулвиндоу снизу: прогоны, за которыми никто не смотрел (задачи входящего HTTP API и пайплайны). Строка прогона: цель, источник, статус с причиной **словами** («окно закрылось, не завершив прогон», а не код), шаги против лимита, число изменённых файлов, агент/модель, время. Сводка сверху всегда печатает числа явно, **включая нули** («требуют внимания 0»): отсутствие строки читалось бы как «всё хорошо», а это утверждение нельзя делать умолчанием. Фильтры «Все / Работают / Завершены / Требуют внимания» и поиск по цели и цели-агенту. Журнал `.vibe/agent-runs.jsonl` **переживает перезапуск IDE**; брошенный прогон определяется по факту, а не по подозрению — окно раз в 30 с отмечается в своих записях, и прогон признаётся брошенным, только если владевшее им окно молчит дольше трёх пропусков (второе окно на том же проекте живым мёртвым не считает). Пишутся **только метаданные** — ни промптов, ни ответов модели, ни аргументов инструментов. Усечение по лимиту (500) и сроку (30 дней) **не трогает незавершённые** прогоны. Обычная переписка в журнал не идёт: у неё есть история чатов. Спека: [manuals/agentRunsSpec.md](manuals/agentRunsSpec.md).
- **Agent Skills (`.vibe/skills/<id>/SKILL.md`)** — переносимые рецепты для модели. `/skill:<id>` в композере: список с описаниями из шапки, а при отправке **тело навыка уходит модели** (ACP — блоком `resource` с `skill://<id>`, прямому провайдеру — `<skill ref="<id>">`); несколько навыков в сообщении — все, без повторов. Формат — открытый контракт Agent Skills: на верхнем уровне шапки только `name`, `description`, `license`, `allowed-tools`, `compatibility`, `metadata` (своё — под `metadata`). Валидатор (действие «VibeIDEA: проверить скиллы проекта» и проверка при каждом вызове): ошибки — нет шапки/`name`/`description`, `name` не совпал с папкой, лишний ключ верхнего уровня, пустое тело, вложение уводит за пределы `.vibe/skills`; предупреждения — слишком длинное описание, тело больше 100 000 символов, каталог `scripts/` рядом. Сломанный навык **не отправляется** и называет причину строкой в ленте; в списке `/skill:` он виден с пометкой, а не исчезает. Тело проходит тот же фильтр контекста, что и файлы проекта. Набор готовых навыков засевается в проект. Спека: [manuals/skillsSpec.md](manuals/skillsSpec.md).
- **Защита контекста от отравления** — всё, что уходит модели (файлы из @-контекста, чтение файла по запросу агента), проходит через один фильтр: **невидимые символы вырезаются молча** — zero-width, мягкий перенос и теговый блок Unicode U+E0000–E007F, которым прячут инструкции в строке, одобряемой человеком глазами; **bidi-переопределения** («Trojan Source») тоже; **фразы-инструкции** («ignore previous instructions», «теперь ты другой», `<system>`, русские аналоги) — только отмечаются строкой «🛡 контекст», без правки чужого файла; **секреты** отмечаются всегда и по настройке маскируются в отправляемом тексте (файл на диске не меняется никогда). Прямому провайдеру контекст уходит с явной подписью, что это данные, а не инструкции. Заголовки и виды tool-call'ов от агента нормализуются (одна строка с капом, закрытый список видов) — они уходят в аудит, хуки и предохранители. При первом открытии незнакомого репозитория — одна поясняющая строка (не блокирует, не повторяется). Настройки: Settings → Tools → VibeIDEA → Агент → «Контекст: что уходит модели».
- **Входящий HTTP API (дёрнуть агента из CI, бота, крона)** — Settings → Tools → VibeIDEA → Агент → «Входящий HTTP API» (выключен по умолчанию), порт `0` = любой свободный. `GET /health` и `POST /run` с телом `{task, sessionId?, wait?}`; ответ — `{sessionId, status}`, где `sessionId` = id треда чата (переживает рестарт, открывается вкладкой). Контракт VibeIDE перенесён дословно — скрипты работают в обоих продуктах. Безопасность: слушается **только** `127.0.0.1` (настройки «слушать снаружи» нет), адрес клиента проверяется на loopback повторно, заголовок `Host` обязан быть локальным (защита от DNS rebinding), `Authorization: Bearer` с константным сравнением, тело до 1 000 000 байт, CORS-заголовков нет (страница не прочитает ответ). Токен генерируется при первом включении и живёт в хранилище ОС, а не в синхронизируемых настройках; действия «показать токен» и «перевыпустить токен» — в Find Action. Ход идёт тем же путём, что и набранный руками: очередь, предохранители, хуки, VERIFY-GATE. Спека: [manuals/httpApiSpec.md](manuals/httpApiSpec.md).
- **Markdown в пузырях сообщений** — модели отвечают разметкой независимо от того, просили её или нет, поэтому жирный текст, курсив, инлайн-код, ссылки, заголовки и списки рендерятся, а не показываются звёздочками. Это не украшение: неразвёрнутый список шагов читается как один абзац — ровно тот случай, когда шаг пропускают. **Экранирование идёт первым**: ответ модели — недоверенный текст, и `<img src=x onerror=…>` обязан отобразиться символами, а не разметкой; ссылки становятся кликабельными только для http(s)/file/mailto. Заголовок рисуется жирной строкой, а не `<h1>` — пузырь чата не документ. Обычный текст и очень длинные ответы остаются простым текстом: HTML-вид перекладывает всё на каждое изменение и мигал бы на стриминге.
- **Свёртка длинных код-блоков** — листинг длиннее заданного числа строк (по умолчанию 24; `0` отключает) показывается началом со ссылкой «развернуть (ещё N строк)». Длинный код иначе отодвигает ответ агента за край экрана, а ответ — то, чего человек ждёт. **«Скопировать код» всегда копирует блок целиком**, а не видимую часть: молчаливая потеря куска — тот отказ, который замечают позже всех. Настройка — Settings → Tools → VibeIDEA → Чат.
- **Тулвиндоу «Аудит»** — журнал `.vibe/audit.jsonl` живьём: панель **дочитывает файл с того места, где остановилась**, а не перечитывает целиком (при ротации на 10 МБ это разница между «мгновенно» и «секунды на каждый тик»). Ротация и очистка распознаются по смене идентификатора файла, а не по размеру — подмена файла той же длины иначе осталась бы незамеченной, и смещение указывало бы в середину чужого журнала; в такой момент панель честно пишет, что читает с начала. Недописанная строка переносится на следующий тик, вид ограничен последними 2000 строк. Фильтр «только неудачи», «следить» с автопрокруткой.
- **Звук уведомления** — три события агента: ход завершён, ход остановлен гейтом, агент ждёт подтверждения (последнее важнее прочих — там человек нужен прямо сейчас). По умолчанию звук **молчит, пока окно активно**: он для того, кто отвернулся, а сигнал в лицо смотрящему на экран заканчивается тем, что звук выключают совсем. Подряд идущие события (шаги пайплайна) объединяются окном в 1,5 секунды. Встроенный сигнал **синтезируется на месте** — ни ассетов, ни зависимостей, одинаково на всех платформах; свой файл проверяется **попыткой открыть**, а не по расширению, потому что набор читаемых форматов зависит от машины, и молча не играющий файл хуже честного отказа. Громкость по логарифмической шкале (линейный ползунок иначе даёт 95 % на середине). Настройки и «Прослушать» — Settings → Tools → VibeIDEA → Чат.
- **Язык интерфейса: база в бинаре, языки — файлами** — Settings → Tools → VibeIDEA → Интерфейс → «Язык интерфейса». Базовый язык (русский) **вкомпилирован** и служит подложкой: ключа нет в переводе — показывается базовая строка, а не пустая кнопка, поэтому половина перевода уже полезна. Остальные языки — файлы `~/.vibe/lang/<код>.json` рядом с рабочими папками: положили `de.json` — язык появился в списке, удалили — исчез. **Свой второй язык (английский) поставляется тем же файлом**, что и чужой: правила проверены на себе. Файл базового языка не засевается (иначе он навсегда заморозил бы сегодняшние формулировки), но его можно создать кнопкой «создать файл базового языка для правки» — тогда перекрытие осознанное. Папка читается один раз при старте: удаление файлов под работающей IDE ничего не ломает. Пропавший язык не залипает: сохранённый код без файла откатывается на системный, тот — на базовый. Ключи плоские точечные, подстановки именованные (`{count}`) — значение не пришло, на экране остаётся видимый `{count}`, потому что молчаливое удаление прячет ошибку. Формат: [manuals/langFileSpec.md](manuals/langFileSpec.md). Каталог **общий для всех наших плагинов** (718 ключей) и покрывает интерфейс целиком: чат и композер, история, настройки, пикеры, терминал, дизайн-панель и её гейт, хуки, скиллы, предохранители, аудит, серверы, `/watch`. Не переводится и переводиться не должно только то, что человек не видит: регэкспы детекторов, преамбулы ролей пайплайнов, тело ответа HTTP API и значения в `.vibe/codeGraph.json` — это форматы и контракты, у каждого исключения записана причина.
- **Тонкие скроллы во всей IDE** — Settings → Tools → VibeIDEA → **Интерфейс**: «Толщина скроллов, px» (по умолчанию 4; `0` возвращает штатные 10–14 px платформы). Значение применяется сразу ко всем открытым окнам и действует везде — дерево проекта, редактор, наши панели, всплывающие списки (в платформе точечно пропатчен `JBScrollBar`, запись в FORK_CHANGES.md; ключ `vibe.scrollbar.thickness` объявлен нашим плагином).
- **Без рекламы платных IDE JetBrains** — платформа умеет показывать в редакторе баннер «*.tsx files are supported by WebStorm» (советник плагинов апстрима). В VibeIDEA такие файлы поддержаны через LSP, поэтому предложение **выключено по умолчанию**; тумблер «Предлагать платные IDE JetBrains для „неподдерживаемых“ файлов» — там же, Settings → Tools → VibeIDEA → Интерфейс, применяется без рестарта. Используется штатный флаг платформы `ide.try.ultimate.disabled` (правок платформы нет); явное решение пользователя не перетирается при обновлении.
- **Видимость моделей (страница «Модели»)** — Settings → Tools → VibeIDEA → Модели: сворачиваемые группы по провайдерам (все свёрнуты по умолчанию; шеврон + счётчик «(N)», при поиске «(X/Y найдено/всего)»), AND-поиск по имени/id/провайдеру/характеристикам с авто-раскрытием совпавших групп, тумблер «активные» (включён по умолчанию — чистый UI-фильтр «только включённые», ничего не сохраняет), значки характеристик у моделей с заявленными полями: «кастом» (рукописная запись), vision/text-only, fim, размер контекста («128K» бинарно для степеней 1024, «200K»/«1M» десятично). Строки страницы рисуются сразу из кэша каталогов (в статусе группы — возраст записи и «обновляю…»), сеть идёт фоном и параллельно. Каталоги обновляются тремя путями: сам собой после сохранения ключа в «Провайдерах», кнопкой «Обновить каталоги» (все провайдеры) и ссылкой «обновить» в шапке группы (один); статус ответа виден и у свёрнутой группы, непринятые галочки переживают обновление. **Модель из каталога по умолчанию скрыта, пока её не включили здесь** (кастомная — видима; явный тумблер сильнее дефолта) — пилюля «Модель ▾» остаётся curated-списком и не зарастает сотнями каталожных id (семантика VibeIDE), панель после подтяжки подсказывает, где включать. Тумблеры видимости — side-map (PropertiesComponent), переживают правки файлов. Apply сразу перечитывает цели открытой панели — «Модель ▾» показывает только включённые без рестарта.
- **ACP-клиент (Vibe Agent)** — тулвиндоу с чатом любого локального ACP-агента (Claude Code через `claude-agent-acp`, Codex, Gemini CLI и др.): стриминг ответа, рендер код-блоков в ответе агента (fenced ```` ``` ````) с настоящей подсветкой синтаксиса IDE (read-only редактор по языку из метки fence; неизвестный язык — моноширинно), меткой языка, горизонтальным скроллом и своей кнопкой «копировать»; сворачиваемый блок «💭 размышления» (ACP `agent_thought_chunk`), кнопка «копировать» на сообщениях агента, индикатор занятости контекста «⛁ N%» в композере (ACP `usage_update`: занято/размер окна, стоимость в тултипе; жёлтый с 80%; сбрасывается с новой сессией), permission-запросы диалогом (закрытый диалог = отказ — молчаливого «разрешить» не существует), чтение файлов агентом видит несохранённые правки редактора (Document-first), записи идут через WriteCommandAction для открытых файлов и с асинхронным VFS-refresh для внешних. Реестр агентов совместим с `~/.jetbrains/acp.json` (битая запись пропускается с предупреждением и не роняет реестр); агент запускается без оболочки (command+args). Дефолтный агент — Claude Code через `npx @agentclientprotocol/claude-agent-acp`.
- **Терминал агента** — живой вывод команд агента прямо в ленте чата: для Claude — стрим Bash через расширение `_meta.terminal_output` (моноширинная консоль со сворачиванием по клику на заголовок и кнопкой «копировать», ANSI-очистка, head+tail 80 000 символов, бейдж кода выхода); для сторонних агентов (Gemini CLI и др.) — исполнение стандартными методами ACP `terminal/create|output|wait_for_exit|kill|release` через платформенные процессы IDE (kill валит всё дерево процессов, `outputByteLimit` режет вывод с начала по границе символа). Флаг «Разрешать агентам исполнять терминал» (Settings → Tools → VibeIDEA → Агент, дефолт вкл) объявляет capability `terminal` только для сторонних агентов; у Claude исполнение всегда внутри агента. **Гейт разрушительных команд** — детерминированный классификатор (`rm -rf`, `dd`, `mkfs`, `git push --force`, `git reset --hard`, `chmod 777`, `Remove-Item`… с разбором строки по `&&`/`;`/`|`) подсвечивает опасную команду в диалоге разрешения (Claude) или требует подтверждения перед `terminal/create` (сторонние).
- **Хуки проекта `.vibe/hooks.json`** — команды проекта вокруг работы агента: `preToolUse` (перед инструментом — блокирует в точках, которыми владеет клиент: запрос разрешения и запись через `fs/write`), `postToolUse` (после — требование исправить), `turnEnd` (конец хода, в stdin `changedFiles`). Код выхода решает: `0` — разрешено (+stdout заметкой), `2` — отказ, прочее/таймаут — поломка хука (не блокирует). Тройной гейт: настройка (дефолт выкл) + Workspace Trust + успешный парсинг. Точный матчинг `tools`, таймаут 30 с/потолок 300 с. Спека и образец — [hooksSpec.md](manuals/hooksSpec.md); образец приходит с засевом окружения.
- **Засев окружения `.vibe/`** — при открытии любого проекта VibeIDEA создаёт и наполняет `.vibe/` дефолтами (решение владельца: VibeIDEA — агентская IDE, без `.vibe` её использовать незачем): `README.md` (что это за папка), `.gitignore` (рантайм-журналы agent/audit/checkpoints не попадают в git), `rules.md` (правила проекта для `@agent`), образцы `hooks/pipelines/servers.example.jsonc` по нашим спекам, каталог провайдеров `providers/` (README, шаблон с примером кастомной модели и готовые конфиги — читаются автоматически, см. пункт о каталоге провайдеров), дизайн-сиды `design/components.md`+`uiKit.md`. Только create-if-missing — файл пользователя не перезаписывается никогда; всё засеянное фиксируется в `.vibe/.seeded.json` (sha256). Обновление окружения новым релизом решается по ревизиям: `versions.json` набора хранит для каждого файла номер ревизии, sha текущей и всех прошлых версий. Нетронутая копия старого релиза (её sha есть в истории) **обновляется молча** — терять нечего; ваша правка **не трогается никогда**, а если ревизия ушла вперёд, приходит уведомление «релиз обновил N файлов» с тремя выходами: «Сравнить» (штатный diff релиз↔ваш файл), «Обновить, сохранив мои тумблеры» (предлагается, только когда единственное отличие — значения `active`: файл обновляется, а ваши «выключено» переезжают в `providers/zz-local-toggles.jsonc` — он сортируется последним в каталоге и потому сильнее сидов) и «Оставить своё» (запоминается на текущей ревизии — не спросим до следующего бампа). Устаревшие сиды (удалённые/переименованные в наборе) подчищаются при засеве по тем же sha-эталонам из `deprecated.json` — только не правленные копии. Набор общий с VibeIDE (репо VibeBrains, submodule).
- **VERIFY-GATE** — реальная проверка сборки/тестов при завершении хода, менявшего файлы (а не инструкция в промпте): `off`/`warn`/`enforce`. В `enforce` красный результат не закрывает ход — агент получает вывод ошибки синтетическим сообщением и обязан исправить (до N возвратов, затем прогон останавливается и отдаётся вам). Команда, режим, попытки и таймаут — Settings → Tools → VibeIDEA → Агент. Битая команда (не запустилась) делает гейт инертным, а не «красным». Триггер — завершение хода `session/prompt` с мутацией файлов (закрывает дефект VibeIDE «гейт только на ветке vibe_complete»).
- **Проверки хода и предохранители** — детерминированные проверки изменённых за ход файлов (`off`/`notify`/`enforce`): утечка секрета (приватные ключи, токены AWS/Anthropic/OpenAI/GitHub/Slack/Google) и запись в защищённый путь (`.git/`, `.ssh/`, `.env`, `*.pem`, `*.key`…). Находка взводит **залипающий защитный предохранитель**, который переживает перезапуск IDE и **блокирует старт следующего хода агента**, пока пользователь не снимет его подтверждением. Команда палитры «Предохранители агента» показывает сработавшие и снимает их. Лимиты скана (макс. файлов, макс. размер файла) настраиваются; о непросканированных сверх лимита сообщается в ленте. LLM-судья не используется.
- **Аудит `.vibe/audit.jsonl`** — журнал действий агента (промпты, ответы, вызовы инструментов, разрешения, записи, хуки, гейты, предохранители, терминал), по умолчанию выключен. Аргументы, тела команд и содержимое файлов не пишутся никогда — только имя инструмента и целевой путь (≤260 символов; у командных инструментов и его нет). Ротация по размеру (дефолт 10 МБ) в `audit.<N>.jsonl.gz`. Команда палитры «Журнал аудита агента» показывает последние записи, экспортирует лог в файл и очищает его (GDPR-эрейз). Формат — [auditSpec.md](manuals/auditSpec.md).
- **Состояние агента в статус-баре и уведомления** — виджет статус-бара показывает текущее состояние агента (⏳ ход / 🔎 проверка / ⛔ предохранитель; в покое скрыт), клик открывает чат. Когда ход завершается, а окно IDE не в фокусе, приходит балуон-уведомление «Vibe Agent завершил ход» (группа «Vibe Agent»).
