# Живой прогон ACP: что проверить руками

Автоматический E2E (`AcpClientE2ETest` против `FakeAcpAgent`) закрывает протокол: рукопожатие,
стрим, обратные вызовы, отмену, смерть агента. Подделка **не может** доказать то, что зависит от
поведения настоящего агента и от интерфейса IDE — это и есть содержание чек-листа.

Прогонять: перед выпуском сборки и после любых правок в `acp/`, `ui/AgentPanel`, `terminal/`,
`gates/`, `hooks/`.

## Подготовка

1. Установлен Claude Code (`npx @agentclientprotocol/claude-agent-acp` — команда агента в
   `~/.jetbrains/acp.json`).
2. Открыт проект с git и незакоммиченными изменениями (для чекпоинтов и VERIFY-GATE).
3. Панель VibeAgent открыта, в пилюле выбран агент `Claude Code`.

## Шаги

| # | Что делаем | Что должно быть |
|---|---|---|
| 1 | Отправляем «привет» | Ответ стримится по частям, а не появляется целиком; лента скроллится за ним |
| 2 | «Прочитай README и перескажи в двух строках» | Виден tool-call чтения; ответ по существу файла |
| 3 | «Создай файл tmp/probe.txt со строкой ok» | Показан diff-превью «Было → Станет» **до** записи; отказ (закрыть диалог) — файла нет; согласие — файл появился |
| 4 | «Запусти `ls -la`» | Вывод команды идёт в консоль ленты живьём (`_meta.terminal_output`), бейдж кода выхода в конце |
| 5 | «Запусти `rm -rf /`» | Гейт разрушительных команд **блокирует** до всякого выполнения |
| 6 | Долгий запрос → «Стоп» | Ход прекращается, процесс агента жив (следующее сообщение уходит без перезапуска) |
| 7 | Переключить «Режим ▾» на план и обратно | Пилюля меняет подпись; агент подтверждает сменой режима в ленте |
| 8 | Отправить картинку вложением | Уходит; на не-vision модели предупреждение, а не молчаливая ошибка |
| 9 | Убить процесс агента снаружи (`kill`) | Панель сообщает о выходе с кодом, висящий ход не остаётся вечным |
| 10 | Перезапустить IDE с открытым тредом | История треда на месте, черновик и выбранная модель сохранены |
| 11 | `.vibe/hooks.json` с preToolUse exit 2 | Инструмент не выполняется, причина видна в ленте |
| 12 | VERIFY-GATE в enforce с заведомо падающей командой | После хода с правками файлов гейт срабатывает и делает bounce |

## Что записать по итогам

Провал любого шага — запись в `docs/vibe/roadmap.md` и, если причина неочевидна, в
`docs/vibe/knowledge/agents/`. Успешный прогон достаточно отметить датой в roadmap — отдельного
журнала не заводим, он превратится в свалку.
