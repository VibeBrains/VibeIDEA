# Свои MCP-серверы: `.vibe/mcp.json`

**Скопируйте этот файл целиком своей модели и попросите собрать `.vibe/mcp.json` для нужных
серверов.** Здесь есть всё: форма файла, каждое поле, рабочие примеры и то, чем VibeIDEA отвечает
на ошибки. В интернет ходить не нужно.

## Что это даёт

Агент VibeIDEA — и прямой чат с моделью, и внешний ACP-агент — получает инструменты ваших
собственных MCP-серверов: трекер задач, база данных, чужой API, что угодно, что говорит по Model
Context Protocol. Свои серверы добавляются К нашим (граф импортов, поиск по корпусу, журнал решений,
чтение и правка файлов, команды), а не вместо них.

## Где лежит

`.vibe/mcp.json` в корне проекта. Файл необязательный: нет файла — нет своих серверов, и это не
ошибка.

## Форма

```json
{
  "mcpServers": {
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": { "GITHUB_PERSONAL_ACCESS_TOKEN": "ghp_..." }
    },
    "postgres": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-postgres", "postgresql://localhost/mydb"]
    },
    "черновик": {
      "command": "node",
      "args": ["tools/my-mcp-server.js"],
      "disabled": true
    }
  }
}
```

Форма намеренно та же, что у Claude Desktop и у VibeIDE: конфиг, который у вас уже есть, переносится
как есть.

## Поля

| Поле | Обязательно | Что значит |
|---|---|---|
| `command` | да | Чем запускать сервер. Ищется в `PATH` процесса IDE |
| `args` | нет | Аргументы команды, по одному элементу массива на аргумент |
| `env` | нет | Переменные окружения сервера. Окружение IDE при этом сохраняется — без `PATH` сервер не найдёт даже `node` |
| `disabled` | нет | `true` — запись остаётся в файле, но сервер не запускается |

Имя сервера — ключ объекта. Оно показывается в ленте, когда сервер предложен агенту.

## Как VibeIDEA отвечает на ошибки

Разбор **терпимый и громкий**: одна битая запись не отменяет остальные, но о ней говорится вслух.

`{"нет": "секции"}` → «нет объекта mcpServers»
запись без `command` → «<имя>: не указан command», остальные серверы работают
файл не разобрался как JSON → сказано прямо, серверов нет
сервер не стартовал → назван по имени, чат продолжает работать

Молчаливо пропущенный сервер выглядит как сломанный инструмент, поэтому его здесь не бывает.

## Права

Инструмент чужого сервера считается **пишущим** и спрашивается у человека перед каждым вызовом —
даже в режиме «Автопилот». Причина простая: класс опасности чужого инструмента нам неизвестен, а
умолчание «читает, пока не доказано иное» однажды тихо выполнило бы чужое действие от вашего имени.

Имя инструмента, совпавшее с нашим, достаётся НАШЕМУ: свои серверы подключаются последними, и
подменить `vibe_read_file` чужой реализацией нельзя.

## Когда сервер просит ввод посреди вызова

Сервер ревизии MCP 2026-07-28 может ответить на вызов не результатом, а просьбой `resultType: "input_required"`: сами просьбы лежат в `inputRequests` под ключами, а рядом — непрозрачный `requestState`, который сервер ждёт обратно дословно.

Что отвечает VibeIDEA:

- `elicitation/create` — форма или ссылка уходит вам тем же диалогом уточнения, что у ACP-агента;
  форма без поля `mode` считается формой, как велит MCP.
- `roots/list` — папка открытого проекта.
- `sampling/createMessage` и всё остальное — не отвечается: свою модель прямой чат серверу не одалживает.

Ответы уходят повтором того же вызова: `inputResponses` под теми же ключами, `requestState` дословно.
Ответ без просьб бывает, когда сервер сбрасывает нагрузку: такой вызов повторяется сразу, без вопроса вам, и несёт только `requestState`.
Спросить снова сервер может не больше четырёх кругов на вызов.

Отказ в диалоге уходит серверу ответом `decline`, и что делать дальше, решает сервер.

Модель получает ошибку с названием метода, если:

- на одну из просьб ответить нечем;
- круги кончились.

Пустого успеха вместо ответа не бывает.
Время, пока вы заполняете форму, в потолок вызова (30 с) не входит.

## Проверка

1. Положите файл, откройте чат, отправьте любое сообщение.
2. В ленте появится строка «свои MCP-серверы: <имена>».
3. Спросите агента, какие инструменты у него есть, — ваши будут в списке.

Ничего не появилось — смотрите в ленту: причина названа там, а не в логе.
