# СПЕКА `.vibe/roles.json` — УМОЛЧАНИЯ РОЛЕЙ АГЕНТА

> Скопируйте этот файл целиком своей LLM и попросите собрать `.vibe/roles.json` для вашего проекта.
> Спека самодостаточна: ни исходников, ни интернета не нужно.

---

## 1. Зачем файл

Роль `qa` в пайплайне пишет только тесты.
Если у шага нет своих `paths`, IDE пускает его писать только в тестовые каталоги и файлы.
Этот файл задаёт, какие именно.

Файл общий для VibeIDEA и VibeIDE и засевается в `.vibe/` из общего набора.
Отдельный файл, а не раздел `pipelines.json`: роль зовут не только пайплайны.

_Пока файл читает только VibeIDEA; VibeIDE до своей правки держит тот же список вшитым_

---

## 2. Формат

JSONC: комментарии и висячие запятые разрешены.

```jsonc
{
  "version": 1,
  "roles": {
    "qa": {
      // Куда шаг qa пишет, если у шага нет своих "paths"
      "writePaths": ["**/tests/**", "*.test.ts", "e2e/**"]
    }
  }
}
```

Поля:
- `version` — версия формата, сейчас `1`
- `roles.qa.writePaths` — список шаблонов, куда `qa` разрешено писать

Синтаксис шаблонов — gitignore:
- `*` не переходит через `/`, `**` переходит
- шаблон без `/` действует на любой глубине: `*.test.ts` — любой такой файл
- шаблон с `/` отсчитывается от корня проекта: `e2e/**`
- шаблон, кончающийся на `/`, — каталог со всем содержимым

---

## 3. Как применяется

- Свои `paths` шага в `pipelines.json` **заменяют** `writePaths` целиком
- Одни `denyPaths` шага `writePaths` **не снимают**, а сужают: запреты сильнее разрешений
- Файл читается один раз в начале прогона пайплайна: правка посреди прогона вступает в силу со следующего

---

## 4. Ошибки не расширяют границу

- Файла нет, или в нём нет записи `qa`, или нет поля `writePaths` — действует вшитый в продукт список, молча
- Файл не разобран или `writePaths` не список непустых строк — действует вшитый список, в чат приходит предупреждение `[roles]`
- `writePaths: []` — шагу `qa` запись **запрещена целиком**, с предупреждением.
  Пустой список разрешений, прочитанный как «без ограничений», превратил бы опечатку в отмену границы

Вшитый список совпадает с засеянным файлом:
`**/test/**`, `**/tests/**`, `**/testSrc/**`, `**/testData/**`, `**/__tests__/**`, `**/spec/**`,
`*Test.kt`, `*Test.java`, `*Tests.kt`, `*Test.php`, `*.test.ts`, `*.test.tsx`, `*.test.js`,
`*.spec.ts`, `*.spec.tsx`, `*.spec.js`, `test_*.py`, `*_test.py`, `*_test.go`

---

## 5. Пример: тесты лежат рядом с кодом и в `e2e/`

```jsonc
{
  "version": 1,
  "roles": {
    "qa": {
      "writePaths": ["*.test.ts", "*.spec.ts", "e2e/**", "**/__snapshots__/**"]
    }
  }
}
```
