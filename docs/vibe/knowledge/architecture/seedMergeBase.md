# Мерж конфликтов сидов `.vibe` и база слияния

Конфликт сида — ваша копия правлена, а набор ушёл вперёд. Раньше кнопка «Смержить» открывала двухпанельный diff: применить в нём было нечего, уведомление возвращалось, выход оставался один — взять релиз целиком.

## Решение

- Штатный `MultipleFileMergeDialog` с `MergeProvider` (`SeedMergeProvider`): Accept Yours / Accept Theirs / Merge… над всеми конфликтными файлами.
- Слева ваш файл (`CURRENT`), справа релиз (`LAST`), в середине база (`ORIGINAL`) — релиз той ревизии, от которой засеян файл.
- Диалог сам пишет результат в файл, а провайдер получает только «решено». Какой был выбор — восстанавливается по результату: равен релизу — Theirs, иначе — своё (`SeedMerge.choice`).

## База

- Хранится файлами в `.vibe/local/seedBase/<путь>`: локально, вне git (`local/` в засеваемом `.gitignore`).
- Пишется при создании, молчаливом обновлении и при совпадении копии с релизом, а также при любом решении (человек увидел эту ревизию — она основа следующего мержа).
- Раньше хранились только sha ревизий, а по sha текст не восстановить — потому двухпанельный просмотр и был единственным честным вариантом.
- Проекты, засеянные до этого, базы не имеют: пустая база, и заголовок окна говорит об этом, а не рисует выдуманную среднюю панель.

## Журнал после решения

- Theirs: `JournalEntry(sha релиза, ревизия)` — как после обычного засева.
- Yours и ручной мерж: существующее «оставить своё» (`reconciled` = текущая ревизия) — конфликт молчит до следующего бампа набора.
- Отмена: ничего не пишется, файл остаётся в списке, уведомление живёт.
