# Хук из чужого хоста: код выхода против решения джейсоном

**[грабли]**

## Что случилось

Наш контракт хука — код выхода: `0` разрешает (напечатанное уходит агенту заметкой), `2` отказывает,
любой другой код, таймаут и несостоявшийся запуск — поломка хука, которая не блокирует. У Claude Code
контракт другой: код остаётся `0`, а решение печатается в stdout джейсоном —
`hookSpecificOutput.permissionDecision`, прежнее верхнеуровневое `decision`, общее `continue: false`.

Пока `HookOutcome.verdictOf` читал только код выхода, готовый хук из Claude Code, положенный в
`.vibe/hooks.json`, **молча разрешал** действие: его `"permissionDecision": "deny"` попадал в ветку
«ноль — значит можно», и запрет уходил модели заметкой, то есть советом. Это хуже сломанного хука:
поломку видно сразу, а здесь человек видит настроенный запрет и уверен, что он работает.

Нашлось не в своём коде, а в чужом: у Spotify в `portal-ai-plugins` хук отвечает несуществующим
`{"decision": "allow"}`, и их эвалы этого не ловят, потому что сверяют хук с его же выводом, а не с
контрактом хоста (их issue #10). Обратная сторона той же ошибки оказалась у нас.

## Как сделано (решение №87)

- `deny`, `block` и `continue: false` — отказ; причина берётся из `permissionDecisionReason`, `reason`
  или `stopReason`.
- `allow` и `approve` — разрешение, и агенту не показывается ничего: это ответ машине, а не сообщение
  модели. Иначе на каждом разрешённом вызове модель получала бы JSON заметкой.
- `ask` — предупреждение пользователю: третьего ответа у нашего хука нет, а молчаливое «разрешено»
  потеряло бы намерение.
- Решением считается только вывод, который начинается с `{` и заканчивается `}` — правило их хоста
  взято дословно, чтобы один хук вёл себя одинаково в обоих. Код `2` сильнее любого JSON.

Обратный перенос работает и без правок: наш хук отказывает кодом `2`, а Claude Code код `2` тоже
считает блокирующим и берёт причину из stderr.

## Применение

- Утверждение «у нас такой ошибки быть не может» проверяйте в обе стороны: не только «наш хук у нас»,
  но и «чужой хук у нас». Первое было верно и усыпило второе — ровно так эта дыра и прожила.
- Контракт, который читают чужие инструменты, проверяется тестом на чужом формате, а не только на
  своём. Таблица случаев одинакова в VibeIDEA (`HookOutcomeTest.kt`) и VibeIDE
  (`projectHooks.test.ts`): один контракт — одно поведение.
- Спека: [manuals/hooksSpec.md](../../manuals/hooksSpec.md), раздел «Хук, написанный для Claude Code».
