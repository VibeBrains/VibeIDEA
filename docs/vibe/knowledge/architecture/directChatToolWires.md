# Вызов инструментов в прямом чате: три провода, одна форма раунда

**Дата:** 13.09.2026
**Где:** `providers/ToolCalls.kt`, `providers/LlmClient.kt`, `mcp/McpStdioClient.kt`, `mcp/DirectChatTools.kt`

---

## Что было

Прямой чат не отправлял модели инструментов ни на одном из трёх проводов.
MCP-клиент без цикла вызова был бы мёртвым кодом, поэтому задача «память VibeMemory в прямом чате» оказалась задачей «цикл вызова инструментов».

---

## Грабли, которые определили форму

**Результаты раунда — одно сообщение, а не по сообщению на вызов.**
Три провода расходятся:
openai — отдельное сообщение `role: tool` на каждый результат
anthropic — все `tool_result` в ОДНОМ сообщении пользователя; два пользовательских сообщения подряд провайдер отвергает
gemini — `functionResponse` частями одного хода, сопоставление по ИМЕНИ, id у вызова нет вовсе

Два провода из трёх требуют результаты вместе, поэтому `ChatMessage` роли `tool` несёт весь раунд, а openai его разворачивает.
Обратный выбор — сообщение на результат и склейка соседних на двух проводах — это код, который помнит, где склеивать.

**Вызов приходит кусками.**
openai шлёт `delta.tool_calls` по индексу: имя в первом куске, аргументы — фрагментами JSON-текста
anthropic шлёт `content_block_start` с `tool_use` и затем `input_json_delta` с тем же `index`
gemini шлёт `functionCall` целиком
Сборщик один на запрос и пересоздаётся на повторе: куски из оборванного потока — не вызов.

**Gemini отвергает запрос целиком** на `$schema` и `additionalProperties` в схеме параметров.
Схемы серверов MCP их содержат; при отдаче в Gemini ключи вычищаются рекурсивно.

**openai-ответ, который только вызывает инструменты, несёт `content: null`**, а не пустую строку.

**Без инструментов тело запроса побайтно прежнее.**
Поле `tools` ставится только при непустом списке: остальные вызовы `chat` (инлайн-правка, Telegram, эвалы, судья пайплайна) не должны узнать о фиче.

---

## Права

Чтение — `memory_search`, `memory_get`, `history_search` — идёт без вопроса.
Всё остальное, включая инструмент, которого список ещё не знает, — запись: доверенный проект и «да» человека на этот вызов.
Список неизвестных считать записью, а не чтением: новый инструмент сервера не должен войти без спроса потому, что никто не обновил список.

---

## Чего нет

Обмен с инструментами не пишется в историю треда — только итоговый ответ.
Следующий ход модель начинает без прошлых результатов; сказано в мануале `directChatTools.md`.
