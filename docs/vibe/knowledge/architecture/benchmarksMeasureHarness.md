# Бенчмарк меряет связку «модель + харнесс», а не модель

**[правило]**

## Контекст

Разбор дайджеста 31.08.2026 ([references/digest20260831.md](../../references/digest20260831.md)),
тема сравнения кодинг-моделей.

## Суть

Один и тот же Claude Opus 4.8 даёт **69,2 %** на SWE-bench через собственный харнесс Anthropic и
**51,9 %** на стандартизированном стенде Scale AI SEAL — разрыв 17,3 пункта, модель одна. У Gemini
3.1 Pro разброс между постановками — 26,4 пункта. Moonshot для K3 на DeepSWE честно приводит обе
цифры (67,5 % с KimiCode и 67,3 % с mini-SWE-agent), но сводная таблица смешивает четыре разных
харнесса.

Отсюда два следствия для нас:

- **В `ModelQuirks` и в документации выбора модели вендорских процентов не приводить.** Каталог
  описывает, что модель ПРИНИМАЕТ (какие поля, какая роль, стрим или нет), а не насколько она
  хороша. Процент из чужого харнесса, поставленный в наш файл, читается как наше измерение — и
  переживёт тот релиз, к которому относился.
- **Сравнивать модели — только своим харнессом на своём репозитории.** У нас для этого есть
  `/measure` (база и сравнение) и повтор прогона со сравнением: одна задача, один харнесс, два
  прогона. Число, полученное так, сопоставимо хотя бы само с собой.

## Применение

Появилось желание записать «эта модель лучше на N %» — источник числа обязан называть харнесс, и
это должен быть НАШ харнесс. Иначе число не пишем вовсе: «направленное свидетельство о системе»
(формулировка авторов разбора) в каталоге, который читают как справочник, превращается в
утверждение о модели.
