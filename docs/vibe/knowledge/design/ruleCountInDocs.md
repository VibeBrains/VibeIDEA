# Число правил в документах считается по id каталога и сверяется гейтом

**[грабли+правило]** · **Дата:** 23.09.2026

## Контекст

Число правил дизайн-детектора называют README, каталог возможностей, сверка с VibeIDE и список
возможностей внутри IDE. К 23.09.2026 они говорили разное: README и сверка держали 81, каталог
возможностей и спека дизайн-контекста — 86, а в `DesignRuleCatalog.ALL` было 85.

## Что случилось

- **81 — не обновили.** Коммит 18.09 добавил правила и поправил две записи, а README, сверку
  и список возможностей в IDE не тронул: где ещё стоит это число, никто не помнил.
- **86 — ошибка сложения.** Тот же коммит принёс пять изменений: контраст в состояниях, исключения
  WCAG для зоны нажатия, исчезающий контент, мёртвый контракт состояния, невидимое состояние. Новых id
  из них четыре: исключения WCAG уточнили старое правило зоны нажатия. В доки записали 81 + 5.
- **Спека врала шире числа.** Раздел «Чего в этом срезе нет» называл живой замер, два вьюпорта,
  оверлей и хук `enforceFloor` делом очереди, хотя всё это работает с 29.08.2026 (этапы 2–4 дизайн-контура
  в дорожной карте). А образец
  `design.md` принимал отклонение `color-accent-overuse`, которого в каталоге нет, — такая строка не
  выключает ничего.

## Правило

- **Считать id каталога, а не правки.** Правило — это id в `DesignRuleCatalog.ALL`; уточнение
  старого правила числа не меняет. Так же уже считает «проверка дизайн-контура»: итог — id, и пол
  плюс вкус обязаны дать итог.
- **Число — в немногих местах и под гейтом.** Проверка 7 гейта `checkVibeDocs.sh` сверяет число в
  четырёх документах с разобранным списком `ALL`. Якорь, который ничего не нашёл, валит гейт:
  документ, переписанный без числа, не должен молча выключать проверку.
- **Остальные документы число не повторяют.** Запись «Дизайн-память» ссылается на запись детектора,
  спека дизайн-контекста — на «проверку дизайн-контура», которая считает по коду.
- **Образец в спеке — рабочий файл.** Модель, собирающая `design.md` по спеке, повторит образец
  дословно, поэтому id в нём обязан существовать.
