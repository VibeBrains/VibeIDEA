# Двойной клик в окне диффа выделял блок, а не слово

**Тип:** баг. **Дата:** 16.10.2026.

## Симптом

В «Repository Diff» (дифф коммита) двойной клик по слову в файле TypeScript выделял целиком изменённый блок.
В обычном редакторе тот же клик выделяет слово.

## Причина

Двойной клик идёт через `SelectWordHandler` и обработчики расширения выделения.
Пока языковой сервер умеет `textDocument/selectionRange`, LSP4IJ делает две вещи для файла:
его `LSPExtendWordSelectionHandler` берёт диапазоны у сервера, а `LSPWordSelectionFilter` отключает платформенное выделение слова.
Слово тогда берётся только от сервера.

Окно диффа показывает ревизию как лёгкую копию в памяти с именем настоящего файла.
Имя подходит под шаблоны сервера, и LSP4IJ спрашивает сервер про файл.
Сервер знает файл по имени и отвечает про текст на диске, а диапазоны применяются к тексту ревизии и попадают не туда.

Нашей кнопочной разметки правок агента (`ReviewSession`) это не касается: она живёт только в обычном редакторе и ловит клики по своим кнопкам.

## Решение

`SelectionRanges.feature()` подменяет `LSPSelectionRangeFeature` в общих клиентских возможностях серверов (`PreciseNavigation.install`).
Сервер спрашивается о выделении только для файла на диске (`VirtualFile.isInLocalFileSystem`).
Для остальных LSP4IJ считает выделение по серверу недоступным, и работает платформенное слово.

Гейт — `SelectionRangesTest`. Это проверка правила; живой двойной клик в окне диффа не прогнан.
