# Двойной клик в окне диффа выделял блок, а не слово

**Тип:** баг. **Дата:** 16.10.2026.

## Симптом

В «Repository Diff» (дифф коммита) двойной клик по слову в файле TypeScript выделял целиком изменённый блок.
В обычном редакторе тот же клик выделяет слово.

## Причина

Двойной клик идёт через `SelectWordHandler` и обработчики расширения выделения.
Пока языковой сервер умеет `textDocument/selectionRange`, LSP4IJ делает две вещи для файла:
его `LSPExtendWordSelectionHandler` берёт диапазоны у сервера, а `LSPWordSelectionFilter` отключает платформенное выделение слова.
Слово тогда берётся только от сервера.

Окно диффа показывает ревизию как лёгкую копию в памяти с именем настоящего файла.
Имя подходит под шаблоны сервера, и LSP4IJ спрашивает сервер про файл.
Сервер знает файл по имени и отвечает про текст на диске, а диапазоны применяются к тексту ревизии и попадают не туда.

Нашей кнопочной разметки правок агента (`ReviewSession`) это не касается: она живёт только в обычном редакторе и ловит клики по своим кнопкам.

## Решение

`SelectionRanges.feature()` подменяет `LSPSelectionRangeFeature` в общих клиентских возможностях серверов (`PreciseNavigation.install`).
Сервер спрашивается о выделении только для файла на диске (`VirtualFile.isInLocalFileSystem`).
Для остальных LSP4IJ считает выделение по серверу недоступным, и работает платформенное слово.

Гейт — `SelectionRangesTest`. Это проверка правила; живой двойной клик в окне диффа не прогнан.

## Второй случай: двойной клик в строке на диске выделял всю строку

**Дата:** 16.10.2026. В обычном редакторе, в файле TypeScript на диске, двойной клик по слову внутри шаблонной строки выделял всю строку.
Правка выше его не закрывает: файл на диске, сервер отвечает про тот же текст.

Причина та же механика, другая точка. `LSPWordSelectionFilter` отключает платформенное слово для любого файла, где сервер умеет `selectionRange`,
а `LSPExtendWordSelectionHandler` берёт диапазоны только у сервера (в байт-коде: `select` собирает `getSelectionTextRanges`, платформенный `LSPWordSelectioner` зовёт только при пустом ответе).
Самый узкий диапазон сервера внутри шаблонной строки — вся строка, а не слово. `SelectWordHandler` берёт самый узкий диапазон, который шире текущего выделения, и слова среди кандидатов нет.

Решение: `WordBeforeServerRanges` — свой `extendWordSelectionHandler` рядом с интеграцией LSP4IJ.
Он отдаёт слово платформенным `SelectWordUtil.addWordOrLexemeSelection` (с учётом настройки camelCase) только там, где LSP4IJ отключил свою.
Слово уже диапазона сервера и выбирается первым, диапазоны сервера идут следующими шагами Extend Selection. Фильтр LSP4IJ и его обработчик не трогаем.

Тройной клик (строка) платформенный, не менялся. Четвёртый клик платформа считает тем же, что третий; теперь он выделяет предложение
(`SentenceClickSelection`, границы — чистая функция `SentenceBounds`: от точки до точки, внутри строки в кавычках или комментария, в которых курсор, и не за пределы строки).
Слушатель стоит на каждом редакторе (`editorFactoryListener`), поэтому работает и в окнах диффа.

Гейты — `SentenceBoundsTest`, `ClickSelectionPlatformTest`. Живой клик с запущенным сервером не прогнан: тесты проверяют слово и выделение на редакторе платформы.
