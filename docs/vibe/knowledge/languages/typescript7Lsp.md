# TypeScript 7: сервер не нужно везти

**Контекст (13.09.2026).**
В разборе 12.09 пункт стоял как «крупная задача сборки»: положить в дистрибутив нативные бинари tsgo под каждую ОС и расширить гейт дистрибутива.
Проверка фактами показала, что везти ничего не нужно.

## Что проверено

- `typescript@7.0.2` — `latest` в npm; бинарь пакета называется `tsc`.
- Нативная часть — **двадцать платформенных пакетов** `@typescript/typescript-<os>-<arch>` по 27–29 МБ каждый, подтягиваются как зависимости.
- Режим сервера — `tsc --lsp --stdio`, с TypeScript 7.0; `tsc` берётся из `node_modules/.bin` проекта (конфиг `lsp/tsc.lua` в nvim-lspconfig; `tsgo.lua` там помечен устаревшим в пользу `tsc`).
- README `microsoft/typescript-go` команду запуска LSP **не называет** — источником стал код конфига, а не документация.

## Почему не везём

Если бы мы клали TypeScript 7 в дистрибутив, пришлось бы:
- ставить npm-дерево отдельно под каждую целевую ОС — `npm ci` на маке кладёт только бинарь хоста, и сборки Windows и Linux остались бы без сервера;
- таскать по ~28 МБ на ОС;
- держать версию компилятора IDE, которая расходится с версией проекта.

А проект на TypeScript 7 **уже содержит** сервер ровно своей версии.
Поэтому «Автоматически» берёт `tsc` проекта, и только его.

## Решение

- `TsEngine`: `AUTO` / `VTSLS` / `TSC`, выбор на уровне приложения, как у PHP.
- `AUTO` → `TSC`, если `node_modules/typescript` версии 7+ и есть `node_modules/.bin/tsc` (`tsc.cmd` на Windows); иначе встроенный vtsls.
- Явный `TSC` без TypeScript 7 в проекте → vtsls и строка в доктор LSP: редактор не остаётся без сервера.
- Идентификатор фабрики остаётся `vtsls`: он называет слот языка, и переименование сбросило бы пользовательские настройки LSP4IJ.

Гейт — `TsEngineTest`.
**Живьём не прогнано** — нужен проект на TypeScript 7 и собранная IDE.
