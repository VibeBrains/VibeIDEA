# PHP на Windows: требование ext-posix у Phpactor оказалось ложным

**Дата:** 03.09.2026 · **Ветка:** next · **Статус:** решено; проверка на живой Windows — гейтом `.ps1`

## Как это выглядело

Встроенный `phpactor.phar` на Windows не стартовал: Box, которым собран phar, проверяет требования
при запуске, и среди них `ext-posix` — расширение, которого в Windows-сборках PHP не существует.
Первый разбор (02–03.09) закончился выводом «невозможно, нужен другой сервер», и на день в сборке
появился второй движок — Intelephense по умолчанию для Windows. Владелец ответил на это единственно
верно: «основной слой программистов на Windows, нужно, чтобы всё работало без костылей».

## Что показал разбор phar, а не его сообщения об ошибке

Phar распакован (`Phar::extractTo`) и просмотрен целиком. Вызовов `posix_*` в **собственном коде
Phpactor нет вовсе**. Все вызовы живут в зависимостях, и **каждый защищён**:

| где | как защищён |
|---|---|
| `symfony/process` | `function_exists('posix_kill')`, иначе `proc_terminate` |
| `symfony/console` | `function_exists('posix_kill')` |
| `monolog` SignalHandler | `extension_loaded('posix') && function_exists(...)` |
| `php-xdg-base-dir` | `function_exists('posix_getuid')`, иначе `getmyuid()` |
| Box `IO.php` | `function_exists('posix_isatty')`, иначе `fstat` |
| `amphp/process` | на Windows выбирает свой `Windows\Runner` по `PHP_OS` |

То есть требование `ext-posix` в манифесте Box — **ложное**: оно объявлено, но ни одна строка кода
его не предполагает. Единственное, что мешает Windows, — сам проверяющий. У него есть
документированный выключатель: `$_SERVER['BOX_REQUIREMENT_CHECKER']` со значением `'0'`.

## Почему первый обход «не помог»

Выключатель читается из `$_SERVER`, и переменная окружения туда попадает — но только если её видит
**процесс php**. В Git Bash `BOX_REQUIREMENT_CHECKER=0 php …` не всегда доходит до `php.exe` тем
же именем, а `php -r` вдобавок **игнорирует `auto_prepend_file`** — оба способа, которыми проверяли
обход, молчали не потому, что обход не работает.

## Решение

Рядом с phar едет однострочный `phpactorNoPosixCheck.php`, устанавливающий `$_SERVER` в `'0'`, а
на Windows IDE запускает phar как `php -d auto_prepend_file=<он> phpactor.phar language-server`.
Именно `-d`, а не окружение: процесс запускает клиент LSP, и его окружение не наше, а опции
интерпретатора — наши. Вне Windows ничего не меняется.

Ни полифиллов, ни правленого phar: там, где всё защищено проверкой `function_exists`, полифилл был
бы кодом, который никто не вызывает.

## Как это проверено на macOS, где posix есть

Отключить расширение в статически собранном PHP нельзя, но можно отключить **все сорок** его функций
(`-d disable_functions=posix_…`): `function_exists` тогда отвечает `false`, ровно как на Windows.
С этим и с prepend сервер отвечает на `initialize` настоящими `capabilities`. Сам выключатель
проверен на распакованном проверяющем Box с подменённым требованием на несуществующее расширение:
без флага — `exit 1` и сообщение, с prepend — проходит. Гейт `checkVibeDist.sh` повторяет эту
эмуляцию при каждой проверке дистрибутива; гейт `.ps1` на Windows запускает phar с выключателем
по-настоящему — это и есть недостающее живое подтверждение.

## Что осталось от второго движка

Intelephense остался **явным выбором** в настройках: он работает на Node, кому-то привычнее, и
бесплатного уровня хватает на дополнение, навигацию и диагностику. Умолчание — встроенный Phpactor
на всех системах. Поставлять Intelephense по-прежнему нельзя (EULA, см. [lspStack.md](lspStack.md)).

## Побочная находка: гейт локализации считал комментарии кодом

Проверка «ключ используется в коде» искала `t("...")` по сырому тексту, поэтому упоминание ключа в
комментарии считалось использованием — так пережили две мёртвые строки, а объясняющий комментарий,
наоборот, изобретал ключ. Разбор вынесен в `vibe-plugins/tools/ktComments.py` со знанием строковых
литералов и raw-строк; наивный `//` съедал бы хвост строки после `https://`.

## Урок общего вида

«Требует расширение X» в манифесте — это утверждение сборщика, а не свойство кода. Прежде чем менять
сервер из-за такого сообщения, стоит распаковать артефакт и посмотреть, кто и как зовёт X: в этот раз
между «невозможно» и «одна строка» лежал час чтения.
