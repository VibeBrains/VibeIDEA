# Навигация LSP: переход, подсказка и трассировка на одних запросах к серверу

**Дата:** 18.09.2026, переписано 23.09.2026 · **Повод:** всплывашка `LSP Symbol "encodeURIComponent"`; 23.09 — слой 19.09 оказался мёртвым

## Откуда берётся надпись

Не из платформы и не из нашего кода: строка `usage.description=LSP Symbol` лежит в
`messages/LanguageServerBundle.properties` внутри **LSP4IJ** (`lsp4ij-0.20.2.jar`), который мы
поставляем готовым плагином. Отвечает на вопрос «что это за элемент» их
`LSPUsageElementDescriptionProvider`, и отвечает всегда — поэтому наш `ElementDescriptionProvider`
стоит `order="first"` и называет язык: «символ TypeScript (vtsls)».

## Как платформа спрашивает (проверено по исходникам 23.09.2026)

- **Ctrl+наведение** считается в фоне: `CtrlMouseHandler.kt:236-241`, `Dispatchers.Default` и
  `constrainedReadAction`. Каждое движение мыши отменяет расчёт, тайм-аута нет.
- **Cmd+B** — `GotoDeclarationOrUsageHandler2.kt:124-130`, `underModalProgress`: пул-поток под
  блокирующим чтением, на EDT крутится модальный цикл.
- **Обработчики перехода** опрашиваются по очереди, и берутся цели ПЕРВОГО, кто вернул хоть одну
  (`gtdProviders.kt:40-57`). Два обработчика с `order="first"` — это не подстраховка, а лотерея:
  порядок между ними не обещан.
- **Подсказка** Ctrl+наведения — `psiDocumentationTargets(target, leaf).first().computeDocumentationHint()`
  (`CtrlMouseData.kt:75,100`). Первой спрашивается точка `psiTargetProvider`, запасной вариант —
  `тип "имя" [файл]` из `ElementDescriptionProvider`.
- **Переход к цели** зовёт её собственный `navigate()`. Подчёркивается лист под мышью, а не
  диапазон цели.

**Вывод:** ждать сервер в обработчике можно — с отменой и потолком. Посылка 18–19.09 «платформа
спрашивает синхронно на EDT» была неверной, и на ней стояла схема «промах — не подчёркиваем,
подчеркнём со второго наведения».

## Что делает LSP4IJ (проверено по байткоду 0.20.2)

- Их `LSPGotoDeclarationHandler` спрашивает сервер по позиции, ждёт ответ
  (`awaitWithCheckCanceled`) и возвращает цель только для найденного определения. Утверждение 19.09
  «их обработчик отвечает «да» на весь файл» неверно: вопрос про файл у них — только отбор серверов
  (`isDefinitionSupported(PsiFile)`).
- `LSPDefinitionSupport.getDefinitions` отдаёт `List<LocationData>`, а `LocationLink` уже переведён в
  `Location` по `targetSelectionRange`.
- `LSPDefinitionFeature.isSupported(file)` вызывает `isDefinitionSupported(file)`, и по нему
  `LSPDefinitionSupport` отбирает серверы.
- `HoverData` — package-private запись: результат их поддержки hover из нашего кода не прочитать.

## Два дефекта слоя 19.09 (найдены 23.09, до первого включения ключа)

1. `toTarget(Any?)` сопоставлял ответ с `Location` и `LocationLink`, а приходил `LocationData`:
   каждый ответ сервера становился «объявления нет». Спрятал это `Any?` — типизированный разбор не
   скомпилировался бы.
2. Переход LSP4IJ выключался подменой `isDefinitionSupported` на `false`, а наши собственные запросы
   шли через тот же `LSPDefinitionSupport` — и не находили ни одного сервера.

Любой из двух в одиночку делал навигацию мёртвой, а включивший ключ терял переход совсем: свой
не работал, чужой был выключен. Тесты зеленели, потому что проверяли только чистый кэш.

## Как устроено теперь

- `nav/LspQueries` — единственное место вопросов к серверам: определение и hover. Шлются напрямую
  через `LanguageServiceAccessor.getLanguageServers`: всем серверам файла, в порядке LSP4IJ, и
  упавший не прячет ответы остальных. Умеет ли сервер отвечать на определение, проверяет
  `PreciseNavigation.serverAnswersDefinitions` — сквозь выключатель.
- `nav/LspAnswerCache` — чистые правила. Ответ живёт до правки документа и не дольше полуминуты.
  Вопрос по позиции уходит один раз, следующий спрашивающий присоединяется к летящему. Упавший
  запрос следа не оставляет. Опоздавший ответ о старой версии не затирает новый.
- **Ждут только вне EDT.** Переход — до 2 с (`PreciseNavigation.WAIT_MS`). Подсказка — 300 мс,
  столько же ждёт собственный клиент LSP платформы: документацию могут спросить и из неотменяемого
  обновления действия. Трассировка агента — 5 с на все вопросы вместе.
- `nav/LspTarget` — цель перехода со своим смещением и строкой (список нескольких целей различает
  перегрузки) и с памятью о том, откуда спрашивали.
- `nav/LspSignatureDocumentation` (`psiTargetProvider`) — подсказка = сигнатура из hover
  (`HoverSignature`: первый блок кода, без `<?php`, не больше 6 строк и 400 символов). Отвечает и за
  наши цели, и за `LSPPsiElement` LSP4IJ, поэтому сигнатура видна и при выключенном ключе. У их цели
  позиция вопроса — имя внутри токена TextMate, а не начало токена: токен бывает шире имени.
- `nav/LspSymbolLookup` — точка `com.vibe.agent.symbolLookup` для `vibe_trace_symbol`: сервер
  разрешает имя через импорты, реэкспорты и псевдонимы, текстовый разбор остаётся запасным.
- Всё, что говорит с серверами через классы LSP4IJ, зарегистрировано в
  `vibe-lsp4ij-integration.xml`. Из главного дескриптора выключенный LSP4IJ превращал бы каждый такой
  класс в ошибку загрузки.

## Ключ `vibe.lsp.precise.navigation`

Выключен по умолчанию: замену навигации проверяет только человек за клавиатурой. Что он меняет на
самом деле: переход идёт нашим обработчиком — с потолком ожидания, кэшем по позиции и нашей целью.
«Подчёркивать только резолвимое» он не добавляет: обработчик LSP4IJ и так возвращает цель только для
найденного определения. Если при выключенном ключе подчёркивается всё подряд, причина не в их
обработчике перехода — это пункт живой проверки ([manuals/liveCheck.md](../../manuals/liveCheck.md)).

## Грабли

- **URI сервера → файл** — только `FileUriSupport.findFileByUri(uri, features)`: сервер кодирует URI
  по своим правилам. Самодельный `URLDecoder` превращал `+` в имени файла в пробел.
- **`Either` из lsp4j лежит в jar JSON-RPC.** Без `//libraries/lsp4j/jsonrpc` в зависимостях модуль
  не компилируется, хотя тестам этот jar виден в рантайме.
- **Сигнатура закрытого файла — утечка.** Hover над константой показывает её значение, поэтому
  трассировка называет объявление в файле, закрытом правилами доступа, без сигнатуры.
