# FreeMarker: подсветка шаблонов своей грамматикой
← [Knowledge Index](../README.md)

## [решение] `.ftl` в открытой платформе — безымянный текст, а чужая грамматика не годится

**Роль:** [решение] · **Найдено:** 22.10.2026, по жалобе владельца: шаблоны HL7 CDA открывались с иконкой текста и без цвета

## Контекст

Поддержка FreeMarker есть только в закрытой Ultimate и копированию не подлежит. Открытая платформа
не знает ни `.ftl`, ни `.ftlh`, ни `.ftlx`: файл открывался «неизвестным типом».

## Что проверено

- В сборнике `tm-grammars` (тот, что везёт Vue и Svelte) FreeMarker нет вовсе.
- Единственная найденная открытая грамматика — расширение `dcortes92/vs-freemarker` (MIT, 2021).
  Читает шаблон построчно, а `${…}` и `<#…>` ищет только на верхнем уровне. Внутри кавычек атрибута
  тега их не видит: в шаблоне `<id root="${Lpu.oid}.100.1.1.51"/>` значение не подсвечивается.
  XML-шаблоны (HL7) — это ровно такие строки, поэтому подсвечивается половина.

## Решение

Свой бандл `freemarker`, исходник — `vibe-plugins/vibe-lsp/textmate/freemarker/` (AGPL-3.0, написан по
документации FreeMarker; чужой код не копировался). Три грамматики:

- `source.ftl` — только конструкции FreeMarker: комментарий `<#-- -->`, директивы, вызов макроса `<@x>`,
  интерполяция `${}`/`#{}`, выражения (строки, встроенные `?has_content`, операторы). Сама ничего не обрамляет.
- `text.html.ftl` и `text.xml.ftl` — «хозяева»: подключают `source.ftl`, затем `text.html.basic` или
  `text.xml` из бандлов платформы. Первый обслуживает `.ftl`/`.ftlh`, второй — `.ftlx`.

**Ключевой приём — `injections` хозяина.** Селектор `L:text.html.ftl (meta.tag | string | source | comment…) - (meta.ftl | comment.block.ftl)`
подмешивает `source.ftl` внутрь тега, строки атрибута и встроенного скрипта. Это то, чего нет у
vs-freemarker, и то, без чего XML-шаблон не подсветить. Исключение `- meta.ftl` обязательно: без него
правило применяется внутри уже разобранной директивы и зацикливается на её же строках.
Каждая наша конструкция поэтому носит `meta.ftl.*` (комментарий — `comment.block.ftl`).

Тип файла — `FreeMarkerFileType`: обычный `FileType` с маркером `TextMateBackedFileType`. Маркер велит
TextMate взять подсветку на себя, но оставить наши имя и значок (`TextMateBackedFileIconProvider`
спрашивает зарегистрированный тип по расширению). Объявлен в необязательном конфиге
`vibe-textmate-bundles.xml`, потому что интерфейс-маркер живёт в плагине TextMate.

## Что не сделано

- Квадратная нотация `[#if x]`/`[@m/]` не подсвечивается: оба варианта скобок в одном правиле
  невозможны (конец директивы `>` или `]` зависит от начала, а обратная ссылка `\1` даёт ту же скобку,
  не парную), второй набор правил был бы копией первого. Нотация редка; нужна будет — отдельным набором.
- Нет автодополнения и разбора: только подсветка и тип файла.

## Проверка

`FreeMarkerGrammarTest` гоняет настоящий лексер TextMate по образцу владельца: директивы, `?has_content`,
`${…}` в тексте и внутри атрибута (область `meta.ftl.interpolation` вместе со `string.quoted.double`),
тег `ClinicalDocument` в обоих хозяевах, комментарии. Что тест НЕ видит: подхват типа по расширению в
живой IDE (необязательный конфиг в юнит-окружении не грузится) — проверяется руками.
