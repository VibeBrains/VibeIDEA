# Сервер ставится и ищется той нодой, которой IDE его запускает

**Дата:** 23.09.2026 · **Ветка:** next · **Статус:** правило + замеры

## Что было не так

Кнопки «Проверить» и «Установить последнее» у языковых серверов работали каждая по-своему, и обе
не так, как запуск самой IDE:

- **Установка** шла через `/bin/sh -lc "npm install -g …"` — то есть `npm`, который первым найдёт
  оболочка. При менеджере версий это нередко другая нода, чем выбранная на странице настроек, и
  пакет уходил в её глобальную папку.
- **Поиск** (`ServerBinaries.find`) смотрел в `PATH` процесса IDE и в несколько известных папок,
  но не рядом с нодой IDE. В GUI-приложении на macOS `PATH` не наследует оболочку, поэтому сервер,
  поставленный через fnm/nvm, оставался невидимым — IDE молча работала на встроенной копии.
  Вместе это значило: кнопка ставила то, чем никто не пользуется.
- **Проверка** запускала файл напрямую и с окружением IDE. Серверы из npm — обёртки
  `#!/usr/bin/env node`; без ноды в `PATH` они падают с `env: node: No such file`, и исправный сервер
  выглядел сломанным. Встроенный `.js` вообще не исполняем сам по себе.
- **Поток интерфейса.** Проверка гоняла процесс прямо в EDT, а серверу без `--version` мы ждём
  весь таймаут — окно настроек замирало на каждое нажатие. Обновление строки из фоновой задачи шло
  без `ModalityState.any()` и потому ждало закрытия модального окна настроек.

## Правило

**Одна нода на всё: ею сервер ставится, рядом с ней ищется и ею же запускается.**

- установка npm-команд — `npm` из папки ноды IDE, с этой папкой первой в `PATH` (`NpmInstall`);
- поиск — папка ноды IDE входит в список (`ServerBinaries.nodeBinDir`);
- запуск и проверка — одно правило для файла сервера (`ServerBinaries.runCommand`: `.js` нодой,
  `.phar` через PHP) и одно окружение (`NodeRuntime.childEnvironment`).

Нет ноды — установка не запускается, а называет причину. Команды не на npm (Phpactor — готовый
phar) идут как написаны.

## Ловушки по дороге

- `Path.of("C:\\…\\node.exe").parent` на macOS равен `null`: обратная косая там не разделитель.
  План установки решается для целевой ОС, поэтому каталог отделяется строкой по обоим разделителям.
- Поиск серверов теперь спрашивает, где нода, а та читает настройку через `PropertiesComponent` —
  без приложения (юнит-тесты) это NPE. Настройка без приложения — пустая строка, а не падение.
