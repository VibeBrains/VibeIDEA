# `languageId` решает, чем сервер разбирает файл

**Роль:** [баг] · **Найдено:** 05.09.2026 владельцем, на живом проекте VibeReel

## Контекст

В редакторе `.tsx`-файл был подчёркнут почти целиком: значок «148 ошибок» и красные волны под
каждым тегом JSX. Тот же проект компилировался `tsc --noEmit` **без единой ошибки**, то есть код
был здоров, а ошибки приходили от нашего клиента LSP.

## Суть

Все расширения были объявлены одним сопоставлением:

```xml
<fileNamePatternMapping patterns="*.ts;*.tsx;*.js;*.jsx;…" serverId="vibeVtsls" languageId="typescript"/>
```

`languageId` — не подпись, а указание tsserver, **каким парсером** открывать документ. Под
`typescript` синтаксис JSX запрещён, поэтому каждый `<div>` даёт «'>' expected», а файл на сотню
строк — полторы сотни ошибок.

Проверено прямым прогоном vtsls на файле владельца:

| languageId | диагностик |
|---|---|
| `typescript` | 152 |
| `typescriptreact` | 0 |

VS Code различает четыре идентификатора (`typescript`, `typescriptreact`, `javascript`,
`javascriptreact`) именно поэтому. Та же ошибка была и у ESLint-сервера: `javascript` на `.tsx`
означает разбор TSX парсером JavaScript.

## Применение

- Новый языковой сервер — сперва выяснить, **что он делает с `languageId`**, и разводить шаблоны по
  идентификаторам, а не подписывать одним «похожим».
- Возврат защищает тест `LanguageIdMappingTest`: он читает XML как данные (падает на правке
  описания, а не повторяет его) и требует реактовых идентификаторов для `.tsx`/`.jsx`.
- Симптом «линтер сошёл с ума на здоровом файле» проверяется в первую очередь так: прогнать
  `tsc --noEmit` проекта. Компилятор чист — виноват не код, а то, как мы открыли документ.
