# Родитель темы ищется по id, а не по имени — и промах молчит

**Дата:** 20.09.2026 · **Ветка:** next · **Статус:** правило + гейт

## Симптом, который выглядел как что угодно, кроме причины

Окно проекта тёмное, диалог настроек светлый; кнопки диалога налезают друг на друга; в логе при
**каждом старте**:

```
java.lang.Error: no ComponentUI class for: com.intellij.openapi.wm.impl.ToolbarComboButton
    at com.intellij.openapi.wm.impl.AbstractToolbarCombo.updateUI(AbstractToolbarCombo.kt:34)
    at com.intellij.openapi.wm.impl.ToolbarComboButton.<init>(ToolbarComboButton.kt:35)
```

Ошибка при СОЗДАНИИ кнопки, а не при переключении темы. Владелец присылал этот вид пять раз
подряд, а я четырежды чинил другое: переключение тем мимо `DarculaInstaller`, фильтр классических
тем, пару «день/ночь», ширину страницы. Всё это были настоящие дефекты — и ни один не был причиной.

## Причина

```kotlin
private fun findParentTheme(themes: Collection<LafEntry>, parentId: String?): UITheme? {
  return if (parentId == null) null else themes.firstOrNull { it.id == parentId }?.theme?.get()?.theme
}
```

Поиск по **id**. А в реестре платформы:

```xml
<themeProvider id="ExperimentalDark" path="/themes/expUI/expUI_dark.theme.json" targetUi="new"/>
```

**id — `ExperimentalDark`, имя темы — «Dark».** Все семь наших тёмных тем писали
`"parentTheme": "Dark"`, совпадения не находилось, и платформа молча подставляла запасного
родителя: `DEFAULT_DARK_PARENT_THEME = "Darcula"` — **классическую** тему.

То есть под новым интерфейсом наши темы наследовали таблицу умолчаний классического: в ней нет
классов UI для новых компонентов (`ToolbarComboButton`), нет новых метрик, и половина диалогов
рисуется чужим светлым набором поверх тёмного окна.

Дефект жил с основания набора (23.08.2026) и не мог быть найден ни одним нашим гейтом: json
валиден, тема грузится, имя «Dark» выглядит правильным.

## Правило

`parentTheme` — **идентификатор из реестра платформы**, не имя темы:

| Сторона | Верно | Как выглядит промах |
|---|---|---|
| тёмная | `ExperimentalDark` | «Dark» — имя, а не id |
| светлая | `ExperimentalLight` | «Light» — имя; id у классической светлой вовсе `JetBrainsLightTheme` |

## Гейт

`checkVibeUi.sh` читает реестр платформы (`intellij.platform.ide.impl.xml`) и требует от каждой
нашей темы: родитель существует по id, его `targetUi` — `new`, и он совпадает со стороной темы.
Проверен возвратом прежнего «Dark»: гейт падает.

## Чему это учит

**Молчаливый запасной вариант опаснее отказа.** Платформа не обязана была ругаться — она сделала
разумную вещь: не нашла родителя и подставила умолчание. Цена — месяц симптомов, которые выглядели
как четыре разных дефекта.

И второе, про меня: я четыре раза докладывал о починке, проверив её наличием класса в jar и
зелёными тестами. Причина лежала в ЛОГЕ владельца с первого же снимка — строка `no ComponentUI
class` печаталась при каждом старте. Смотреть надо было туда.
