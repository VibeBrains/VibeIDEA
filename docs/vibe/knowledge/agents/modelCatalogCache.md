# Кэш каталогов моделей: сервируй всегда, пиши только успех

**Дата:** 2026-08-29 · **Ветка:** next

## Симптом

При первом открытии панели пилюля «Модель ▾» состояла только из статических моделей, полный
список появлялся примерно через полминуты. Владелец нашёл это на живой сборке.

## Две причины, а не одна

1. **Результат похода в сеть нигде не сохранялся.** Каждый старт IDE собирал каталоги с нуля,
   хотя они меняются раз в недели.
2. **Провайдеры опрашивались последовательно.** При 11 провайдерах платился таймаут каждого
   мёртвого endpoint по очереди (`zai` — connect timeout, шесть — HTTP 401). Хуже: результат
   публиковался **одним пакетом в конце** (`if (changed) { providers = updated }`), поэтому даже
   уже полученные каталоги ждали самого медленного соседа.

Лечить надо обе: кэш убирает ожидание на старте, параллельность — на обновлении. Кэш без
параллельности оставил бы «первый запуск после установки» тем же получасом ожидания.

## Правила, которые делают кэш безопасным

- **Отдаём всегда, обновляем всегда, TTL нет.** Устаревший каталог никогда не хуже пустого, а
  срок годности — лишняя настройка, которую придётся объяснять.
- **Пишет только успешный ответ.** 401 или таймаут не трогают запись — иначе первый же день с
  протухшим ключом стёр бы каталог, и пользователь остался бы без списка вообще.
- **Запись помнит отпечаток источника** (`baseURL` + `models.fetch.url`). Провайдер, переехавший
  на другой endpoint, не наследует каталог старого — id совпадает, а сервер уже чужой.
- **Место — системный каталог IDE (`PathManager.getSystemPath()/vibe/`), не `~/.vibe`.** В
  `.vibe` живут файлы, которые правит пользователь; кэш регенерируем и правкам не подлежит.
- **Возраст видно.** Строка «каталоги моделей из кэша (2 часа назад) — обновляю в фоне» отвечает
  на вопрос «откуда взялись модели, если сеть ещё молчит».

## Грабли

- **`invokeAndWait` с пула в модальном диалоге — заготовка дедлока.** Страница «Модели» живёт в
  модальном окне настроек: фоновый поток, ждущий EDT в неподходящем modality state, не дождётся
  его никогда, а координатор ждёт этот поток. Публикация результатов — только `invokeLater`,
  а счётчик «сколько добавлено» считается **внутри** EDT-блока и оттуда же пишется в статус.
- **Снимок `staticModelIds` берётся ДО подмешивания кэша.** Иначе кэшированные модели
  притворятся рукописными, получат `defaultHidden = false` и зарастят curated-пикер сотнями
  каталожных id — ровно то, от чего его чистили.
- **Таймаут каталога — отдельный HTTP-клиент.** `connectTimeout` живёт на `HttpClient`, а не на
  запросе, поэтому короткий таймаут нельзя выставить одним `HttpRequest.timeout`. Чат ждать
  соединения имеет право, каталог за спиной кэша — нет: `LlmClient.forCatalog()` (10 с).
