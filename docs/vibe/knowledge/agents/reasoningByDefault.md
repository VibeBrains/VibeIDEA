# Модели, которые думают по умолчанию: «ничего не отправить» — не «выключить»

**Дата:** 23.09.2026 · **Повод:** разбор дайджеста 23.09 — Claude Opus 5.5, GPT-6 Sol/Luna, MiMo v2.6

## Суть

Прежние рассуждающие модели думали, только когда их просили: поле рассуждения не прислано — рассуждения нет.
Новые устроены наоборот: поле без значения — это рассуждение на умолчании вендора.
Наш ползунок на «выключено» не присылал ничего, и у таких моделей это значило «думай на `medium`» —
человек видел «выключено» и платил за рассуждение по ставке выхода.

Выключатель у каждого вендора свой, и бывает, что его нет вовсе:

| Модель | Поле не прислано | Как выключить |
|---|---|---|
| Claude Opus 5.5, Fable 5 / 5.1, Mythos 5 / 5.1 | адаптивное мышление на `medium` (Opus 5.5) или `high` | никак: `thinking.type: "disabled"` — 400; честно — самый низкий уровень `low` |
| Claude Opus 5, Sonnet 5 | адаптивное мышление | `thinking: {"type": "disabled"}` (у Opus 5 — при усилии не выше `high`) |
| Claude Opus 4.7 / 4.8 | мышления нет | не присылать ничего |
| GPT-6 Sol, Luna | `reasoning_effort: "medium"` | `reasoning_effort: "none"`; на проводе Responses — `reasoning: {"effort": "none"}` |
| GPT-6 Astra | рассуждение на умолчании (его значение страница модели не называет) | никак: `"none"` — 400 |
| MiMo v2.6 | мышление включено | `thinking: {"type": "disabled"}`; уровней у модели нет |

## Как устроено у нас

- Знание — в каталоге особенностей моделей (`ModelQuirks`), по имени модели: четыре причуды
  `THINKING_ALWAYS_ON`, `OFF_THINKING_DISABLED`, `OFF_EFFORT_NONE`, `NO_REASONING_LEVELS`.
  Одних сидов мало: модели из каталога вендора (`fetch: true`) приходят без объявления `reasoning`.
- `ModelQuirks.reasoningOf(id, wire)` отдаёт выключатель **только на своём проводе**: `thinking` — на
  Anthropic, `reasoning_effort` — на chat/completions, `reasoning.effort` — на Responses ([responsesWire.md](responsesWire.md)). Та же модель за роутером говорит на диалекте
  роутера, и поле, которого он не знает, было бы нашей догадкой.
- Объявление в записи модели сильнее каталога поле за полем (`ReasoningMode.merged`). Так объявлен
  выключатель MiMo: вендор документирует `thinking` и на chat/completions, а каталог шлёт `thinking` только
  на Anthropic.
- Всё решение собрано в одной чистой функции `LlmClient.reasoningFields` и проверено тестом насквозь
  (`ReasoningByDefaultTest`), а не по частям.

## Рядом нашлось ещё три вещи

- **Пустое мышление.** У Claude Opus 4.7 и новее `thinking.display` по умолчанию `"omitted"`: блоки
  мышления приходят с пустым текстом, и блок рассуждения в чате молчал. Мы просим `"summarized"`. На
  Opus 5.5 это важнее вдвойне: короткие заметки между вызовами инструментов у неё уехали из текста в
  блоки мышления, и без `summarized` прямой чат молчит всю длинную ходку.
- **Выборка.** Opus 4.7 и новее и вся линейка 5 отвергают `temperature`, `top_p` и `top_k` с 400 —
  правило `ADAPTIVE_THINKING` этого не знало.
- **Лимит вывода.** Модель из каталога получала наше умолчание 8192, а неотключаемое мышление делит
  этот лимит с ответом. Каталог Anthropic называет настоящий потолок (`max_tokens` рядом с
  `max_input_tokens`), и мы его берём. По официальной странице лимитов `max_tokens` в расчёт OTPM не входит,
  так что высокий потолок лимитам не вредит.

## Грабли

- **Одна и та же регулярка ловит больше, чем кажется.** `^claude-(opus|sonnet|fable|mythos)-5` ловит и
  `claude-opus-5-5`. Правила каталога объединяются, поэтому правило «выключатель Opus 5» написано точными
  id (`^claude-(opus|sonnet)-5$`): иначе Opus 5.5 получил бы оба ответа сразу.
- **Причина остановки была слепым пятном.** Отказ классификатора у Claude — это ответ 200 с
  `stop_reason: "refusal"`, часто без текста; обрыв по лимиту — ответ без конца. Ни один провод её не
  читал; теперь `StopReason` читает все три, и лента называет причину.
- **Роутер пишет рассуждение по-своему, хотя провод тот же.** OpenRouter говорит по протоколу `openai`, но
  рассуждение принимает только объектом `reasoning`, а поле `reasoning_effort` в его документации не упомянуто.
  «Выключено» у модели из его каталога не слало ничего: записи с `off` у неё нет. MiMo, которая думает по
  умолчанию, на OpenRouter продолжала думать при «выключено» (24.09.2026). Теперь поле провайдера
  `reasoningDialect: "openrouter"` переводит ползунок в `reasoning.effort`, а «выключено» — в `effort: "none"`
  для любой модели за роутером. Поле объявлено в засеянном `openrouter.jsonc`, потому что знание о роутере —
  свойство провайдера, а не каждой из его моделей. Причуды при этом работают и за роутером: id сравнивается
  без префикса `vendor/`.
