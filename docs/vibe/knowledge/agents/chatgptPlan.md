# ChatGPT по подписке: вход открытого клиента и маршрут плана

**[архитектура+грабли]**

## Контекст

OpenAI открыл открытым клиентам вход аккаунтом ChatGPT: запросы оплачивает план Plus или Pro, ключ API не нужен.
Источник — developers.openai.com/siwc/token-sharing-open-source, страницы сверены 01.10.2026; маршрут — превью.
Решение №126; отличие от запрета №65 — там вендор запрещает вход подпиской сторонним продуктам, здесь сам зовёт.

## Суть

- **Регистрация приложения не нужна.** Первый вход идёт с `client_id=dynamic_agent_client` и `agent_name_hint`, вендор выдаёт клиента в ответе колбэка; следующий вход называет выданного клиента и прошлый ID-токен и пропускает выбор аккаунта.
- **Колбэк — только `http://127.0.0.1:<порт>/auth/callback`.** Встроенный сервер IDE живёт под `/api/…`, поэтому слушатель свой; `localhost` вендор не принимает. Порт 1455 занимает и вход Codex CLI — свободный порт вендор разрешает.
- **ID-токен — не право тратить план.** Право даёт только выданный scope `chatgpt.tokens.use.direct`; без него вход стоит, план не тратится.
- **Refresh-токен ротируется.** Каждое обновление выдаёт новый, старый сгорает: обновления одного аккаунта идут по очереди, новый токен пишется в связку сразу.
- **Связка ключей спрашивает пароль.** Поэтому токен доступа живёт только в памяти, а фоновые вызовы берут токен из памяти и связку не трогают.
- **Успех — только `response.completed`.** Поток, оборванный лимитом, кончается без него, и без проверки пустой ответ выглядел бы успехом.
- **Маршрут уже API.** Отвергает `temperature`, `top_p`, `max_output_tokens`, `previous_response_id` и ещё ряд полей; функции — только в пространстве имён, и вызов из истории должен нести `namespace`. Тело приводится последним шагом, после причуд и `extraBody`.
- **Каталог другой формы.** `models[].slug` с полем `visibility`; показывать только `"list"`.

## Как применять

- Список отвергаемых полей — общий с VibeIDE в `testVectors/chatgptPlan.json`; превью поменяется — меняется там, тест сверяет код со списком.
- Ошибки маршрута (`subscription_sharing_*`) называются словами с кодом и request id; лимит не уводит запросы на платный ключ сам.
- Живьём не проверено: нужен вход владельца аккаунтом Plus или Pro.
