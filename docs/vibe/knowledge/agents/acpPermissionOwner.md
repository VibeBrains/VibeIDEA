# Два владельца одного решения: кто спрашивает у ACP-агента

[решение+баг] Режим прав IDE (автопилот / правки / вручную / план) и режим сессии ACP-агента отвечают на один вопрос: «когда спрашивать человека».

## Контекст

У прямого чата с моделью спрашивает только IDE, поэтому пилюля прав IDE нужна. У ACP-агента (Claude Agent и др.) есть свой режим сессии («Режим: …»), и именно он решает, послать ли `session/request_permission`.
Две пилюли рядом выглядели как два рычага одного решения, хотя режим IDE на запросы агента не влиял вовсе: человек выбирал «Автопилот» и ждал молчаливых правок, а агент в своём режиме всё равно спрашивал.

## Суть

- Владелец решения у ACP-агента — его режим. IDE не отвечает на запрос за человека ни в одном из своих режимов: запрос идёт диалогом, закрытый диалог = отказ.
- Пилюля прав IDE скрыта при цели-агенте и видна у прямого чата. Единственная точка — `selectTarget` (старт, восстановление вкладки и ручной выбор проходят через неё).
- Доверие к проекту IDE держит сама, независимо от любого режима. Раньше оно проверялось только у прямых инструментов и MCP, а у ACP не проверялось вовсе: недоверенный проект мог получить запись через `fs/write_text_file`. Теперь `AcpPermissionPolicy` отклоняет запись и запросы на изменение/запуск (неизвестный вид инструмента считается худшим случаем). Чтение не блокируется.

## Применение

В `AcpPermissionPolicy.answer` нет параметра «режим IDE» намеренно: появится соблазн добавить его — это возвращение второго владельца.

## Дополнение 20.11.2026: режимы и обратимость удаления

Хендофф VibeIDE сверил правила с кодом и закрыл одну настоящую дыру.

- Имена режимов прямого чата приведены к VibeIDE: **Авто** (было «Автопилот») — всё без вопросов, кроме необратимого и выходящего за проект; **Принимать правки** (было «Правки») — правки файлов проекта молча, команды оболочки и MCP с вопросом; **Вручную** и **План** — как были. Пилюля по-прежнему только у прямого чата.
- `BYPASS` не заводился: в VibeIDE он отличается от «Авто» только отсутствием вопроса о чтении/поиске вне проекта, а такого шлюза у нас нет — «Авто» уже и есть «одобрять всё, кроме необратимого».
- Удаление внутри папки проекта **не** обратимо, хотя чекпоинт и создаёт такую видимость: снимок идёт через `git add -A` и `ls-files --exclude-standard`, поэтому `.env`, `node_modules` и выход сборки в него не попадают; папка без git снимка не имеет; снимок снимается на ход, значит созданное в этом же ходе до `rm` не вернётся; у внешнего ACP-агента снимка всей папки нет. `RemovalScope` теперь молча пропускает только удаление внутри временной папки (VibeIDE 16aa3eb244c), `rm .env` снова вопрос.
- Ход, чья последняя непустая строка кончается «?», останавливает автопилот (`AutopilotPolicy.Decision.STOP_QUESTION`): иначе «продолжай» утверждал план за человека. Закрытие вопроса человека не касается — у прогонов без человека автопилота нет.
- Одобрение в карточке `session/request_permission` запоминается в `TurnState.approvedCommands` и снимает повторный вопрос разрушительного шлюза `terminal/create` о той же строке; запись расходуется одним запуском, а не становится постоянным разрешением.

Проверять: `PermissionModeTest`, `RemovalScopeTest`, `AutopilotPolicyTest`.
