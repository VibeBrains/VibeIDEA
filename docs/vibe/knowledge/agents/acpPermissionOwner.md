# Два владельца одного решения: кто спрашивает у ACP-агента

[решение+баг] Режим прав IDE (автопилот / правки / вручную / план) и режим сессии ACP-агента отвечают на один вопрос: «когда спрашивать человека».

## Контекст

У прямого чата с моделью спрашивает только IDE, поэтому пилюля прав IDE нужна. У ACP-агента (Claude Agent и др.) есть свой режим сессии («Режим: …»), и именно он решает, послать ли `session/request_permission`.
Две пилюли рядом выглядели как два рычага одного решения, хотя режим IDE на запросы агента не влиял вовсе: человек выбирал «Автопилот» и ждал молчаливых правок, а агент в своём режиме всё равно спрашивал.

## Суть

- Владелец решения у ACP-агента — его режим. IDE не отвечает на запрос за человека ни в одном из своих режимов: запрос идёт диалогом, закрытый диалог = отказ.
- Пилюля прав IDE скрыта при цели-агенте и видна у прямого чата. Единственная точка — `selectTarget` (старт, восстановление вкладки и ручной выбор проходят через неё).
- Доверие к проекту IDE держит сама, независимо от любого режима. Раньше оно проверялось только у прямых инструментов и MCP, а у ACP не проверялось вовсе: недоверенный проект мог получить запись через `fs/write_text_file`. Теперь `AcpPermissionPolicy` отклоняет запись и запросы на изменение/запуск (неизвестный вид инструмента считается худшим случаем). Чтение не блокируется.

## Применение

В `AcpPermissionPolicy.answer` нет параметра «режим IDE» намеренно: появится соблазн добавить его — это возвращение второго владельца.
