# Правки внешнего агента мимо клиента

Claude Code ACP не зовёт `fs/write_text_file`: его инструменты `Edit`/`Write` меняют файл сами, поэтому клиент узнаёт о правке только из кадров вызова инструмента. Журнал правок (`AgentEditJournal`), разбор по одной правке в редакторе и полоска изменённых файлов питались лишь клиентской записью, так что правки Claude шли мимо них.

## Что приходит в кадрах

- `tool_call` и `tool_call_update` несут `content: [{type:"diff", path, oldText, newText}]`.
- У `Edit` `oldText` и `newText` — обрывки файла, а не весь текст. У `Write` `oldText` пуст и для уже существующего файла. Поэтому из `diff` базу «до» брать нельзя: откат по такой базе стёр бы файл.
- Вопрос `session/request_permission` приходит до записи и тоже несёт `content`.

## Решение

- База «до» — снимок файла с диска при первом взгляде на вызов (объявление или вопрос о разрешении). Отсутствие файла — тоже снимок: файл создан агентом.
- «После» — диск на момент `completed`, после обновления VFS, а не `newText`.
- Снимка нет (увидели только `completed`): для правки база собирается обратной подстановкой `oldText` вместо `newText` в текущий текст; для записи целиком базы нет, и запись пропускается — угаданная база делает «отклонить» разрушительным.
- Снимок расходуется при записи в журнал: следующий вызов на тот же файл снимает его заново. Первое касание держит сам журнал (`record` не трогает прежнее «до»).
- Окно разрешения показывает diff строками «-» и «+» (урезан до `MAX_PREVIEW_CHARS`).

Код: `acp/ToolCallRegistry.kt` (`ToolDiff`), `acp/ExternalEditCapture.kt`, проводка в `AgentPanel` (`snapshotAgentEdit`, `recordAgentEdit`). Не проверено в живой IDE с настоящим Claude Code: покрыто тестами по форме кадров и сценарием FakeAcpAgent.
