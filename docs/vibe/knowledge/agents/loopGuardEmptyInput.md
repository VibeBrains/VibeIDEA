# Охранник петель и пустые аргументы при объявлении вызова

**[грабли]**

## Контекст

Ход остановился сообщением «агент повторяет один и тот же вызов 4 раза подряд … write|{}», хотя агент писал четыре разных файла.
Адаптер Claude ACP объявляет вызов кадром `tool_call` («Preparing file…») с пустым `rawInput: {}` и присылает аргументы позже, кадром `tool_call_update`.

## Суть

- **Отпечаток по пустому вводу не отличает вызовы.** `LoopDetector.fingerprint` склеивает имя и аргументы, и все четыре записи получали `write|{}`.
- **Пустой ввод не учитывается.** Вызов без аргументов (нет, `{}`, `null`, пробелы) при объявлении не записывается.
- **Запись — один раз на номер вызова,** когда аргументы пришли: `LoopDetector.History.noteCall(callId, tool, arguments)`. Повторные обновления того же вызова второй записи не дают.
- **Настоящая петля ловится по-прежнему:** те же аргументы четыре раза подряд дают REPEAT.
- **Окно исходов (`ThrashDetector`) не затронуто:** оно смотрит на вызов при завершении, когда аргументы уже известны.

## Как проверять

`LoopAnnounceTest` проигрывает реальную последовательность кадров через `ToolCallRegistry` и историю: четыре записи с пустым объявлением дают OK, четыре с одинаковыми аргументами дают REPEAT.
Любой новый детектор по вызовам агента должен получать вызов с его настоящими аргументами, а не с тем, что пришло в первом кадре.
