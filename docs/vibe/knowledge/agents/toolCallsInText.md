# Вызов инструмента текстом: разметка семейств моделей в ответе

**[квирк]**

## Контекст

30.09.2026 VibeIDE прислал журнал: `deepseek-flash` шесть ходов подряд писал вызов инструмента текстом в ответе, а поле `tool_calls` оставлял пустым.
Клиент не видел ни одного вызова, человек видел обрывки разметки, автопилот гонял круги.
Первая правка (решение №115) читала только DSML и только у `deepseek-*`.
На вопрос владельца, почему только DeepSeek, ответ оказался таким: беда вовсе не в одной модели, а в том, кто разбирает её разметку (решение №118).

## Суть

У каждой открытой модели в шаблоне чата своя разметка вызова, и в `tool_calls` её превращает сервер: vLLM, SGLang, Ollama, LM Studio, провайдер агрегатора.
Сервер без парсера семейства или модель, которая сбилась, оставляют разметку в ответе.
Имя модели тут ничего не решает: одно семейство живёт под десятками имён и хостов.

Как устроено:
- `TextToolCalls` решает, есть ли вызов, `TextToolCallFormats` читает формы семейств.
- Чтение включено, когда запрос предлагал инструменты и провод не принёс ни одного вызова.
- Вызов засчитывается только при двух условиях: разметка стоит вне блока кода и инлайн-кода, вызванное имя есть среди предложенных.
- Незнакомое имя — текст: модель рассказывает о разметке, а не вызывает.
- Разметка, не называющая ни одного предложенного инструмента, — тоже текст.
- Разметка, которая называет инструмент, но не читается, — неудавшийся вызов: одна просьба модели повторить, второй провал останавливает ход.
- `ToolMarkupFilter` в потоке придерживает текст с первого признака разметки: тег приходит разрезанным между кусками, как `<think>`.
- Ответ, который начинается с `{` или `[`, ждёт до 80 символов: так начинаются формы, где вызов — весь ответ.
- Каждый случай — строка в журнале IDE: `Tool calls read from answer text` (info) или `did not parse` (warn), с моделью и форматом.

Формы (сверены 30.09.2026 с шаблонами и энкодерами вендоров и грамматиками vLLM, коммит `ed3f6d1a`):

| Формат | Семейства | Признак |
|---|---|---|
| `dsml` | DeepSeek V3.2, V4, V4.1 | `<｜DSML｜function_calls>`, `tool_calls`, у V4.1 пробел: `<｜DSML｜ calls>` |
| `invoke` | V3.2 после вырезания маркера, XML в стиле Anthropic | `<function_calls>`, `<invoke name=…>` |
| `minimax-m2` | MiniMax M2, M2.7 | `<minimax:tool_call>` |
| `minimax-m3` | MiniMax M3 | префикс `]<]minimax[>[` перед каждым тегом, вложенные элементы |
| `deepseek-v3` | DeepSeek V3, R1, V3.1 | `<｜tool▁calls▁begin｜>` |
| `hermes` | Hermes, Qwen 2.5 и 3, Granite 3.1 и 4 | `<tool_call>` и JSON |
| `qwen-xml` | Qwen3-Coder, Qwen 3.5+, Seed-OSS | `<tool_call><function=…><parameter=…>` |
| `glm` | GLM 4.5+ | `<tool_call>имя<arg_key>…<arg_value>` |
| `kimi-k2` | Kimi K2 … K2.6 | `<\|tool_calls_section_begin\|>`, имя `functions.x:0` |
| `kimi-k3` | Kimi K3 | каналы XTML `<\|open\|>tools<\|sep\|>` |
| `mistral` | Mistral | `[TOOL_CALLS]`: список JSON или `имя[ARGS]{…}` |
| `llama` | Llama 3.x | `<\|python_tag\|>` и JSON с `parameters` |
| `json` | Llama без тега, Mistral и Granite после вырезания маркера | весь ответ — JSON вызова или список |
| `granite` | Granite 3.x, 20B | `<\|tool_call\|>`, `<function_call>` |
| `harmony` | gpt-oss | `to=functions.x` … JSON |
| `gemma` | Gemma 4 | `<\|tool_call>call:x{…}<tool_call\|>` |
| `pythonic` | Llama 4 | весь ответ — `[x(a="…")]` |

## Грабли

- **`<tool_call>` открывает пять форм.** Различает первое после тега: `{` или `[` — Hermes, `<function=` — Qwen XML, имя — GLM. Префикс MiniMax M3 содержит `<tool_call>`, поэтому проверяется первым.
- **В половине форм нет типа значения** (Qwen XML, GLM, MiniMax, Gemma, DSML без атрибута `string`). Значения приводятся по JSON-схеме инструмента правилом vLLM: типы пробуются в порядке null, integer, number, boolean, object, array, string. Без схемы значение остаётся строкой.
- **Спецтокены сервер вырезает.** V3.2 без `skip_special_tokens=False` приходит голым `<invoke>`, harmony и Gemma теряют почти все опоры. Такие формы взяты, только где у текста осталась опора; остальное — пометка в `SPEC.md` копии.
- **`Json.parseToJsonElement` в kotlinx принимает голое слово** (`forty`) как литерал. Значение `string="false"` поэтому проверяется отдельно: без кавычек допустимы только число, `true`, `false` и `null`.
- **Маркер DSML — только полноширинная черта `｜`.** Пара обычных черт встречается внутри значений (`cat a |sort| uniq`).
- **Инлайн-код ломается на резке потока.** Обратная кавычка, ушедшая в ленту раньше тега, уносила признак «внутри кода». Поэтому фильтр держит состояние кода (блок, спан на строке) через все куски, а не смотрит на соседний символ.
- **Опознавательный литерал придерживается целиком.** Префикс `]<]minimax[>[` и заголовок harmony `<|start|>assistant ` уже закрыты `>` и без этого уходили в ленту до того, как узнавалась разметка.
- Имя сверяется как есть, затем без `functions.` (Kimi, harmony) и без пространства имён `ns::` (DeepSeek V4.1).
- **Цена придержки.** Если тег стоит в прозе вне кода, остаток ответа приходит в ленту разом в конце хода, а не потоком. Это касается и Claude с GPT: фильтр стоит на любом запросе с инструментами.

## Как применять

- Новая форма из журнала — случай в `testVectors/textToolCalls.json` набора, а не в тест одного продукта. Тест требует, чтобы у каждого формата были свои случаи.
- Первоисточники и полная спецификация форм лежат в `/Volumes/Storage/Caches/tool-call-formats/SPEC.md`: вне репозитория, её можно скачать заново.
- Живьём не проверено: ключей к открытым моделям на машине нет. Как часто модели так делают, покажет журнал IDE.
