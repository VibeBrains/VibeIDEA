# «Спросить не удалось» — не «ключа нет», и на Windows это было видно всегда

**Дата:** 21.09.2026 · **Ветка:** next · **Статус:** баг + правило + замеры

## Симптом

Владелец на Windows: страница провайдеров показывает «Ключа нет» у каждого провайдера, каталоги
моделей сообщают «без ключа 13», ключ, введённый в этой же сессии, «пропадает» после перезапуска.
На macOS — «то пропадают, то появляются».

## Причина

```kotlin
KeychainProbe.State.UNKNOWN -> false      // ApiKeyResolver.hasStoredKey
```

А сам `KeychainProbe` первой строкой: `if (!SystemInfo.isMac) return State.UNKNOWN`.

Проба заведена, чтобы не читать ЗНАЧЕНИЕ ключа и не вызывать диалог связки macOS. Но ответ «не
удалось спросить» сворачивался в «нет», а вне macOS он приходит **всегда** — значит на Windows
ответ «ключа нет» выдавался при любом сохранённом ключе. В комментарии той же функции было
написано, что «не знаю» честнее ложного «нет»; код делал обратное.

На macOS то же самое случалось при каждом молчании связки дольше пяти секунд — отсюда «то
пропадают, то появляются»: `known` держит прочитанные ключи в памяти процесса, поэтому до
перезапуска всё выглядит целым.

## Проверено фактом, а не рассуждением

Осмотр связки владельца (наличие записей, без чтения значений — пароля не спросило): записи
`minimax`, `openrouter`, `deepseek` **на месте**, страховочных `(backup)` нет ни одной. То есть
ключи не терялись вовсе — их не видел интерфейс.

## Правило

- **Три ответа, а не два:** есть, нет, спросить не удалось. Третий показывается человеку своей
  строкой: тот, кому сказали «ключа нет», идёт вводить ключ заново.
- **Диалог вызывает чтение ЗНАЧЕНИЯ и только у связки macOS.** Где связки нет — читаем свободно,
  потому что «не знаю» там выдумка.
- **Ветка, недостижимая на машине разработчика, выносится в чистую функцию** (`KeyPresenceRule`),
  иначе она не измеряется: `SystemInfo.isMac` на маке истинно всегда, и сломанная ветка Windows
  прожила бы до следующего скриншота владельца.

## Рядом: два каталога настроек на Windows

Вывод с машины владельца:

```
AppData\Roaming\VibeBrains\VibeIdea\c.kdbx          2218  21.09.2026
AppData\Roaming\VibeBrains\VibeIdea2026.3\c.kdbx    2202  03.09.2026
```

`getSystemSelector` у нас сделан стабильным (`VibeIdea`, без версии) — осознанно, разбор в самом
методе. Но сборки ДО той правки писали в `VibeIdea2026.3`, и ключи остались там: на Windows
хранилище паролей — файл внутри каталога настроек, а не системная связка. Отсюда «на винде сразу
было пусто от прошлой версии». Переноса настроек у нас нет — это отдельная работа, и она названа
в roadmap, а не сделана молча.
