# Цена контекста у ACP-агента: правила в каждом сообщении

**Роль:** [замер+решение] · **Найдено:** 21.10.2026, одно и то же ревью кода через Claude Code в VibeIDEA и VibeIDE

## Что заметил владелец

Ревью через Claude Code как ACP-агента в VibeIDEA:
10 вызовов модели, запись в кэш 92 454, чтение из кэша 838 311, вход 20, выход 4 706 — всего 935 491 токен
Ответ начался без метки «Бригадир: включён», агент всё делал сам в главной сессии
То же ревью в VibeIDE: метка на месте, работа ушла субагенту на Sonnet, 99 745 у субагента и около 66 тыс. в главной

## Замеры

Адаптер `@agentclientprotocol/claude-agent-acp` 0.93.0, запуск как из IDE: `initialize`, `session/new` с `cwd` и
пустым `mcpServers`, один `session/prompt`
Числа взяты из `usage` ответа `session/prompt` и совпали с транскриптом сессии до токена

| Прогон | Начало ответа | Токены |
|---|---|---|
| Пустая папка, «сколько будет 2+2» | «Бригадир: включён» | 43 691 |
| То же с приставкой VibeIDEA: стиль сжатых ответов 3 122 симв. + засеянные правила 19 413 симв. | «Бригадир: включён» | 53 180 |
| Ревью файла в этом репозитории, без приставки | «Бригадир: включён» | 404 105, 7 вызовов |
| То же ревью с приставкой VibeIDEA (с AGENTS.md репозитория — 28 633 симв.) | «Читаю резолвер секретов…», метка только в итоговом ответе | 561 448, 8 вызовов |

Отсюда:
- Приставка из засеянных правил и стиля — около 9,4 тыс. токенов на сообщение (разница 53 180 − 43 691)
- Её же получает побочный вызов Haiku в адаптере: 1 201 токен без приставки, 10 570 с ней
- На одном и том же ревью приставка дала +39 % токенов: она лежит в истории и перечитывается каждым вызовом модели,
  а каждое следующее сообщение добавляет ещё одну копию
- С приставкой первая строка ответа перестала быть меткой из правил пользователя

## Причины

**Двойная загрузка.** VibeIDEA приклеивала к каждому сообщению ACP-агенту правила проекта, указатели базы знаний,
решений и входящего, дизайн-контекст и требования минимализма
Claude Code сам читает CLAUDE.md, AGENTS.md и правила пользователя: адаптер открывает сессию с
`settingSources: ["user", "project", "local"]` во всех трёх версиях на машине (0.79.0, 0.91.0, 0.93.0)
Что AGENTS.md он читает, проверено отдельно: папка с одним AGENTS.md «заканчивай ответ словом КИВИ» — ответ кончился «КИВИ»
VibeIDE в ACP-сообщение правил не добавляет: только стиль ответа, раз на сессию, и контекст редактора

**Метка пропала из-за приставки — это гипотеза, а не доказанная причина.** Прогон владельца не воспроизведён один в
один; на коротком ревью с приставкой метка ушла из начала ответа, без приставки стояла первой строкой
Заголовок блока правил говорил «при конфликте с общими привычками побеждают они», а стиль сжатых ответов требует
делать вызовы без преамбулы — оба тянут модель от строки-метки перед работой

**Окружение запуска правила пользователя не отключает.** Проверено командой:
- `CLAUDE_CONFIG_DIR` в оболочке владельца — `~/.claude`, то есть умолчание
- Агент, запущенный с окружением этой оболочки, метку ставит
- С унаследованными метками сессии Claude Code (`CLAUDECODE`, `CLAUDE_CODE_ENTRYPOINT` и другие) на 0.93.0 тоже
  ставит, но контекст вырос до 57 091 токена: переменные хоста включают лишние инструменты
- С `CLAUDE_CODE_SIMPLE=1` агент стартует голым и отвечает «Authentication required»: без CLAUDE.md, правил и входа

VibeIDE эти метки снимает (`NESTED_SESSION_MARKERS` в `vibeAcpMainService.ts`), VibeIDEA не снимала

## Решение

- Агент, который сам читает файлы инструкций, получает контекст проекта **один раз на сессию**:
  системным промптом (`systemPrompt`, `mode: "append"` в `session/new` и `session/resume`), если агент заявил
  `sessionCapabilities.systemPrompt`; иначе первым сообщением
- В этом блоке только то, чего агент сам не прочтёт: корневые правила `.vibe/rules`, `.cursor/rules`, `.cursorrules`
  (всегда действующие — целиком, остальные — строкой с путём, маской и фразами), где лежат знания, решения и входящее,
  дизайн-контекст; AGENTS.md не повторяется, а про правила пакетов сказано одной строкой
- Заголовок блока не объявляет правила проекта сильнее правил пользователя
- Правила поправили посреди сессии — новый текст уходит один раз, следующим сообщением (`AgentInstructions.due`)
- Кто читает сам, решает поле записи агента `readsInstructions`; без поля — адаптер Claude да, остальные нет
- Минимализм уходит ACP-агенту раз на сессию и при смене уровня, как стиль сжатых ответов
- Метки чужой сессии Claude Code и `CLAUDE_CODE_SIMPLE` снимаются при запуске агента; заданное в `env` записи остаётся
- Прямой чат с моделью правила получает как раньше: другого источника у неё нет

Код: `acp/AgentInstructions.kt`, `AcpClient.openSession`, `AgentPanel.sendToAcp`, `AgentEnvironment.dropForeignSession`

## Как перемерить одинаково в обоих продуктах

Оба продукта запускают Claude Code с корнем проекта как рабочей папкой, поэтому их сессии лежат в одном каталоге
транскриптов: `$CLAUDE_CONFIG_DIR/projects/<путь проекта, где всё кроме букв и цифр заменено на «-»>/`

Порядок:
1. Открыть один и тот же проект в VibeIDEA и VibeIDE
2. В каждом — новый тред с Claude Agent и одно и то же сообщение, слово в слово
3. `python3 vibe-plugins/tools/agentTurnUsage.py <корень проекта> --last 4`

Скрипт печатает по каждой сессии вызовы модели и запись, чтение, вход, выход — отдельно главную сессию и субагентов
Это те же числа, которые выставляет API: вызов, разбитый в транскрипте на несколько строк, считается один раз

## Правило

- Агенту, у которого своя история, постоянный текст отправляется раз на сессию, а не с каждым сообщением
- Прежде чем передавать агенту правила, проверить, не читает ли он их сам: двойная загрузка не видна ни в одном тесте,
  только в счёте
- Утверждение «агент не видит правил пользователя» проверяется запуском адаптера с тем же окружением, а не чтением кода
