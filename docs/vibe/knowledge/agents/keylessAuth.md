# Сервер без ключа: `"auth": "none"` и умолчание, равное явному значению

Повод — хендофф VibeIDE 24.09.2026: у них провайдер с `"auth": "none"` не показывал моделей
Сверка нашла у нас четыре дыры вокруг того же поля, и ни одна не была видна снаружи, пока провайдер работал на localhost

## Что было

- Допуск провайдера без ключа решался только адресом: `apiKey == null && !isLocal` — шесть копий условия
  - vLLM в локальной сети (`http://192.168.1.50:8000/v1`) с `"none"` оставался без моделей
- Правило «куда уходит ключ» было записано трижды: каталог моделей, OpenAI/Anthropic, Gemini
  - Gemini слал `x-goog-api-key` при `"none"` и игнорировал `name` у `"header"`
  - `"query"` без `name` на OpenAI-проводе не отправлял ключ никуда
  - Gemini не добавлял `query` провайдера в адрес
- При `"none"` ключ всё равно искался, в том числе в связке ключей ОС — а это диалог с паролем
- Явный `"auth": "bearer"` в своём `providers.json` не перекрывал засеянный `"none"`

## Грабля: умолчание, равное законному значению

Слияние слоёв решало «написано ли поле» сравнением с умолчанием: `if (over.auth != AuthSpec()) over.auth else base.auth`.
`AuthSpec()` — это и есть `bearer`.
Поэтому явный `bearer` для слияния неотличим от молчания, и слабый слой побеждает сильный.

Лечение — хранить написанное отдельно от действующего:
- `ProviderEntry.declaredAuth: AuthSpec?` — null значит «слой молчит»
- `ProviderEntry.auth` — вычисляемое `declaredAuth ?: AuthSpec()`, читатели не меняются
- слияние — `over.declaredAuth ?: base.declaredAuth`, как у всех прочих необязательных полей

Та же ловушка ждёт любое поле, у которого умолчание — одно из допустимых значений.
Проверка при ревью: слияние сравнивает с конструктором по умолчанию — значит, оно не отличает явное от молчания.

## Как теперь

- `ResolvedProvider.missingKey` — одно определение: нет ключа, не localhost и не `"none"`
- `ProviderAuth.placement(auth, key, wire)` — чистая функция, одна на все провода и каталог; тестируется без IDE
- `ApiKeyResolver.resolve` / `resolveQuietly` при `"none"` возвращают null, ни к одному источнику не обращаясь
- 401/403 на каталоге у `"none"` — своё состояние `keyRequired`, а не «ключ отклонён»: ключа не было
- `"none"` рядом с `apiKeyEnv` / `apiKeyRef` и незнакомый тип `auth` — предупреждения при загрузке
  - противоречие проверяется после слияния: обычно оно поперёк слоёв

Поведение сведено с VibeIDE по правилу «брать там, где шире»: `"none"` пускает на любом адресе (как у них),
localhost пускается и без объявления (как у нас).

Тесты — `KeylessAuthTest`, спека — раздел «Как ключ уходит в запрос» в [providersSpec.md](../../manuals/providersSpec.md).
