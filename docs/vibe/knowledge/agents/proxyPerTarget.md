# Прокси по целям: мимо прокси для одних, через прокси для других

Разбор 25.09.2026, повод — просьба владельца: Claude и DeepSeek через прокси, MiniMax напрямую.

## Где хранится выбор

В настройках IDE, списком `provider:<id>` и `agent:<имя>` (`ProxyTargets`).
Какой маршрут работает — свойство сети этой машины: `providers.json` уезжает с проектом в чужую сеть и решал бы там за человека.
Заодно общий с VibeIDE формат не растёт полем, которого у них нет.

## Грабля: по адресу выбирать нельзя

Селектор прокси JDK видит только адрес запроса.
А у `minimax` и `minimax-anthropic`, у `opencode-go` и `opencode-zen` общий хост: выбор «по адресу» склеил бы их.
Поэтому запросы провайдера уходят одним из двух клиентов (`ProviderClients`): маршрутизированным или без прокси, по id провайдера.
Второй клиент строится при первом обращении — машина без «прямых» провайдеров его не строит.
«Без прокси» — это `HttpClient.Builder.NO_PROXY`: без селектора клиент взял бы умолчание JVM, а это прокси IDE.

## Агент — отдельный процесс

Ни прокси IDE, ни наш прокси до процесса агента не доходили, а IDE из Dock не видит переменных оболочки.
Прямой чат за корпоративным прокси работал, агент — нет.
Маршрут передаётся переменными окружения (`AgentProxyEnv`, чистая), выбор маршрута — `AgentProxyRoute`:
отмечен «напрямую» → переменные прокси снимаются; задан наш прокси → он; ручной прокси IDE → его адрес с логином из хранилища IDE.
PAC и автоопределение выбирают прокси на каждый запрос, а переменная держит один адрес, поэтому они агенту не передаются — об этом строка в журнале.
Логин в адресе кодируется процентами: `URLEncoder` пишет пробел плюсом, а в части адреса с логином плюс — буквальный символ.

`env` записи агента применяется после маршрута и сильнее: рукой написанное — последнее слово человека.

Тесты — `AgentProxyEnvTest`; выбор клиента по провайдеру и чтение настроек IDE покрыты только сборкой: юнит-тестам без приложения недоступно хранилище настроек.
