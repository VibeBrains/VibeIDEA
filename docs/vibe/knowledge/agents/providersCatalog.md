# Каталог провайдеров `.vibe/providers/`: слоистость, семантика active, грабли

**Дата:** 2026-08-28 · **Ветка:** next · **Решение:** №24 в [decisions.md](../../decisions.md)

## Что построено

У VibeIDE `providers.json` дополнял **вшитых** провайдеров, а каталог `.vibe/providers/*.jsonc`
был библиотекой для копирования. У нас вшитых нет, поэтому каталог сделан **авточитаемым** —
он и есть «встроенные провайдеры», только обычными файлами. Реестр собирается из четырёх
слоёв, от слабого к сильному:

```
каталог ~/.vibe/providers/            (глобальные файлы, по алфавиту)
  → каталог <проект>/.vibe/providers/ (засеянный; по алфавиту)
    → ~/.vibe/providers.json          (пользовательский, глобальный)
      → <проект>/.vibe/providers.json (пользовательский, самый сильный)
        → resolveExtends (один строгий проход по слитому реестру)
          → фильтр active             (в самом конце)
```

## Главный урок: где лежат «встроенные»

Первая версия складывала слой «каталог + providers.json» на каждом уровне и мержила
уровни (проект сильнее глобали). Адверсариальное ревью поймало следствие: **засеянный в
каждый проект файл с `active:false` оказывался в самом сильном слое и глушил живой
глобальный `providers.json` пользователя с тем же id** (а активные сиды затирали его
baseURL/apiKeyEnv). У VibeIDE builtins лежат ПОД пользовательскими файлами — при переносе
«встроенных в файлы» их место в слоёнке обязано сохраниться: каталог — слабейший слой,
и только пользовательские providers.json дерутся между собой по правилу «проект сильнее».

## Семантика active: осознанно НЕ тристейт

Пробовали тристейт (`active: Boolean?`, патч без поля не переключает тумблер) — упало на
главном сценарии: пользовательский providers.json, писанный ДО появления каталога, без
полей `active`, наследовал `false` от одноимённого выключенного сида и умирал. Итог:
**запись без `active` считается активной**; патч, который не должен включать выключенную
запись, обязан явно повторить `"active": false` (строка в спеке). Обратная совместимость
пользовательского конфига важнее гиковского «патча без включения».
`models.fetch` при этом — честный тристейт (`ModelsFetch?`): «не задано» ≠ «true», иначе
`fetch: true` поверх базового `fetch: false` был бы невыразим.

## Прочие решения

- **Фильтр `active` — после слияния и resolveExtends**: `extends` работает от неактивной
  базы (клон при этом жив, если сам не скажет иного), активация — переопределением по id.
- **resolveExtends — один строгий проход по слитому реестру** (пофайловый lenient-проход
  был избыточен и давал два разных снимка базы); `overlay()` протаскивает `extendsId`
  (`over.extendsId ?: base.extendsId`), иначе патч терял отложенный extends. Extends
  одноуровневый, без цепочек.
- **Вшитых моделей нет** — `models.fetch` у активных (наш fetch ходит на `<baseURL>/models`,
  поэтому z.ai работает простым `true`). Static остаётся там, где каталог недоступен или
  врёт: Alibaba Coding Plan (каталог возвращает модели вне плана, имена сверяются
  посимвольно) и выключенные маршруты Meta Muse / minimax-anthropic (каталога нет).
- **Кастомные модели** (`models.static`) — фича «для гиков»: пример в
  `_template-openai-compatible.jsonc`, раздел в providersSpec.md; бейдж «кастом» в пикере
  и на странице «Модели». Через кастомную модель включаются `vision:false`, `fim:true`,
  `extraBody`-квирки (thinking у Moonshot, tool_stream у DashScope/GLM).
- **Ключ без рестарта**: apply в «Провайдерах» публикует project-топик
  `ProvidersChangeListener.TOPIC` → открытая панель перечитывает реестр и каталоги моделей.
  Вотчер файлов на диске — отдельный пункт roadmap, топик покрывает только изменения из IDE.
- **Пустое поле ключа не удаляет запись хранилища, если ключа не было** — иначе две
  карточки с общим `apiKeyRef` (OpenCode Go/Zen: один аккаунт, один ключ) затирали друг
  друга в одном apply: близнец с пустым полем удалял только что сохранённое.
- **`listModels` = тот же транспортный контракт, что чат**: статические `headers`/`query`,
  query-auth в URL, `anthropic-version` для anthropic-протокола — иначе каталог Anthropic
  отвергал запрос, а query-auth провайдеры ходили за каталогом без ключа.

## Грабли

- **Kotlin: вложенные блочные комментарии.** `providers/*.jsonc` в KDoc — это `/*` внутри
  `/** … */`: вложенный комментарий съедает закрывающую `*/`, компилятор падает «Unclosed
  comment» в конце файла. Глоб-паттерны со `/*` в блочных комментариях писать нельзя.
- **Хвостовая лямбда против новых параметров с дефолтом.** Новый опциональный параметр
  ПОСЛЕ `onWarning: (String) -> Unit` ломает все вызовы `parse(text) { … }`: trailing
  lambda биндится к последнему параметру. Добавлять только ПЕРЕД лямбдой.
- **Откуда выкапывать «встроенных» VibeIDE** (для будущих переносов): baseURL —
  `electron-main/llmMessage/sendLLMMessage.impl.ts` и `aiSdkAdapter.ts` (OpenCode Zen
  `https://opencode.ai/zen/v1`, Go `https://opencode.ai/zen/go/v1`, OpenRouter
  `https://openrouter.ai/api/v1`); env-конвенции ключей — `common/vibeideSettingsTypes.ts`
  (`apiKeyEnvVarOfProvider`; у OpenCode env-имени осознанно нет — у нас введено своё
  `OPENCODE_API_KEY` + общий `apiKeyRef: "opencode"` на Zen и Go).
- **Сеялка не подчищает удалённое из манифеста:** снятый с засева providers.example.jsonc
  остаётся в уже засеянных проектах до release-обновления сидов (открытый пункт roadmap).
