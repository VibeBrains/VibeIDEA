# Голосовой ввод: два whisper, PATH без Homebrew и окно разрешения

**Роль:** [баг+правило] · **Найдено:** 15.10.2026, жалоба владельца на 0.8.9 «голосовой не работает»

## Что было

Микрофон работал: записи во временной папке содержат настоящую речь.
Ломалось всё вокруг записи, и каждый обрыв был молчаливым.

- **Зависание на 7,7 с.** Первый клик по микрофону macOS встречает запросом разрешения, и показывает его изнутри
  открытия устройства. Открытие шло в потоке интерфейса — IDE замирала, пока человек отвечал на запрос.
- **Пустое поле «Модель whisper.cpp».** Модель лежала на диске (`~/.cache/whisper.cpp/ggml-base-q5_1.bin`), но в
  настройках её не было. Без неё расшифровка уходила в другой инструмент с тем же именем — openai-whisper, — а он при
  первом запуске качает свою модель на 1,5 ГБ без ограничения по времени. Три запуска качали её параллельно,
  человек видел «расшифровываю…» без конца.
- **PATH дочернего процесса без `/opt/homebrew/bin`.** IDE, запущенная из Finder, получает `/usr/bin:/bin:/usr/sbin:/sbin`.
  openai-whisper не находил `ffmpeg`, выходил с кодом 0 без расшифровки, и выглядело это как «ни слова не разобрано».
- **Ошибки только в журнале** — и в журнале того проекта, где диктовали. Журнал свой у каждого проекта, поэтому в
  соседнем окне про голос не было ни строки.

## Что сделано

- Открытие и остановка микрофона — в пуле потоков; под вводом «включаю микрофон… если система спросит разрешение —
  ответьте на её запрос», повторный клик отменяет
- PATH дочернего процесса дополняется папками Homebrew (`VoiceTranscription.processOf`, им же пользуется мост в Telegram)
- Одноразовая расшифровка ограничена 180 с, процесс и его потомки убиваются, сбой называет код выхода и последнюю строку вывода
- Запись из одних нулей (нет разрешения) не отправляется в расшифровку — человек получает путь в системные настройки
- Каждый обрыв — в ленте у композера, раз это ответ на действие человека, а не только в журнале

## Правило

- Внешний инструмент из IDE запускается с дополненным PATH: окружение приложения из Finder беднее терминала.
- Ожидание внешнего процесса — с потолком по времени и с убийством потомков.
- Действие человека, которое может зависнуть на системном окне, — не в потоке интерфейса.
- Ответ на действие человека — там, где он смотрит, а не в журнале.
