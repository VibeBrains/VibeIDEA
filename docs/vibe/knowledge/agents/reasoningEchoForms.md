# Рассуждение обратно в истории: у каждого вендора своя форма

**[квирк]**

## Контекст

25.09.2026 списки моделей, которым рассуждение возвращается в истории, у VibeIDE и у нас разошлись в трёх местах.
Сверка шла по страницам вендоров, а не по спискам соседей.

## Суть

Кому вендор велит возвращать рассуждение:
- Kimi — `kimi-k3`, `kimi-k2.7-code`, `kimi-k2.6` и Kimi Code; про `kimi-k2.5` руководство молчит
- DeepSeek — с инструментами рассуждение всех прошлых ходов
- MiMo — думающие v2.6 и v2.5; без возврата вендор отвечает 400
- MiniMax — M2 и новее, на обоих протоколах

Форма у вендоров разная, и одного поля мало:
- OpenAI-совместимый провод у Kimi, DeepSeek и MiMo — поле `reasoning_content` у ответа ассистента
- MiniMax на том же проводе присылает рассуждение внутри `content` тегами `<think>` и просит вернуть `content` без изменений.
  Мы вынимаем теги из ответа, пока он идёт, поэтому при возврате кладём их обратно в начало текста (`REASONING_AS_THINK_TAGS`)
- Anthropic-совместимый провод — блоки `thinking`. Ответ без вызовов инструментов хранит рассуждение только строкой.
  Такой ответ уходит одним блоком без `signature`: так его присылают вендоры без подписи
- Claude получает только свои подписанные блоки текущего хода, строкой — никогда

Разбор по MiniMax открыл нашу дыру: правила для него не было, и рассуждение не уходило ни по одному протоколу.
Строковое рассуждение на Anthropic-проводе не уходило ни одной модели — ту же дыру VibeIDE нашёл живым смоуком.

## Применение

- Новая модель с возвратом рассуждения — строка в общих векторах `testVectors/reasoningEcho.json` вместе с источником вендора.
  Тесты обоих продуктов читают этот файл, и расхождение падает у того, кто разошёлся.
- Правило из вторичного источника (апстрим OpenCode, пересказ в статье) в векторы не вносится: `kimi-k2.5` без источника вендора остался вне списка.
- Форму возврата сверять с тем, что вендор присылает сам: MiniMax ждёт теги в тексте, а не поле, которое понимают другие.
