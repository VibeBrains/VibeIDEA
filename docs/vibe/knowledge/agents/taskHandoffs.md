## Контекст

## Суть

- Группу в VibeIDEA не читать: ни `tgWatch.sh`, ни `getUpdates` — второй читатель крадёт сообщения у диспетчера
- Имя хендоффа такой задачи — `*-from-troshkovs`
- Отчёт по завершении каждой задачи: что сделано, где посмотреть, что не проверено; одна мысль на строку
- Отчёт — `zsh /Volumes/Storage/Caches/Borodatych/tg/tgSend.sh "текст"`, файл — `tgSendDoc.sh <файл> "подпись"`
- Смена реакции на сообщении задачи — `zsh /Volumes/Storage/Caches/Borodatych/tg/tgReact.sh <номер> 👌`, номер приходит в хендоффе; шаг отложен и записан в план, пока не делается
- Наружное и необратимое по задаче брата — только с «да» владельца

## Применение

Правило про порядок работы сессии, а не про возможность IDE: в сборке ничего не проверяется
Единственное исключение из «не читать группу» — сама сессия VibeMemory, у неё эта роль и есть
