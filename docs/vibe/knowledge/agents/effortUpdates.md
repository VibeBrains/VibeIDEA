# Усилие посреди треда без потери кэша: GPT-6 и Claude

**[квирк]**

## Контекст

Уровень `reasoning.effort` в запросе — часть префикса, по которому вендор узнаёт кэш промпта.
Сдвиг ползунка посреди треда переписывал его, и всё после оплачивалось как новый ввод.
OpenAI даёт для этого элемент входа `configuration_update` (developers.openai.com/api/docs/guides/reasoning, сверено 01.10.2026).

## Суть

- Запрос держит усилие первого ответа этой модели в треде, новое уходит элементом перед вопросом, где ползунок сдвинули.
- **История идёт целиком, поэтому обновления повторяются на своих местах.** Так требует вендор при ручной истории.
- **Где помнить усилие.** История только дописывается: сообщение человека после отправки не правится. Метку `провайдер/модель#усилие` хранит ответ (`effortMark`) — его запрос и шёл с этим усилием, — а план ставит обновление перед сообщением человека, которое ответу предшествует.
- Ответы другой модели о текущей ничего не говорят: метка с чужим ключом пропускается.
- Два обновления подряд вендор отвергает; обновление стоит только перед сообщением человека, поэтому подряд они не встают.

## Claude (08.10.2026, решение №132)

У Anthropic то же самое — системное сообщение без текста с `output_config.effort` и бета-заголовок `mid-conversation-output-config-2026-07-01`
(platform.claude.com/docs/en/build-with-claude/effort, сверено 08.10.2026).
Планировщик тот же: метки, повтор на своих местах, усилие запроса — первое.
Отличия:
- **Только при адаптивном мышлении.** С `between_tools` (Sonnet 5.5) и `disabled` (Haiku 5.5) смена усилия посреди треда — 400; смена самого режима мышления сбрасывает кэш и без этого.
- **Только собственный API Anthropic.** Другие адреса провода не обещали поле, а отвергнутое поле роняет весь ход.
- **Метка кэша не встаёт на обновление.** Граница кэша — сообщение перед последним вопросом, а теперь там может стоять обновление без текста: граница отступает на сообщение раньше.
- **Отдельная причуда, `EFFORT_BY_SYSTEM_MESSAGE`.** Причуда выбирается по имени модели, а не по проводу: общая на два написания отдала бы Claude за роутером на проводе Responses элемент `configuration_update`.

## Как применять

- Причуды `EFFORT_BY_UPDATE` для `^gpt-6` и `EFFORT_BY_SYSTEM_MESSAGE` для Claude Fable 5.1, Mythos 5.1, Opus 5, 5.5, Sonnet 5.5 и Haiku 5.5; планировщик — чистый `EffortUpdates`.
- Тело запроса GPT-6 проверено заглушкой провода (`WireBodyTest`); для Claude заглушка видит только отказ стороннему адресу, путь с обновлениями покрыт чистыми функциями.
- Живым ключом не проверено.
