# [архитектура] Опора задачи после свёртки истории

**Контекст.** Прямой чат сворачивает старые сообщения в сводку, когда оценка переходит 80 % окна.
Сводку делает та же модель по просьбе «сохрани решения, открытые вопросы, имена файлов» — то есть
пересказчик решает, что важно. Одну строку задачи он теряет молча, и следующий ход уходит не туда.

**Суть.** Первоисточники лежат вне разговора, поэтому свёртка не обязана их нести. После свёртки
модель получает системное сообщение-опору: задачу дословно (первое сообщение человека, без
вложенных контекстных блоков — они снимок момента) и индекс журнала решений проекта целиком
(`DecisionStore.indexText`). Закреплённое, уже ушедшее дословно, не повторяется. Опора
пересобирается каждый ход из треда и файла решений, поэтому решение, записанное в разговоре,
попадает в неё сразу.

**Применение.** `context/CompactionAnchor` (чистая: записи и текст журнала внутрь, сообщение наружу)
вызывается из `AgentPanel.compactForWindow` после свёртки; в запрос идёт сразу после сводки.
Тест `CompactionAnchorTest`. У ACP-агента окно ведёт он сам — опоры нет.
