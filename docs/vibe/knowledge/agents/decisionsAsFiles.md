# Решения проекта — файлы в репозитории, а не база рядом с ним

**Роль:** [архитектура] · **Появилось:** 05.09.2026, ветка `next`

## Контекст

Владелец показал внешнюю агентную систему (raytsystem: Python + веб-интерфейс на `127.0.0.1:8765`,
локальный «второй мозг» с документами, задачами и журналом решений) и спросил, можно ли сделать
подобное у себя. Сравнение показало, что большая часть у нас уже есть — библиотекарь, граф
документации, граф импортов, RAG, задачи, свой MCP-сервер, — а нет ровно двух вещей: **журнала
решений** и **входящих документов**.

## Суть

Обе вещи сделаны файлами в репозитории проекта, а не хранилищем в своём формате. Причины, в порядке
важности:

1. **Второй источник правды расходится с первым.** База рядом с git живёт своей жизнью: ветка
   откатывается, а решение остаётся; решение правится, а код нет. Файл в репозитории откатывается
   вместе с веткой и обсуждается в код-ревью.
2. **Формат должен пережить инструмент.** Markdown с индексом читается глазами, ищется `grep`,
   разбирается чужим агентом и не требует нашего приложения. Пользователь не должен зависеть от
   того, останется ли VibeIDEA.
3. **Дисциплина уже есть и уже проверяется.** «Записи без строки в индексе не существует» — правило
   базы знаний; журнал решений использует **тот же** парсер индекса, тот же поиск библиотекаря и
   тот же гейт связности документации. Свой формат означал бы третий парсер и второй гейт.

Два следствия, принятых осознанно:

- **Заголовок записи — вопрос, а не выбранный вариант.** Через полгода ищут по вопросу, который
  возник снова, а не по названию решения, которое к тому времени забыто.
- **Причина обязательна, и её отсутствие — отказ.** Запись «решили так» не спасает от повторного
  обсуждения, то есть не делает ровно того, ради чего заводится журнал.

## Применение

- Появляется новый вид знания у продукта (риски, требования, глоссарий) — сперва проверить, ложится
  ли он на ту же схему «папка + обязательный индекс + библиотекарь»; свой формат заводить, только
  если не ложится, и записывать почему.
- Текст файла-формата (`## Решение`, `## Почему`, шапка входящего) — **не строка интерфейса**: он
  лежит в чужом репозитории и не имеет права меняться от языка IDE. Такие файлы идут в
  `i18nExclusions.txt` с причиной, как уже сделано для формата графа кода.
- Внешнюю систему при этом не отвергли: она поднимается записью в `.vibe/servers.json` и
  открывается кнопкой «Превью» — интеграция без вшивания чужого рантайма в дистрибутив.
