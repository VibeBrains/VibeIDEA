# Область удаления, а не слово `rm`

[правило] Контекст: автопилот спрашивал про каждый `rm`, и прогон, который десять раз собирает и чистит, задавал
десять диалогов — тот же ритуал нечитаемых вопросов, от которого спасают режимы прав. VibeIDE перестала спрашивать
удаление внутри проекта и временной папки: снимок хода возвращает файлы, временная папка — расходник.

Суть: решение принимает чистая `guard/RemovalScope.isReversible(line, projectRoot, cwd, tempRoots)`. Молча
пропускается только одна команда `rm`, у которой все цели — литеральные пути внутри проекта или `TMPDIR`/`/tmp`:
без масок, `..`, `~`, `.git`, подстановок `$`/бэктиков, обёрток (`sudo`, `sh -c`, `xargs`), второй программы в
конвейере и без чтения имён со стандартного входа. Рабочая папка тоже обязана быть внутри области, иначе `../../..`
из неё достал бы куда угодно. Непонятое считается необратимым — ошибка только в безопасную сторону: лишний вопрос
дешевле потерянного дня. Подключено в `onCreateTerminal` и только для `PermissionMode.AUTO`; `EDITS`, `MANUAL` и
`PLAN` не меняются.

Применение: расширять список флагов и целей — только с тестом в `RemovalScopeTest`; всякая новая форма команды
(переменная, несколько программ, подстановка) сначала считается необратимой. Тот же принцип, что у
`ShellSafetyAnalyzer`: детектор — триаж перед вопросом, а не разрешение.
