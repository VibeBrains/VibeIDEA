# Case-insensitive APFS и файлы апстрима
← [Knowledge Index](../README.md)

## [квирк] README.md ≡ readme.md: копирование молча перетирает чужой файл

**Контекст:** ночь основания 2026-08-23. Пакет доков форка готовился как `docs/README.md` и копировался в репо, где у апстрима уже есть `docs/readme.md`. macOS APFS по умолчанию case-insensitive.

**Суть:** `cp` «нового» `README.md` молча перезаписал содержимое апстримного `readme.md` — имена различаются только регистром, на такой ФС это один файл. git показал это как ` M docs/readme.md`, а не как новый файл. На Linux (CI) это два разных файла — поведение репо разошлось бы между ОС.

**Применение:** свои файлы класть только в собственный неймспейс (`docs/vibe/**`, `com.vibe.*`) — оверлей защищает и от коллизий имён; перед добавлением файла в каталог апстрима проверять существование имени без учёта регистра; после любого копирования в дерево апстрима — смотреть `git status` на предмет ` M` до коммита.
