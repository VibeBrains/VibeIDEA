# Временный индекс git: путь, а не пустой файл

[gitAndTools] · 11.09.2026 · найдено первым тестом на настоящем git

## Контекст

Чекпоинты (`checkpoints/CheckpointService.kt`) снимают рабочую папку через временный индекс:
`GIT_INDEX_FILE=<временный> git add -A`, потом `git write-tree` и `git commit-tree`. Настоящий индекс
и HEAD при этом не трогаются. Временный файл создавался через `Files.createTempFile` — то есть
**пустым**.

## Суть

- Git не принимает пустой файл индекса: `fatal: …: index file smaller than expected`, код выхода 128
  (проверено на git 2.54). Несуществующий путь git создаёт сам.
- `create()` возвращал null на каждом сообщении, а null означал «чекпоинты недоступны» — то же, что у
  проекта без git. Ни ошибки, ни строки в ленте: функция молча не работала **с первого выпуска**
  (`6201c50a38`, 23.08.2026; v0.1.0–v0.3.0). Откатывать по чекпоинту было нечего.
- Нашёл это первый тест, который гоняет сервис на настоящем репозитории (`CheckpointServiceTest`,
  11.09.2026). Писался он вовсе не ради чекпоинтов, а ради диффа для судьи пайплайна.

## Как правильно

1. Временный индекс — путь внутри свежей временной папки, которого ещё нет.
2. Стартовать с копии настоящего индекса (`git rev-parse --git-path index`): тогда `git add -A`
   перехеширует только изменённые файлы. С пустого индекса git хеширует всё дерево на каждом снимке,
   и на большом репозитории это упирается в тайм-аут — снимок снова молча не случается.
3. Убирать за собой и `index`, и `index.lock`.

## Урок

Функция, которая при отказе деградирует до «недоступно», обязана иметь тест против настоящего
инструмента. Иначе «недоступно по уважительной причине» и «сломано» выглядят одинаково, и отличить
их некому.
