# Пуш из поверхностного клона отвергается: `index-pack failed`

**[инцидент]**

## Контекст

31.08.2026, первая публикация форка в `VibeBrains/VibeIDEA`. Права на запись есть, ветка готова,
280 МБ уходят на сервер — и в конце:

```
remote: error: remote unpack failed: index-pack failed
 ! [remote rejected]       next -> next (failed)
```

## Суть

Клон был **поверхностным** (`git clone --depth`, файл `.git/shallow`): у корневого коммита
записаны родители, которых в репозитории нет. Сервер собирает граф объектов и отказывается принять
пак, в котором чего-то не хватает. Права, размер и сеть тут ни при чём — сообщение про них молчит,
и на этом теряется время.

**Починка — сделать корень настоящим корнем**, то есть пересобрать историю так, чтобы у первого
коммита не было родителей. Дозакачивать полную историю апстрима (`--unshallow`) не нужно и дорого:
у intellij-community это гигабайты, а на GitHub ещё и
[ломается](shallowDeepenGithub.md).

Рабочий рецепт — плумбинг, без единого чекаута рабочего дерева (183 коммита, **13 секунд**; тот же
результат через `rebase --onto` занял бы десятки минут на дереве такого размера):

```bash
ROOT=<хеш поверхностного корня>
NEWROOT=$(git log -1 --format=%B "$ROOT" | git commit-tree "$ROOT^{tree}")   # то же дерево, без родителей
PREV=$NEWROOT
for C in $(git rev-list --reverse "$ROOT..ветка"); do
  PREV=$(git log -1 --format=%B "$C" | git commit-tree "$(git rev-parse $C^{tree})" -p "$PREV")
done
git reset --hard "$PREV"
```

В настоящем скрипте к каждому `commit-tree` добавляются `GIT_AUTHOR_*` и `GIT_COMMITTER_*` из
исходного коммита — иначе авторство и даты схлопнутся в «сейчас, от текущего пользователя».

**Проверка перед тем, как поверить:** `git diff --stat старая-ветка новая-голова` обязан быть пуст —
меняется только форма графа, содержимое обязано совпасть до байта. Число коммитов сверить тоже.

## Применение

Собираетесь публиковать форк — проверьте `ls .git/shallow` **до** первого пуша, а не после
неудачного. Если файл есть, пересоберите корень по рецепту выше; хеши изменятся, и это безболезненно
ровно до тех пор, пока ничего не опубликовано.

Последствие, которое стоит назвать вслух: в опубликованном репозитории истории апстрима нет, она
начинается со снимка. Для форка это нормально (синк идёт по тегам релизов), но выглядит непривычно —
лучше сказать это в README, чем оставить на догадку.
