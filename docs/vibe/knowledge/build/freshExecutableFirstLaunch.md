# Первый запуск свежего исполняемого файла на macOS: 10–26 секунд

## Симптом

Тесты `VoiceTranscriptionRunTest` падали по таймауту 20 с — то одни, то другие, воспроизводимо на чистом HEAD
Часом раньше те же тесты проходили за секунды
Падал всегда тест, шедший первым по очереди запуска свежего скрипта

## Причина

Не код и не login-shell: в `VoiceTranscription` нет запуска оболочки, PATH собирается из `WatchTools.searchPath()` без процессов
Вне Bazel: `printf '#!/bin/sh\necho z\n' > s; chmod +x s; time ./s` — `real 10–26 s` при нулевом CPU процесса
Тот же файл вторым запуском — 5 мс, `/bin/sh ./s` на свежем файле — 3 мс
Первый запуск каждого нового исполняемого файла проверяет `syspolicyd`; на загруженной машине (он держал 45% CPU, load 6.9) проверка идёт десятки секунд

## Правило для тестов

Заглушка внешней программы не создаётся как новый исполняемый файл
Заглушка — существующий системный бинарник: `/bin/sh`, а тело заглушки лежит в файле, который он получает аргументом (`sh note.wav --output_format …`)
Так сделан `VoiceTranscriptionRunTest`: тело — в «аудиофайле», путь транскрайбера — `/bin/sh`
