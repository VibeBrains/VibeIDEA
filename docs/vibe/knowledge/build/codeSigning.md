# Подпись кода: что готово и чего нет

**Дата:** 03.09.2026 · **Статус:** заблокировано учётками владельца; скрипты готовы

## Почему это не «фича на потом»

Неподписанная сборка — не косметика. На macOS это Gatekeeper с «Файл не может быть открыт» на
каждом первом запуске; на Windows — SmartScreen на инсталляторе и **удаление `idea64.exe`
антивирусом по поведению** ([windowsAntivirus.md](windowsAntivirus.md)). Для человека, у которого
IDE исчезла после первого запуска, различие между «не подписано» и «вредоносно» не существует.

## Почему не через сборку платформы

У платформы есть путь подписи — интерфейс `SignTool`, который `ProprietaryBuildTools` передаёт в
сборку. Он рассчитан на инфраструктуру вендора: отдельная машина подписи, свой протокол, учётки в
их хранилище; для macOS он ещё и требует адрес такой машины, иначе собирает только `.sit`. Для
одного человека с одним Mac реализовывать этот интерфейс — писать клиента к серверу, которого нет.

Честный путь — штатные инструменты поверх готового образа, отдельным шагом **после сборки и до
штампа**: штамп фиксирует хеши, и подписывать после него значило бы публиковать не то, что
заштамповано.

## Что делают скрипты

`signMac.sh`: монтирует dmg, копирует `.app`, `codesign --force --deep --options runtime
--timestamp` (deep — вложенные бинари JBR и нативные библиотеки; runtime — hardened runtime, без
него нотаризация отказывает; timestamp — подпись живёт после истечения сертификата), пересобирает
dmg (подпись dmg не подписывает содержимое — Gatekeeper проверяет `.app`), подписывает образ,
`notarytool submit --wait`, `stapler staple`, `spctl --assess`.

`signWindows.ps1`: распаковывает `.win.zip`, `signtool sign /fd SHA256 /tr <TSA> /td SHA256` по
всем `exe`/`dll` (jar — не PE-файл, signtool на нём падает, и подпись ему не нужна), собирает
`-signed.win.zip`, отдельно подписывает инсталлятор — его хеш видит SmartScreen. Два способа: отпечаток
сертификата из хранилища или Azure Trusted Signing (`/dlib` + `/dmdf`).

Оба без учётки **останавливаются первой строкой** и говорят, чего нет. Молча выпустить неподписанное
они не умеют по построению — иначе «подписал» означало бы «запустил скрипт».

## Что нужно от владельца

- **macOS:** Apple Developer Program; сертификат «Developer ID Application» в связке ключей
  (`security find-identity -v -p codesigning` его показывает); профиль
  `xcrun notarytool store-credentials vibeidea --apple-id … --team-id … --password <app-specific>`;
  переменные `VIBE_MAC_SIGN_IDENTITY`, `VIBE_NOTARY_PROFILE`.
- **Windows:** сертификат подписи кода — OV дешевле, но репутацию SmartScreen набирает месяцами;
  EV или **Azure Trusted Signing** дают репутацию с первого файла (второй — подписка вместо
  железного токена, нужна проверка организации). Переменные `VIBE_WIN_SIGN_THUMBPRINT` либо
  `VIBE_WIN_SIGN_DLIB` + `VIBE_WIN_SIGN_METADATA`; `signtool` из Windows SDK.

## Что не проверено и почему

Сами подписи. На этой машине `codesign`, `notarytool` и `stapler` есть, идентичностей — ноль;
`pwsh` нет, синтаксис `.ps1` не прогонялся. Скрипт macOS в `--dry-run` доходит до проверки учётки и
честно останавливается — это единственное, что здесь можно было прогнать.
