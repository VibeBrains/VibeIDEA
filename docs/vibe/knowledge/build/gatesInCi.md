# CI гейтов: окружение — не вердикт, упавший шаг не прячет соседей

**Роль:** [грабли+правило] · **Найдено:** 23.09.2026, CI гейтов красный с 19.09

## Контекст

19.09 в `checkVibeUi.sh` появился блок 8б: перенос подсказки настроек меряется тестом
`SettingsHintWidthTest` через `./bazel.cmd test`. Локально гейт зеленел, а в CI (`vibeGates.yml`) с того
же коммита пошли красные прогоны: 52 подряд, на `next` и на `main`, включая выпуск 0.7.0. Шаг UI каждый
раз писал «подсказка настроек не переносится по ширине».

## Что было под одним красным

- **На раннере Bazel ничего не собирал.** От старта до вердикта проходило сорок две секунды, а у цели 1163
  действия (столько насчитал локальный прогон). Вывод, который старый гейт не печатал, показал прогон 23.09:
  ```
  ERROR: …/build/jps_model.bzl:307:31: An error occurred during the fetch of repository '+jps_dynamic_deps_community_extension+jps_dynamic_deps_community':
  ERROR: no such package '@@+jps_dynamic_deps_community_extension+jps_dynamic_deps_community//': java.io.FileNotFoundException: …/android/android-adb/intellij.android.adb.iml (No such file or directory)
  ERROR: Analysis of target '//vibe-plugins/vibe-agent:vibe-agent_test' failed; build aborted: Analysis failed
  ```
  Модель проекта читает клон `android/`, а он живёт вне репозитория: его нет в git, его кладёт
  `getPlugins.sh`. Эта стена записана в [bazelBuild.md](bazelBuild.md) ещё 23.08, и она стоит перед любой
  целью, а не только перед инсталлятором.
- **Гейт принял отказ сборки за вердикт.** Он разбирал вывод по словам: «FAILED TO BUILD» — тесты не
  собрались, «tests pass» — прошло, любое «FAILED» или «failing» — подсказка не переносится. У сборки,
  упавшей на анализе, строки «FAILED TO BUILD» нет. Зато после отказа Bazel печатает пустой итог `FAILED: `,
  когда вывод идёт не в терминал, и гейт принял его за упавший тест. Строку показало воспроизведение
  отказа (рецепт ниже).
- **Скрипт умирал на собственной улике.** Под `set -euo pipefail` конвейер
  `printf … | grep -F AssertionFailedError | head | sed` без совпадений роняет весь скрипт. Строки
  «Прогоните:» в логах CI нет ни разу, и вместе с ней молчали восемь блоков после 8б: списки настроек,
  образец кода и реестр тем, цвета проекта, контраст, фон окна установки, переключение темы,
  идентификаторы панелей, группы уведомлений.
- **Упавший шаг прятал следующие.** Шаг после упавшего без условия получает `skipped`: каталог строк,
  брендинг и документация в CI не выполнялись пять дней, гейт комментариев (22.09) — ни разу.

## Дыра того же корня

Фильтр, не нашедший ни одного теста, Bazel считает успехом: код 0, «1 test passes», итог «0 passing … out
of 0 test cases». Замер после переименования теста позеленел бы, ничего не измерив.

Гейт сидов на этой дыре уже стоял. Успехом он считал подстроку «and 0 failing», а её печатает и сборка, в
которой тесты не скомпилировались. Старая версия гейта на нарочно сломанной компиляции ответила «навыки
проходят валидатор» с кодом 0. Строка итога с «0 failing» делала гейт сидов зелёным на несобранных тестах, а
UI-гейт увидел в словах отказавшей сборки приговор: слова в логе — не контракт ни в одну сторону.

## Аудит форка: тот же класс

`vibeAudit.yml` краснел три недели подряд (07, 14, 21.09). `checkUpstreamLag.sh` в клоне CI не находил
коммит базы и писал «синк делался мимо реестра?».

- **База — коммит апстрима, и в клоне нашего репозитория его может не быть при любой глубине.** Первый
  синк лёг обычным коммитом `7f2003570e` с одним родителем, поэтому базы в нашей истории нет вовсе:
  клон `next` без деревьев — 571 коммит, базы среди них нет. Локально она есть только благодаря
  `git fetch upstream`. База, влитая слиянием по плейбуку, будет в истории, но глубже того одного коммита,
  который берёт checkout CI.
- **Шаг за ним не выполнялся ни разу.** Аудит уязвимостей поставляемых серверов (`checkServerDeps.sh`)
  стоял после упавшего шага и все три прогона получал `skipped`.
- **Три собственных сообщения скрипта были недостижимы.** Под `set -euo pipefail` упавший конвейер в
  присваивании (`X=$(git ls-remote … | awk … | head -1)`) завершает скрипт тут же, и проверка следом не
  успевает сказать, что не так. Старая версия на реестре без базы выходила молча с кодом 1, без remote
  `upstream` — молча с кодом 128.

Теперь коммита нет в клоне — скрипт спрашивает апстрим: `gh api repos/<апстрим>/commits/<короткий id>`
раскрывает короткий id реестра и отдаёт дату. Ответ 422 или 404 — в реестре опечатка или синк мимо реестра.
Любой другой отказ — «отставание не измерено» с причиной. В CI шагу нужен `GH_TOKEN`, шаги идут с
`!cancelled()`, конвейеры в присваиваниях кончаются `|| true`.

## Как воспроизвести раннер локально

Клон `android/` прячется пустой `tmpfs`, остальное дерево монтируется только на чтение:

```bash
docker run --rm --dns 1.1.1.1 -v "$PWD":/repo:ro --tmpfs /repo/android -w /repo python:3.12-slim-trixie bash -c \
  'apt-get update -qq && apt-get install -y -qq curl && ./bazel.cmd --host_jvm_args=-Xmx1600m test //vibe-plugins/vibe-agent:vibe-agent_test --test_filter=SettingsHintWidth'
```

- `--dns` — без него резолвер колимы не нашёл `bcr.bazel.build`, и Bazel упал раньше, чем дошёл до модели.
- `-Xmx1600m` — `common.bazelrc` даёт серверу 12 ГБ, а у виртуальной машины колимы 2 ГБ.
- В колиме прогон занял десять минут против сорока двух секунд на раннере; строки `ERROR` и код 1 те же.

## Правило

- **Вердикт — по коду выхода и итогу Bazel, а не по словам.** Код 0 — прошло, 3 — тесты упали, остальное —
  сборка или окружение. «Сломано» — только когда упал хоть один случай, «прошло» — только когда хоть один
  прошёл, иначе «НЕ ВЫПОЛНЕН» с причиной. Разбор один на все гейты: `vibe-plugins/tools/bazelTest.sh`.
- **Гейт, который не смог измерить, показывает улики:** строки `ERROR` Bazel и ошибку компилятора с местом.
  По ним видно, что чинить — код или окружение.
- **Пустой поиск — ответ, а не авария.** Конвейер с `grep` под `set -o pipefail` пишется с `|| true`, и в
  присваивании тоже: иначе проверка следом не узнает, что искать было нечего.
- **Чего нет в клоне, спрашивается у источника.** Коммит апстрима в клоне CI не лежит; «не нашёл у себя»
  и «такого нет» — разные ответы, и путать их — та же ошибка, что принять отказ сборки за вердикт.
- **CI проверяет то, что может проверить честно, а остальное называет.** Гейты со сборкой в CI не идут:
  UI-гейт зовётся с `--no-build` и печатает «замер ПРОПУЩЕН», сиды, нейрослоп и тесты гоняются только
  локально, где они обязательны. Решение №108 журнала.
- **Шаг гейта в workflow — с `if: ${{ !cancelled() && steps.checkout.outcome == 'success' }}`.** Каждый гейт
  отчитывается, а job остаётся красным, если упал хоть один.
- **Правка workflow в `next` не чинит расписание.** Прогон по расписанию берёт файл workflow и код
  ветки по умолчанию, то есть `main`: фикс CI, живущий в `next`, до выпуска не действует. Его несут в
  `main` хотфиксом от `main` и вливают обратно в `next` слиянием — так сделано 24.09 (`44602a09f5`).
- **Фильтра путей у гейтов нет.** Они читают правки платформы и `vibeidea-customization/`, а список путей был
  бы второй правдой об их входах, которая расходится молча.
