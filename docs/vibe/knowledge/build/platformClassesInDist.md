# Класс платформы, которого нет в дистрибутиве

**Дата:** 18.09.2026
**Повод:** граф кода падал в установленной IDE с `NoClassDefFoundError: org/jetbrains/uast/UFile` — в 0.6.0, 0.6.1 и 0.6.2 одинаково

## Что случилось

Разбор файлов графа брал символы и импорты из UAST.
`intellij.vibe.agent.iml` объявлял модуль `intellij.platform.uast`, поэтому компиляция и все 1857 тестов были зелёными.
В собранной IDE класса нет: UAST лежит внутри плагина Java — `plugins/java/lib/modules/intellij.platform.uast.jar`, — а наш `plugin.xml` от плагина Java не зависит.

Ход это не ронял: построение ушло в фон, и оттуда прилетал SEVERE в `idea.log`.
Наружу дефект выглядел так: «граф импортов ещё не построен, я запустил построение в фоне, спросите через минуту» — и через минуту то же самое, навсегда.

## Урок первый: зависимость модуля в `.iml` — это компиляция, а не дистрибутив

`.iml` описывает, чем собирать. Видимость класса в работающей IDE задаёт дескриптор плагина и раскладка сборки.
Классы из **плагина** (Java, Kotlin, JSON…) доступны только тому, кто на этот плагин объявил зависимость.
Проверять надо не тем, что собралось, а тем, что лежит в образе:

```bash
for j in $(find /Applications/VibeIDEA.app/Contents -name '*.jar'); do
  unzip -l "$j" | grep -q 'org/jetbrains/uast/UFile.class' && echo "$j"
done
```

## Урок второй: чужая зависимость может оказаться не нужной вовсе

UAST понимает JVM-языки. VibeIDEA — IDE для TypeScript и PHP.
То есть даже там, где класс грузился (запуск из исходников), граф проекта на Next.js не имел **ни одного** ребра: `vibe_code_graph_imports` отвечал «связей не найдено» про проект, целиком состоящий из импортов.

Поэтому решением стала не зависимость на плагин Java, а свой разбор по тексту — `SourceOutline`: TS/JS, PHP, JVM, Python.
Побочно ушли PSI-обход ради импортов и часть read-action внутри хода.

## Как не повторить

- Класс платформы, который берётся не из `com.intellij.modules.platform`, — повод спросить, в каком плагине он лежит.
- Тест на такой дефект невозможен в юнитах по построению: в тестах classpath шире, чем в образе. Ловит только проверка собранного дистрибутива (`checkVibeDist.sh`).
- Первым делом спросить, нужен ли класс: библиотека платформы для языков, которых у нашей аудитории нет, — это зависимость ради пустого результата.
