# Каталог возможностей VibeIDEA

Версионно-независимый каталог «что умеет продукт». Одна исчерпывающая запись на возможность; расширили — переписываем пункт, не дописываем второй. Чистые баг-фиксы сюда не идут.

## 🧩 Платформа

*(наследуемое от intellij-community описывается только там, где мы меняем поведение)*

- **Собственный дистрибутив VibeIDEA** — продукт собирается из исходников в неподписанный dmg/sit (macOS arm64): свой product code `VI`, `VibeIDEA.app`, своё лого «терминал + искра ИИ» (промпт `>`, строка ввода и четырёхлучевая искра, неон циан→фиолет→маджента) — в приложении (About/welcome, SVG) и в macOS Dock (`.icns`); вендорные mcpserver и featuresTrainer из комплекта исключены. Сборка: `./vibeidea-installers.cmd -Dintellij.build.target.os=current`.

## 🌐 Языки

- **TypeScript/JavaScript через LSP (vtsls)** — completion, диагностика, навигация, hover, форматирование для `*.ts/tsx/js/jsx/mts/cts/mjs/cjs`; сервер vtsls (MIT) подключён через бандленный LSP4IJ, подсветка — TextMate. Сервер ставится пользователем один раз ([мануал](manuals/languageServers.md)); IDE ищет его в PATH и типовых местах установки — GUI-приложениям macOS shell-PATH не достаётся, поэтому известные каталоги проверяются явно.
- **PHP через LSP (Phpactor)** — то же для `*.php`; Phpactor (MIT). Intelephense не поставляется (его EULA запрещает редистрибуцию) — задокументирован путь самостоятельной установки как «премиум»-вариант.

## 🖥 Дев-стек

- **Vibe Server (`.vibe/servers.json`)** — декларативный дев-стек: сервисы и task-и с `dependsOn`, волны запуска (зависимые ждут ГОТОВНОСТИ — TCP-порт / HTTP не-5xx / regex по логу / exit 0 / spawn), `skipIf`-пробы («уже сделано» — пропуск), `pathPrepend`-пин тулчейна, `envFile`, `stopCommand` best-effort. Тулвиндоу внизу IDE: Запустить/Остановить всё, запуск выбранного с транзитивными зависимостями; исключённые записи (неизвестная зависимость, цикл) видны с причиной — ничего не стартует втихую. Спека: [manuals/serversSpec.md](manuals/serversSpec.md).

## 🎯 Дизайн-контекст

- **Дизайн-память проекта (`.vibe/design/`)** — 4 markdown-файла (uiKit / components / design / product, с fallback на корневые файлы чужих дизайн-скиллов); при наличии панель Vibe Agent подмешивает агенту пути к ним с правильным порядком подачи (uiKit первым) и разобранные именованные правила + осознанные отклонения. Формат правил `**Имя.** тело` и дрейф-строк `- rule-id — причина` разбирается автоматически. Спека: [manuals/designSpec.md](manuals/designSpec.md). Браузерный движок замера (81 детектор) — в очереди.

- **Граф проекта (`code_graph`, первый срез)** — Tools → «Vibe: экспорт графа проекта» → `.vibe/codeGraph.json`: файлы (до 5000), top-level символы и импорты (UAST: Java/Kotlin/Groovy), TODO/FIXME из платформенного индекса; агент читает файл сам. Построено поверх PSI — случай, где платформа сильнее самодельного индекса VibeIDE.

## 📚 Документация

- **Гейт графа доков** — `vibe-tools/docsGraphCheck.py` (stdlib-python, без зависимостей): dead links, wikilinks, записи knowledge без строки в индексе, недостижимость от `docs/vibe/README.md`; exit 1 на любой дефект. Перенос контракта `docs-graph-check` VibeIDE.

## 🎨 Оформление

- **Тема Vibe Neon Dark** — фирменная тёмная тема с неоновыми акцентами (циан/маджента/пурпур): своя палитра UI (фокус, ссылки, прогресс, вкладки) и схема редактора (наследует Darcula, неоновый курсор и синтаксические акценты). Выбирается в Settings → Appearance; новая UI (`targetUi=new`).

## 🤖 Агентская обвязка

- **FIM-автокомплит из реестра провайдеров** — серый инлайн-текст при наборе: модель с `fim: true` (openai-протокол; напр. qwen2.5-coder в Ollama, codestral) получает legacy `/completions`-запрос с prefix/suffix полями API (спец-токены — дело сервера); механика VibeIDE: дебаунс 250 мс, 25 строк контекста в обе стороны, стоп `\n` в середине строки / `\n\n` на пустой, max_tokens 300 (облако) / 96 (localhost), строки длиннее 500 символов пропускаются. Прим.: в самом VibeIDE FIM для провайдеров из файла остался follow-up — здесь он первоклассный.
- **Пайплайны (`.vibe/pipelines.json`)** — линейные цепочки шагов-ролей поверх ACP-агента (кнопка «Пайплайн…»): роли из закрытого списка (неизвестная — ошибка со списком доступных), шагу передаются пути затронутых файлов (накапливаются) и резюме последнего шага (не содержимое!), провал останавливает хвост со статусом «пропущен», `continueOnFailure`/`ignorePreviousArtifacts` — по спеке VibeIDE; битая запись не роняет файл, предупреждения — до списка. Спека: [manuals/pipelinesSpec.md](manuals/pipelinesSpec.md).
- **Каталог LLM-провайдеров (`.vibe/providers/` + `providers.json`)** — прямой стриминговый чат с любым openai/anthropic/gemini-совместимым endpoint без ACP-агента: записи `LLM: провайдер · модель` в той же панели. Реестр собирается из четырёх слоёв (слабый → сильный): глобальный каталог `~/.vibe/providers/*.jsonc` → засеянный проектный каталог (по файлу на провайдера; OpenCode Go/Zen, OpenRouter, MiniMax, Z.AI, Kimi, DeepSeek активны из коробки, OpenAI/Anthropic/Alibaba Coding Plan/Meta Muse/Ollama/vLLM лежат выключенными; внутри каталога — наложение по алфавиту файлов) → глобальный `providers.json` → проектный `providers.json` (перекрытие по `id` по-полево, мерж моделей по id) — каталог играет роль встроенных провайдеров и не может заглушить пользовательский файл. Тумблер `active` на провайдере и модели: неактивные участвуют в слиянии (их можно `extends`-ить и включать переопределением `{"id":…,"active":true}` в своём `providers.json`), но не видны в списках; запись без `active` считается активной. Провайдер, для которого ключ не найден нигде (хранилище → `.vibe/.env` → `~/.vibe/.env` → env ОС), **в сеть не опрашивается и в пилюлю «Модель ▾» не попадает**: строка, падающая на первом же запросе, хуже отсутствующей. Итог опроса каталогов — одна строка в чате вместо строки на провайдера, и состояния в ней различаются по смыслу: «обновлено», «без ключа» (с адресом настроек), «ключ отклонён» (401/403 — ключ есть, но не принят), «локальный сервер не запущен» (ollama/vLLM), «не ответили» с причиной. Изменения подхватываются без рестарта: ключ из настроек — сразу, правки файлов (`providers.json`, каталог `providers/`, `.vibe/.env` обоих уровней) ловит VFS-вотчер с дебаунсом, открытая панель перечитывает реестр и каталоги моделей сама; модели каталога включаются на странице «Модели» (по умолчанию скрыты — curated-список). Вшитых моделей нет — список подтягивается с каталога провайдера (`models.fetch`); **каталоги кэшируются**: на старте пилюля «Модель ▾» сразу полна списком из прошлого сеанса (в чат уходит строка с возрастом кэша), а сеть опрашивается фоном и **параллельно** по всем провайдерам — раньше список наполнялся одним пакетом в конце последовательного обхода и ждал таймаута каждого мёртвого endpoint. В кэш пишется только успешный ответ: 401 или таймаут оставляют вчерашний каталог в силе, а смена `baseURL`/`models.fetch.url` его обесценивает (кэш — регенерируемый файл в системном каталоге IDE, не в `.vibe`); кастомная модель в `models.static` (фикс-параметры, `extraBody`-квирки, `vision:false`, `fim`) помечается в списке бейджем «кастом» — если перестала отвечать, возможно, у провайдера её больше нет. JSONC, битая запись/файл не роняет реестр, `extends`-клоны (в т.ч. поперёк файлов и от неактивных записей), `order`. Ключи — только `apiKeyRef` (хранилище ОС; общий ref = один ключ на несколько провайдеров, как у OpenCode Go/Zen) / `apiKeyEnv` + `.vibe/.env` (файлы можно коммитить); localhost-провайдер помечается «локальная модель»; реестр сканируется Config Guard (не-HTTPS, сырой IP, секрет в headers/query — предупреждения в чате). Спека: [manuals/providersSpec.md](manuals/providersSpec.md).
- **Чекпоинты на каждое сообщение** — git-снимок всей рабочей папки перед каждым сообщением агенту (временный индекс: HEAD и ваш индекс не трогаются; снимок — dangling-коммит в `.vibe/checkpoints.jsonl`); строка чекпоинта в ленте кликабельна (паттерн VibeIDE): клик → подтверждение → откат (файлы, созданные после снимка, не удаляются); правки мимо чата входят в снимок. Не-git-проект — честное «недоступны».
- **Diff-превью перед каждой записью агента** — контракт VibeIDE: любой `fs/write` показывает диалог «Было → Станет» (настоящий диффер платформы) с кнопками Применить/Отклонить ДО записи на диск; закрытый диалог = отказ; запись без изменений применяется молча.
- **Чат по дизайн-системе VibeIDE (и лучше)** — пузырь (радиус 8, токен темы) только у ваших сообщений, прижат вправо; ответ агента — полной шириной без рамки, с капом ширины строки для читаемости в широкой панели (у оригинала капа не было); tool-calls — тихие карточки (радиус 4); чекпоинты — центрированные строки-призраки; таймстампы 11px нейтральные; длительность ответа в мете по завершении; DnD файлов из дерева — чипами контекста. Все цвета — токены `Vibe.Chat.*` / `Vibe.Composer.*`.
- **Композер (паритет с VibeIDE)** — скруглённый блок с полем «План, @ для контекста» (автовысота 60–500 px, дальше скролл; Enter — отправить, Shift+Enter — перенос, Esc — стоп при генерации, Backspace в пустом поле снимает последний чип, Cmd/Ctrl+Backspace — все чипы; клик по пустому месту возвращает фокус). В пустом чате композер стоит **сверху** и под ним чипы «Файл <активный>» / «Модель Провайдер:модель» и — пока в истории один тред — 4 «Подсказки» (клик отправляет); когда тредов больше, вместо подсказок блок «Прошлые чаты». После первого сообщения композер переезжает **под ленту**. Ряд иконок справа: скрепка (изображения png/jpg/webp/gif — выбор, вставка из буфера, перетаскивание), ▷ «продолжи» (текст настраивается: Settings → Tools → VibeIDEA → Чат), Отправить ↔ Стоп. Ряд пилюль: «Режим ▾» (режимы сессии ACP-агента — Plan/Accept Edits/… — переключение через `session/set_mode`; у прямого LLM скрыта), «Модель ▾» (один список с поиском: агенты ACP + модели провайдеров, ✓ у текущей, метка «кастом» у рукописных static-моделей; выбор запоминается на проект; без единой цели — «Нужен ключ провайдера» → настройки), иконки «Пайплайн…» и «Настройки». Slash-меню: `/` в начале сообщения — «Команды чата» (`/commit` — уходит тексту модели, `/skill:` — переключает в список скиллов), `/skill:` в любом месте — скиллы из `.vibe/skills/<id>/SKILL.md` (id = папка, описание из frontmatter `description:` или первой строки; Enter/Tab вставляет `/skill:имя `; пустые состояния по спеке; `/watch` и `/shot` появятся вместе со своими пайплайнами). Один ход за раз: во время генерации Enter ставит текст и вложения в **очередь** (жёлтая полоса «📌 В очереди … (N)» с × у каждой заметки), очередь сливается в следующий ход. Картинка + модель с `vision: false` — блокирующая ошибка; агент без `promptCapabilities.image` — уведомление, картинки не уходят.
- **История чатов** — каждый разговор — персистный тред в глобальном сторе IDE (JSON в конфиг-каталоге, запись с дебаунсом 1,5 с; треды переживают перезапуск и видны из всех проектов). Тред штампуется проектом создания; треды «без проекта» видны везде. Три поверхности: блок «Прошлые чаты» на лендинге (первые 3 + «Ещё N…»/«Свернуть»), выпадашка «история ▾» в ряду пилюль (поиск «Фильтр…» с автофокусом) и правая рейка «История» 280px (кнопка в строке вкладок; по умолчанию свёрнута; группировка «Сегодня/Вчера/Последние 7 дней/Последние 30 дней/Ранее»). Скоуп «Этот проект / Все проекты +N» (виден только при чужих тредах; «Этот проект» = свои + без проекта; выбор синхронен во всех поверхностях). Строка треда: заголовок = первое сообщение пользователя, бейдж проекта у чужих, пилюля «N · Сегодня/Вчера/23 авг»; на ховере — переместить в этот проект / дублировать / удалить (двухшаговое ✕/✓ без диалога). Кап 500 сообщений на тред (настраивается) с маркером обрезки (при повторных обрезках счётчик накопительный). Картинки в LLM-историю уходят только из последних 4 сообщений пользователя (стоимость и защита от «отравленного» запроса; при отказе провайдера картинки из последнего сообщения убираются автоматически).
- **Поиск по истории** — лексический офлайн-движок по всему транскрипту (веса: первое сообщение ×12, ваше ×6, ответ ×2, служебное ×1; бонус за все термины; сатурация 3 вхождения), порядок выдачи — по свежести; под заголовком строка-цитата «Вы:/Ответ:/В переписке:», клик по ней открывает тред **на этом сообщении** (скролл + подсветка, гаснущая через 2,6 с); в скоупе «Этот проект» совпадения чужих проектов не теряются — кнопка «Найдено ещё N в других проектах — показать».
- **Вкладки чатов** — строка 34px над лентой: ярлык = первые 22 символа первого сообщения («Новый чат» у пустого), полный текст в тултипе, × на ховере (тред остаётся в истории), «+» (пустой текущий тред переиспользуется), лимит открытых вкладок (дефолт 5, настройка) с тихим выселением старейшей; набор и активная вкладка переживают перезапуск (на проект). Черновик композера и выбранная модель/режим — свои у каждого треда (черновики — до перезапуска, осознанно). Возобновление треда LLM-провайдера продолжает разговор с полным контекстом; возобновление ACP-треда открывает новую сессию агента (транскрипт виден, контекст процесса не восстановим).
- **Команды палитры (VibeIDEA)** — «История чата» (открыть выпадашку), «Экспортировать историю текущего проекта» (Markdown-стенограмма или JSON), «Удалить историю текущего проекта» (только свои треды, с предупреждением), «Привязать историю без проекта к текущему».
- **@-контекст** — `@` в поле открывает меню под полем (фокус остаётся в поле): Выделение / Недавние / Воркспейс / Файлы / Папки; набор текста в корне ищет файлы и папки сразу (subsequence-матч, ≤100, дебаунс 300 мс); клавиатура: ↑/↓ циклично, Alt±10, Cmd/Ctrl — края, →/Enter — выбрать/провалиться, ← — назад, Backspace — символ фильтра / уровень вверх / закрыть и стереть `@`, Esc. Выбор — чип над полем (иконка + имя, для выделения `имя (N1-N2)`, × — убрать, клик открывает файл/диапазон/папку). При отправке дополнительно разбираются набранные вручную `@"путь с пробелами"`, `@путь`, `@selection`, `@workspace`, `@recent`, `@agent` (AGENTS.md + .vibe/rules.md), `@sym:Имя`, `@folder:путь`; неразрешённое не блокирует отправку — предупреждение в ленте. На проводе: ACP — блоки `resource` (текст файла/выделения; >100k символов — `resource_link`) и `image`; прямой LLM — блоки `<context ref="путь#L…">` после текста и image-части (OpenAI/Anthropic/Gemini).
- **Ключи провайдеров в защищённом хранилище** — Settings → Tools → VibeIDEA → Провайдеры: поле ключа на каждого активного провайдера реестра (подсказка карточки называет источник записи: глобальная `~/.vibe`, проектная `<проект>/.vibe` или «глобальная + проектное переопределение»), значение уходит в PasswordSafe (Keychain) под `apiKeyRef` или id провайдера (общий `apiKeyRef` = один ключ на несколько карточек: близнецы обновляются сразу, пустая карточка-близнец ключ не стирает). Кнопка **«Проверить и сохранить»** запрашивает каталог моделей введённым ключом и, если провайдер его принял, кладёт ключ в хранилище и обновляет модели без рестарта (у endpoint без авторизации так и написано — «ключ этому endpoint не нужен», ложного «действителен» не будет); ключ, набранный поверх во время запроса, не затирается. Apply тоже перечитывает реестр открытой панели. Приоритет резолва: хранилище → `.vibe/.env` проекта → `~/.vibe/.env` → env ОС. В файлах ключи не живут никогда.
- **Диспетчерская агентов** — тулвиндоу снизу: прогоны, за которыми никто не смотрел (задачи входящего HTTP API и пайплайны). Строка прогона: цель, источник, статус с причиной **словами** («окно закрылось, не завершив прогон», а не код), шаги против лимита, число изменённых файлов, агент/модель, время. Сводка сверху всегда печатает числа явно, **включая нули** («требуют внимания 0»): отсутствие строки читалось бы как «всё хорошо», а это утверждение нельзя делать умолчанием. Фильтры «Все / Работают / Завершены / Требуют внимания» и поиск по цели и цели-агенту. Журнал `.vibe/agent-runs.jsonl` **переживает перезапуск IDE**; брошенный прогон определяется по факту, а не по подозрению — окно раз в 30 с отмечается в своих записях, и прогон признаётся брошенным, только если владевшее им окно молчит дольше трёх пропусков (второе окно на том же проекте живым мёртвым не считает). Пишутся **только метаданные** — ни промптов, ни ответов модели, ни аргументов инструментов. Усечение по лимиту (500) и сроку (30 дней) **не трогает незавершённые** прогоны. Обычная переписка в журнал не идёт: у неё есть история чатов. Спека: [manuals/agentRunsSpec.md](manuals/agentRunsSpec.md).
- **Agent Skills (`.vibe/skills/<id>/SKILL.md`)** — переносимые рецепты для модели. `/skill:<id>` в композере: список с описаниями из шапки, а при отправке **тело навыка уходит модели** (ACP — блоком `resource` с `skill://<id>`, прямому провайдеру — `<skill ref="<id>">`); несколько навыков в сообщении — все, без повторов. Формат — открытый контракт Agent Skills: на верхнем уровне шапки только `name`, `description`, `license`, `allowed-tools`, `compatibility`, `metadata` (своё — под `metadata`). Валидатор (действие «VibeIDEA: проверить скиллы проекта» и проверка при каждом вызове): ошибки — нет шапки/`name`/`description`, `name` не совпал с папкой, лишний ключ верхнего уровня, пустое тело, вложение уводит за пределы `.vibe/skills`; предупреждения — слишком длинное описание, тело больше 100 000 символов, каталог `scripts/` рядом. Сломанный навык **не отправляется** и называет причину строкой в ленте; в списке `/skill:` он виден с пометкой, а не исчезает. Тело проходит тот же фильтр контекста, что и файлы проекта. Набор готовых навыков засевается в проект. Спека: [manuals/skillsSpec.md](manuals/skillsSpec.md).
- **Защита контекста от отравления** — всё, что уходит модели (файлы из @-контекста, чтение файла по запросу агента), проходит через один фильтр: **невидимые символы вырезаются молча** — zero-width, мягкий перенос и теговый блок Unicode U+E0000–E007F, которым прячут инструкции в строке, одобряемой человеком глазами; **bidi-переопределения** («Trojan Source») тоже; **фразы-инструкции** («ignore previous instructions», «теперь ты другой», `<system>`, русские аналоги) — только отмечаются строкой «🛡 контекст», без правки чужого файла; **секреты** отмечаются всегда и по настройке маскируются в отправляемом тексте (файл на диске не меняется никогда). Прямому провайдеру контекст уходит с явной подписью, что это данные, а не инструкции. Заголовки и виды tool-call'ов от агента нормализуются (одна строка с капом, закрытый список видов) — они уходят в аудит, хуки и предохранители. При первом открытии незнакомого репозитория — одна поясняющая строка (не блокирует, не повторяется). Настройки: Settings → Tools → VibeIDEA → Агент → «Контекст: что уходит модели».
- **Входящий HTTP API (дёрнуть агента из CI, бота, крона)** — Settings → Tools → VibeIDEA → Агент → «Входящий HTTP API» (выключен по умолчанию), порт `0` = любой свободный. `GET /health` и `POST /run` с телом `{task, sessionId?, wait?}`; ответ — `{sessionId, status}`, где `sessionId` = id треда чата (переживает рестарт, открывается вкладкой). Контракт VibeIDE перенесён дословно — скрипты работают в обоих продуктах. Безопасность: слушается **только** `127.0.0.1` (настройки «слушать снаружи» нет), адрес клиента проверяется на loopback повторно, заголовок `Host` обязан быть локальным (защита от DNS rebinding), `Authorization: Bearer` с константным сравнением, тело до 1 000 000 байт, CORS-заголовков нет (страница не прочитает ответ). Токен генерируется при первом включении и живёт в хранилище ОС, а не в синхронизируемых настройках; действия «показать токен» и «перевыпустить токен» — в Find Action. Ход идёт тем же путём, что и набранный руками: очередь, предохранители, хуки, VERIFY-GATE. Спека: [manuals/httpApiSpec.md](manuals/httpApiSpec.md).
- **Тонкие скроллы во всей IDE** — Settings → Tools → VibeIDEA → **Интерфейс**: «Толщина скроллов, px» (по умолчанию 4; `0` возвращает штатные 10–14 px платформы). Значение применяется сразу ко всем открытым окнам и действует везде — дерево проекта, редактор, наши панели, всплывающие списки (в платформе точечно пропатчен `JBScrollBar`, запись в FORK_CHANGES.md; ключ `vibe.scrollbar.thickness` объявлен нашим плагином).
- **Без рекламы платных IDE JetBrains** — платформа умеет показывать в редакторе баннер «*.tsx files are supported by WebStorm» (советник плагинов апстрима). В VibeIDEA такие файлы поддержаны через LSP, поэтому предложение **выключено по умолчанию**; тумблер «Предлагать платные IDE JetBrains для „неподдерживаемых“ файлов» — там же, Settings → Tools → VibeIDEA → Интерфейс, применяется без рестарта. Используется штатный флаг платформы `ide.try.ultimate.disabled` (правок платформы нет); явное решение пользователя не перетирается при обновлении.
- **Видимость моделей (страница «Модели»)** — Settings → Tools → VibeIDEA → Модели: сворачиваемые группы по провайдерам (все свёрнуты по умолчанию; шеврон + счётчик «(N)», при поиске «(X/Y найдено/всего)»), AND-поиск по имени/id/провайдеру/характеристикам с авто-раскрытием совпавших групп, тумблер «активные» (включён по умолчанию — чистый UI-фильтр «только включённые», ничего не сохраняет), значки характеристик у моделей с заявленными полями: «кастом» (рукописная запись), vision/text-only, fim, размер контекста («128K» бинарно для степеней 1024, «200K»/«1M» десятично). Строки страницы рисуются сразу из кэша каталогов (в статусе группы — возраст записи и «обновляю…»), сеть идёт фоном и параллельно. Каталоги обновляются тремя путями: сам собой после сохранения ключа в «Провайдерах», кнопкой «Обновить каталоги» (все провайдеры) и ссылкой «обновить» в шапке группы (один); статус ответа виден и у свёрнутой группы, непринятые галочки переживают обновление. **Модель из каталога по умолчанию скрыта, пока её не включили здесь** (кастомная — видима; явный тумблер сильнее дефолта) — пилюля «Модель ▾» остаётся curated-списком и не зарастает сотнями каталожных id (семантика VibeIDE), панель после подтяжки подсказывает, где включать. Тумблеры видимости — side-map (PropertiesComponent), переживают правки файлов. Apply сразу перечитывает цели открытой панели — «Модель ▾» показывает только включённые без рестарта.
- **ACP-клиент (Vibe Agent)** — тулвиндоу с чатом любого локального ACP-агента (Claude Code через `claude-agent-acp`, Codex, Gemini CLI и др.): стриминг ответа, рендер код-блоков в ответе агента (fenced ```` ``` ````) с настоящей подсветкой синтаксиса IDE (read-only редактор по языку из метки fence; неизвестный язык — моноширинно), меткой языка, горизонтальным скроллом и своей кнопкой «копировать»; сворачиваемый блок «💭 размышления» (ACP `agent_thought_chunk`), кнопка «копировать» на сообщениях агента, индикатор занятости контекста «⛁ N%» в композере (ACP `usage_update`: занято/размер окна, стоимость в тултипе; жёлтый с 80%; сбрасывается с новой сессией), permission-запросы диалогом (закрытый диалог = отказ — молчаливого «разрешить» не существует), чтение файлов агентом видит несохранённые правки редактора (Document-first), записи идут через WriteCommandAction для открытых файлов и с асинхронным VFS-refresh для внешних. Реестр агентов совместим с `~/.jetbrains/acp.json` (битая запись пропускается с предупреждением и не роняет реестр); агент запускается без оболочки (command+args). Дефолтный агент — Claude Code через `npx @agentclientprotocol/claude-agent-acp`.
- **Терминал агента** — живой вывод команд агента прямо в ленте чата: для Claude — стрим Bash через расширение `_meta.terminal_output` (моноширинная консоль со сворачиванием по клику на заголовок и кнопкой «копировать», ANSI-очистка, head+tail 80 000 символов, бейдж кода выхода); для сторонних агентов (Gemini CLI и др.) — исполнение стандартными методами ACP `terminal/create|output|wait_for_exit|kill|release` через платформенные процессы IDE (kill валит всё дерево процессов, `outputByteLimit` режет вывод с начала по границе символа). Флаг «Разрешать агентам исполнять терминал» (Settings → Tools → VibeIDEA → Агент, дефолт вкл) объявляет capability `terminal` только для сторонних агентов; у Claude исполнение всегда внутри агента. **Гейт разрушительных команд** — детерминированный классификатор (`rm -rf`, `dd`, `mkfs`, `git push --force`, `git reset --hard`, `chmod 777`, `Remove-Item`… с разбором строки по `&&`/`;`/`|`) подсвечивает опасную команду в диалоге разрешения (Claude) или требует подтверждения перед `terminal/create` (сторонние).
- **Хуки проекта `.vibe/hooks.json`** — команды проекта вокруг работы агента: `preToolUse` (перед инструментом — блокирует в точках, которыми владеет клиент: запрос разрешения и запись через `fs/write`), `postToolUse` (после — требование исправить), `turnEnd` (конец хода, в stdin `changedFiles`). Код выхода решает: `0` — разрешено (+stdout заметкой), `2` — отказ, прочее/таймаут — поломка хука (не блокирует). Тройной гейт: настройка (дефолт выкл) + Workspace Trust + успешный парсинг. Точный матчинг `tools`, таймаут 30 с/потолок 300 с. Спека и образец — [hooksSpec.md](manuals/hooksSpec.md); образец приходит с засевом окружения.
- **Засев окружения `.vibe/`** — при открытии любого проекта VibeIDEA создаёт и наполняет `.vibe/` дефолтами (решение владельца: VibeIDEA — агентская IDE, без `.vibe` её использовать незачем): `README.md` (что это за папка), `.gitignore` (рантайм-журналы agent/audit/checkpoints не попадают в git), `rules.md` (правила проекта для `@agent`), образцы `hooks/pipelines/servers.example.jsonc` по нашим спекам, каталог провайдеров `providers/` (README, шаблон с примером кастомной модели и готовые конфиги — читаются автоматически, см. пункт о каталоге провайдеров), дизайн-сиды `design/components.md`+`uiKit.md`. Только create-if-missing — файл пользователя не перезаписывается никогда; всё засеянное фиксируется в `.vibe/.seeded.json` (sha256). Обновление окружения новым релизом решается по ревизиям: `versions.json` набора хранит для каждого файла номер ревизии, sha текущей и всех прошлых версий. Нетронутая копия старого релиза (её sha есть в истории) **обновляется молча** — терять нечего; ваша правка **не трогается никогда**, а если ревизия ушла вперёд, приходит уведомление «релиз обновил N файлов» с тремя выходами: «Сравнить» (штатный diff релиз↔ваш файл), «Обновить, сохранив мои тумблеры» (предлагается, только когда единственное отличие — значения `active`: файл обновляется, а ваши «выключено» переезжают в `providers/zz-local-toggles.jsonc` — он сортируется последним в каталоге и потому сильнее сидов) и «Оставить своё» (запоминается на текущей ревизии — не спросим до следующего бампа). Устаревшие сиды (удалённые/переименованные в наборе) подчищаются при засеве по тем же sha-эталонам из `deprecated.json` — только не правленные копии. Набор общий с VibeIDE (репо VibeBrains, submodule).
- **VERIFY-GATE** — реальная проверка сборки/тестов при завершении хода, менявшего файлы (а не инструкция в промпте): `off`/`warn`/`enforce`. В `enforce` красный результат не закрывает ход — агент получает вывод ошибки синтетическим сообщением и обязан исправить (до N возвратов, затем прогон останавливается и отдаётся вам). Команда, режим, попытки и таймаут — Settings → Tools → VibeIDEA → Агент. Битая команда (не запустилась) делает гейт инертным, а не «красным». Триггер — завершение хода `session/prompt` с мутацией файлов (закрывает дефект VibeIDE «гейт только на ветке vibe_complete»).
- **Проверки хода и предохранители** — детерминированные проверки изменённых за ход файлов (`off`/`notify`/`enforce`): утечка секрета (приватные ключи, токены AWS/Anthropic/OpenAI/GitHub/Slack/Google) и запись в защищённый путь (`.git/`, `.ssh/`, `.env`, `*.pem`, `*.key`…). Находка взводит **залипающий защитный предохранитель**, который переживает перезапуск IDE и **блокирует старт следующего хода агента**, пока пользователь не снимет его подтверждением. Команда палитры «Предохранители агента» показывает сработавшие и снимает их. Лимиты скана (макс. файлов, макс. размер файла) настраиваются; о непросканированных сверх лимита сообщается в ленте. LLM-судья не используется.
- **Аудит `.vibe/audit.jsonl`** — журнал действий агента (промпты, ответы, вызовы инструментов, разрешения, записи, хуки, гейты, предохранители, терминал), по умолчанию выключен. Аргументы, тела команд и содержимое файлов не пишутся никогда — только имя инструмента и целевой путь (≤260 символов; у командных инструментов и его нет). Ротация по размеру (дефолт 10 МБ) в `audit.<N>.jsonl.gz`. Команда палитры «Журнал аудита агента» показывает последние записи, экспортирует лог в файл и очищает его (GDPR-эрейз). Формат — [auditSpec.md](manuals/auditSpec.md).
- **Состояние агента в статус-баре и уведомления** — виджет статус-бара показывает текущее состояние агента (⏳ ход / 🔎 проверка / ⛔ предохранитель; в покое скрыт), клик открывает чат. Когда ход завершается, а окно IDE не в фокусе, приходит балуон-уведомление «Vibe Agent завершил ход» (группа «Vibe Agent»).
