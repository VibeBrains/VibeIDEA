# Правила для AI-агентов, работающих в этом репозитории

> Корневой `AGENTS.md` принадлежит **апстриму** (генерируется `community/.ai/render-guides.mjs`).
> Править его нельзя: это конфликт на каждом синке по правилу границы форка. Наши правила — здесь.

Читать вместе с [CLAUDE.md](../../CLAUDE.md) (специфика форка) и глобальными правилами владельца.

## 1. Граница форка — первое, что нужно знать

Свой код живёт **только** в `vibe-plugins/*` (пакеты `com.vibe.*`) и `vibeidea-customization/`.
Всё остальное — апстрим:

- платформенные файлы **не правятся** ради стиля, формата или линта — это налог на каждый синк;
- точечная правка платформы допустима за реальный баг, проводку фичи или безопасность — и
  **каждая** фиксируется записью в [FORK_CHANGES.md](../../FORK_CHANGES.md);
- прежде чем менять чужой файл, спросите себя, нельзя ли то же самое сделать точкой расширения.

Проверить принадлежность файла: `git log -1 -- <путь>` и `git cat-file -e upstream/master:<путь>`.

## 2. Язык

- Общение, коммиты, документация — **по-русски**.
- Комментарии в коде — **по-английски**.
- Строки интерфейса — **через каталог** (`VibeI18n.t("ключ")`), не литералами: иначе падает гейт
  локализации. Диагностика (логи) переводу не подлежит и под гейт не идёт.

## 3. Три гейта, каждый обязателен

```bash
./vibe-plugins/tools/checkVibeUi.sh        # тонкие скроллы: наши панели + правка платформы
./vibe-plugins/tools/checkVibeI18n.sh      # каталог строк + храповик по литералам
./vibe-plugins/tools/checkVibeBranding.sh  # чужой брендинг в наших файлах
./bazel.cmd test //vibe-plugins/vibe-agent:vibe-agent_test
```

Тесты никогда не запускаются при ошибках компиляции. Сборка dmg — **только**
`./vibeidea-installers.cmd`; соседний `./installers.cmd` принадлежит апстриму и собирает чистую
IDEA CE, причём с кодом возврата 0 (ошибка не видна по выводу).

## 4. Инварианты продукта — то, что нельзя «оптимизировать»

Каждый пункт стоил отдельного разбора; ломать их молча нельзя.

- **Числа не выдумываются.** Кэш каталогов моделей пишет только успешный ответ; 401 не стирает
  вчерашний каталог. Дизайн-детектор молчит там, где не может знать (нечитаемые стили, нет замера).
- **Пол качества нельзя принять как стиль.** Нечитаемый текст не бывает фирменным решением.
- **Вкус не блокирует ход.** Bounce по стилевой находке превратил бы мнение в блокировку.
- **Молчание запрещено.** Детектор, который не смог измерить, обязан сказать почему: тишина
  читается как «всё хорошо», а это утверждение нельзя делать умолчанием.
- **Незавершённый прогон не удаляется** из журнала ни по сроку, ни по лимиту — это единственный
  след того, что могло остаться работать.
- **Контекст модели — данные, а не команды.** Невидимые символы и bidi вырезаются всегда; фразы,
  похожие на инструкции, только отмечаются — правка чужого файла хуже предупреждения.
- **Копирование отдаёт целое.** Свёрнутый код-блок копируется полностью: молчаливая потеря куска —
  тот отказ, который замечают позже всех.

## 5. Как здесь принято работать

1. Сначала план, потом код: что создаём, что меняем, что удаляем и почему.
2. Каждый пункт закрывается **фактом** — прогон, вывод команды, лог. Не «должно работать».
3. Нетривиальная грабля — записью в `docs/vibe/knowledge/<домен>/` со строкой в индексе.
4. Сделанное — пунктом `[x]` в `docs/vibe/roadmap.md`; видимая возможность — в `functional.md`.
5. Фича с форматом файла обязана иметь спеку в `docs/vibe/manuals/`, пригодную скормить модели.
6. Перед удалением «мёртвого» кода — раскопки: что делает, откуда взялся, нет ли живого замысла.
