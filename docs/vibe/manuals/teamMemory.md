# Память команды VibeMemory в VibeIDEA

Как подключить общую память команды с хоста VibeMemory, чтобы ею пользовались прямой чат с моделью и внешние агенты.

Локальная память семейства (`~/.vibememory/bin/vibememory-mcp`) работает сама и этого мануала не требует.
Здесь — память **команды**: она живёт на хосте VibeMemory, и доступ к ней дают токены из кабинета.

## Что нужно заранее

- Установленный VibeMemory: в `~/.vibememory/bin/` лежит `vibememory` (или каталог из `VIBEMEMORY_DIR`).
- Место в команде: владелец команды добавил вас в кабинете VibeMemory.

## Шаги

1. В кабинете откройте команду, «Connect an agent», выберите агента `vibeidea` и права.
   Кабинет покажет одноразовый код.
2. На своей машине выполните и введите код, когда команда попросит:

   ```bash
   vibememory connect --cabinet https://app.vibememory.ru --agent vibeidea
   ```

   Код не передаётся аргументом нарочно: его не должно быть видно в списке процессов и в истории оболочки.
3. Проверьте: «VibeIDEA: диагностика» → строка «Память команды».
   «отвечают: acme» — всё готово; «сервер не принял токен» — переподключите агента в кабинете и повторите шаг 2.

Перезапускать IDE не нужно: команды читаются заново на каждом ходе.

## Что происходит дальше

**Прямой чат с моделью** получает инструменты каждой команды с её именем впереди: `team-acme__memory_search`,
`team-acme__memory_save` и так далее. Инструменты локальной памяти остаются под своими именами, и одно не прячет другое.
Чтение идёт без вопроса, запись — с вопросом, как у локальной памяти.

**Внешний агент** (Claude и другие ACP-агенты) получает сервер команды при открытии сессии, если объявил MCP по HTTP.
Агенту, который умеет только stdio, сервер команды не передаётся: в ленте появится строка с причиной, а памятью команды
можно пользоваться из прямого чата.
Запрет своих MCP-серверов в `~/.jetbrains/acp.json` (`"default_mcp_settings": {"use_custom_mcp": false}`) отключает и память команды.

**Проект** сервер команды сам не определяет: он не видит каталога вашей машины.
Запись требует явного `project`, а `project_resolve` команды перечисляет проекты, которые токену можно.

## Где токен

- Токен лежит только в файле `~/.vibememory/tokens/<команда>/vibeidea` с правами владельца.
- Рядом — `vibeidea.json` без токена: кабинет, команда, адрес сервера (`mcpUrl`). По этому файлу IDE находит команду.
- Заголовок `Authorization` IDE спрашивает у `vibememory mcp-headers <команда> vibeidea` при каждом подключении и нигде не хранит.
- Ни в `.vibe/mcp.json`, ни в `${secret:…}` проекта токен класть не нужно: проектные файлы уезжают с репозиторием.
- Внешнему агенту токен уходит открытым текстом в `session/new`: без него агент не подключится.
  Всё, что агент печатает в stderr, попадает в ленту с этим токеном под `***`.

## Если что-то не так

| Строка | Что делать |
|---|---|
| «память команды «acme»: сервер не принял токен» | Токен отозван или истёк: переподключите агента `vibeidea` в кабинете и выполните `vibememory connect` |
| «память команды «acme» недоступна: … not found» | Нет `vibememory` в `~/.vibememory/bin/`: переустановите VibeMemory |
| «память команды не передана агенту: он не объявил MCP по HTTP» | Агент умеет только stdio: пользуйтесь памятью команды из прямого чата |
| Строки «Память команды» в диагностике нет, пишет «не подключена» | Шаг 2 не выполнен, или токен выдан другому агенту (не `vibeidea`) |

Сервер доступен только по HTTPS; адрес `http://` принимается лишь для сервера на этой машине — так проверяют локальный `vibememory-mcp --http`.
