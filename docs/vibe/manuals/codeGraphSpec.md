# Граф проекта `.vibe/codeGraph.json` — спецификация

> **Как этим пользоваться.** Скопируйте файл целиком своей LLM и попросите:
> *«По этой спецификации ответь по `.vibe/codeGraph.json`: кто импортирует `<файл>` / как связаны
> `<A>` и `<B>` / что трогает `<файл>`»*. Документ самодостаточный.

---

## 1. Что это

Снимок структуры проекта: файлы, объявленные символы, импорты, TODO-комментарии и связи между
файлами. Строится в IDE (**Tools → «Vibe: экспорт графа проекта»**) и кладётся в
`.vibe/codeGraph.json`. Агент читает файл сам — принцип тот же, что и во всём остальном: агенту
даются **пути и структура**, а не пересказанное содержимое.

Граф отвечает на три вопроса, на которые обычный поиск по тексту не отвечает:

1. **Кто импортирует этот файл** — сам файл о своих импортёрах не знает.
2. **Как связаны вот эти двое** — кратчайшая цепочка, без учёта направления.
3. **Что трогает этот файл** — его импорты, символы и заметки в комментариях.

## 2. Формат

```json
{
  "version": 2,
  "generatedBy": "VibeIDEA code_graph: …",
  "nodes": [
    {
      "path": "src/App.kt",
      "size": 4213,
      "modifiedAt": 1800000000000,
      "symbols": ["app.App"],
      "imports": ["app.Service"],
      "todos": ["// TODO: вынести таймаут в настройки"],
      "importers": [{ "path": "src/Main.kt", "symbol": "app.App", "provenance": "факт" }]
    }
  ],
  "edges": [
    { "from": "src/App.kt", "to": "src/Service.kt", "symbol": "app.Service", "provenance": "факт" }
  ]
}
```

| Поле узла | Смысл |
|---|---|
| `path` | Путь относительно корня проекта. |
| `size`, `modifiedAt` | Отпечаток файла. Нужен инкрементальному пересбору (раздел 4). |
| `symbols` | Объявленные типы верхнего уровня, полными именами (UAST: JVM-языки). |
| `imports` | Строки импортов как в исходнике. |
| `todos` | Первые строки TODO/FIXME-комментариев. |
| `importers` | Кто импортирует **этот** файл, с происхождением связи. |

## 3. Происхождение связи — главное поле

У каждой связи есть `provenance`:

| Значение | Когда | Как читать |
|---|---|---|
| `факт` | строка импорта совпала с объявленным полным именем | связь прочитана в исходнике |
| `догадка` | совпал только последний сегмент имени | связь правдоподобна, но не доказана |

Связи не будет вовсе, если простое имя разрешается больше чем в один файл: два `Utils` в разных
пакетах — это не связь, а подбрасывание монеты.

**Зачем это нужно.** Модель, получившая перемешанную кучу без пометок, не отличает прочитанное от
достроенного и обращается с догадкой как с фактом — так правдоподобный ответ превращается в
неверный рефакторинг. Правило: по `догадке` можно предложить проверить, по `факту` — действовать.

## 4. Инкрементальность

Повторный экспорт **не переразбирает** файлы, у которых совпали `size` и `modifiedAt` — они
берутся из прошлого графа. Отпечаток именно такой, а не хэш содержимого: хэширование требует
прочитать все файлы, то есть ровно ту работу, которой отпечаток и позволяет избежать.

Уведомление после экспорта говорит, сколько файлов разобрано заново, — по нему видно, работает ли
инкрементальность.

Файл прошлой версии формата читается без ошибки: переиспользовать просто нечего, будет полный
разбор.

## 5. Примеры

```bash
# кто импортирует файл (только доказанные связи)
jq '.edges[] | select(.to=="src/Service.kt" and .provenance=="факт") | .from' .vibe/codeGraph.json

# что этот файл тянет в себя
jq '.edges[] | select(.from=="src/App.kt") | {to, symbol, provenance}' .vibe/codeGraph.json

# файлы без единого импортёра — кандидаты в мёртвый код (проверять глазами!)
jq -r '[.edges[].to] as $used | .nodes[] | select(.path as $p | $used | index($p) | not) | .path' .vibe/codeGraph.json

# все заметки в коде одним списком
jq -r '.nodes[] | select(.todos) | .path as $p | .todos[] | "\($p): \(.)"' .vibe/codeGraph.json
```

## 6. Границы

- Символы и импорты разбираются через UAST — это **JVM-языки**. Файлы других языков попадают в
  граф узлами (путь, размер, TODO), но без символов и связей.
- Лимиты: до 5000 файлов, файлы больше 1 МБ пропускаются.
- Граф — снимок, а не индекс: после правок его нужно выгрузить заново (это дёшево, см. раздел 4).
- Отсутствие связей у файла означает «связей не найдено данным способом», а не «файл ни с чем не
  связан»: динамический импорт, рефлексия и строковые пути графу не видны.
