# Мост в Telegram: агент с телефона

Поставить задачу, следить за длинным прогоном и получить ответ, не сидя за компьютером.

## Как поднять

1. **Свой бот.** У @BotFather команда `/newbot`, минута — и есть токен. Бот ваш: наш сервер в
   переписке не участвует вовсе.
2. **Токен в IDE.** Tools → «VibeIDEA: токен Telegram-бота». Токен уходит в защищённое хранилище ОС
   (Keychain / DPAPI / libsecret), в конфиги проекта не пишется и в репозиторий не поедет.
3. **Первое сообщение боту.** IDE покажет уведомление «неизвестный чат просит доступ» с кнопкой
   «Разрешить этот чат». До разрешения чат не может **ничего** — включая вопрос, что запущено.

Пустой токен отключает мост.

## Что умеет

| Сообщение | Что делает |
|---|---|
| обычный текст | задача агенту в выбранном проекте |
| `/projects` | какие окна открыты, кнопкой на каждое |
| `/use <проект>` | куда слать задачи |
| `/digest` | сводка за сутки: прогоны, падения, расход |
| `/menu` | те же команды кнопками |
| `/stop` | остановить текущий ход |

## Решения, которые стоит знать

- **Чужой чат не узнаёт ничего.** Ответ неизвестному — одна строка «этот чат не подключён», без
  имени машины, без списка проектов, без объяснения, что здесь вообще есть.
- **Прогресс редактирует одно сообщение.** Сорок уведомлений о прогоне на телефоне — это телефон с
  выключенными уведомлениями, а вместе с ними и с пропущенным ответом.
- **Свой прокси.** `vibe.agent.telegramProxy` отдельно от прокси провайдеров моделей: Telegram и
  API моделей блокируются в разных местах и разными людьми, и один адрес для обоих не работает ни у
  кого.
- **Опрос, а не webhook.** Webhook требует публичного адреса и сертификата; long polling работает с
  ноутбука за NAT, а именно там IDE и живёт.

## Чего пока нет

- Подтверждения разрушительных команд кнопками из чата — они по-прежнему делаются в IDE.
- Голосовые сообщения (упираются в тот же нативный распознаватель, что и голосовой ввод).
- Скриншот превью в чат.
