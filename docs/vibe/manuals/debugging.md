# Отладка TypeScript и PHP

**Адаптеры едут вместе с IDE, конфигурацию заводит она сама.** Ставить ничего не нужно: точку
останова поставить и нажать «Debug». Со стороны языка нужен только рантайм с вашей машины — Node
для JavaScript/TypeScript, PHP с включённым Xdebug для PHP.

Что раньше делалось руками и теперь не делается: командная строка адаптера, JSON запуска и признак
готовности сервера. Ни одно из трёх значений не угадывается по памяти, и именно поэтому отладкой
через LSP4IJ никто не пользовался.

## 1. Проверить, что есть

Tools → **«VibeIDEA: языковые серверы»** — отчёт показывает и серверы, и отладчики отдельной
секцией, и говорит, чей адаптер работает: ваш или встроенный.

## 2. Поставить свой адаптер (необязательно)

Свой сильнее встроенного: каталоги пользователя просматриваются раньше нашего, потому что проект
может быть прибит к другой версии. Обе команды — из релизов самих проектов, распаковка идёт туда,
где IDE потом ищет адаптер. Ни `sudo`, ни установки в системные каталоги.

**JavaScript / TypeScript** (vscode-js-debug, MIT):

```bash
mkdir -p ~/.lsp4ij/dap/vibeJsDebug && curl -sL "$(curl -s https://api.github.com/repos/microsoft/vscode-js-debug/releases/latest | grep -o 'https[^"]*js-debug-dap[^"]*tar.gz')" | tar -xz -C ~/.lsp4ij/dap/vibeJsDebug
```

**PHP** (vscode-php-debug, MIT; нужен Xdebug в самом PHP):

```bash
mkdir -p ~/.lsp4ij/dap/vibePhpDebug && curl -sL "$(curl -s https://api.github.com/repos/xdebug/vscode-php-debug/releases/latest | grep -o 'https[^"]*vsix')" -o /tmp/php-debug.vsix && unzip -oq /tmp/php-debug.vsix -d ~/.lsp4ij/dap/vibePhpDebug
```

> Ни `npm install -g js-debug-adapter`, ни `composer global require xdebug/vscode-php-debug` не
> работают — таких пакетов не существует, обе команды отвечают 404 (проверено 01.09.2026). Раньше
> доктор выдавал именно их; та же ошибка, что и `brew install phpactor`, и та же цена: команда,
> которая падает, читается как «фича сломана».

Свой уже установленный адаптер сильнее: каталог `~/.lsp4ij/dap/` просматривается первым, потому что
это тот экземпляр, который вы сами обновляете.

## 3. Отладить

Точку останова поставить в файле, дальше — **«Debug»** на этом файле. Конфигурация заполняется
сама:

| | JavaScript / TypeScript | PHP |
|---|---|---|
| Что делает по умолчанию | запускает открытый файл (`pwa-node`, карты исходников включены) | **слушает** Xdebug на 9003 |
| Ещё в списке | `npm run dev` — поднимает дев-сервер проекта и отлаживает его | встроенный сервер PHP на `localhost:8000` с уже включённым Xdebug |
| Attach | к процессу на 5858 | к Xdebug на 9003 |

Список конфигураций виден в самом окне запуска: одной формы не хватает на обе половины работы —
скрипт запускают, веб-приложение поднимают и открывают в браузере. Пока была только «этот файл»,
всем, чей код живёт за дев-сервером, приходилось дописывать JSON руками — то есть ровно то, ради
чего эта возможность и делалась.

PHP по умолчанию именно слушает, а не запускает скрипт: страницу отлаживают запросом к веб-серверу,
и конфигурация, запускающая файл под CLI-интерпретатором, ломается на первой же странице с сессией.
Со стороны PHP нужен включённый Xdebug (`xdebug.mode=debug`, `xdebug.client_port=9003`).

Адаптера нет вовсе (сборка из исходников без `download.sh`) — конфигурация не создаётся, и доктор
говорит, что поставить. Это намеренно: конфигурация, которая выглядит готовой и умирает с «Cannot
run program», обвиняет проект вместо отсутствующего пакета.

## Что мы везём, а что берём с машины

| Едет с IDE | Берётся с машины |
|---|---|
| vscode-js-debug 1.117.0 (MIT), vscode-php-debug 1.40.1 (MIT) | Node, PHP с Xdebug |

Решение владельца 01.09.2026: 1,2 и 1,8 МБ архивов — цена того, что точка останова работает сразу
после установки, как и переход к определению. Рантаймы по-прежнему не везём: второй интерпретатор в
дистрибутиве — это второе, что придётся обновлять при каждой его уязвимости.
