# Спека формата `.vibe/hooks.json` — хуки проекта (VibeIDEA)

← [Дерево документации](../README.md)

> **Как этим пользоваться:** скопируйте этот файл целиком своей LLM и попросите собрать `.vibe/hooks.json` для вашего проекта. Здесь есть всё: поля, значения по умолчанию, контракт кода выхода, формат входных данных и рабочие примеры. Выходить в интернет и читать исходники не нужно.

## Что такое хук

Хук — команда **вашего проекта**, которую VibeIDEA запускает вокруг работы агента: перед вызовом инструмента, сразу после него или в конце хода.

Разница между хуком и правилом принципиальна. Правило (`AGENTS.md`, `.vibe/rules.md`, `CLAUDE.md`) просит модель вести себя определённым образом — и она обычно слушается. Хук ничего не просит: он выполняет вашу команду, и её **код выхода** решает, состоится действие или нет. «Не трогай `migrations/`» — пожелание; `preToolUse`-хук, возвращающий `2` на путь внутри `migrations/`, — факт.

## Где лежит и когда работает

Файл: `.vibe/hooks.json` в корне проекта.

Хуки выполняются, только когда выполнены **все три** условия:

1. включена настройка Settings → Tools → VibeIDEA → **Агент** → «Включить хуки проекта» (по умолчанию **выключена**);
2. папка помечена доверенной (Workspace Trust);
3. файл разобрался без ошибок.

Выключено по умолчанию не из осторожности вообще, а по конкретной причине: иначе клонирование чужого репозитория означало бы выполнение его кода у вас на машине. Если в проекте есть хуки, а настройка выключена, VibeIDEA один раз скажет об этом при открытии чата.

## Граница ACP (чем VibeIDEA отличается от VibeIDE)

В VibeIDEA агент (Claude Code и др.) работает **отдельным процессом** по протоколу ACP, и клиент видит его действия только через поток обновлений. Отсюда:

- **`preToolUse` может ЗАБЛОКИРОВАТЬ** действие только в двух точках, которыми управляет клиент: (а) когда агент **спрашивает разрешение** на инструмент, и (б) когда агент пишет файл через клиента (`fs/write`). Инструменты, которые агент выполняет внутри себя (его собственный Bash, его правки), обходят блокировку `preToolUse`, **если** режим разрешений не заставляет агента спрашивать. Хотите гарантированную блокировку опасных команд — держите режим разрешений строгим (не «автопилот»).
- **`postToolUse` и `turnEnd`** наблюдаются полностью: они не отменяют уже сделанное, а формулируют требование исправить.

## Формат

```jsonc
{
  "hooks": [
    {
      "event": "preToolUse",          // preToolUse | postToolUse | turnEnd
      "command": "node .vibe/hooks/guard.js",
      "tools": ["write_text_file"],   // необязательно; пусто = любой инструмент
      "timeoutMs": 5000,              // необязательно; по умолчанию 30000, максимум 300000
      "label": "Политика записи"      // необязательно; так хук назовут в сообщениях
    }
  ]
}
```

| Поле | Обязательное | Значение |
|---|---|---|
| `event` | да | `preToolUse` — перед инструментом; `postToolUse` — после; `turnEnd` — когда агент закончил ход |
| `command` | да | Командная строка. Выполняется через системную оболочку, рабочая папка — корень проекта |
| `tools` | нет | Точные имена инструментов. Пусто — любой. Для `turnEnd` игнорируется |
| `timeoutMs` | нет | По умолчанию 30 000, потолок 300 000. Больший таймаут урезается, и вам об этом скажут |
| `label` | нет | Человеческое имя хука в сообщениях агенту и в уведомлениях |

Хуки одного события выполняются **по очереди, сверху вниз**; первый же отказ прекращает цепочку.

Имена инструментов зависят от агента. У Claude Code это, например, `write_text_file` (запись через клиента), а также имена его собственных инструментов (`Bash`, `Edit`, `Write`), которые приходят в запросе разрешения. Пустой `tools` (любой инструмент) — самый переносимый вариант.

## Контракт кода выхода

| Код | Что значит |
|---|---|
| `0` | Разрешено. Всё, что хук напечатал в stdout, показывается заметкой |
| `2` | **Отказ.** Для `preToolUse` инструмент не выполняется (там, где клиент может заблокировать — см. «Граница ACP»); агент получает текст из stderr (или stdout) как причину. Для `postToolUse` и `turnEnd` действие уже произошло — приходит требование исправить |
| любой другой | Считается **поломкой самого хука**: работа продолжается, пользователь видит предупреждение |

Почему отказ — это `2`, а не `1`: единицу возвращает любой сломанный скрипт (нет бинарника, опечатка в пути, синтаксическая ошибка). Если бы единица блокировала агента, опечатка в хуке молча запирала бы проект. Остановить агента можно только намеренно.

Таймаут и невозможность запустить процесс тоже считаются поломкой хука и **не блокируют** работу. Вывод хука обрезается до 4000 символов.

## Что хук получает на вход

В stdin приходит JSON одной строкой:

```json
{
  "event": "preToolUse",
  "tool": "write_text_file",
  "params": { "path": "/path/to/project/src/a.kt", "content": "…" },
  "cwd": "/path/to/project",
  "changedFiles": ["src/a.ts"]
}
```

- `tool` и `params` — есть у `preToolUse` и `postToolUse`; `params` — сырые параметры инструмента, как их выдал агент;
- `changedFiles` — только у `turnEnd`: файлы, изменённые за ход (через клиента);
- `cwd` — корень проекта, он же рабочая папка команды.

Дополнительно в окружении команды доступны `VIBE_HOOK_EVENT` и `VIBE_HOOK_TOOL` — для однострочников, которым разбирать JSON незачем.

## Примеры

**1. Запретить агенту трогать миграции (по пути записи)**

`.vibe/hooks.json`:

```json
{
  "hooks": [
    { "event": "preToolUse", "command": "node .vibe/hooks/no-migrations.js", "tools": ["write_text_file"], "label": "Миграции только руками" }
  ]
}
```

`.vibe/hooks/no-migrations.js`:

```js
let raw = '';
process.stdin.on('data', chunk => { raw += chunk; });
process.stdin.on('end', () => {
  const payload = JSON.parse(raw || '{}');
  const target = String(payload.params?.path ?? '');
  if (target.includes('/migrations/')) {
    console.error('Файлы миграций правятся только вручную: ' + target);
    process.exit(2);
  }
  process.exit(0);
});
```

**2. Прогонять линтер после каждой записи файла**

```json
{
  "hooks": [
    { "event": "postToolUse", "command": "npm run lint --silent", "tools": ["write_text_file"], "timeoutMs": 60000, "label": "ESLint" }
  ]
}
```

**3. Тесты в конце хода**

```json
{
  "hooks": [
    { "event": "turnEnd", "command": "npm test --silent", "timeoutMs": 300000, "label": "Тесты" }
  ]
}
```

**4. Однострочник без разбора JSON**

```json
{
  "hooks": [
    { "event": "preToolUse", "command": "sh -c 'test \"$VIBE_HOOK_TOOL\" != write_text_file || { echo \"Запись файлов запрещена\" >&2; exit 2; }'", "label": "Только чтение" }
  ]
}
```

## Как проверить, что всё работает

1. Включите настройку «Включить хуки проекта» и убедитесь, что папка доверенная.
2. Положите хук, который всегда отказывает на запись: `{ "event": "preToolUse", "command": "sh -c 'echo стоп >&2; exit 2'", "tools": ["write_text_file"] }`.
3. Попросите агента записать любой файл — он получит отказ и назовёт причину «стоп».
4. Уберите хук: агент снова работает.

Если ничего не происходит — проверьте настройку, доверие к папке и то, что агент действительно спрашивает разрешение либо пишет через клиента (см. «Граница ACP»).

## Чего хуки не делают

- Не откатывают уже выполненное: `postToolUse` не отменяет правку, а требует её исправить.
- Не заменяют подтверждения опасных действий (разрушительные команды) — это отдельный механизм, он остаётся.
- Не выполняются в недоверенной папке и при выключенной настройке, даже если файл есть.
