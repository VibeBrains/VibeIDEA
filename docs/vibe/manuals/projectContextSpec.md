# Что агент обязан читать и чего не должен касаться

Три файла и одна настройка задают границы работы агента в проекте VibeIDEA. Ни один из них не
обязателен: без них агент работает как раньше — читает и правит проект, и только его.

## `.cursor/rules/` — правила проекта

Формат чужой (Cursor), и это осознанно: репозиторий, склонированный у коллеги, уже несёт свои
правила, а агент, который их не видит, спорит с проектом на каждом ходу.

Один файл — одно правило, расширение `.mdc`, имя файла без расширения — имя правила:

```
---
description: как называем сущности
globs: src/**/*.ts, src/**/*.tsx
alwaysApply: false
---
Компоненты — PascalCase, хуки — use*, файлы — по имени экспорта.
Стили только токенами темы, вшитые цвета запрещены.
```

Три вида правил, и путать их нельзя:

| Заголовок | Когда попадает в ход |
|---|---|
| `alwaysApply: true` | всегда |
| `globs: ...` | когда ход трогает подходящий файл |
| ни того, ни другого | только по имени: `@имя-правила` в сообщении |

`@имя` внутри тела правила подтягивает другое правило — один раз и без зацикливания. Почта
(`user@example.com`) ссылкой не считается.

Заголовка может не быть вовсе — файл всё равно правило, просто без метаданных: наказывать
пользователя за опечатку в чужом формате хуже, чем прочитать файл как есть.

Старый `.cursorrules` в корне проекта подхватывается как правило, которое применяется всегда —
именно это он и означал до появления папки.

Тело правила проходит тот же контроль, что любой файл с диска: невидимые символы вырезаются,
фразы-инъекции отмечаются. «Правила проекта» — ровно та вывеска, которую хотела бы носить
подсунутая инструкция.

**Ограничение:** тело длиннее 20 000 символов обрезается — одно правило не должно съедать ход.

## `.vibe/ignore` — что агент не читает и не ищет

Проблема невидима, пока не укусит: один минифицированный бандл — это строка в 400 000 символов,
и одно её чтение съедает контекст на весь ход. Пользователь видит только, что ответ стал хуже.

Синтаксис — полезное подмножество gitignore, и намеренно не больше (вторая полная реализация
разошлась бы с git и врала бы о том, какие файлы игнорируются):

```
# комментарий
dist/                 # папка и всё внутри неё
*.min.js              # по имени, на любой глубине
build/reports         # путь от корня проекта
docs/**/*.png         # ** пересекает каталоги
!vendor/keep.min.js   # вернуть обратно; побеждает последнее совпадение
```

Игнорируемый файл не предлагается и в `@`-меню: предложить файл, который агенту запрещено
читать, — ловушка (пользователь выбирает, ход падает на отказе, о котором он не просил).

## Папки-справочники — читать, но не править

«Прочитай мои заметки, но не редактируй их» — фраза, которую произносят постоянно, и пока её не
исполняет механизм, это надежда, а не правило.

- **Вне проекта:** команда «VibeIDEA: добавить папку-справочник для агента (только чтение)».
  Отключить — «VibeIDEA: папки-справочники».
- **Внутри проекта:** список путей `vibe.agent.sourceFolders` (например `raw`, `docs/sources`) —
  агент читает, запись отклоняется всегда.

## Итоговая таблица доступа

| Где файл | Чтение | Запись |
|---|---|---|
| В проекте | да | да |
| В проекте, но в `.vibe/ignore` | **нет** | **нет** |
| В `sourceFolders` проекта | да | **нет** |
| В папке-справочнике | да | **нет** |
| Где угодно ещё вне проекта | **нет** | **нет** |

Решение принимается **до** действия, а не объясняется после: запрещённый файл не читается и не
попадает в процесс. Проект не открыт — ограничений нет (иначе сломался бы сценарий с одиночным
файлом на черновике).

## Вложенные правила

`.cursor/rules` читаются не только в корне проекта, но и в папках-предках файлов, которых касается ход. Правило пакета с тем же именем, что корневое, **перекрывает** корневое — так выражается «у нас в этом пакете иначе». Вложенное правило подмешивается только когда ход трогает файлы его папки.

Обхода всего дерева нет: он ушёл бы в `node_modules` и стоил бы паузы на каждом ходу. Поэтому правило, лежащее в папке, которую ход не трогает, в ход и не попадёт.
