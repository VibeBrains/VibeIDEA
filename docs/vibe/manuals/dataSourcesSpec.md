# Подключения к БД: `.vibe/dataSources.json`

Самодостаточный документ: скопируйте его целиком своей модели и попросите собрать файл подключений —
в интернет за форматом ходить не придётся.

## Файл

```jsonc
{
  "dataSources": [
    {
      "id": "app",                                  // обязателен, уникален в файле
      "name": "Прод (только чтение)",               // необязательно; без него зовётся по id
      "url": "jdbc:postgresql://db.example.com:5432/app",   // обязателен
      "user": "reader",                             // необязательно
      "driverPath": "~/drivers/postgresql-42.7.11.jar",     // jar драйвера JDBC
      "driverClass": "org.postgresql.Driver"        // нужен только старым драйверам без сервиса
    },
    { "id": "local", "url": "jdbc:sqlite:./dev.db" }
  ]
}
```

Массив можно писать и без обёртки: `[ { … }, { … } ]`.

**Пароля в файле нет и быть не может.** Файл живёт в git, а пароль в git — это утечка с
отложенным сроком. Пароль хранится в связке ключей системы (PasswordSafe платформы). Если поле
`password` в файле всё-таки окажется, панель скажет об этом красным: это не «неподдерживаемое
поле», а находка — секрет уже в репозитории.

Битая запись пропускается с указанием места, остальные подключения остаются рабочими: файл правят
руками, и опечатка в одном подключении не должна отключать все.

## Драйверы

**Мы их не поставляем.** У драйверов разные лицензии (MySQL Connector/J — GPL с исключением для
свободного ПО), и класть их в дистрибутив значит принимать чужие условия за пользователя. Драйвер
скачивается один раз и указывается в `driverPath`:

| База | Драйвер | Лицензия |
|---|---|---|
| PostgreSQL | `org.postgresql:postgresql` | BSD-2 |
| SQLite | `org.xerial:sqlite-jdbc` | Apache-2.0 |
| MySQL | `com.mysql:mysql-connector-j` | GPL-2.0 + FOSS exception |
| MariaDB | `org.mariadb.jdbc:mariadb-java-client` | LGPL-2.1 |
| H2 | `com.h2database:h2` | MPL-2.0 / EPL-1.0 |

Каждый jar грузится **в своём загрузчике классов**: два драйвера разных версий в одном classpath
однажды встретятся, и разбираться в этом будет невозможно.

## Панель «БД»

Слева дерево объектов с поиском, справа консоль запросов и таблица результата — раскладка знакомая
по PhpStorm и DataGrip, потому что менять её незачем.

- **Двойной щелчок по таблице** — `SELECT * FROM … LIMIT 200`.
- **«Выполнить»** — выполняется оператор, **внутри которого стоит курсор**; файл с десятком
  операторов не запускается целиком по случайному нажатию.
- Служебные схемы (`pg_catalog`, `information_schema`, `mysql`, `sys`, …) по умолчанию спрятаны:
  их десятки, и среди них теряются две схемы проекта.
- `NULL` печатается словом, а не пустотой: в базе это разные вещи, и человек, чинящий данные,
  обязан видеть, какая перед ним. Двоичное показывается размером, а не байтами.
- Одинаковые имена столбцов разводятся (`id`, `id (2)`): иначе `SELECT a.id, b.id` молча показывал
  бы один столбец вместо двух.

## Пределы, названные вслух

- **Правки данных нет.** Только показ: правка требует подтверждений и генерации `UPDATE` по
  первичному ключу, а сделанная наполовину она опаснее отсутствующей.
- Выборка ограничена 200 строками — предел ставится и в тексте запроса, и на стороне драйвера
  (`setMaxRows`), поэтому миллион строк не приедет в память, даже если запрос написан руками.
  Свой `LIMIT` человека не подменяется.
- Таймаут запроса — 30 секунд.
- Разбор SQL знает строки, комментарии и долларовые кавычки PostgreSQL, поэтому `CREATE FUNCTION`
  не разъезжается на середине. Но это разбиение на операторы, а не разбор SQL: подсветки и
  автодополнения по схеме пока нет.
