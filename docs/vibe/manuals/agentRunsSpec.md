# Журнал прогонов `.vibe/agent-runs.jsonl` — спецификация формата

> **Как этим пользоваться.** Скопируйте весь файл целиком своей LLM и попросите:
> *«По этой спецификации напиши мне <дашборд / скрипт проверки / отчёт> по журналу прогонов
> VibeIDEA»*. Документ самодостаточный.

---

## 1. Что это

Машинно-локальный журнал прогонов агента, за которыми **никто не смотрел**: задач входящего HTTP
API и пайплайнов. Его читает панель «Диспетчерская» (тулвиндоу снизу).

Обычная переписка в чате сюда **не пишется** — у неё есть полная история тредов, и вторая копия
того же протухала бы по-своему. Практическое следствие, которое стоит помнить, читая файл: пустой
журнал означает «ничего не запускалось без наблюдения», а не «ничего не происходило».

Файл лежит в `.vibe/agent-runs.jsonl` и попадает в `.vibe/.gitignore`: он про конкретную машину.

## 2. Формат

JSON Lines: одна запись — одна строка. Файл **append-only**: обновление прогона дописывается новой
строкой с тем же `runId`, и при чтении **побеждает последняя**. Раз в час файл переписывается
компактно (по одной актуальной строке на прогон).

Битая строка при чтении пропускается — одна неудачная запись не стоит всей истории.

```json
{"runId":"7b1e…","epoch":"3f9a…","source":"http_api","goal":"прогони тесты и почини падения",
 "status":"running","target":"acp/Claude Code","startedAt":1800000000000,
 "heartbeatAt":1800000030000,"steps":2,"maxSteps":5,"changedFiles":3}
```

| Поле | Тип | Смысл |
|---|---|---|
| `runId` | строка | Идентификатор прогона. Обязателен: строка без него игнорируется. |
| `epoch` | строка | Окно IDE, которому принадлежит прогон. Нужен для правила сиротства. |
| `source` | `http_api` \| `pipeline` | Откуда пришла задача. |
| `goal` | строка | Цель, одна строка, до 200 символов. |
| `status` | `running` \| `completed` \| `failed` \| `cancelled` \| `orphaned` | Состояние. |
| `target` | строка | Агент или модель, которым исполнялось. |
| `startedAt` | число | Момент старта, мс epoch. Обязателен. |
| `finishedAt` | число | Момент завершения; у сироты — момент **последней отметки**, а не обнаружения. |
| `heartbeatAt` | число | Когда окно последний раз подтвердило, что живо. |
| `steps` / `maxSteps` | число | Сделано шагов и лимит (у пайплайна — число шагов). |
| `changedFiles` | число | Сколько файлов затронуто. |
| `outcome` | строка | Итог **словами**: «пройден целиком: 3 шагов», «окно закрылось, не завершив прогон». |

## 3. Чего в журнале нет никогда

Ни промптов, ни ответов модели, ни аргументов инструментов, ни содержимого файлов. Только
метаданные из таблицы выше. Журнал, тихо копящий переписку, был бы утечкой с красивой таблицей
сверху; это правило закреплено тестом.

## 4. Правило сиротства

Прогон признаётся брошенным **по факту, а не по подозрению**:

1. Окно раз в 30 секунд обновляет `heartbeatAt` своих незавершённых прогонов.
2. Прогон становится `orphaned`, только если **все три** условия верны: он `running`; его `epoch`
   не принадлежит ни одному живому окну; последняя отметка старше трёх интервалов (90 секунд).
3. `finishedAt` сироты — момент последней отметки: это когда работа реально прекратилась.

Второе окно на том же проекте живым мёртвым не считает: у каждого окна свой `epoch`.

## 5. Усечение

Раз в час: записи старше срока хранения (по умолчанию 30 дней) и превышающие лимит (500) удаляются
— **кроме незавершённых**. Незавершённый прогон не удаляется ни по сроку, ни по лимиту: это
единственный след того, что могло остаться работать, и потерять его означает ровно тот отказ, ради
которого журнал заведён.

Настройки: Settings → Tools → VibeIDEA → Агент → «Диспетчерская».

## 6. Как прочитать снаружи

```bash
# что требует внимания
jq -c 'select(.status=="orphaned" or .status=="failed")' .vibe/agent-runs.jsonl

# последняя запись по каждому прогону (файл append-only)
jq -s 'group_by(.runId) | map(last) | .[]' .vibe/agent-runs.jsonl
```
