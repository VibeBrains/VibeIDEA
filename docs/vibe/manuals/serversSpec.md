# Спека: Vibe Server (`.vibe/servers.json`)

> Скопируйте этот файл целиком своей LLM и попросите: «собери мне `.vibe/servers.json` для моего проекта» — этого документа достаточно. Порты и команды бери из package.json / docker-compose, не выдумывай.

## Что это

Декларативный дев-стек проекта: сервисы и одноразовые задачи с зависимостями и проверками готовности. Тулвиндоу «Vibe Server» (низ IDE): Запустить всё / Остановить всё / запустить выбранный (поднимет и его транзитивные зависимости). Контракт совместим с VibeIDE.

## Формат (JSONC: комментарии и висячие запятые разрешены)

```jsonc
{
  "version": 1,
  "servers": [
    // Инфраструктура — это task (+readyCheck exit +skipIf), не service!
    { "id": "colima", "kind": "task", "command": "colima start",
      "readyCheck": "exit", "skipIf": "docker info" },

    { "id": "api", "dir": "api", "command": "yarn dev", "port": 3000,
      "readyTimeoutMs": 180000, "dependsOn": ["colima"],
      "pathPrepend": ["/opt/homebrew/opt/node@20/bin"],
      "stopCommand": "docker compose down" },

    { "id": "web", "dir": "web", "command": "npm run dev", "port": 5173,
      "readyCheck": "log", "readyPattern": "Ready in", "readyTimeoutMs": 420000 }
  ]
}
```

## Поля записи

- **`id`** (обяз., уникален — по нему `dependsOn` и UI), **`command`** (обяз., выполняется через системную оболочку).
- `kind`: `service` (долгоживущий, дефолт) | `task` (обязан **успешно завершиться до** старта зависимых: миграции, кодоген, демоны).
- `name`, `note`, `active: false` (запись задокументирована, но вне стека).
- Где: `dir` (относительно корня), `env`, `envFile` (строки `ИМЯ=значение`), `pathPrepend` (папки в начало PATH — пин тулчейна).
- Готовность: `port` (объявляется явно — из вывода не вычитывается), `readyCheck`: `port` (TCP-коннект; дефолт service) | `http` (GET `readyPath`, не-5xx = готов) | `log` (`readyPattern`-regex по строке вывода) | `exit` (код 0; дефолт task) | `spawn` (готов сразу); `readyTimeoutMs` (дефолт 60000; тяжёлые фронтенды — 420000, бэкенд — 180000). Принцип: **запущенный процесс — ещё не готовый**.
- Порядок: `dependsOn` (ждут ГОТОВНОСТИ, не запуска; порядок выводится отсюда, не из позиции), `skipIf` (команда-проба: exit 0 → запись пропускается; делает повторный запуск дешёвым).
- Прочее: `stopCommand` (best-effort при остановке), `autoStart`, `previewPath`.

## Волны и провалы

Независимые записи стартуют параллельно одной волной; зависимые ждут готовности. Провал предусловия останавливает зависимых — **ничего не стартует втихую**: неизвестный id в `dependsOn`, цикл зависимостей, провал — всё видно в списке с причиной. Битая запись пропускается с предупреждением; дубль id — пропуск второй; не-JSON верхнего уровня отключает файл. Сервис, умерший сам, помечается `stopped`/`failed`; своя остановка ставит `stopped` до убийства процесса. Перечитывание файла сохраняет живые статусы совпавших id.

## Отличия от VibeIDE (честные границы)

- `autoStart` парсится, но автозапуска с проектом пока нет (нет гейта доверия командам — появится вместе с ним).
- `previewPath` парсится; встроенного превью-браузера пока нет.
- По истечении `readyTimeoutMs` запись помечается `failed`, зависимые не стартуют (в спеке VibeIDE поведение не оговорено — здесь оговорено).
