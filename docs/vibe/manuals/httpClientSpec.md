# Формат `.http` в VibeIDEA — спека и как пользоваться

Самодостаточный документ: скопируйте его целиком своей модели и попросите собрать файл запросов —
в интернет за форматом ходить не придётся.

## Зачем файлами, а не как в Postman

Запросы — часть проекта: их правят вместе с эндпоинтом, обсуждают в код-ревью и откатывают вместе
с кодом. Коллекция в чужом облаке ничего из этого не умеет. Поэтому запросы лежат в репозитории
файлами `.http` (или `.rest`), а из Postman взято то, что там действительно хорошо: **окружения**
и **импорт-экспорт cURL**.

## Файл запросов

```http
### Список пользователей
GET {{host}}/users
Accept: application/json

### Создать пользователя
# @name Создание
POST {{host}}/users
Content-Type: application/json
Authorization: Bearer {{token}}

{"name": "Иван", "email": "ivan@example.com"}

### Загрузить из файла и сохранить ответ
POST {{host}}/import
Content-Type: application/json

< payload.json
>> out/last-import.json
```

Правила:

| Запись | Смысл |
|---|---|
| `### Имя` | разделитель запросов; текст после решёток — имя следующего |
| `GET https://…` | строка запроса; метод можно опустить — это `GET` |
| `Имя: значение` | заголовок; заголовки идут до первой пустой строки |
| пустая строка, затем текст | тело запроса |
| `< payload.json` | тело из файла рядом (путь считается от папки запроса) |
| `>> out/answer.json` | куда сохранить тело ответа |
| `> handler.js` или `> {% … %}` | обработчик ответа: **распознаём, но не выполняем** |
| `@host = https://…` | переменная файла; видна всем запросам ниже |
| `# @name Имя` | имя запроса (сильнее имени из `###`) |
| `# @no-redirect` | не идти по 3xx |
| `# @timeout 12` | свой таймаут в секундах |
| `#` или `//` в начале строки | комментарий |

Незнакомая пометка `# @что-то` ошибкой не считается: формат растёт, а файл должен остаться читаемым.

## Окружения

Рядом с запросами (или выше по дереву до корня проекта) кладутся два файла:

```jsonc
// http-client.env.json — едет в git
{
  "dev":  { "host": "http://localhost:8080" },
  "prod": { "host": "https://api.example.com" }
}
```

```jsonc
// http-client.private.env.json — в .gitignore, здесь секреты
{
  "dev":  { "token": "локальный-токен" },
  "prod": { "token": "настоящий-токен" }
}
```

Приватный файл перекрывает общий по ключу. Окружение выбирается в панели **HTTP**; переменные
файла (`@host = …`) сильнее окружения — их для того рядом с запросом и пишут.

**Неподставленная переменная остаётся видимой** как `{{token}}`, и строка состояния называет её
отдельно. Пустая строка вместо неё отправила бы запрос на `https:///users` и спрятала причину.

Динамические: `{{$uuid}}`, `{{$timestamp}}`, `{{$randomInt}}`.

## Как выполнить

- **Ctrl+Alt+Enter** в редакторе — выполняется запрос, внутри которого стоит курсор.
- Панель **HTTP** справа: список запросов открытого файла, выбор окружения, кнопка «Выполнить».
- Правая кнопка в редакторе → «Выполнить HTTP-запрос».

Ответ показывается строкой «статус · время · размер» и двумя вкладками — тело и заголовки. JSON
раскладывается с отступами **без разбора в объект**: порядок ключей и точность чисел сохраняются,
а это ровно то, на что смотрят, сравнивая два ответа.

## Границы, названные вслух

- **JS-обработчики ответа не выполняются.** Свой движок JavaScript означал бы зависимость размером
  с половину плагина. Обработчик распознан и виден в разборе — молча проглотить его нельзя, иначе
  человек будет искать ошибку в собственном скрипте.
- **Нет мастера OAuth 2.0, gRPC, WebSocket и GraphQL-подсказок.** Токен получают снаружи и кладут
  в приватное окружение.
- **Куки** живут в памяти процесса: сессия работает до перезапуска IDE и не попадает в файлы.
- Заголовки `Host`, `Content-Length`, `Connection` и подобные пропускаются: их выставляет сам
  клиент, а попытка задать их вручную уронила бы запрос целиком.

## cURL в обе стороны

Команда из чужого тикета или из вкладки «Network» превращается в запрос, и наоборот — запрос
превращается в команду, которую можно вставить в терминал. Понимаются `-X`, `-H`, `-d`/`--data-raw`,
`-u`, `--url`, `-L`, перенос строки обратным слэшем; незнакомый флаг (вроде `-s` или `-o`)
пропускается молча — иначе команда из документации не импортировалась бы никогда.
