# MCP-сервер VibeIDEA — спека и подключение

Самодостаточный документ: скопируйте его целиком своей модели и попросите настроить подключение —
в интернет за форматом ходить не придётся.

VibeIDEA поднимает **MCP-сервер прямо в IDE**. Смысл: внешний агент (Claude Code, Claude Desktop,
любой MCP-клиент) получает ответы про **открытый проект** — граф импортов, состав, постановку
задачи агенту IDE, — не имея доступа к самой IDE и не парся её файлы наугад.

## Что нужно включить

1. Settings → Tools → VibeIDEA → HTTP API → включить. **По умолчанию выключено осознанно:** это
   вход, по которому на машине владельца выполняется работа.
2. Tools → «VibeIDEA: показать токен API» — токен нужен в конфиге клиента.
3. Порт слушается **только на 127.0.0.1**, и настройки «слушать наружу» нет: она превратила бы
   запуск IDE на личной машине в сетевую службу.

## Адрес и авторизация

```
POST http://127.0.0.1:<порт>/mcp
Authorization: Bearer <токен>
Content-Type: application/json
Mcp-Method: <тот же метод, что в теле>   # требуется ревизией 2026-07-28; без него тоже примем
```

Транспорт — Streamable HTTP: одно JSON-RPC сообщение в теле POST. Сессий нет и заголовка
`Mcp-Session-Id` нет — ревизия 2026-07-28 сделала протокол stateless, и наш сервер такой же.

## Пример конфигурации клиента

```json
{
  "mcpServers": {
    "vibeidea": {
      "type": "http",
      "url": "http://127.0.0.1:63342/mcp",
      "headers": { "Authorization": "Bearer ВАШ_ТОКЕН" }
    }
  }
}
```

Порт подставьте свой — он показан там же, где токен.

## Версии протокола

Сервер объявляет две: **`2026-07-28`** (stateless; `server/discover`, `resultType`, `ttlMs`) и
**`2025-06-18`** (с рукопожатием `initialize`). Вторая — не украшение: большинство клиентов до сих
пор открывают разговор именно так, и поддержка только новой сделала бы сервер правильным и
непригодным.

Версию можно прислать в `_meta["io.modelcontextprotocol/protocolVersion"]` или в
`params.protocolVersion` у `initialize`. Незнакомая версия отвергается кодом `-32022`.

## Методы

| Метод | Что делает |
|---|---|
| `server/discover` | версии, возможности, имя и версия сервера |
| `initialize` | рукопожатие ревизии 2025-06-18; отвечает запрошенной версией |
| `tools/list` | каталог инструментов, `ttlMs` = 10000, `cacheScope` = `private` |
| `tools/call` | вызов инструмента |

Уведомление (сообщение без `id`) не получает тела вовсе — ответ на то, о чём не спрашивали, был бы
протокольной ошибкой на нашей стороне. Ответ на него: HTTP 202 без содержимого.

## Инструменты

| Имя | Аргументы | Ответ |
|---|---|---|
| `vibe_code_graph_importers` | `path` | файлы, которые импортируют указанный |
| `vibe_code_graph_imports` | `path` | файлы, которые импортирует указанный |
| `vibe_code_graph_path` | `from`, `to` | кратчайшая цепочка между двумя файлами |
| `vibe_project_info` | — | имя, корень проекта, размер графа |
| `vibe_run_agent` | `task` | ставит задачу агенту IDE, возвращает id сессии |

**Каждое ребро графа помечено происхождением:** `факт` — импорт совпал с объявленным полным
именем, `догадка` — совпал только последний сегмент (два `Utils` в разных пакетах из голого имени
неотличимы). Пометка едет в ответ, а не отбрасывается: агент, получивший смешанную кучу, считает
прочитанным и то, что было угадано.

Граф обновляется инкрементально при каждом обращении: изменившиеся файлы перечитываются,
остальные берутся из `.vibe/codeGraph.json`. Отдельного «сначала выгрузите граф» не требуется —
у агента, который спрашивает, нет рук.

## Ошибки

| Код | Когда |
|---|---|
| `-32700` / `-32600` / `-32601` / `-32602` | не JSON, нет `method`, метод неизвестен, аргументы не те |
| `-32020` | заголовок `Mcp-Method` не совпал с методом тела |
| `-32022` | версия протокола не поддерживается |
| `-32603` | в IDE нет открытого проекта |

**Упавший инструмент — не ошибка протокола.** Запрос был корректным, упало исполнение: ответ
приходит как обычный результат с `isError: true` и текстом причины, чтобы модель увидела, что
пошло не так, и решила, что делать дальше.

## Границы

- `vibe_run_agent` не ждёт завершения хода: инструмент, висящий минутами, клиент считает зависшим
  и рвёт соединение, а ход при этом продолжается — работа без запросившего.
- Никаких прав сверх тех, что уже есть у HTTP API: тот же токен, тот же loopback, тот же проект.
  MCP — другой язык к той же двери, а не новая дверь.
- Записи в файлы у инструментов нет вовсе: правит файлы агент IDE, и его правки проходят гейты,
  хуки и аудит проекта.
