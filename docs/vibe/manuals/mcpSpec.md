# MCP-сервер VibeIDEA — спека и подключение

Самодостаточный документ: скопируйте его целиком своей модели и попросите настроить подключение —
в интернет за форматом ходить не придётся.

VibeIDEA поднимает **MCP-сервер прямо в IDE**. Смысл: внешний агент (Claude Code, Claude Desktop,
любой MCP-клиент) работает с **открытым проектом** через саму IDE, а не разбирает её файлы наугад:
граф импортов, поиск по индексу слов, происхождение имени через языковой сервер, открытый файл и его
ошибки, знания и решения проекта, документация VibeIDEA, проверка текста — а если человек разрешил,
то и запись файлов, команды оболочки и задача агенту IDE. Полный список — в разделе «Инструменты»,
права — в разделе «Доступ».

**Агенту, которого запускает сама IDE, эти инструменты предлагаются автоматически.** До 08.09.2026
он их не видел: в `session/new` уезжал пустой список серверов, и агент работал в проекте без графа
импортов, поиска по корпусу и журнала решений — свести их руками было можно, но для этого надо было
знать, что они есть. Условий три, и они те же, что у внешнего клиента: HTTP API включён (сервер
живёт на том же входе), токен выпущен, и агент **заявил** поддержку MCP по HTTP
(`agentCapabilities.mcpCapabilities.http` — спека ACP требует спросить: агент, не знающий этого
варианта, роняет разбор `session/new` целиком). Причина, по которой предложить не вышло, называется
строкой в ленте и строкой в диагностике — молчание здесь неотличимо от «работает».

Включать HTTP API за пользователя мы не станем: это дверь, по которой на машине выполняется работа,
и она выключена по умолчанию осознанно.

## Что нужно включить

1. Settings → Tools → VibeIDEA → Агент, раздел «Входящий HTTP API» → включить. **По умолчанию
   выключено осознанно:** это вход, по которому на машине владельца выполняется работа.
2. Tools → «VibeIDEA: показать токен HTTP API» — токен нужен в конфиге клиента.
3. Порт слушается **только на 127.0.0.1**, и настройки «слушать наружу» нет: она превратила бы
   запуск IDE на личной машине в сетевую службу.
4. Нужны запись файлов или команды — там же две отдельные галочки, см. раздел «Доступ». Без них
   работают только читающие инструменты.

## Адрес и авторизация

```
POST http://127.0.0.1:<порт>/mcp
Authorization: Bearer <токен>
Content-Type: application/json
MCP-Protocol-Version: 2026-07-28           # ревизия 2026-07-28: обязателен, совпадает с _meta
Mcp-Method: <тот же метод, что в теле>     # ревизия 2026-07-28: обязателен
Mcp-Name: <params.name у tools/call>       # ревизия 2026-07-28: обязателен у tools/call
```

Транспорт — Streamable HTTP: одно JSON-RPC сообщение в теле POST. Сессий нет и заголовка
`Mcp-Session-Id` нет — ревизия 2026-07-28 сделала протокол stateless, и наш сервер такой же.
`GET` и `DELETE` к `/mcp` получают 405: сессий и возобновляемых потоков в ревизии нет, а 404
сказал бы клиенту, что эндпоинта нет вовсе.

**Строгость зависит от ревизии, которую назвал запрос.**

- Запрос, назвавший `2026-07-28` — заголовком `MCP-Protocol-Version` или полем
  `params._meta["io.modelcontextprotocol/protocolVersion"]`, — проверяется по контракту этой
  ревизии. Заголовок версии обязателен и совпадает с `_meta`, а `_meta` обязан версию нести.
  `Mcp-Method` обязателен и совпадает с методом тела. `Mcp-Name` обязателен у `tools/call` и
  совпадает с `params.name`. Нарушение — HTTP 400 и `-32020` до исполнения чего-либо.
- Имя вне безопасного ASCII (кириллица, пробелы по краям) передаётся как
  `=?base64?<base64 от UTF-8>?=`; сервер декодирует его перед сверкой. Битый base64 и сырой
  не-ASCII в заголовке — тоже 400 и `-32020`.
- Запрос без версии — клиент ревизии `2025-06-18`: её рукопожатие `initialize` по её же спеке идёт
  без заголовка, и такие запросы обслуживаются без требований к заголовкам. Отказ им сделал бы
  сервер правильным и непригодным.
- Присланные заголовки сверяются с телом **в любой ревизии**: по ним мог маршрутизировать шлюз, и
  расхождение значит, что направили один вызов, а исполнился бы другой.
- Уведомлениям (сообщение без `id`) заголовки не нужны: ревизия 2026-07-28 требований к ним не
  задаёт.

**`Origin`.** Запрос с любым `Origin` получает 403, в том числе с адреса этой машины (`localhost`,
`127.0.0.1`, `[::1]`) — на всех путях входа, не только на `/mcp`, и до проверки токена. Клиенты MCP
(агенты, CI, `curl`) `Origin` не шлют; его прикладывает браузер, а страница на соседнем локальном
порту (dev-сервер, другое приложение) сюда ходить не должна.

## Пример конфигурации клиента

```json
{
  "mcpServers": {
    "vibeidea": {
      "type": "http",
      "url": "http://127.0.0.1:63342/mcp",
      "headers": { "Authorization": "Bearer ВАШ_ТОКЕН" }
    }
  }
}
```

Порт подставьте свой — он показан там же, где токен. Заголовки ревизии клиент ставит сам.

## Версии протокола

Сервер объявляет две: **`2026-07-28`** (stateless; `server/discover`, `resultType`, `ttlMs`) и
**`2025-06-18`** (с рукопожатием `initialize`). Вторая — не украшение: большинство клиентов до сих
пор открывают разговор именно так, и поддержка только новой сделала бы сервер правильным и
непригодным.

Версию присылают в заголовке `MCP-Protocol-Version` и в
`params._meta["io.modelcontextprotocol/protocolVersion"]` (ревизия 2026-07-28) или в
`params.protocolVersion` у `initialize` (ревизия 2025-06-18).

- **Незнакомая версия** — HTTP 400 и `-32022`, а в `error.data` — `supported` (что есть) и
  `requested` (что просили): клиент повторяет запрос с одной из них.
- **Исключение — `initialize`.** Там незнакомая версия не ошибка: сервер отвечает своей
  `2025-06-18`, как требует рукопожатие, и клиент решает, продолжать ли. Клиент `2025-11-25`,
  получив `2025-06-18`, продолжает; получив отказ, он остался бы без сервера.

## Методы

| Метод | Что делает |
|---|---|
| `server/discover` | `supportedVersions`, возможности, `ttlMs` = 10000, `cacheScope` = `private`; имя и версия сервера — в `_meta["io.modelcontextprotocol/serverInfo"]` |
| `initialize` | рукопожатие ревизии 2025-06-18; отвечает запрошенной версией, незнакомую заменяет на `2025-06-18` |
| `ping` | пустой результат |
| `tools/list` | каталог инструментов, `ttlMs` = 10000, `cacheScope` = `private` |
| `tools/call` | вызов инструмента |

**Неизвестный метод:** в ревизии 2026-07-28 — HTTP 404 и `-32601`; в прежней — `-32601` в ответе
200. Клиенту прежней ревизии 404 говорит, что пропала сессия или сам эндпоинт, а ошибку он ждёт в
теле.

Уведомление (сообщение без `id`) не получает тела вовсе — ответ на то, о чём не спрашивали, был бы
протокольной ошибкой на нашей стороне. Ответ на него: HTTP 202 без содержимого.

## Доступ

У каждого инструмента свой класс — колонка «Доступ» в таблице ниже. Класс объявлен в коде рядом с
инструментом, а не выводится из имени, и тест сверяет эту колонку с кодом.

| Класс | Что делает инструмент | Когда работает у внешнего клиента |
|---|---|---|
| `чтение` | читает проект, документацию и журналы IDE | всегда, когда HTTP API включён |
| `запись` | меняет файлы проекта | проект доверенный (File → Trust Project) и отмечено «разрешить через MCP запись» |
| `запуск` | выполняет команды на этой машине или ставит задачу агенту IDE | проект доверенный и отмечено «разрешить через MCP запуск» |

Обе галочки стоят там же, где HTTP API (Settings → Tools → VibeIDEA → Агент, раздел «Входящий HTTP
API»), и обе выключены по умолчанию: HTTP API, включённый ради графа импортов, не должен молча
раздавать запись файлов и команды оболочки. В недоверенном проекте запись и запуск закрыты при
любых галочках.

Диалогов здесь нет. Неразрешённый вызов получает отказ с причиной — результат с `isError: true` и
текстом, где сказано, что и где открыть: модель передаёт это человеку словами, а не повторяет вызов.

Правила чтения одни на все каналы: файл из `.vibe/ignore`, файл вне проекта и ссылка из проекта
наружу не отдаются ни одним инструментом, отказ называется словами. Запись подчиняется тем же
границам.

**Агент, запущенный самой IDE,** ходит к инструментам через этот же сервер, и для него действуют
те же галочки. **Прямой чат IDE с моделью** получает те же инструменты своим путём, кроме
`vibe_run_agent`: тот поставил бы задачу той же панели, чей ход идёт. Доверие к проекту там
действует так же, а вместо галочек решает режим прав в композере — автопилот, правки, вручную,
план. Опасная команда оболочки спрашивается у человека всегда, даже на автопилоте.

## Инструменты

Аргументы без пометки обязательны; умолчания и потолки — из кода. Отказ приходит результатом с
`isError: true` и текстом причины.

Файла нет в графе — сказано, сколько файлов в графе; связей нет — сказано; графа ещё нет — построение уходит в фон, и ответ просит спросить снова |

**`vibe_symbol_usages` идёт по индексу слов IDE, а не перебором файлов.** Ради этого инструмента
граф импортов и существовал наполовину: он отвечает «какие файлы связаны», но не «где именно живёт
эта функция», и без ответа агенту остаётся единственный путь — читать файлы целиком и тащить их в
контекст каждого следующего хода. Это и есть та статья расхода, которая потом удивляет в счёте
(«контекстный налог»: у SonarSource замерено ~234 млн контекстных токенов и ≈$65 на средний PR —
[Stop the Context Tax](https://www.sonarsource.com/blog/stop-the-context-tax/), 01.09.2026).
Свой замер живёт в `/trace`, строкой «контекстный налог».

Индекс слов **не разбирает синтаксис**: совпадение в комментарии он не отличает от вызова, и это
сказано прямо в описании инструмента. Инструмент, обещающий «вызовы» и отдающий совпадения, хуже
инструмента, обещающего совпадения. Настоящая иерархия вызовов требует поддержки на каждый язык
(в нашем стеке TS и PHP отвечают через LSP) — отдельная работа, не сделанная.

**Строки закрытых файлов инструмент не отдаёт.** Вернуть строку — значит прочитать её, поэтому
действует правило файлового канала агента, по тому же развёрнутому пути: файл из `.vibe/ignore`,
файл вне проекта и ссылка из проекта наружу в ответ не попадают.

**Каждое ребро графа помечено происхождением:** `факт` — импорт совпал с объявленным полным
именем, `догадка` — совпал только последний сегмент (два `Utils` в разных пакетах из голого имени
неотличимы). Пометка едет в ответ, а не отбрасывается: агент, получивший смешанную кучу, считает
прочитанным и то, что было угадано.

**Граф берётся готовым** — из `.vibe/codeGraph.json`: сканировать монорепозиторий внутри вызова
значит минуты тишины, и ход выглядел зависшим. Графа ещё нет — ответ так и говорит, а построение
уходит в фон, одно на весь процесс; следующий вопрос получит ответ. Готовый граф сам не обновляется:
после правок его перестраивает действие Tools → «Vibe: экспорт графа проекта», перечитывая только
изменившиеся файлы.

## Ошибки

| Код | HTTP | Когда |
|---|---|---|
| `-32700` / `-32600` | 400 | не JSON, нет `method` |
| `-32601` | 404 в ревизии 2026-07-28, иначе 200 | метод неизвестен |
| `-32602` | 200 | аргументы не те, инструмент неизвестен |
| `-32020` | 400 | заголовок не совпал с телом, обязательного заголовка нет или он не разбирается |
| `-32022` | 400 | версия протокола не поддерживается; `data.supported`, `data.requested` |
| `-32603` | 503 | в IDE нет открытого проекта |

Отказы входа приходят раньше MCP и не в формате JSON-RPC: 401 — нет токена или он чужой,
403 — запрос не с этой машины, чужой `Host` или любой `Origin`, 413 — тело больше мегабайта.

**Упавший инструмент — не ошибка протокола.** Запрос был корректным, упало исполнение: ответ
приходит как обычный результат с `isError: true` и текстом причины, чтобы модель увидела, что
пошло не так, и решила, что делать дальше.

## Самопроверка

Tools → «VibeIDEA: диагностика», строка **«самопроверка MCP»**. IDE спрашивает собственный порт
как клиент ревизии 2026-07-28. `server/discover` должен ответить 200 и назвать ревизию в
`supportedVersions`; запрос с чужим `Mcp-Method` должен получить 400 и `-32020`. Отдельно
называется невыпущенный токен. Смысл строки: юнит-тесты видят сервер и политику HTTP по
отдельности, но не проводку между ними — заголовок, потерянный там, ломает каждого клиента при
зелёных тестах.

## Границы

- `vibe_run_agent` не ждёт завершения хода: инструмент, висящий минутами, клиент считает зависшим
  и рвёт соединение, а ход при этом продолжается — работа без запросившего.
- Вход тот же, что у HTTP API: тот же токен, тот же loopback, тот же проект. Запись и запуск сверх
  чтения открываются только галочками и только в доверенном проекте (раздел «Доступ»).
- Хуки проекта (`.vibe/hooks.json`) работают вокруг действий агента IDE; вызовы через этот сервер
  их не проходят. Такие вызовы ограничивают класс доступа и правила чтения.
- Прежний текст файла, записанного или поправленного через MCP, запоминается в журнале правок
  агента: по нему правку можно отклонить.
