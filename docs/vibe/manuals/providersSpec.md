# Спека: провайдеры — каталог `.vibe/providers/` + `providers.json`

> Скопируйте этот файл целиком своей LLM и попросите собрать конфиг провайдера под вашу задачу — этого документа достаточно, в интернет и исходники ходить не нужно.

## Что это

Реестр LLM-провайдеров для прямого чата в панели **Vibe Agent** (записи вида `LLM: <провайдер> · <модель>` в выпадашке). Формат записи совместим с VibeIDE (форк VSCode) — конфиг переносится между продуктами. Ключи API в файлах **не хранятся никогда** — файлы можно коммитить.

## Откуда собирается реестр

Четыре слоя, от слабого к сильному (поздний перекрывает ранний по `id`, по-полево; `models.static` мёржится по id модели):

1. **Каталог `~/.vibe/providers/`** — глобальные файлы-провайдеры (`*.jsonc` или `*.json`, по файлу на провайдера, читаются автоматически, внутри каталога — по алфавиту имён).
2. **Каталог `<проект>/.vibe/providers/`** — то же на уровне проекта. VibeIDEA засевает его готовыми конфигами (OpenCode Go/Zen, OpenRouter, MiniMax, Z.AI, Kimi, DeepSeek активны; OpenAI, Anthropic, Alibaba Coding Plan, Meta Muse, локальные Ollama/vLLM лежат выключенными).
3. **`~/.vibe/providers.json`** — глобальный пользовательский файл.
4. **`<проект>/.vibe/providers.json`** — проектный пользовательский файл, самый сильный.

Каталог играет роль «встроенных провайдеров» VibeIDE — и, как встроенные, лежит **под** обоими пользовательскими файлами: засеянная запись не может заглушить или переписать ваш `providers.json` ни на одном уровне.

- **Тумблер — `active`**: неактивные записи участвуют в слиянии (их можно `extends`-ить и патчить по `id`), но не видны в списках. Важно: **запись без поля `active` считается активной** — поэтому ваш давний `providers.json` продолжает работать, даже если засеянный файл с тем же `id` выключен. Обратная сторона: патч по `id`, который не должен включать выключенную запись, обязан явно повторить `"active": false`.
- Включить засеянного провайдера, не трогая каталог: `{ "id": "openai", "active": true }` в своём `providers.json` (проектном — для проекта, глобальном — везде).
- Каждый файл разбирается независимо: сломанный файл не гасит остальных; битая запись пропускается с предупреждением в чате и не роняет реестр.
- Формат JSONC: `//`-комментарии и висячие запятые разрешены. Ключ, применённый в настройках, панель подхватывает сразу (реестр и каталоги моделей перечитываются); правки самих файлов видны при переоткрытии панели/страниц настроек или перезапуске IDE, FIM перечитывает реестр раз в 30 секунд.

## Формат

Каждый файл каталога — самодостаточный документ той же схемы, что `providers.json`:

```jsonc
{
  "version": 1,
  "providers": [
    {
      // Обязательное: id (уникальный) и baseURL.
      "id": "ollama",
      "name": "Ollama (локально)",
      "protocol": "openai",              // openai (дефолт) | anthropic | gemini
      "baseURL": "http://localhost:11434/v1",
      "auth": "bearer",                  // "bearer" | "none" | {"type":"header","name":"x-api-key"} | {"type":"query","name":"key"}
      "apiKeyEnv": "OLLAMA_API_KEY",     // имя переменной: ищется в <проект>/.vibe/.env → ~/.vibe/.env → окружении ОС
      "apiKeyRef": "ollama",             // или ключ из защищённого хранилища ОС (PasswordSafe), сильнее apiKeyEnv
      "headers": {},                     // статические заголовки
      "query": {},                       // статические query-параметры
      "timeoutMs": 600000,
      "active": true,                    // тумблер: false прячет провайдера и его модели (но слияние/extends работают)
      "order": 10,                       // порядок среди ваших провайдеров (меньше = выше)
      "models": {
        // fetch: true (дефолт) = авто-каталог с <baseURL>/models; строка = полный URL каталога;
        // false = только static. Ответ понимается и openai-вида {data:[{id}]}, и gemini-вида {models:[{name}]}.
        // Найденные модели добавляются к static; static сильнее по совпавшему id.
        "fetch": true,
        "static": [                      // кастомные модели — см. раздел ниже; обычно НЕ нужны
          {
            "id": "qwen3:14b",           // обязательное: как принимает API
            "name": "Qwen3 14B",
            "default": true,             // модель по умолчанию (первая в списке)
            "pinned": false,
            "active": true,
            "contextWindow": 131072,
            "maxOutputTokens": 8192,
            "temperature": 0.7,
            "topP": 0.95,
            "topK": 40,
            "extraBody": {},             // доливается в тело запроса дословно (квирки вендора)
            "fim": false,                // отдать модель inline-автокомплиту (openai-протокол, см. ниже)
            "vision": true               // модель принимает изображения; отсутствует = неизвестно (вложение не блокируется),
                                         // false = композер заблокирует отправку картинки с этой моделью
          }
        ]
      }
    },
    // Клон: новый id + extends — унаследовать все поля другой записи и переопределить нужные.
    // extends работает и поперёк файлов (базой может быть запись любого файла реестра, включая
    // неактивную — клон при этом активен, если сам не скажет иного); одноуровневый, без цепочек.
    { "id": "ollama-fast", "extends": "ollama", "name": "Ollama fast", "models": { "static": [ { "id": "qwen3:4b", "default": true } ] } }
  ]
}
```

## Кастомные модели (для гиков)

Вшитых списков моделей нет — модели приходят с каталога провайдера (`models.fetch`) после подключения ключа. Запись в `models.static` — **кастомная модель**: она нужна, только когда

- модели нет в каталоге провайдера (или каталога нет вовсе — `fetch: false`);
- модели нужны фиксированные параметры: `temperature`/`topP`/`topK`, `maxOutputTokens`, вендоро-специфичное поле в `extraBody` (например `{"thinking":{"type":"enabled"}}` у Moonshot или `{"tool_stream":true}` у DashScope/GLM);
- надо объявить `vision: false` для text-only модели (композер начнёт блокировать картинки заранее);
- модель отдаётся inline-автокомплиту: `fim: true` (openai-протокол, legacy `/completions`).

В списке моделей кастомная запись помечается бейджем **«кастом»** — осознанно: она задана рукой, и если модель перестала отвечать, возможно, у провайдера её уже нет (каталог этого не заметит за вас). Закомментированный образец — в засеянном `_template-openai-compatible.jsonc`.

## Ключи API

**Удобный путь: Settings → Tools → VibeIDEA → Провайдеры** — поле ключа на каждого активного провайдера, значение сохраняется в защищённое хранилище ОС (Keychain) под `apiKeyRef` (или id провайдера, если `apiKeyRef` не задан). Один `apiKeyRef` у нескольких провайдеров = один ключ на всех (так у OpenCode Go/Zen).

Приоритет резолва: защищённое хранилище (`apiKeyRef` → id) → `.vibe/.env` проекта → `~/.vibe/.env` → переменная окружения ОС (имя из `apiKeyEnv`). Формат `.env`: строки `ИМЯ=значение`, `#`-комментарии; интерполяции нет; файл в `.gitignore`. Для localhost-провайдера ключ не обязателен, чат помечается меткой `[локальная модель]`.

Точный путь: клиент дописывает к `baseURL` только имя метода — anthropic: `/messages`, openai: `/chat/completions`, gemini: `/models/<id>:streamGenerateContent` — поэтому версию пути включайте в `baseURL` сами: `https://api.anthropic.com/v1`, `http://localhost:11434/v1`, `https://generativelanguage.googleapis.com/v1beta`. Для gemini дефолтный auth-способ — `{"type":"query","name":"key"}` либо заголовок `x-goog-api-key` (auth `header`).

## Безопасность (Config Guard)

При загрузке реестр сканируется чистой функцией; находки печатаются в чат:
- `provider-endpoint-non-https` (critical) — не-HTTPS endpoint (localhost/127.0.0.1 легитимны, не флагаются);
- `provider-endpoint-raw-ip` (high) — сырой IP;
- `provider-hardcoded-secret` (critical) — креды в URL (`user:pass@`) или секрет-подобный литерал в `headers`/`query`.

## Отличия от VibeIDE (честные границы этой реализации)

- Встроенных (вшитых в код) провайдеров нет — их роль играет засеваемый каталог `providers/*.jsonc`: та же библиотека готовых конфигов, но обычными файлами, которые можно читать, править и `extends`-ить.
- `models.fetch` по умолчанию ходит на `<baseURL>/models` (в VibeIDE — `<baseURL>/v1/models`): у нас `baseURL` всегда включает версионный корень. Нестандартный путь — строкой с полным URL, как и в VibeIDE.
- `vision` — тристейт: `true`/`false`/отсутствует (неизвестно). При `extends` и слиянии незаданный `vision` наследуется от базовой записи той же модели.
- `fim: true` питает inline-автокомплит (в VibeIDE для файловых провайдеров это осталось follow-up); `maxTools`/`maxPromptDirectoryChars` не читаются (нет потребителей).
- Кэша последнего рабочего набора и вотчера файлов нет — перезапуск IDE.

## Проверка

Откройте любой проект — каталог `.vibe/providers/` уже засеян, семь провайдеров активны. Введите ключ в Settings → Tools → VibeIDEA → Провайдеры (кнопка «Проверить» дёргает каталог моделей), затем на странице «Модели» включите нужные модели из каталога (по умолчанию они скрыты — список выбора остаётся curated; кастомные из `static` видимы сразу) и нажмите OK/Apply — открытая панель Vibe Agent сама перечитает реестр: в выпадашке появятся `LLM: …`-записи → выберите и напишите сообщение: ответ стримится прямо с endpoint, без ACP-агента.
