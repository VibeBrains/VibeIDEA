## 1. ACP elicitation: структурные формы и URL-режим

**Находки**

1. [Обновления ACP](https://agentclientprotocol.com/updates) — «структурированные формы и
   взаимодействия в URL-режиме **стабилизированы**», дата **22.07.2026**. Агент может запросить
   структурированный ввод или увести человека во внешний безопасный канал.
2. Это отдельная поверхность от `request_permission`: разрешение отвечает «да/нет» на действие, а
   форма собирает **данные** (значение, выбор из списка, строку).
3. У нас ACP-клиент **свой минимальный** (решение №14 в `decisions.md`), и elicitation в нём нет:
   в `acp/` есть `AcpTypes`, `ToolCallRegistry`, `WritePreview`, права и режимы — форм нет.

**→ VibeIDEA:** забрать метод elicitation в клиент: разбор описания формы, диалог по нему и ответ
агенту; подписи — из каталога i18n, цвета — токенами `Vibe.*`, как везде. URL-режим отдельным
решением: увод человека во внешний браузер по просьбе чужого агента — это действие наружу, и оно
должно спрашивать. — **фича**.

## 3. ACP Registry

**Находки**

1. [Анонс Zed](https://zed.dev/blog/acp-registry) — единый реестр агентов; «и Zed, и IDE JetBrains
   имеют встроенную поддержку реестра», агент публикуется один раз и появляется у всех клиентов.
2. [Репозиторий реестра](https://github.com/agentclientprotocol/registry) — раздача каталога по CDN:
   `https://cdn.agentclientprotocol.com/registry/v1/latest/registry.json`; схемы `agent.schema.json`
   и `registry.schema.json`; типы поставки npm / PyPI / GitHub releases; версии обновляются кроном
   ежечасно; лицензия реестра Apache-2.0, у агентов свои.
3. Приём в реестр проверяется CI: запись обязана возвращать корректные `authMethods` в рукопожатии
   ACP.
4. У нас список агентов сейчас — это `.vibe/agents.jsonc` из общего набора сидов (submodule
   VibeBrains), то есть **наш** список, который стареет вместе с нами.

**→ VibeIDEA:** взять каталог как **источник, а не как замену**: действие «обновить список агентов»
читает `registry.json`, показывает, что появилось, и предлагает дописать в `.vibe/agents.jsonc`.
Автоматической установки чужого агента быть не должно — это запуск чужого процесса на машине
пользователя. Плюс строка в диагностике «каталог читался N дней назад». — **фича** (плюс **сид**:
образец записи с полем «откуда взято»).

## 4. Ревизия MCP 2026-07-28

**Находки**

1. [Анонс ревизии](https://blog.modelcontextprotocol.io/posts/2026-07-28/) — протокол становится
   **stateless**: убраны рукопожатие `initialize`/`initialized` и заголовок `Mcp-Session-Id`, каждый
   запрос самоописателен, появился необязательный `server/discover`.
2. Имена метода и инструмента едут в заголовках `Mcp-Method` и `Mcp-Name` — шлюз маршрутизирует, не
   разбирая тело.
3. Результаты списков кэшируются клиентом: `ttlMs` и `cacheScope`. Серверные запросы к клиенту
   заменены на MRTR (`resultType: "input_required"` + `inputResponses`).
4. Авторизация: обязательная проверка издателя по RFC 9207, переход от динамической регистрации
   клиента (DCR) к CIMD; Roots, Sampling и Logging объявлены устаревшими с окном не меньше
   двенадцати месяцев; устаревает и транспорт HTTP+SSE.

**→ VibeIDEA:** **уже реализовано** на нашей стороне — мы MCP-**сервер**, и `McpProtocol` объявляет
обе ревизии (`2026-07-28` stateless + `2025-06-18`), с `server/discover`, `ttlMs`, `resultType` и
кодами ошибок из новой политики; разбор — `knowledge/architecture/mcpBridge.md`. MCP-**клиента** у
нас нет вовсе, поэтому требования к клиенту (CIMD, RFC 9207) применять не к чему. Единственное, чего
нет: **проверки авторизации по RFC 9207 на нашем сервере** — но у нас токен свой, локальный, и
внешнего сервера авторизации в схеме нет. — **уже реализовано / не применимо**.

## 5. IntelliJ Platform 2026.1–2026.2

**Находки** ([список заметных изменений API](https://plugins.jetbrains.com/docs/intellij/api-notable-list-2026.html))

1. **2026.1:** `ReadAction.compute()`, `ReadAction.run()` и `runReadAction()` объявлены устаревшими —
   длинная неотменяемая read action на фоновом потоке блокирует write action; миграция на
   `readAction {}`, `smartReadAction {}` или `ReadAction.nonBlocking()`.
2. **2026.1:** `AnActionEvent.coroutineScope` — область корутин прямо в `actionPerformed`.
3. **2026.1:** `BulkFileListenerBackgroundable` + топик `VirtualFileManager.VFS_CHANGES_BG` —
   слушатель VFS вне EDT, меньше задержек интерфейса при массовых файловых операциях.
4. **2026.1:** у LSP-поддержки платформы появились Range Formatting, Code Lens и Optimize Imports,
   плюс переработана подсветка ради производительности.
5. **2026.2:** запись содержимого `VirtualFile` через `getOutputStream()`/`setBinaryContent()` может
   быть **отложена** — изменение на диске произойдёт с задержкой.

**Сверка с нашим кодом:** мы собираемся на ветке `263` (2026.3), то есть все эти API доступны.
Устаревшие вызовы у нас есть: `ReadAction.compute` в `graph/CodeGraphBuilder.kt:66`, `runReadAction`
в `acp/IdeFileOps.kt:53` и `:136`. Слушатель провайдеров (`providers/VibeProvidersWatcher.kt:41`)
сидит на обычном `BulkFileListener`/`VFS_CHANGES`. Отложенная запись 2026.2 касается нас напрямую:
`IdeFileOps` пишет файлы по просьбе агента, и «записал» перестаёт означать «на диске».

**→ VibeIDEA:**
- миграция трёх мест с устаревших read action — **фича (малая)**, чистый долг;
- `BulkFileListenerBackgroundable` для наблюдателя конфигов — **фича (малая)**: чтение `.vibe/*` с
  EDT сейчас и есть та задержка, ради которой API сделан;
- **проверить отложенную запись** в `IdeFileOps`: после правки агент читает файл обратно и гоняет
  гейты — если запись отложена, гейт увидит вчерашнее содержимое. — **фича**, и это первое, что
  стоит проверить на 2026.2+;
- LSP-возможности платформы (Code Lens и прочее) нам **не применимы**: мы используем не встроенный
  LSP-клиент платформы, а LSP4IJ (наш `vibe-lsp`), — это отдельная реализация.
- Патч платформы ни для одного пункта **не нужен**: всё перечисленное — публичный API.

## 6. Anthropic prompt caching: цена чтения кэша и часовой TTL

**Находки**

1. [VentureBeat, 01.09.2026](https://venturebeat.com/technology/anthropics-claude-fable-5-1-and-mythos-5-1-arrive-with-a-75-cost-reduction-for-fable-cache-reads) —
   у Fable 5.1 чтение кэша подешевело с $1.00 до **$0.25 за 1M** (−75%); ввод $10, вывод $50, запись
   в пятиминутный кэш $12.50, в **часовой — $20** за 1M.
2. [Документация Anthropic по кэшированию](https://platform.claude.com/docs/en/build-with-claude/prompt-caching) —
   часовой TTL включается полем в самом маркере: `"cache_control": {"type": "ephemeral", "ttl": "1h"}`,
   и требует бета-заголовка `extended-cache-ttl-2025-04-11`.
3. Время жизни считается **от начала запроса**, который пишет или читает запись, а не от конца
   ответа.
4. Сценарий, ради которого часовой кэш существует, — ровно наш: длинная агентская сессия с паузами
   больше пяти минут (ревью, ожидание CI, отладка).

**→ VibeIDEA:** ставить `cache_control` мы уже умеем (`PromptCache` + `LlmClient`, маркер
`ephemeral` на границе стабильного префикса), но **только пятиминутный**. Забрать: поле
`cacheTtl: "5m" | "1h"` у модели в `providers.json` (по умолчанию пятиминутный — часовой дороже в
записи и оправдан не всем), бета-заголовок при `1h`. — **конфиг + фича (малая)**.

## 7. Провайдеры новых моделей

**Находки**

1. [llm-stats, GPT-6 Astra](https://llm-stats.com/models/gpt-6-astra) — вышла **04.09.2026**;
   `POST /v1/chat/completions`, SDK OpenAI-совместимый; вход 1.1M токенов, выход 128K; ввод $10,
   кэшированный ввод $1, вывод $50 за 1M; **TTFT p95 = 14.43 с**, пропускная способность p5 — 30
   символов в секунду.
2. [Блог Google, 02.09.2026](https://blog.google/innovation-and-ai/models-and-research/gemini-models/3-8-flash-and-3-8-flash-cyber/) —
   Gemini 3.8 Flash доступен через Gemini API и AI Studio; вводная цена **$0.75 / $3.75** за 1M до
   **31.12.2026**, дальше **$1.50 / $7.50**.
3. Вариант 3.8 Flash Cyber раздаётся только через программу Fairwind для «доверенных защитников» —
   в общий каталог провайдеров он не попадает.

**Сверка:** протоколы `openai` и `gemini` у нас уже есть, свой список моделей мы не ведём принципиально
(модели приезжают из каталога провайдера). Таймаут запроса по умолчанию — 10 минут
(`LlmClient.DEFAULT_REQUEST_TIMEOUT_MS`), молчание хода ловит `DeadManSwitch` с порогом 5 минут: 14
секунд до первого токена не задевают ни один из порогов.

**→ VibeIDEA:** кода не требуется. Что имеет смысл — **сид**: у Gemini-провайдера в наборе
`.vibe/providers/` прописать `priceValidUntil: "2026-12-31"` для вводной цены (поле появилось
сегодня же), чтобы 1 января отчёт о расходе не считал по вводной цене молча. — **сид**.

## 8. Anthropic-совместимые эндпоинты китайских провайдеров

**Находки**

1. [cc-compatible-models](https://github.com/Alorse/cc-compatible-models) — адреса:
   MiniMax `https://api.minimax.io/anthropic`, Moonshot `https://api.moonshot.ai/anthropic`,
   Z.AI `https://api.z.ai/api/anthropic`, DeepSeek `https://api.deepseek.com/anthropic`,
   Qwen `https://dashscope-intl.aliyuncs.com/apps/anthropic`.
2. [litellm#29518](https://github.com/BerriAI/litellm/issues/29518) — при отдаче `/v1/messages`
   поверх OpenAI-совместимого бэкенда `reasoning_content` **молча теряется**: ни блока `thinking`,
   ни событий `thinking_delta` в SSE; страдают именно стриминговые клиенты.
3. [hermes-agent#16748](https://github.com/NousResearch/hermes-agent/issues/16748) — обратная
   сторона у DeepSeek: его Anthropic-совместимый API **срезает** блоки thinking из истории, но при
   включённом reasoning **требует** их в следующем запросе — многоходовый разговор падает с HTTP 400.
4. Z.AI: расход квоты 3× в пик и 2× ночью (совпадает с тем, что мы видели в теме про цены).

**Сверка с нашим кодом:** наш разбор Anthropic-стрима читает **только** `delta.text`
(`LlmClient.kt:386`) — `thinking_delta` игнорируется. То есть рассуждающая модель на совместимом
эндпоинте у нас «молчит» ровно столько, сколько думает, и это выглядит как зависание. Квирки MiniMax
у нас уже описаны (`NO_TOP_K`, `NO_STOP`).

**→ VibeIDEA:**
- показывать `thinking_delta` в анthropic-стриме наравне с текстом (у нас уже есть поверхность для
  рассуждений в других протоколах) — **фича (малая)**, и она же убирает «зависание»;
- квирк «этот эндпоинт требует блоки thinking в истории» — **не брать пока**: у нас прямой чат не
  ведёт многоходовые reasoning-истории с блоками, а описывать чужую ошибку в каталоге без
  собственного пути данных — то же, от чего мы отказались вчера с квирком `name`;
- адреса эндпоинтов — **сид**: сверить `.vibe/providers/*.jsonc` с таблицей.
