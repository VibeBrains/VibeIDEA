## Сделано сейчас: файлы инструкций, которые проект не добавлял (пункт 12)

`AGENTS.md` — не документация, а канал команд: агент, открывший файл, его выполняет. Файл приезжает без коммита — в распакованном архиве,
папке синхронизации, случайной загрузке; вредоносный `AGENTS.md` из «Загрузок» подхватывал Codex. Наш санитайзер контекста ловит инъекцию
в тексте, но не отвечает на вопрос «а кто этот файл сюда положил».

- `context/InstructionOrigin.kt` — чистая часть: имена (`AGENTS.md`, `CLAUDE.md`), каталоги выше корня, разбор `git ls-files -z`, что считать
  предупреждением (файл выше корня или файл не под git), обход проекта, который не заходит в `node_modules`/`build`/`.git`.
- `context/ProjectFiles.kt` — появился `skips()`: обход пропускает каталог по его собственному пути. Старое правило знало только «внутри
  каталога» (`startsWith("build/")`), поэтому каталог `build` в момент входа не считался пропускаемым.
- `doctor/VibeDoctorAction.kt` — строка «Файлы инструкций»: WARN с первым найденным файлом и числом таких файлов, OK — когда всё внутри корня
  и под git, «файлов нет» называется отдельно. `git` зовётся argv-списком с литеральными путями (`:(literal)`) и потолком 3 с; git не ответил —
  файл не объявляется неотслеживаемым (ложное обвинение учит игнорировать строку).
- Строки — `doctor.line.instructionFiles`, `doctor.detail.instructionFiles{None,Ok,Warn}`, `doctor.instruction.{above,untracked}` в `base.json` и `en.json`.
- Тесты — `InstructionOriginTest` (9): границы обхода выше корня, разбор NUL-вывода git, «git молчит ≠ untracked», приоритет «выше корня»,
  обход с пропуском деревьев зависимостей, пропуск каталога по его собственному пути.

### `providers/kimi.jsonc` (новый файл — значит, запись в манифест)

```jsonc
{ "version": 1, "providers": [ {
  "id": "kimi", "name": "Kimi (Moonshot)", "protocol": "anthropic",
  "baseURL": "https://api.kimi.com/coding/", "apiKeyEnv": "KIMI_API_KEY",
  "docsUrl": "https://www.kimi.com/code/docs/en/kimi-code/whats-new.html",
  "models": { "fetch": true, "static": [
    { "id": "kimi-k3.1-pro", "name": "Kimi K3.1 Pro", "default": true, "contextWindow": 262144,
      "cost": { "input": 2, "output": 10 }, "costNote": "kimi.ai/blog/kimi-k3-1-pro, 24.10.2026" },
    { "id": "kimi-k2.7-code", "name": "Kimi K2.7 Code", "cost": { "input": 0.95, "output": 4.00 } }
  ] } } ] }
```

Оговорки: id в источниках расходится (`k3.1-pro` против `kimi-for-coding`) — сверить с ответом `/v1/models`; `contextWindow` 256K, а не 1M:
1M контекста и Highspeed доступны с тарифа Pro/Allegretto, а наш пресет описывает Moderato. Квирк `reasoning_content` для `kimi-k3…` уже в коде,
`kimi-k2.7-code` покрыт тем же шаблоном.

### `providers/openai.jsonc` — модель GPT-6.1 Terra, только после появления кодинг-замеров

### `agents/mcode.jsonc` (или запись в `.vibe/agents.json` сида)

```jsonc
{ "agent_servers": { "MiniMax Code": { "command": "mcode", "args": ["acp"], "env": { "MINIMAX_API_KEY": "" } } } }
```

Пустое значение в `env` — способ снять переменную, которая иначе молча побеждает подписку (тот же приём, что для `ANTHROPIC_API_KEY`, см.
`acpAgentsSpec.md`). Запись имеет смысл только после проверки, что `mcode acp` действительно говорит по ACP: в README проекта режим назван,
но протокол в сводке описан по документации MiniMax, а не по живому рукопожатию.

### `rules/no-invented-api.mdc` (пункт 2)

```markdown
---
description: Сверяйся с источником, а не с памятью
alwaysApply: true
---

Перед использованием API, флага, поля конфига или имени метода — найди его в проекте, в документации или в `--help`.
Не выдумывай сигнатуру и не достраивай её по аналогии: если источника нет, скажи «не нашёл» и назови, где искал.
Фактическое утверждение о чужом коде помечай источником (файл:строка, адрес документации).
```

Числа из сводки (56 % верных ответов и 93 % галлюцинаций у M3.1 Flash на AA-Omniscience) — довод за правило, а не его содержание;
в правило они не переносятся: цифра протухает, а требование «назови источник» — нет.
