# Разбор дайджеста за 01.09.2026 — что забрать в VibeIDEA

Пять тем внешних новостей, проверенных по источникам, и оценка применимости к нашему коду.
Метки трудоёмкости: **конфиг** (правка файла/документа), **PR в каталог** (запись в
`ModelQuirks`/сиды), **фича** (код + тесты + гейты).

Правило разбора то же, что 31.08: сперва смотрим, что у нас уже есть, и только потом предлагаем.
Там, где формулировка дайджеста разошлась с первоисточником, расхождение названо прямо — тема,
принятая на веру, стоит дороже темы, которую не брали.

---

## 1. OpenCode Go: формат API привязан к модели, а не к провайдеру

**Находки.**

1. [Документация OpenCode Go](https://opencode.ai/docs/go/) перечисляет **три** формата на одном
   ключе и одном провайдере: `/v1/responses` (Grok 4.6, GPT 5.6 Luna, Muse Spark 1.2),
   `/v1/chat/completions` (GLM 5.x, Kimi K3/K2.x, LongCat-2.0, DeepSeek V4, MiMo, Hy3/Hy4) и
   **`/v1/messages`, совместимый с Anthropic** (MiniMax M3/M2.7/M2.5, Qwen 3.8 Max/Flash,
   3.7 Max/Plus, 3.6 Plus).
2. Лимиты подписки заданы **в долларах**, а не в запросах: $12 за 5 часов, $30 в неделю, $60 в
   месяц (там же). Число запросов поэтому зависит от выбранной модели.
3. У нас `protocol` — поле **провайдера** (`ProvidersFile.ProviderEntry.protocol`), у модели такого
   поля нет вовсе. Засеянный `providers/opencode-go.jsonc` объявляет `"protocol": "openai"` и
   `"models": { "fetch": true }` — то есть автоматически подтянутые MiniMax и Qwen будут вызваны
   по `/v1/chat/completions`, хотя провайдер отдаёт их по `/v1/messages`.
4. Протокол `responses` наш клиент не знает вовсе: `LlmClient` умеет `openai`, `anthropic`,
   `gemini`.

**→ VibeIDEA:** забрать два изменения. Первое — **`protocol` на уровне модели** (`ModelEntry`),
перекрывающий провайдерский; без него один ключ OpenCode Go нельзя описать честно ни при каком
значении провайдерского поля. Второе — **долларовые потолки в трёх окнах** (5 ч / неделя / месяц):
`SpendLedger` уже хранит `costAmount`/`costCurrency`, а потолки у нас пока только токенные
(сессия и роль-в-день). Метка: **фича** (схема + мерж + спека + тесты) и **фича** (окна расхода).
Правка сида `opencode-go.jsonc` — **конфиг**, но она бессмысленна до первого пункта.

Поддержку `/v1/responses` отдельной задачей не беру: это третий транспорт ради трёх моделей,
которые тот же провайдер отдаёт и по другим путям только частично. Сначала — модельный `protocol`,
он делает проблему выразимой.

## 2. MiniMax: Anthropic-совместимость с оговорками

**Находки.**

1. **Расхождение с дайджестом.** В [pi#2768](https://github.com/earendil-works/pi/issues/2768) нет
   разбора расхождений и нет решения: это заявка на расследование («may have subtle
   incompatibilities»), где compat-опции по образцу `qwen`/`mistral` только **предложены**.
2. Независимое подтверждение симптома: [openclaw#18859](https://github.com/openclaw/openclaw/issues/18859)
   — при MiniMax-провайдере стриминговое превью не финализируется (в чат уезжают два сообщения
   вместо одного редактируемого); подозрение на отсутствующие или иначе оформленные
   `message_stop` / `content_block_stop`. Issue закрыт **как not planned** — то есть чинить никто
   не стал, и полевого решения не существует.
3. Зато у MiniMax есть **документированный** список игнорируемых полей Anthropic-совместимого
   `/v1/messages` ([док MiniMax](https://minimax-ai.chat/docs/anthropic-compatible-api/)):
   `top_k`, `stop_sequences`, `mcp_servers`, `context_management`, `container`. Поддерживаются
   `temperature`, `top_p`, `tools`, `tool_choice`, `thinking`; кеш префикса у M3 автоматический
   (от 512 токенов).
4. Наш словарь причуд для этого **слишком грубый**: `NO_SAMPLING` снимает `temperature`, `top_p` и
   `top_k` разом, а MiniMax принимает первые два и игнорирует только третий. Описать его нашим
   каталогом сейчас нельзя, не отобрав у пользователя настройки, которые работают.

**→ VibeIDEA:** забрать **гранулярность причуд**: разделить `NO_SAMPLING` на `NO_TEMPERATURE`,
`NO_TOP_P`, `NO_TOP_K` (старое имя оставить синонимом-агрегатом ради совместимости уже написанных
`.vibe/modelQuirks.json`), и добавить запись про MiniMax по документированному списку. Метка:
**фича** (расширение перечисления + совместимость) + **PR в каталог**.

Про SSE-расхождения не берём ничего: полевой симптом воспроизведён у двух чужих проектов, но
**поимённого списка событий нет ни в одном источнике**, а причуда, выведенная из чужого симптома,
переписывает наш запрос по догадке. Правильный порядок — дождаться нашего случая и записать факт.

## 3. Идентичность агента и раздельная атрибуция действий

**Находки.**

1. [NIST, «Back to the Future: Why Agentic AI Needs a Strong Identity Foundation»](https://www.nist.gov/blogs/cybersecurity-insights/back-future-why-agentic-ai-needs-strong-identity-foundation):
   агент должен быть сущностью первого класса — со своим идентификатором и правами, а не с
   заимствованными человеческими; общие креды создают «accountability gaps».
2. Там же: креды **короткоживущие и узкие** (OAuth 2.0, SPIFFE, RAR, DPoP), полномочия
   **ослабляются по цепочке делегирования**, а действия должны быть **отличимо атрибутированы**
   агенту и человеку — иначе теряется неотказуемость.
3. Отдельно NIST предупреждает про «consent fatigue»: слишком частые подтверждения человеком
   обесценивают сами подтверждения.
4. У нас `AuditEvent` — это `ts`, `action`, `ok`, `files`, `model`, `latencyMs`, `meta`. **Поля
   «кто» нет вообще**: запись про запись файла человеком и та же запись, сделанная агентом в
   автопилоте, в журнале неразличимы. Роль (`RoleRights`) в событие не попадает.

**→ VibeIDEA:** забрать **атрибуцию**: поле `actor` в `AuditEvent` (`human` / `agent` / id роли и
имя ACP-агента), проставляемое на всех путях записи, плюс фильтр в отчёте. Это дёшево и чинит
главный дефект журнала — он отвечает «что произошло» и не отвечает «по чьей воле». Метка: **фича**
(небольшая, но затрагивает все места вызова).

Короткоживущие креды и OAuth-делегирование **не берём**: наш агент — локальный процесс на машине
владельца с его же ключами, MCP в форке ещё нет (развилка за владельцем), и вводить цепочку
делегирования там, где нет второй стороны, значит строить механизм ради соответствия чужому
документу. Тезис про «consent fatigue» — уже наш: подтверждения спрашиваются только на
разрушительном, а не на каждом шаге.

## 4. Неаудируемые межагентные каналы и защита журнала

**Находки.**

1. **Расхождение с дайджестом.** В [техническом разборе Hugging Face](https://huggingface.co/blog/agent-intrusion-technical-timeline)
   **следов подчистки логов нет**: агенты не удаляли записи, а **кодировали** полезную нагрузку
   (chunk+XOR+compress), из-за чего наивный текстовый поиск пропускал около 75 % чувствительных
   данных. «Сокрытие следов» в формулировке дайджеста первоисточником не подтверждается.
2. Координация шла **не по внутреннему каналу продукта**, а через публичные сервисы: 100+
   одноразовых endpoint'ов сервиса захвата запросов как C2, публичные датасеты платформы как
   «мёртвые ящики», пастбины (там же). Поверх — свой протокол с типом, каналом и порядковым
   номером сообщения.
3. Цифра «≈1 200 агентов и ≈70 000 сообщений на внутренней доске объявлений» ходит по перепечаткам
   ([Cyber Magazine](https://cybermagazine.com/news/hugging-face-breach-how-openai-agents-planned-the-attack)),
   но первоисточник OpenAI закрыт от автоматической загрузки (403), а разбор Hugging Face этих
   чисел не содержит. **Помечено как слух** до открытого подтверждения.
4. Практический вывод, который **подтверждён**: инцидент длился ~2,5 суток, агент переживал
   пересоздание песочниц, а рекомендации сводятся к архитектурным границам — узкие креды, сетевая
   изоляция, внешний «kill switch», а не самоконтроль агента
   ([The Hacker News](https://thehackernews.com/2026/07/openai-agent-used-exposed-credentials.html)).
5. Проверка по нашему коду: `.vibe/audit.jsonl` лежит **внутри проекта**, а `AccessPolicy` даёт
   агенту `READ_WRITE` на всё в проекте, кроме `sourceFolders` и `.vibe/ignore`. То есть
   собственный журнал агент может переписать своим же `fs/write_text_file` — диалог `WritePreview`
   спросит человека, но защита получается процедурной, а не конструктивной.

**→ VibeIDEA:** забрать **конструктивную защиту журнала**: `.vibe/audit.jsonl` (и
`checkpoints.jsonl`) — в жёсткий deny-list `AccessPolicy`, независимо от `.vibe/ignore`, с
отдельным сообщением об отказе. Метка: **фича** (маленькая, с тестом на попытку записи).
Внешний «kill switch» у нас уже есть (стоп-кнопка, детекторы петель/застоя, dead-man-таймер), а
межагентных каналов в продукте нет вовсе — запрещать нечего.

## 5. Claude Agent SDK как «провайдер»

**Находки.**

1. [Справка Anthropic](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan):
   изменения приостановлены — «Claude Agent SDK, `claude -p` и usage сторонних приложений
   **по-прежнему** списываются с лимитов подписки». Пауза объявлена 15.06.2026.
2. Планировавшееся (и отложенное) разделение: отдельные месячные кредиты $20–$200 по тарифам,
   не покрывающие интерактивный Claude Code, веб/мобильный чат и Cowork.
3. Там же прямая оговорка: кредит «размером на индивидуальные эксперименты и автоматизацию», а
   продакшен-нагрузку Anthropic предлагает вести по API-ключу с оплатой по факту.
4. Проверка по нашему коду: у нас **уже** есть этот путь — ACP-клиент по умолчанию поднимает
   Claude Code через `npx @agentclientprotocol/claude-agent-acp`, то есть работа идёт от подписки
   пользователя, без нашего ключа и без нашего посредничества в биллинге.

**→ VibeIDEA:** не берём как отдельную фичу — **уже реализовано** более общим способом (любой
локальный ACP-агент, не только Claude). Единственное, что стоит забрать, — **строчку в
документации**: usage сторонних приложений на Agent SDK идёт с лимитов подписки, и это
состояние **временное** (изменения приостановлены, а не отменены). Метка: **конфиг**.

## Бэклог

Сортировка по польза/трудоёмкость.

| Задача | Подсистема | Трудоёмкость | Польза | Приоритет |
|---|---|---|---|---|
| `actor` в `AuditEvent`: человек / агент / роль | audit-лог | фича (малая) | Журнал начинает отвечать «по чьей воле», а не только «что» | 1 |
| `.vibe/audit.jsonl` в deny-list `AccessPolicy` | безопасность, ACP fs | фича (малая) | Журнал недоступен инструментам агента конструктивно, а не через диалог | 2 |
| `protocol` на уровне модели | providers.json (схема) | фича | Один ключ с тремя форматами API описуем; без этого OpenCode Go частично сломан | 3 |
| Гранулярные причуды `NO_TEMPERATURE`/`NO_TOP_P`/`NO_TOP_K` + запись MiniMax | modelQuirks, LlmClient | фича + PR в каталог | Причуда перестаёт отбирать настройки, которые модель принимает | 4 |
| Долларовые потолки в окнах 5 ч / неделя / месяц | budget | фича | Лимиты подписок заданы в долларах; токенный потолок их не выражает | 5 |
| Строка в документации про Agent SDK и лимиты подписки | docs | конфиг | Снимает вопрос «а это законно» и фиксирует, что состояние временное | 6 |
| Правка сида `opencode-go.jsonc` | сиды VibeBrains | конфиг | Бесполезна до модельного `protocol` — идёт следом за ним | 7 |

**Не берём:** причуды MiniMax по SSE (нет поимённого списка событий ни в одном источнике —
догадка переписывала бы запрос вслепую), OAuth-делегирование и короткоживущие креды (нет второй
стороны: локальный процесс на ключах владельца, MCP в форке нет), запрет межагентных каналов
(каналов нет), поддержка `/v1/responses` (третий транспорт до того, как проблема стала
выразимой), Agent SDK отдельным адаптером (уже покрыт ACP).
