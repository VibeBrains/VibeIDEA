## 1. Модель Opus 5.5 и версия агента в кэше npx

Находки:

- Руководство Anthropic по миграции: мышление не выключается (`disabled` и бюджет — 400), единственное управление — `effort` от `low` до `max`, умолчание `medium`.
  Там же: `tool_choice` `any` и `tool` дают 400; блоки мышления — 400 после правки `system` или `tools` у аккаунтов, созданных с 31.08.2026;
  на `xhigh` и `max` советуют `max_tokens` от 64K ([migration guide](https://platform.claude.com/docs/en/models/opus-5-5/migration-guide)).
- Журнал изменений Claude Code 2.1.280: «Added Claude Opus 5.5 (claude-opus-5-5), now the default Opus model» ([ClaudeCodeLog](https://x.com/ClaudeCodeLog/status/2102442227033116867), [DevelopersIO](https://dev.classmethod.jp/en/articles/20260923-cc-updates-v2-1-280/)).
- Реестр npm, 24.09: адаптер `@agentclientprotocol/claude-agent-acp` 0.81.1 точно закрепляет `@anthropic-ai/claude-agent-sdk` 0.3.280, а в SDK 0.3.280 зашит Claude Code 2.1.280 (поле `claudeCodeVersion`).
  Цепочка: адаптер 0.79.0 → SDK 0.3.274, 0.80.0 → 0.3.278, 0.81.0 → 0.3.280. Минимальный адаптер для Opus 5.5 — 0.81.0.
- На машине владельца `~/.npm/_npx/…/claude-agent-acp` — 0.79.0 от 22.09, внутри Claude Code 2.1.274.
  Наша запись агента зовёт `npx @agentclientprotocol/claude-agent-acp` без версии.
- Опыт: копия этого кэша в отдельном каталоге (`npm_config_cache`), запуск той же командой — `npx` сообщил
  «The following package was not found and will be installed: …@0.81.2» и переустановил адаптер в тот же каталог.
  Кэш без версии сверяется с реестром при каждом запуске; 0.79.0 у владельца — потому что агент не запускался с 22.09.
- Сводка дайджеста ([aicatchup](https://aicatchup.com/news/claude-opus-5-5)) называет те же правила и формулирует 2.1.280 как требование; первоисточник — только журнал изменений.

Что у нас уже есть:

- Адаптивное мышление, явный `effort`, `display: "summarized"`, снятая выборка, отказ с категорией и потолок вывода из каталога — пункты 1–10 бэклога 23.09.
- `tool_choice` мы не посылаем нигде — «не берём» записано в разборе 02.09.
- Append-only закрыт решением №105: к Claude уходят только блоки текущего хода, чей запрос был с тем же `system` и тем же набором инструментов (сравнивается хэш).
- Computer use на проводе Anthropic у нас нет.

→ VibeIDEA:

- Строку доктора не делаем: она ловила бы только состояние между запусками, а оно лечится первым же запуском онлайн.
  Без сети Claude Code не работает всё равно.
- `max` на верхнем положении — умолчание не меняем: Anthropic советует `xhigh` для задач дольше 30 минут с бюджетом
  в миллионы токенов, а `max` — «без ограничений по расходу»; середина ползунка уже даёт умолчание вендора `medium`.
  Как открыть `xhigh` и `max` объявлением уровней — написано в закомментированной записи Opus 5.5 в `anthropic.jsonc`.
  Если объявить в `anthropic.jsonc` `"reasoning": {"effort": ["low", "medium", "high", "xhigh", "max"]}`, ползунок станет «low / high / max»: середина уйдёт с умолчания вендора `medium` на `high`.
  Так уже устроены GPT-6 Sol и Luna.

## 3. MiMo V2.6 Pro через OpenRouter

Находки:

- Xiaomi выпустила V2.6 Pro (1.02T параметров, 42B активных) и Flash (310B, 15B): окно 1M, выход до 128K, MIT, веса на Hugging Face.
  Цены вендора: Pro $0.435 / $0.87, Flash $0.14 / $0.28 ([VentureBeat](https://venturebeat.com/technology/better-than-deepseek-xiaomis-mimo-v2-6-pro-debuts-as-the-top-open-weights-model-in-the-world-alongside-cheaper-v2-6-flash)).
- OpenRouter: слаг `xiaomi/mimo-v2.6-pro`, параметры `reasoning`, `tools`, `tool_choice` и выборка ([OpenRouter](https://openrouter.ai/xiaomi/mimo-v2.6-pro)).
- OpenRouter отдаёт рассуждение полями `reasoning` и `reasoning_details`; `reasoning_content` — синоним, «functions identically to `reasoning`», и его принимают обратно в сообщении ассистента.
  Возвращать рассуждение советуют именно в цикле инструментов ([reasoning tokens](https://openrouter.ai/docs/use-cases/reasoning-tokens)).
- Управление рассуждением у OpenRouter — только объект `reasoning`: `effort` от `none` до `max`, `enabled`, `max_tokens`, `exclude`.
  Выключают его `effort: "none"` или `enabled: false`; у моделей с обязательным рассуждением `none` отвергается.
  Верхнеуровневый `reasoning_effort` в документации не упомянут ([reasoning tokens](https://openrouter.ai/docs/use-cases/reasoning-tokens)).

Что у нас уже есть:

- Эхо рассуждения у MiMo работает и на OpenRouter. Причуды сравниваются с id без префикса роутера (`ModelQuirks.normalize`: `xiaomi/mimo-v2.6-pro` → `mimo-v2.6-pro`).
  Поэтому `ECHO_REASONING`, `NO_SAMPLING` и `NO_REASONING_LEVELS` применяются.
  Возвращаем `reasoning_content`, который OpenRouter понимает как синоним; читаем оба поля, `reasoning_content` и `reasoning` (`ReasoningStream`).
  Проверено чтением кода и документации, живым ключом нет.

→ VibeIDEA:

- Новой причуды для MiMo не нужно.
- Дыра шире MiMo — диалект рассуждения OpenRouter, фича (малая).
  На проводе OpenAI мы шлём `reasoning_effort`, а «выключено» берём из записи модели. У модели из каталога OpenRouter такой записи нет, и «выключено» не шлёт ничего.
  MiMo по умолчанию думает — значит, «выключено» на OpenRouter у неё не выключает.
  Принимает ли OpenRouter `reasoning_effort` молча, не проверено: ключа нет.
  Правильное место признака — сид `openrouter.jsonc` (поле диалекта у провайдера), тогда он общий с VibeIDE.

## 4. Junie Local

Находки:

- JetBrains: Junie Local — `Qwen3.8-3.6-27B-blend`, слияние Qwen3.8-27B и Qwen3.6-27B поровну.
  Основная поддержка — Apple M5; Windows — экспериментально, RTX Ampere и новее с 24 ГБ видеопамяти; контекст проверяли от 16K до 128K.
  Ставится командой `/local` в Junie ([блог JetBrains](https://blog.jetbrains.com/junie/2026/09/smarter-local-al/)).
- Карточка модели: Apache-2.0, форматы BF16, GGUF, MLX 4-bit; примеры запуска — vLLM, SGLang, Docker Model Runner; шаблон чата от Qwen3.8-27B ([Hugging Face](https://huggingface.co/JetBrains/Qwen3.8-3.6-27B-blend)).
- В библиотеке Ollama тега нет, но JetBrains публикует GGUF сам: `JetBrains/Qwen3.8-3.6-27B-blend-GGUF`, файлы Q4_K_M
  (16.8 ГБ), IQ3_S (12.6 ГБ), Q5_K_M (19.5 ГБ); в README — `ollama run hf.co/JetBrains/Qwen3.8-3.6-27B-blend-GGUF:Q4_K_M`
  ([GGUF](https://huggingface.co/JetBrains/Qwen3.8-3.6-27B-blend-GGUF)).

→ VibeIDEA: дефолтом — нет.
Модель в 27B с требованием 24 ГБ видеопамяти не запустится у большинства; провайдер Ollama в наборе и так читает список моделей сервера, а `LocalProbe` находит поставленное.
Отдельный провайдер не нужен: скачанная командой Ollama модель появится в списке сама. В `ollama.jsonc` — пример с командой,
размерами, лицензией и пометкой, что вызовы инструментов через Ollama не проверены.
Гейт брендинга набор не читает (`/vibeDefaults/` исключён), имя `JetBrains/…` в сиде его не уронит.
