# Паритет с PhpStorm: что можно включить, что нельзя, что писать самим

**Дата исследования:** 03.09.2026 · **Метод:** 4 параллельных разведчика + адверсариальная проверка
каждого утверждения по первоисточнику (Marketplace API, GitHub API, help.jetbrains.com, дерево
репозитория). Собрано 129 утверждений, проверено 61, из них опровергнуто 2. **68 утверждений
проверить не успели** — исследование остановилось на исчерпании лимита; такие помечены ниже как
«не проверено».

## Короткий ответ

«Подключить сразу всё, что есть в PhpStorm» нельзя: **половина PhpStorm — проприетарные плагины
JetBrains, исходников которых нет в открытом репозитории.** Их нельзя ни собрать, ни вбандлить —
не по нашему решению, а по их лицензии. Что реально:

- **три плагина добавлены сразу** (лежали в нашем же дереве невключёнными);
- **два больших направления** — БД и HTTP-клиент — требуют решения владельца: чужой плагин весом
  76 МБ либо свой код;
- **остальное** либо уже закрыто, либо проприетарно.

## Уже сделано этим разбором

| Плагин | Что даёт | Почему сразу |
|---|---|---|
| `intellij.dotenv` | `.env`: подсветка, автодополнение ключей, переход к использованию | MIT, лежит в `plugins/env-files-support`; JetBrains бандлит его в PhpStorm с 2024.3.2. В каждом PHP-проекте |
| `intellij.xpath` | XPath/XSLT — поиск по XML, отладка преобразований | Apache 2.0, раскладка уже написана в `CommunityRepositoryModules.kt:84` |
| `intellij.jsonpath` | JSONPath-выражения | Apache 2.0, в дереве; на нём же держатся переменные HTTP-клиента |

Модуль без явной раскладки получает `PluginLayout.pluginAuto`
(`DistributionJARsBuilder.kt:554`), поэтому цена каждого — одна строка в `bundledPluginModules`.
Присутствие в дистрибутиве проверяет гейт `checkVibeDist.sh`.

## Работа с БД — развилка для владельца

**Database Tools and SQL (то, что стоит в PhpStorm) взять нельзя.** Плагин проприетарный:
`licenseUrl` — JetBrains Toolbox Subscription Agreement, `sourceCodeUrl` пуст, продуктовый код
`PDB`, триал 30 дней ([Marketplace API 10925](https://plugins.jetbrains.com/api/plugins/10925)).
Исходников в дереве нет: каталоги с `database`/`sql` в имени — это `platform/sqlite` (библиотека
для внутренних нужд платформы) и `android/transport-database`; ни один `plugin.xml` не объявляет
`com.intellij.database`.

Из открытого в дереве есть **`grid/`** — табличный компонент (`intellij.grid.core.plugin`, уже в
бандле). Это движок таблиц, а не БД-инструмент: ни JDBC-консоли, ни источников данных.

Дальше два пути:

**А. Вбандлить Database Navigator (DBN).** С начала 2025 — продукт Oracle, лицензия Apache-2.0,
исходники [oracle/database-navigator](https://github.com/oracle/database-navigator). Даёт браузер
объектов, SQL/PL-SQL редактор, редактор данных, выполнение скриптов. Родные СУБД: Oracle, MySQL,
PostgreSQL, SQLite; остальное — «any JDBC-compatible (experimental)».

- **Цена — вес:** 76,6 МБ архивом, ~86,5 МБ распакованным (для сравнения LSP4IJ — 4,5 МБ). Половина
  — ораклов стек (OCI SDK, langchain4j для DB Assistant, ojdbc 19,3 МБ), бесполезный
  PHP/TS-разработчику и неотделимый без пересборки.
- **Совместимость:** выпущенная 4.0.0.6 объявляет `until-build="262.*"`, а мы на 263. Для
  **вшитого** плагина это не помеха: `PluginInitializationContext.validatePluginIsCompatible`
  первой строкой возвращает `null` для `isBundled`, а всё из `plugin-classpath.txt` грузится как
  bundled. **Вывод сделан по коду платформы, на живой сборке не прогонялся** — это первое, что
  нужно проверить, если путь выбран.
- **Механизм включения** — тот же, что у LSP4IJ: пин версии и sha256 в `pins.env` → `download.sh`
  → `getAdditionalPluginPaths` → строка в `allLibraryLicenses` → проверка гейтом. Отличие: у DBN
  нет GitHub-релизов, качать пришлось бы с CDN Marketplace.

**Б. Свой минимальный БД-инструмент** поверх открытого `grid/`: подключение по JDBC, дерево
объектов, консоль запросов, таблица результата. Дороже по работе, но без 76 МБ чужого веса и без
ораклового меню.

**Моя рекомендация — А, но не сейчас:** DBN закрывает вопрос за день работы, и пока не проверено,
что вшитый плагин с чужим `until-build` действительно грузится, обсуждать вариант Б рано. Проверка
— полчаса.

## HTTP-клиент («как Postman») — своими руками, и это реально

**Плагин JetBrains недоступен даже теоретически:** `com.jetbrains.restClient` проприетарен, а в
списке совместимости последней версии `IDEA_COMMUNITY` **отсутствует вовсе** — только PRO-продукты
([API 13121](https://plugins.jetbrains.com/api/plugins/13121)). Готового открытого аналога
«поставить и получить HTTP Client» на Marketplace нет.

Зато формат открыт, и всё нужное для своего клиента уже есть:

- **спека формата** — [JetBrains/http-request-in-editor-spec](https://github.com/JetBrains/http-request-in-editor-spec),
  CC-BY-4.0: строка запроса, заголовки, тело, multipart, переменные `{{}}`, разделитель `###`;
- **три открытых JVM-парсера** как референс: Explyt (`Http.bnf`, Apache-2.0), restcli (MIT),
  httpx (Apache-2.0);
- **транспорт и просмотр ответа** — в платформе: `java.net.http`, Apache HttpClient как
  `@lib//:http-client`, JSON-плагин уже в бандле.

Объём: тип файла + язык на Grammar-Kit + гаттер «выполнить» + вкладка ответа + `http-client.env.json`.
Всё в своём `vibe`-плагине, без патчей платформы. **Не покроем без новых зависимостей:**
JS-скрипты обработки ответа, мастер OAuth 2.0, gRPC/WebSocket/GraphQL.

## Что уже есть и трогать не надо

Terminal, Git/GitHub/GitLab, Markdown с Mermaid, Emmet/HTML/CSS, TextMate-подсветка, задачи и
трекеры (добавлены сегодня), TypeScript/JS через LSP, отладка PHP и TS, Composer-схема
`composer.json` (через каталог SchemaStore в JSON-плагине — автодополнение и валидация без нашего
кода). Инфраструктура WSL в платформе открыта (`platform/wsl-impl`, `platform/eel`) — *попадают ли
ijent-бинарники в наш дистрибутив, не проверено*.

## Чего не будет: проприетарное

Docker, Vue.js, Tailwind, Angular, Laravel Idea, Symfony Plugin, Diagrams (UML), Deployment
(FTP/SFTP/WebDAV), Remote Development/Gateway, Code With Me, Kubernetes, File Watchers, Vagrant,
Space, AI Assistant, Pest-плагин, Behat/Codeception/Drupal/WordPress-интеграции, Php Inspections
(EA Extended). Все — плагины JetBrains или закрытые сторонние; исходников в открытом репозитории
нет.

Полуоткрытые заменители существуют, но паритета не дают: **SFTP-деплой** — `sourcesync` (MIT), одна
сторона, без обзора удалённого хоста и diff, 15 месяцев без коммитов; **SQLite** —
SimpleSqliteBrowser (Apache-2.0, 15,8 МБ), нишевый.

## Куда идти дальше по PHP

- **PHPUnit/Pest** — открытый путь есть и он аккуратный: у обоих есть `--teamcity`, а в дереве
  лежит открытый парсер этого формата (`platform/smRunner`), дающий дерево тестов, статистику и
  перезапуск без PHP-PSI. Своя конфигурация запуска — наш код. Ограничение: `--parallel` у Pest
  с teamcity-выводом не дружит.
- **Laravel** — появился первый официальный сервер [laravel/lsp](https://github.com/laravel/lsp)
  (MIT, версия 0.0.x, ранняя). Рассчитан на работу рядом с общим PHP-сервером, а у нас по решению
  «один вход на `*.php`»; совместимость двух серверов на одном файле в LSP4IJ не проверялась.
- **Symfony/Twig** — расширение Symfony есть в ядре Phpactor (объём не исследован), twiggy умеет
  Symfony-осведомлённое дополнение через `bin/console`.
- **Composer UI** — установка пакетов, поиск по Packagist, запуск скриптов: только свой код.

## Опровергнутое проверкой (чтобы не всплыло снова)

1. «DBN опционально зависит от `org.jetbrains.idea.maven`» — **неверно**: в `plugin.xml` семь
   зависимостей, maven среди них нет; утверждение было выдумано разведчиком.
2. «Исходников выпущенных DBN 4.0.0.x на GitHub нет» — **неверно**: ветка
   `releases/DBN-4.0.0.0` содержит `version = "4.0.0.6"`, совпадающую с Marketplace.

Оба случая — про то, зачем нужна проверка: правдоподобная деталь со ссылкой на настоящий файл
может оказаться придуманной.
