## Что это

**VibeIDEA — открытая IDE PhpStorm-класса со встроенным агентом.**
Форк [intellij-community](https://github.com/JetBrains/intellij-community): платформа JetBrains, языки через LSP, вся агентская обвязка своя.

Этот выпуск перестаёт обрывать долго думающую модель на первом слове и возвращает вопрос при удалении внутри проекта.
Ещё в нём хук может считать собственную поломку запретом, а доктор называет двойной источник ключа.
Путь вне проекта в аргументе команды стал поводом спросить, инструменты больше не уезжают к провайдеру дважды, а HDR-видео разбирается в цвете.
Ставится поверх 1.1.1.

---

## Долго думающая модель не обрывается на первом слове

**Ожидание первого фрагмента считается по запросу и модели, а не одним числом на все случаи.**

- Раньше сторож рвал запрос на 30-й секунде, повтор начинался с нуля, и после трёх попыток человек получал «Модель не ответила» о модели, которая работала всё это время.
- Нижний порог задаёт настройка «Первые секунды ответа»: по умолчанию и минимум 30 с, Settings → Tools → VibeIDEA → Агент → «Сторож молчания».
- Длинная переписка добавляет +10 с на каждые начатые 50k токенов запроса сверх 50k.
- Самая медленная из последних десяти задержек первого фрагмента этой модели поднимает порог до 1,5× своего значения.
- Каждый повтор поднимает нижний порог ещё на шаг: 30 → 60 → 90 с, сверху — жёсткий потолок 300 с.
- Отказ называет реальное время ожидания, а не константу из настройки.
- Между фрагментами терпение прежнее: молчащий посреди ответа поток лечится сторожем молчания.

## Агент спрашивает о необратимом

**Удаление внутри проекта снова вопрос, потому что чекпоинт его не всегда возвращает.**

- Снимок хода идёт через git, поэтому файлы из `.gitignore`, `node_modules`, выход сборки и созданное в том же ходе он не вернёт.
- Папка без git снимка не имеет вовсе, а у внешнего ACP-агента снимка всей папки нет.
- Молча пропускается только удаление внутри временной папки: `rm .env` в проекте на автопилоте спрашивается.
- Ход, чья последняя непустая строка кончается «?», останавливает автопилот: на «Приступать к реализации?» отвечает человек.
- Одобрение в карточке разрешения запоминается на этот ход и снимает повторный вопрос о той же строке; расходуется оно одним запуском.

**Режимы прав переименованы и говорят, что делают.**

- «Автопилот» стал «Авто»: всё без вопросов, кроме необратимого и выходящего за проект.
- «Правки» стали «Принимать правки»: правки файлов проекта без вопроса, команды оболочки и MCP — с вопросом.
- «Вручную» и «План» не изменились.
- Описание режима несёт вся строка пункта меню, а «?» только помечает, что оно есть.

## Команда, которая трогает не то

**Путь в аргументе команды проверяется так же, как текст самой команды.**

- Разбирается путь у любой программы: `--opt=/path`, `-o/path`, `~`, `$HOME`, `..`, буквы дисков Windows и UNC.
- На macOS и Windows сравнение идёт без учёта регистра: `/VolumES` и `/Volumes` — один и тот же корень.
- Корень тома, домашняя папка, корень диска, сетевой ресурс и корень проекта всегда вопрос.
- Неразбираемая переменная вроде `$ARCHIVE` тоже вопрос: неизвестное не считается безопасным.
- Читающие команды (`cat`, `grep`, `find`, `ls`) и временные папки молчат — иначе обычный `cat /etc/hosts` учил бы пролистывать диалог.

## Хук, который важнее собственной исправности

**У записи `.vibe/hooks.json` появилось поле `onFailure`.**

- `allow` по умолчанию оставляет прежнее поведение: сломанный хук не блокирует вызов.
- `block` превращает поломку самого хука в отказ, и проверка, чья исправность дороже проходимости действия, больше не выглядит разрешением.
- Имя сломанного хука остаётся в списке сломанных, даже когда вызов остановлен: человеку нужны оба факта.
- Решение хука `exit 2` блокирует независимо от политики.
- Неизвестное значение поля даёт предупреждение в журнал и считается `allow`.

## Инструменты: без дублей и без лишнего веса

**Два инструмента с одним именем больше не уходят провайдеру.**

- Обновлённый список MCP-сервера мог приехать рядом со старым определением, и провайдер отвергал весь запрос с дублем.
- Теперь на каждом проводе остаётся первое определение имени, порядок не меняется.
- Если сервер поменял схему, а старое определение с тем же именем осталось, уйдёт старое: какая из двух версий верна, по ответу не понять.

**Поиск по инструментам включается и по объёму схем, а не только по их числу.**

- Порог — 20 инструментов или 60 000 символов схем.
- Чтение, запись, правка, команда и проблемы проекта не откладываются никогда: иначе модель платила раундом поиска перед каждой правкой.
- Первыми откладываются чужие серверы — с конца реестра.
- Имена отложенных модель видит блоком `<deferred_tools>` и может загрузить их точно через `tool_search` с `select:имя1,имя2`.
- На большом теле запроса отказ 5xx больше не повторяется: тот же запрос вернулся бы тем же отказом.

## Видео: HDR и один лист кадров

**Кадры из HDR-ролика больше не бледные.**

- Перевод цвета ставится до масштабирования: PQ и HLG приводятся к BT.709.
- Если в сборке ffmpeg нет `zscale`, кадры уходят без перевода, а лента говорит об этом строкой, а не падением.

**Несколько кадров приходят одной картинкой-сеткой.**

- Сетка строится под число кадров: один кадр — 1×1, а не 4×3 с пустыми ячейками.
- Тайм-код стоит на кадре до укладки.
- Если лист собрать не удалось, уходят отдельные файлы.

## Сжатие контекста не теряет задачу

**Свёртка сохраняет первоисточники.**

- Задача идёт дословно — первое сообщение человека, без вложенных контекстных блоков.
- Рядом идёт индекс журнала решений проекта целиком.
- Закреплённое, уже ушедшее дословно, не повторяется.
- Опора пересобирается каждый ход и встаёт в запрос сразу после сводки.
- У ACP-агента окно ведёт он сам, опоры у него нет.

## Провайдеры и ключи

**Kimi K3.1 Pro получает свои квирки и без префикса в id.**

- Имя `k3.1-pro` теперь ловится правилами так же, как `kimi-k3.1-pro`: рассуждение возвращается, «выключено» уходит как `low`, а не как `none`.
- Уровни — `low`, `high` и `max`, умолчание вендора — `high`.
- Ответ 200 не доказывает, что ответила выбранная модель: у `k3` с выключенным рассуждением вендор может молча обслужить запрос другой моделью, и видно это только по полю модели в ответе.

**Доктор называет провайдера, у которого ключ есть и в IDE, и в переменной.**

- Ключ из IDE сильнее переменной окружения, и до сих пор об этом молчали.
- Строка «Источники ключей» называет провайдера и переменную, которая не используется, но самих значений не показывает.

**Модели провайдера больше не исчезают из выбора, если ключ лежит в связке непрочитанным.**

- Непрочитанный ключ — не то же самое, что отсутствующий: провайдер остаётся с каталогом из кэша, а связку прочтёт первый запрос.

**Строка доктора предупреждает о выведенном fast mode у Opus 4.8.**

- С 30.11.2026 вендор отвечает ошибкой на `speed: fast` у Opus 4.8.
- Строка называет поле, которое надо убрать, или модель, на которую можно перейти; Opus 5.5 не задет.
- Клиент это поле сам не шлёт, поэтому предупреждение касается рукописного `extraBody`.

## Набор VibeBrains

**Набор обновляется сам, а его версии видно в отчёте сверки.**

- «Автообновление набора Vibe» включено по умолчанию и обновляет нетронутые копии при открытии проекта, показывая список «файл: было → стало».
- Ваши правки не трогаются ни в одном режиме.
- Выключенное автообновление ждёт команды: уведомление с кнопкой «Обновить» или действие «Проверить обновления набора Vibe».
- Действие сверяет без записи и говорит «набор актуален», если обновлять нечего.
- Каталог навыков показывает semver набора рядом с ревизией.

**В наборе появились новые навыки и правило, а один снят.**

- Добавлены `design-identity`, `page-design`, `save-session`, `release-flow`, `simplify-review` и `skzi-review` вместе с их эвалами.
- Появилось правило `context`.
- Навык `save-tokens` из набора убран.
- Набор поднят до dev-engine 1.1.0.
- В каталог добавлены GLM-5.4 и Gemini 4 Neon.
- Их характеристики взяты из ежедневных сводок и не проверены живым запросом.
- У воркера Бригадира появился запасной способ узнать имя пользователя в Unix.
- Проверка результата воркера стала отдельной командой, а принятие использует `merge --ff-only`.

## Установка

**macOS (Apple Silicon):** `VibeIDEA-1.2.0-aarch64.dmg` — перетащить в «Программы».

```bash
shasum -a 256 VibeIDEA-1.2.0-aarch64.dmg
# 2fe526f9fb3243dcb1add5856e6c93d6764f82b0b622746442d1dd6403360730
```

**Windows (x64):** `VibeIDEA-1.2.0.exe` — обычный инсталлятор; или `VibeIDEA-1.2.0.win.zip` — распаковать куда угодно и запустить `bin\idea64.exe`.

```powershell
Get-FileHash VibeIDEA-1.2.0.exe -Algorithm SHA256
# cf49c790ad382ae99745db5a1c5de172946608023e10b9a01ff5d2268e5fa5f9

```

**Linux (x64):** `VibeIDEA-1.2.0.tar.gz` — распаковать и запустить `bin/idea.sh`.

```bash
sha256sum VibeIDEA-1.2.0.tar.gz
# 6e5f6b055476cd86e1dfd86e5de865d86ff99c3ae9fd739455d33ad661485bf3
```

**Что нужно на машине:** PHP 8.1+ и Node 18+.
Для отладки PHP — Xdebug.
Для базы — драйвер JDBC, его скачает кнопка в панели «БД».
Для общей памяти в чате — установленный VibeMemory.
Для голоса — модель распознавания: её предложит скачать кнопка микрофона.
Для голосовых сообщений через Telegram — ffmpeg.
Чтобы агент разбирал видео и аудио — ffmpeg.

**Обновление с 1.1.1:** ставится поверх.

## Чего пока нет

Сборка **не нотаризована** у Apple: macOS предупредит при первом запуске, Windows покажет SmartScreen.

**Живьём не проверено** (собрано, покрыто тестами, но руками не обкатано):

- дедупликация инструментов по имени: проверена тестом, живого прогона не было ⚠;
- строка доктора о fast mode у Opus 4.8: тест без живой IDE ⚠;
- путь вне проекта в аргументе команды: проверен тест-вектором `npm run x -- --save /VolumES`, живой IDE не было ⚠;
- HDR и лист кадров: разбор баннера, фильтр и сборка листа проверены, живого HDR-ролика не было ⚠;
- опора после свёртки есть только у прямого чата: у ACP-агента окно ведёт он сам ⚠;
- разбор архитектуры Craft Anything записан в базу знаний с меткой ⚠ перепроверить;
- версии набора и автообновление помечены ⚠ перепроверить: тесты есть, живой IDE не было.

**Про Windows честно:** `.exe` собран здесь же, на macOS, и проверен по составу.
Тихой установкой на Windows он **не проверялся**.

**Про Linux честно:** артефакт собран здесь же и проверен по составу.
**На Linux он не запускался**: линуксовый лаунчер и JBR на маке выполнить нечем.

Обкатывает продукт один человек.
Если что-то ведёт себя не так — самый полезный [issue](https://github.com/VibeBrains/VibeIDEA/issues/new), который сейчас можно завести.
