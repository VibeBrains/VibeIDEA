## 1. Claude Opus 5.5: причуды и переход на запасную модель

Находки:

- Документация Anthropic ([What's new in Opus 5.5](https://platform.claude.com/docs/en/models/opus-5-5/whats-new-opus-5-5)): мышление не выключается, умолчание усилия `medium`, `tool_choice` `any`/`tool` — 400, в том числе на подсчёте токенов; запись в кэш — $5 на 5 минут и $8 на час.
- Там же, раздел Feature support: сообщение `tool_addition` в системном сообщении посреди разговора добавляет или меняет инструмент «without editing `tools` and without losing the prompt cache» — бета `inline-tools-2026-09-15`.
- Страница модели ([anthropic.com/claude-opus-5-5](https://www.anthropic.com/claude-opus-5-5)): при срабатывании защит «cybersecurity tasks were completed by Claude Opus 4.8». Речь о поведении защит; в API переход идёт по правилам ниже.
- [Refusals and fallback](https://platform.claude.com/docs/en/build-with-claude/refusals-and-fallback): переход на другую модель в API включает только параметр `fallbacks` (бета `server-side-fallback-2026-07-01`). Ответ тогда называет модель, которая ответила: поле `model`, блок `{"type": "fallback", "from", "to"}` и запись `fallback_message` в `usage.iterations`. При переходе посреди стрима `message_start` уже назвал заказанную модель, и настоящую видно только в блоке `fallback`.
- Там же: блок `fallback` в следующем ходе надо вернуть «exactly where it appeared» — иначе запрос с блоками рассуждения по обе стороны границы отвергается. После перехода работает «липкая» маршрутизация на час.
- Там же: свой повтор без кредита пишет кэш запасной модели заново; кредит `fallback-credit-2026-07-01` это гасит.
- Статья The New Stack «Your agent calls might secretly get routed to an older model» (22.09.2026) — прочитать не удалось, доступна только шапка. Утверждение о **молчаливой** подмене в API документацией не подтверждается: без `fallbacks` запрос получает отказ, а не ответ другой модели. **Слух, в бэклог не берётся.**

Что у нас уже есть (проверено по коду):

- «Выключено» у Opus 5.5 — нижний уровень усилия; `display: "summarized"`; явное усилие на каждом запросе (решение №103).
- `NO_FORCED_TOOL_CHOICE` и строка доктора про `tool_choice` (решение №113).
- Отказ до первого раунда инструментов уводит на следующую цель цепочки (25.09).
- `ModelEcho` сравнивает `model` из ответа с заказанной и пишет строку в ленту и событие `MODEL_SUBSTITUTED` в журнал аудита.
- Блоки рассуждения прошлых ходов — по ключу всего префикса (решение №113).

Чего нет:

- `fallbacks`, вписанный руками в `extraBody`: блок `fallback` у нас не хранится, и `ModelEcho` не увидит переход посреди стрима. Правильнее назвать это в доктора, чем поддерживать бету поверх собственного перехода.
- Сводки подмен в доктора: событие в журнале есть, строки нет.
- Кредита на повтор: запасная цель на том же провайдере пишет кэш заново.
- `tool_addition`: поиск по инструментам (`ToolSearch`) меняет `tools` посреди треда, и префикс рвётся.

→ VibeIDEA: пункты 1, 2, 3 и 5 бэклога. Патча платформы не нужно.

## 6. Ломающие изменения IntelliJ Platform 2026.3

Находки ([Incompatible Changes 2026](https://plugins.jetbrains.com/docs/intellij/api-changes-list-2026.html)):

- Модули `intellij.platform.debugger`, `…externalSystem`, `…remoteServers` вынесены — нужна явная зависимость.
- `Sdk` расширяет `UserDataHolderEx` (реализовывать `Sdk` нельзя).
- Встроенный OkHttp удалён — переход на `java.net.http.HttpClient` через `PlatformHttpClient`.
- Kotlin UI DSL v1 (`com.intellij.ui.layout`) удалён целиком.

→ Не применимо: форк уже на линии 263 (2026.3), модули `vibe-*` не используют OkHttp и UI DSL v1, не зависят от вынесенных модулей и не реализуют `Sdk` — проверено поиском по `vibe-plugins`.
