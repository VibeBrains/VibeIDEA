## 1. Как открывается

Страница — не диалог, а **вкладка редактора** с именем «Настройки VibeIDE» (иконка codicon `checklist`, ресурс `vibe://settings`, минимальная ширина пейна 700 px). Точки входа:

1. **Палитра (F1):** команда «VibeIDE: Открыть настройки» (`workbench.action.openVibeideSettings`) — закрывает все открытые экземпляры и открывает один свежий.
2. **Toggle-команда** «VibeIDE: Переключить настройки» (`workbench.action.toggleVibeideSettings`): если вкладка уже открыта и активна — закрывает её; открыта, но не активна — фокусирует; не открыта — открывает.
3. **Шестерёнка в заголовке чат-панели** (иконка `settings-gear`, action `vibe.settingsAction`, group `navigation`, order 3) — вызывает toggle.
4. **Шестерёнка Global Activity (левый нижний угол)** — пункт «Настройки VibeIDE» первым в меню (group `0_command`, order 1).
5. **Меню VibeIDE в title-bar** — пункт «Настройки VibeIDE» (group `b_config`, order 1).

## 2. Общая раскладка

Контейнер max-width 1040 px по центру, две колонки (на узком экране — столбиком): слева **вертикальный список pill-кнопок навигации** (1/4 ширины), справа — контент (max-w-3xl) с заголовком `h1` «Настройки VibeIDE». Активная секция подсвечена (`--active` + font-medium). Выбор секции — локальный state, дефолт при каждом открытии — **«Рабочая область»**. Клик «Все настройки» дополнительно плавно скроллит страницу вверх.

Порядок пунктов навигации (дословно): **Рабочая область · Модели · Локальные провайдеры · Облачные провайдеры · Функции · Общие · Оформление · Уведомления · Безопасность · MCP · Все настройки**.

Режим «Все настройки»: все 10 секций отрендерены подряд, каждая завёрнута в сворачиваемый блок (`AllSettingsFold`) с шевроном; **по умолчанию все свёрнуты**, клик по заголовку разворачивает. В обычном режиме секции существуют в DOM всегда, невыбранные скрыты классом `hidden` (state форм не теряется при переключении).

Все переключатели/поля сохраняются немедленно, кнопок «Сохранить» нет (исключение — текстовые формы Рабочей области и JSON-диалог модели).

4. Разделитель, затем строки «Обновить каталог моделей {X}» для каждого настроенного нелокального провайдера (иконка → спиннер → «Каталог {X} обновлён!» / «Не удалось обновить каталог {X}» на 2 секунды).

**Карточка провайдера** (общая для встроенных и динамических, рамка `rounded-lg` на подложке):
- Заголовок `h3` — título провайдера («Anthropic», «OpenRouter»…). У **динамического** заголовок — **сырой id из файла** (это намеренный сигнал, что провайдер пришёл из `providers.json`).
- Поля по списку настроек провайдера. Главное — **«Ключ API»**: парольное поле (значение блюрится), placeholder внутри поля собирается как `«Ключ API (sk-ant-key...)»` — хвост зависит от провайдера (`sk-proj-key...`, `sk-or-key...`, `AIzaSy...`, `gsk_key...`, `xai-key...`, `eyJ...` и т.д.). У части провайдеров вместо/помимо ключа — «Конечная точка»/`baseURL`, «Регион», «Версия API», «Ресурс»/«Проект», «Произвольные заголовки» (placeholder `{ "X-Request-Id": "..." }`). Сохранение — на каждое изменение, без кнопки.
- **Подпись под последним полем** (markdown, приглушённая): ссылка на консоль ключей провайдера, дословно например «[Ключ API](https://console.anthropic.com/settings/keys).», у OpenRouter — «[Ключ API](…). [Лимиты](…).», у openAICompatible — «Любой провайдер с совместимым с OpenAI API (llama.cpp и др.).». У **динамического** провайдера подпись всегда: «Провайдер из `.vibe/providers.json`. Введите ключ здесь или задайте `apiKeyEnv` в `.vibe/.env`.»
- Только у OpenRouter — дополнительный тумблер: «Загружать полный список моделей с OpenRouter без ключа (для запросов к API ключ по-прежнему нужен, если не используете только бесплатные эндпоинты).»
- Если провайдер подключён, но моделей нет: warning «Добавьте модель для {X} (раздел «Модели»).» (для Ollama — «Установите модель Ollama — мы её подхватим автоматически.»); рядом компактная кнопка обновления каталога и подсказка «Список не появился — обновите каталог. Переключатели моделей сохраняются в настройках VibeIDE и не сбрасываются при обновлении.»

**Строка статуса ключа — ТОЛЬКО у динамических провайдеров** (мелкий текст под полями). Шесть статусов, дословно и с цветом:

| keyStatus | Текст | Цвет |
|---|---|---|
| `valid` | «Ключ действителен» | зелёный (emerald-400) |
| `invalid` | «Ключ недействителен (ошибка авторизации)» | красный (red-400) |
| `error` | «Не удалось проверить ключ (сеть или сервер)» | янтарный (amber-400) |
| `pending` | «Проверка ключа…» | приглушённый серый |
| `unverified` | «Ключ не проверяется (static-список)» | приглушённый серый |
| `none` | «Ключ не задан» | самый тусклый серый |

К статусам, кроме `none` и `pending`, добавляется суффикс источника: « · источник: {значение}», где значения: `gui` → «введён в IDE», `env` → «.vibe/.env» (покрывает и OS-переменную окружения), `ref` → «apiKeyRef», иначе «—». Итоговые примеры: «Ключ действителен · источник: введён в IDE», «Ключ не проверяется (static-список) · источник: .vibe/.env».

**Как и когда проверяется ключ** (логика `vibeDynamicProvidersService._buildAndApply` / `_enrichWithCatalog`):
- Ключ резолвится по приоритету: введённый в UI → `apiKeyRef` (ключ другого провайдера) → `.vibe/.env` (`apiKeyEnv`) → OS-переменная окружения (значение видит только electron-main).
- Проверка = **GET на models-эндпоинт** (`<baseURL>/v1/models` или кастомный URL из `models.fetch`), одновременно валидирующий ключ и подтягивающий живой каталог. HTTP 401/403 → `invalid` (модели провайдера НЕ предлагаются), сетевая/серверная ошибка → `error` (модели тоже не предлагаются), успех → `valid` (каталог — источник истины; при пустом каталоге — статический список из файла).
- Срабатывает при каждой перезагрузке overlay: изменение `providers.json` или `.vibe/.env`, смена воркспейса, ввод ключа. Синхронный проход сначала выставляет `pending` (моделей нет, «Проверка ключа…»), асинхронный probe затем переводит в `valid`/`invalid`/`error`.
- `models.fetch: false` в файле → probe не делается вовсе → `unverified`, показывается статический список из файла. Ключ только в OS env (значение недоступно рендереру) → тоже `unverified` + статический список.
- Провайдер считается «настроенным» (`_didFillInProviderSettings`, модели попадают в «Модели» и пикеры) только при `valid` или `unverified`.

**Встроенные провайдеры ключ не проверяют вообще** — никакой строки статуса; заполненность поля и есть «настроен».

**Отличия карточки динамического провайдера от встроенной** (суммарно): заголовок — id из файла, а не красивое имя; есть строка статуса ключа с источником; подпись под полями — стандартная про `providers.json`/`apiKeyEnv`; поле ключа хранится отдельно (`dynamicProviderApiKeys`) и переживает удаление провайдера из файла; модели из `static`-списка файла помечаются в «Моделях» значком «✎» («Параметры модели заданы в .vibe/providers.json» / «Модель добавлена в .vibe/providers.json (нет в каталоге провайдера)»); каталожные модели без записи в файле по умолчанию скрыты, пока пользователь не включит их тумблером.

## 2. Какие провайдеры получают группу (карточку)

- Базовый список `configuredProviders`: **сначала динамические** провайдеры из `.vibe/providers.json` (id, которых нет среди встроенных), **затем встроенные** в фиксированном порядке. Фильтр: только `_didFillInProviderSettings === true`.
  - Облачный считается настроенным, когда заполнены все его поля (обычно ключ API), либо ключ найден в переменных окружения ОС, либо для OpenRouter включён тумблер публичного каталога (`publicCatalog === '1'`).
  - Локальные (Ollama / vLLM / LM Studio) считаются настроенными **по одному только дефолтному endpoint** — то есть всегда.
- Из карточек (но не из дропдауна «Добавить модель»!) исключаются **локальные провайдеры с нулём моделей**, если выключен тумблер «Показывать пустые локальные провайдеры» (`visibleProviderCards`: `configured.filter(p => !isLocal(p) || modelCount > 0)`). Локальный провайдер с моделями виден всегда, независимо от тумблера.
- Если настроенных провайдеров нет вообще — вместо всего списка два абзаца:
  - «Провайдеры ещё не настроены. Списки моделей появятся после сохранения ключей API или конечных точек на вкладке **Облачные провайдеры** (и обновления там, где доступно).»
  - мелким: «Значения по умолчанию скрыты, пока не подключён провайдер — список короче.»

## 3. Тумблер «Показывать пустые локальные провайдеры»

Первая строка над группами: мини-тумблер (xxs) + текст **«Показывать пустые локальные провайдеры»** + значок `(i)` с нативным title-тултипом:

> «Ollama, vLLM и LM Studio считаются настроенными по одному только адресу по умолчанию, поэтому их карточки видны даже там, где локальный сервер никогда не ставили. Выключено — карточка появляется, как только у провайдера есть хотя бы одна модель; добавить первую можно через «Добавить модель» ниже, там доступны все провайдеры.»

Состояние — `globalSettings.showEmptyLocalProviders` (дефолт **false**), персистится вместе с остальными настройками (см. раздел 12). Важно: тумблер не исчезает, даже когда все видимые карточки отфильтровались — гард стоит на `configuredProviders`, а не на видимом подмножестве.

## 4. Группа провайдера (сворачиваемый блок)

- Заголовок-кнопка: шеврон (▸ свёрнуто / ▾ развёрнуто) + **название провайдера** (полужирно) + счётчик в скобках.
- **Все группы по умолчанию свёрнуты.** Состояние развёрнутости, строка поиска, тумблер «активные» и раскрытые вендор-группы — **React-state компонента, не персистятся** (сбрасываются при закрытии настроек).
- **Счётчик** (это и есть «422 у OpenRouter»):

## 7. Семантика тумблера модели — два разных хранилища

**Встроенный провайдер** (`isBuiltinProviderId`):
- Флип `isHidden` прямо в `settingsOfProvider[provider].models[i]` через `setSettingOfProvider(provider, 'models', …)`.
- Следствия: скрытая модель исчезает из **всех** дропдаунов выбора модели (пересчёт `_modelOptions`: строки с `isHidden` пропускаются); если скрыли активную выбранную модель какой-то фичи — выбор автоматически переезжает на первую доступную (или null; см. защиту динамических в п. ниже); «Авто» тоже перебирает только не-скрытые.
- Метрика `Toggle Model Hidden`.

**Динамический провайдер** (id из `.vibe/providers.json`) — **да, это side-map `dynamicModelHidden`**:
- Список моделей такого провайдера — производный (пересобирается из файла + живого каталога), поэтому флип пишется не в него, а в отдельную персистентную карту `state.dynamicModelHidden[providerId][modelId] = boolean` (true = скрыта). Метрика `Toggle Dynamic Model Hidden`.
- `vibeDynamicProvidersService` слушает изменение состояния: если изменилась **только** карта скрытия — дешёвый `_reapplyOverlay()` (пересборка оверлея и ре-гейт чат-пикера) **без** перечитывания файла и без повторной проверки ключа; если изменился ключ — полный `reload()`.
- **Дефолты без явного тумблера**: модели из `models.static` файла — видимы; модели только-из-каталога — скрыты, пока пользователь не включит их на этой странице. Явный тумблер пользователя всегда сильнее дефолта: `hidden = dynamicModelHidden[id] ?? !fileNote`.

## 8. «+ Добавить модель»

- Свёрнутое состояние: строка с иконкой Plus и текстом **«Добавить модель»** (кликабельна вся).
- Раскрытая форма в одну строку: дропдаун провайдера (placeholder **«Имя провайдера»**; варианты — **все** настроенные провайдеры, включая пустые локальные и динамические) + текстовое поле (placeholder **«Имя модели»**) + кнопка **«Добавить»** (disabled, пока не заполнены оба) + крестик-отмена (сбрасывает поля и ошибку).
- Ошибки (красным под формой): **«Выберите провайдера.»**, **«Введите имя модели.»**, **«Такая модель уже есть.»**
- Успех: форма заменяется анимированной галкой с текстом **«Добавлено»** на 1,5 с, затем закрывается и очищается.
- Куда пишется: `settingsOfProvider[provider].models` += `{ modelName, type: 'custom', isHidden: false }` — то есть в тот же персистентный стейт, модель сразу видима во всех дропдаунах. Метрика `Add Model`.
- ⚠️ Известная особенность кода: для **динамического** провайдера `setSettingOfProvider` игнорирует всё, кроме `apiKey` → добавление модели молча не сохранится (галка «Добавлено» всё равно покажется). В IntelliJ-реализации это место надо решить осознанно (для конфиг-провайдеров модели добавляются через файл `models.static`).

## 9. Автообнаружение локальных провайдеров (Ollama / vLLM / LM Studio)

- Глобальный тумблер (xxs): **«Автоматически обнаруживать локальные провайдеры и модели (Ollama, vLLM, LM Studio).»** — `globalSettings.autoRefreshModels`, дефолт **true**.
- Механика (`RefreshModelService`): при старте (после инициализации настроек) для каждого из трёх провайдеров запускается опрос; после **каждого** завершения попытки (успех или ошибка) следующая планируется через **`REFRESH_INTERVAL = 5000` мс** — фактически постоянный опрос каждые ~5 секунд на провайдера, пока тумблер включён. Дополнительно немедленный опрос при изменении `endpoint` или флага настроенности провайдера. Выключение тумблера снимает все таймеры.
- Что пробуется:
  - **Ollama**: дефолтный endpoint `http://127.0.0.1:11434`, список через ollama-клиент `.list()` (эндпоинт `/api/tags`); имя модели — поле `name`.
  - **vLLM**: `http://localhost:8000`, OpenAI-совместимый `GET <endpoint>/v1/models` (`openai.models.list()`); имя — `id`.
  - **LM Studio**: `http://localhost:1234`, тот же `GET /v1/models`; имя — `id`.
  - Endpoint у каждого можно поменять на вкладке «Локальные провайдеры» — опрос идёт по нему.
- Автоопрос идёт с опциями `{ enableProviderOnSuccess: true, doNotFire: true }`: при успехе провайдер помечается настроенным (`_didFillInProviderSettings = true` — карточка «оживает»), а статусы UI не дёргаются (нет мигания).
- Слияние результата (`setAutodetectedModels`): **все** строки `type: 'autodetected'` провайдера заменяются свежим списком; `isHidden` сохраняется по имени для уже известных; **новые локальные модели по умолчанию видимы** (`defaultHiddenForNew: false`) — «поставил модель в Ollama — она сама появилась включённой». Модель, пропавшая с сервера, исчезает из списка. Строки `custom`/`default` не трогаются.

## 12. Хранение состояний и живучесть при правке providers.json

Весь стейт настроек — один зашифрованный блоб под ключом `VOID_SETTINGS_STORAGE_KEY`, `StorageScope.APPLICATION` (глобально для приложения, не per-workspace), `StorageTarget.USER`; запись при каждом изменении.

| Состояние | Где хранится | Переживает правку/удаление providers.json |
|---|---|---|
| Тумблеры моделей встроенных провайдеров (`isHidden`) | `settingsOfProvider[p].models` в блобе | Да (файла не касаются); переживают и обновление каталога (мёрж по имени) |

| Overrides моделей (vision/JSON/apiProtocol) | `overridesOfModel[provider][model]` в блобе | Да; но подчищаются `pruneOverridesToProviderModels` после синка каталога, если модель исчезла |

| Развёрнутость групп, поиск, «активные», вендор-группы | React-state | Нет (сброс при размонтировании) |

## 3. @-контекст

**Триггер:** ввод символа `@` открывает выпадающее меню под полем (флип вверх при нехватке места, ширина = ширине поля).

**Корневые пункты** (каждый с иконкой File/Folder и шевроном `>` у ветвящихся):
- `selection` — текущее выделение активного редактора; ветка показывает один пункт вида `file.ts:12-42`;
- `recent` — недавние файлы из истории редактора;
- `workspace` — корневые папки воркспейса;
- `files` — поиск файлов по имени (инструмент `search_pathnames_only`);
- `folders` — поиск папок (директории, выведенные из найденных файлов).

Если в корне сразу печатать текст — ищутся одновременно и папки, и файлы. Фильтрация — subsequence-матч со скорингом, максимум 100 пунктов, дебаунс 300мс.

**Шапка меню (хлебные крошки):** пока ничего не введено на первом уровне — не показывается; внутри ветки без текста — «Введите текст для фильтра…» (приглушённо); при вводе — сам введённый фильтр. Пусто: «Ничего не найдено».

**Клавиатура в меню:** ↑/↓ — навигация (циклично), Alt+↑/↓ — на 10 позиций, Ctrl/Cmd+↑/↓ — в начало/конец, →/Enter — выбрать/провалиться, ← — назад на уровень, Backspace — стереть символ фильтра / подняться на уровень / (в корне без текста) закрыть меню и стереть сам `@`, Esc — закрыть. Клик мышью выбирает, ховер двигает подсветку.

**Результат выбора листа:** `@` и набранный хвост удаляются из текста, а выбранный файл/папка добавляется **чипом** в полосу контекста над полем (staging selection). Чип: иконка + имя файла (для выделения — `имя (N1-N2)`), крестик × для удаления; клик по чипу-файлу открывает файл, по чипу-выделению — файл с выделенным диапазоном.

**Второй слой — резолвер при отправке.** Набранные вручную токены разбираются в момент сабмита и превращаются в те же чипы-вложения: `@"путь с пробелами"`, `@путь/имя`, `@selection`, `@workspace`, `@recent`, `@agent` (прикрепляет `AGENTS.md` и `.vibe/rules.md` из корней воркспейса), `@sym:Имя`/`@symbol:Имя` (поиск символа по outline-моделям → CodeSelection с диапазоном), `@folder:путь`. Неразрешённые ссылки не блокируют отправку — показывается предупреждение (текст в коде англоязычный): `Could not resolve reference(s): @x, @y and N more. Please check the file path or symbol name.`

3. **▷ (StepForward)** — «быстрое продолжение»: отправляет как пользовательское сообщение текст из конфига `vibeide.chat.continueButtonText` (дефолт — **«продолжи»**); тултип и aria — сам этот текст. Скрыта во время генерации.
4. **Стрелка-вверх (ArrowUp в круге, акцентный фон)** — отправка, aria «Отправить сообщение». Во время генерации на её месте — **Стоп**: круг с красным квадратом, aria «Остановить генерацию».

Это НЕ «run/план»: ▷ — именно кнопка-подпинывание «продолжи». Запуск «плана» живёт в карточке плана в ленте (кнопки «Одобрить и выполнить», «Выполнить в Агенте», «Отклонить», «Пауза»/«Возобновить»), не в композере.

## 6. Нижний ряд пилюль

Левая группа (переносится по строкам):

**6.1. Режим чата** — первая пилюля `[Агент ▾]`. Дропдаун из 4 режимов (глобальная настройка `chatMode`, дефолт `agent`); подпись — имя режима, у каждой строки значок `?` с тултипом:
- «Чат» — «Обычный диалог»
- «Обзор» — «Обход кодовой базы, только чтение»
- «План» — «Сначала план, потом действие»
- «Агент» — «Правит файлы и вызывает инструменты»

**6.2. Модель** — вторая пилюля `[имя-модели ▾]` (`ModelDropdown` для фичи Chat). Показывает только имя модели (или «Авто»). Дропдаун: строка быстрого поиска (placeholder «Быстрый поиск…», пусто → «Нет совпадений»), строки = галочка у выбранной + имя модели + серым название провайдера; пункт «Авто» с деталью «Автовыбор модели»; у моделей из `.vibe/providers.json` — бейдж «✎» с тултипом «Параметры модели заданы в .vibe/providers.json» либо «Модель добавлена в .vibe/providers.json (нет в каталоге провайдера)». Если фича недоступна — вместо пилюли WarningBox с текстом «Нужен провайдер» / «Включите модель в списке» / «Добавьте модель», клик открывает настройки. **Деградация провайдера** (серия ошибок за ~10 мин): пилюля подсвечивается оранжевым кольцом, тултип «Провайдер нестабилен (серия сбоев за ~10 мин) — кликните, чтобы сменить модель.»

**Связь пилюль:** это независимые вещи — первая задаёт РЕЖИМ работы (что агенту можно), вторая — LLM. Режим не фильтрует список моделей Chat (фильтр пропускает все), но от режима зависит видимость части пилюль (6.6–6.13 показываются только в режимах «Агент» и «План»). Обе настройки, плюс автопилот и счётчик итераций, **снапшотятся per-вкладка** (`ThreadChatConfig`): при активации вкладки её сохранённые режим/модель/автопилот/итерации применяются к глобальным сторам, изменения контролов сохраняются обратно в вкладку.

**6.3. Маршрут ролей** — иконка Waypoints, тултип «Выполнить маршрут ролей: команда субагентов (планировщик → разработчики → ревьюер → QA → security) по вашей задаче». Открывает модал:
- заголовок «Выполнить маршрут ролей»;
- текст: «**Промпт для субагента.** Команда ролей (планировщик → разработчики → ревьюер → QA → security) выполнит задачу под автопилотом. Приложите картинку (скриншот/макет/ошибку) — её разберёт роль с vision-моделью. Лимиты ниже — на этот прогон (под автопилотом всё равно авто-продлеваются; правьте базу).»;
- многострочное поле с placeholder «Что должна сделать команда ролей? Напр.: разбери ошибку на скриншоте и почини», валидация «Опишите задачу»; вход для картинок;
- числовые поля: «Шаги» (5–500, дефолт из конфига, обычно 60), «Токены» (10000–100000000), «Время, с» (10–3600), «Авто-резюм» (0–10);
- слева внизу кнопка «🎭 Роли» → под-модал «Роли агентов — модель на роль» (кнопка «Готово»), после него маршрут-модал открывается заново с сохранённым вводом;

Выключен: тултип «Сначала разведать: перед ответом собрать зацепки по последним правкам и плану (read-only)». Включён: синяя подсветка, тултип «Разведка следующего запроса включена — нажмите, чтобы выключить». Флаг само-сбрасывается после срабатывания.

**6.5. Кольцо контекста** — SVG-кольцо 18px, заполнение = % занятости окна контекста; цвет: синий < 80%, жёлтый ≥ 80%, красный ≥ 100%. Тултип «Контекст заполнен на N% — нажмите, чтобы посмотреть детали» (до первых данных — «Пока нет данных — отправьте первый запрос»). При ≥80% сессионного бюджета кнопка пульсирует, тултип «Сессия израсходовала N% токенов — сбросьте счётчик сессии или поднимите лимит в настройках». Клик — поповер «Контекст и токены»:
- строка «Окно контекста» — `X / Y (N%)` + полоска;
- строка «Токены сессии» — `X / Y (N%)` либо `X · лимит отключён`;
- строка «Лимит провайдера» (если провайдер сообщает остаток) — `осталось / лимит вид (N%)`, виды: «запросы»/«токены»/«входные токены»/«выходные токены»; при исчерпании красным «Лимит провайдера почти исчерпан — следующий запрос может быть отклонён. Подождите обновления или переключите провайдера.»; строка «обновится HH:MM»;

- секция «Что занимает контекст» — построчная разбивка промпта (сегменты + «История переписки»), пока считается — «Считаем…»;
- кнопка «Полный отчёт» → команда `vibeide.context.status`.

Далее — только при выключенном упрощённом виде:

**6.6. Бейдж политики обучения** — «📚» + короткая метка: «без обуч.» / «opt-in» / «opt-out» / «может обуч.» / «обуч.?»; тултип = `Провайдер/модель` + расшифровка, напр. «Каталог: провайдер указывает, что данные API по умолчанию не используются для обучения.». Скрыт при «Авто».

**6.7. Автопилот** (только режимы Агент/План) — свитч + подпись «Автопилот». Тултип: «Автопилот (вкл. по умолчанию): запускать инструменты (правки, удаление, терминал, MCP) без подтверждения. Выключите — подтверждать каждый шаг.» Связан двусторонне со счётчиком «итер.»: включение ставит счётчик в 0 (∞), выключение — в 25.

**6.8. Ссылки↻** — свитч рекурсии по ссылкам в правилах проекта; тултип «Рекурсия по ссылкам в правилах проекта. Вкл — следовать по ссылкам внутри уже подтянутых файлов (с лимитами и защитой от циклов); выкл — только один уровень. Дубль настройки vibeide.projectRules.resolveLinksRecursive.» Скрыт, если resolveLinks выключен.

**6.9. Сброс сессии** (только Агент/План) — иконка RotateCcw; тултип «Сбросить счётчик токенов сессии (израсходовано X). Обнуляет session-лимит безопасности — история чата не затрагивается.»

**6.10–6.13. Числовые степперы** `[−][поле][+] подпись [пресеты]` (только Агент/План; при 0 подпись меняется на «off»-вариант; Enter — применить, Esc — откат):
- «итер.» / при 0 «∞ итер.» — soft-checkpoint: после N шагов агент паузится и спрашивает «продолжить?»; пресеты `∞ 25 50 100`; 0 ⟺ Автопилот ВКЛ;
- «подпин.» / «без подпин.» — сколько раз ПОДРЯД подтолкнуть модель, завершившую ход текстом без вызова инструмента; дефолт 2, пресеты `∞ 2 5` (кнопка «0» рисуется как ∞ — визуальная особенность общего компонента);
- «подпин?» / «∞ подпин?» — авто-продолжение хода, оканчивающегося «?»; здесь 0 = без лимита; дефолт 3, пресеты `∞ 5 10`;
- «субпин.» / «без субпин.» — авто-резюм остановленной по лимиту роли субагента; дефолт 2, пресеты `∞ 2 5`.

**6.14. «Рассуждение»** — пилюля, вид зависит от возможностей модели: свитч (вкл/выкл); либо слайдер бюджета + «N токенов» / «off»; либо слайдер усилия + «Low/Medium/High…» / «off». Скрыта, если модель не умеет reasoning.

Правая часть ряда: во время генерации — индикатор загрузки; всегда — **история ▾** (иконка History + шеврон, тултип «История чатов»). Клик — поповер: строка поиска (placeholder «Фильтр…»; поиск идёт по всему тексту тредов), переключатель охвата «Этот проект»/«Все проекты» (+ «Ещё N в других проектах — нажмите, чтобы показать» / «Найдено ещё N в других проектах — показать»), список тредов с бейджами «Другой проект»/«Без проекта», действием «Переместить в этот проект», дублированием и удалением; у найденного по содержимому — строка-совпадение с префиксом «Вы:» / «Ответ:» / «В переписке:», клик по ней открывает чат прямо на этом сообщении («Открыть чат на этом сообщении»). Пусто: «Нет совпадений».

## 7. Чип «Модель …» под композером (лендинг)

На **пустом чате** под композером — ряд информационных чипов `ContextChipsBar` (не кнопки):
- «Файл» + имя активного файла (только для настоящих файлов; webview/настройки не показываются);
- «Модель» + `<Название провайдера>:<имя модели>` — напр. **«Модель MiniMax:MiniMax-M3»**. Это дубль текущего выбора модели фичи Chat для быстрой ориентировки; меняется через пилюлю модели, сам чип некликабелен.

Ниже (если не упрощённый вид) — ряд пилюль-кнопок быстрых действий с бейджами хоткеев: «Объяснить», «Рефакторинг», «Добавить тесты», «Починить тесты», «Докстринг», «Оптимизация», «Отладка» (каждая выполняет соответствующую команду `vibe.*`).

Ещё ниже: если тредов > 1 — заголовок «Прошлые чаты» + список; иначе заголовок «Подсказки» + 4 кнопки-промпта, клик сразу отправляет текст: «Кратко опиши мой проект», «Как устроены типы в Rust?», «Помоги написать AGENTS.md для этого репозитория», «Прикрепить правила агента (@agent)».

## 8. Вкладки чатов

Строка над чатом (34px, горизонтальный скролл):
- **Ярлык вкладки** = первые 22 символа первого пользовательского сообщения + «…», у пустого треда — «Новый чат»; полный текст — в тултипе. Активная — светлый фон + синее подчёркивание.
- **Клик** — переключение (композер полностью пере-рендеривается под тред: своя лента, свой черновик, свой per-tab конфиг режим/модель/автопилот/итерации).
- **× на ховере** (показывается только когда вкладок > 1), тултип «Закрыть вкладку (чат останется в истории)». Закрытие НЕ удаляет тред — он остаётся в истории; при закрытии активной активируется соседняя слева (иначе справа); если вкладок не осталось — автоматически открывается свежий чат (пустая панель невозможна).
- **«+»**, тултип «Новый чат» — всегда создаёт новый тред и вкладку (без переиспользования пустого).
- **Лимит открытых вкладок**: `vibeide.chat.maxOpenTabs`, дефолт 5 (кламп 1–20); при превышении тихо выталкиваются самые старые вкладки (тред остаётся в истории, активная не выталкивается).
- **Drag-and-drop** — перестановка вкладок (перетаскиваемая полупрозрачна, цель подсвечена синей кромкой).
- Справа в строке — кнопка колонки истории: «Показать историю» / «Свернуть историю (оставить только чат)».
- Набор открытых вкладок (`openTabIds`) персистится и восстанавливается при перезапуске; черновики — нет (in-memory).

## 9. Очередь инъекций (ввод во время работы агента)

Пока агент работает, Enter не прерывает его: текст (и приложенные картинки/PDF) уходят в очередь и показываются жёлтой полосой над полем: «📌 В очереди — подмешается в следующем ходе агента (N)», под ней — до 3 строк текста каждой заметки и счётчики вложений «🖼 N · 📄 N», у каждой — × с тултипом «Убрать из очереди». На следующем ходе агента очередь сливается в настоящее сообщение и полоса исчезает.

## 10. Отправка: валидации и побочные эффекты

Порядок при сабмите: перехват `/watch`/`/shot` → резолв @-токенов в чипы → проверка vision: картинка + невижн-модель — **блокирующая ошибка** «Выбранная модель (Провайдер/модель) не поддерживает изображения. Переключитесь на vision-модель (Claude, GPT-4o/4.1/5, Gemini, vision-модель OpenRouter или Ollama llava/bakllava) либо удалите вложение.»; PDF + невижн-модель — только предупреждение «Выбранная модель может не поддерживать PDF. Текст из PDF будет извлечён и отправлен — для PDF с большим количеством картинок выберите vision-модель.» → оптимистичная очистка поля/чипов/вложений/черновика, фокус обратно в поле → отправка сообщения со staged-selections.

Служебные состояния над композером в ленте: «Модель молчит ~Ns — возможно, стрим завис.», «Провайдер взял паузу (лимит запросов). Автопродолжение через M:SS · попытка X из Y» + кнопка «Продолжить сейчас»; при остановке агента без вызова инструмента — кнопка «Продолжить» с тултипом «Подтолкнуть модель продолжить: она завершила ход текстом без вызова инструмента».

## 1. Хранение тредов

- **Не файлы, не `.vibe`** — вся история лежит в storage-сервисе IDE: ключ `vibeide.chatThreadStorageII`, `StorageScope.APPLICATION` (глобальная state-БД юзер-даты, общая для всех окон и всех проектов). Один JSON-блоб со словарём `{threadId → thread}`.
- Картинки-вложения (`Uint8Array`) сериализуются в строки `__base64__:<base64>`; URI восстанавливаются через `URI.revive`.
- Запись **дебаунсится 1500 мс** (буферизуется последнее состояние, пишется один раз на всплеск мутаций).
- Тред-объект: `id` (uuid), `createdAt`/`lastModified` (ISO-строки), `workspaceId?`, `workspaceLabel?`, `messages[]`, `state{…}`. `workspaceId` — id workspace на момент создания треда; `workspaceLabel` — имя первой папки, для multi-root — `«имя +N»`. Окно без папки даёт `id: ''` → тред остаётся **непомеченным** (виден во всех проектах); нестабильный transient-id окна нарочно не штампуется.
- Отдельно: список открытых чат-вкладок — ключ `vibeide.chatOpenTabIds`, `StorageScope.WORKSPACE` (пер-проектный).
- Тумблер скоупа истории — ключ `vibeide.history.showAllProjects`, `StorageScope.PROFILE`: один на все окна, все списки синхронизируются через storage-событие. Пока пользователь его ни разу не трогал, дефолт берётся из настройки `vibeide.history.defaultShowAllProjects` (по умолчанию `false`).
- Свёрнутость правой рейки — ключ `vibeide.chatHistoryRailCollapsed`, PROFILE, **по умолчанию `true` (свёрнута)**.

## 2. Три поверхности истории

### 2.1. Блок под композером (лендинг пустого чата)
На стартовой странице чата (нет сообщений в текущем треде), под полем ввода/чипсами/квик-экшенами:
- Если тредов в сторе > 1 (включая текущий пустой) — заголовок **«Прошлые чаты»** (приглушённый, некликабельный) и список `PastThreadsList`.
- Иначе — вместо него заголовок **«Подсказки»** и стартовые подсказки-промпты.
- Список показывает **первые 3** треда; если их больше — внизу кликабельная строка **«Ещё N…»** (N = остаток), по клику раскрывает всё, взамен появляется строка **«Свернуть»**.
- Над списком (справа) — сегментный переключатель скоупа (п. 4), **только если есть треды других проектов**.

## 3. Строка треда (общая для всех трёх поверхностей)

Во все списки попадают **только треды с ≥1 сообщением**, сортировка — по `lastModified`, новые сверху.

Строка — скруглённая карточка (px-3 py-2, rounded-2xl), содержимое:
- **Статус-иконка** (слева, только если тред сейчас работает): крутящийся спиннер — состояния `LLM` / `tool` / `preparing`; иконка «облачко с вопросом» — `awaiting_user` (ждёт одобрения). Иначе иконки нет.
- **Заголовок** = `displayContent` **первого сообщения пользователя**, в одну строку с многоточием. Если пользовательского сообщения нет — литерал `""` (две кавычки).
- **Бейдж проекта** (только в режиме «Все проекты» и только у «чужих» тредов): пилюля с иконкой папки-со-стрелкой + текст = `workspaceLabel`, а без него — **«Другой проект»** (есть чужой `workspaceId`) или **«Без проекта»** (тред без `workspaceId`); капсом, 9px, максимум 120px, полный текст в тултипе.
- **Справа — бейдж-пилюля** `N · Дата`: N — число сообщений ролей user+assistant; дата — `Today` / `Yesterday` / `«Aug 23»` (⚠️ эти литералы в компактной строке **англоязычные, не локализованы** — `formatDate` в `SidebarThreadSelector.tsx`; русские «Сегодня/Вчера…» есть только в заголовках групп панели). Часы/минуты в строке не показываются (хелпер 12-часового времени есть, но не используется).
- **Ховер**: бейдж скрывается (место зарезервировано — ширина не прыгает), на его месте иконки действий:
  1. **Папка-со-стрелкой** — «Переместить в этот проект» (тултип дословно) — только у чужого треда в режиме «Все проекты»; клик перештамповывает `workspaceId`/`workspaceLabel` на текущий проект (в окне без папки — no-op).
  2. **Копия** — дублировать тред: глубокий клон с новым id (`lastModified` не меняется — копия встаёт рядом с оригиналом).
  3. **Корзина** — удалить; первый клик превращает её в пару **✕ (отмена) / ✓ (подтвердить)** — двухшаговое подтверждение inline, без диалога. Пока корзина «нажата», иконки перемещения/дублирования скрыты.
- **Клик по карточке** — переключение на тред (п. 5).
- **Строка совпадения** (только в результатах поиска, п. 6): под заголовком, 11px, приглушённая — метка автора + обрезанная цитата.

## 4. Фильтры «Этот проект / Все проекты +N»

- Компактный сегментный переключатель-пилюля (10px): две кнопки **«Этот проект»** и **«Все проекты»**; активная — с фоном и ярким текстом.
- Показывается **только когда есть что скрывать**: `otherProjectsCount > 0`, где считаются треды с непустым `workspaceId`, отличным от текущего. Треды «без проекта» в счётчик не входят — они видны всегда.
- **Семантика «Этот проект»** (предикат `threadMatchesWorkspace`): видны треды текущего workspace **плюс** все непомеченные (legacy/без папки) — «ничто не выглядит потерянным».
- **«Все проекты»** — видно всё.
- **Счётчик «+N»**: маленькая пилюля внутри кнопки «Все проекты», видна только в режиме «Этот проект»; N = число тредов других проектов. Тултип кнопки: **«Ещё N в других проектах — нажмите, чтобы показать»**.
- Выбор персистится (PROFILE) и мгновенно синхронизируется во всех списках и всех окнах.
- Сопутствующие команды палитры: **«Привязать историю без проекта к текущему»** (`vibeide.history.claimUntaggedThreads`) — массово штампует непомеченные треды на текущий проект, уведомления: «Привязано к текущему проекту: {0} чатов без проекта.» / «Нет чатов без проекта — привязывать нечего.»

## 5. Открытие старого треда

- Клик = `switchToThread(id)`: тред становится текущим **и открывается как чат-вкладка** (мульти-чат таб-стрип), не новое окно. Идемпотентно.
- Лимит одновременных вкладок — настройка `vibeide.chat.maxOpenTabs`, **дефолт 5** (клампится 1..20); при переполнении тихо выселяется **самая старая** вкладка (активируемая — никогда). Выселение закрывает только вкладку — тред остаётся в истории.
- Закрытие вкладки тред **не удаляет**; удаление треда закрывает и его вкладку; если удалили текущий и вкладок не осталось — автоматически открывается свежий пустой чат («вьюха никогда не пуста»).
- Из панели-рейки после переключения дополнительно фокусируется чат (`vibeide.chat.open`); из попапа — попап закрывается.

## 6. Поиск по истории (транскриптный)

Общий движок для попапа и панели (`useThreadSearch` → чистый `transcriptSearch.ts`; лексический, офлайн, детерминированный, без модели и сети).

- **Ищет по всему разговору**, не по первой строке: текст каждого сообщения = `displayContent || content`; роли кроме user/assistant считаются `other`.
- **Дебаунс 150 мс**; нормализация текста кэшируется по объекту треда (WeakMap) — печать не пересканирует весь корпус.
- **Веса** (очки за вхождение термина в сообщение, помноженные на):
  - первое сообщение треда — **12** (де-факто заголовок);
  - сообщение пользователя — **6**;
  - ответ модели — **2**;
  - служебное (`other`) — **1**;
  - бонус **+10**, если **все** термины запроса нашлись где-то в треде (при ≥2 терминах);
  - **сатурация**: не больше **3** вхождений одного термина в одном сообщении идут в зачёт.
- Тред без единого совпадения **исключается** (не «score 0»). Тай-брейк: score → свежесть (`lastModified`) → id.
- **Но порядок выдачи в списках — не по score**: существующий список фильтруется, сохраняя сортировку по свежести/группам. Score определяет только членство и выбор лучшей цитаты.
- **Строка-цитата**: показывается под заголовком, когда лучшее совпадение — **не первое сообщение** (иначе строка дублировала бы заголовок). Формат: метка + обрезанный фрагмент вокруг совпадения (окно 240 символов; сообщение короче показывается целиком). Метки дословно: **«Вы:»** (user), **«Ответ:»** (assistant), **«В переписке:»** (other). Тултип строки: **«Открыть чат на этом сообщении»**.
- **Клик по цитате** (не по карточке): `revealMessageInThread` — тред открывается **ровно на этом сообщении**: скролл к нему по центру (ретраи 0/90/260 мс — виртуализованный список монтируется асинхронно), сообщение подсвечивается и подсветка сама гаснет через **2600 мс**. Запрос «переживает» немонтированную вьюху (pending-map по threadId).
- При скоупе «Этот проект» совпадения в чужих проектах не теряются: кнопка **«Найдено ещё N в других проектах — показать»** (клик = переключить на «Все проекты»).

## 7. Лимиты и чистка

Автоудаления тредов по возрасту/количеству **нет** — история растёт, пока её не чистят вручную. Ограничивается размер каждого треда:

- **Кап сообщений на тред**: `vibeide.chat.maxMessagesPerThread`, дефолт **500** (клампится 100..5000). При превышении после аппенда старейшие сообщения срезаются до `cap − 100`, в голову вставляется один синтетический маркер-сообщение о триме; исходная задача «пиннится» (не забывается); закреплённые булавкой сообщения при обрезке не вырезаются.
- **Кап размера тул-результатов**: старые результаты инструментов режутся до `vibeide.chat.maxStoredToolResultKB` (дефолт **24 КБ**, 4..2048), последние `vibeide.chat.keepRecentFullToolResults` (дефолт **16**, 0..200) на тред хранятся целиком. Одноразовый проход при загрузке стора чинит и исторический балласт.
- **Удаление одного треда** — корзина в строке (двухшаговое подтверждение); чистит и связанное: план-биндинги, session-memory, territorial-локи, снапшоты, вкладку.
- **Команды палитры (категория VibeIDE):**
  - **«Экспортировать историю текущего проекта»** (`vibeide.history.exportProject`): берёт только треды, строго принадлежащие проекту (непомеченные и чужие не входят; в окне без папки — no-op). Пикер формата: «Markdown (.md) — Читаемая стенограмма» / «JSON (.json) — Полные данные тредов», плейсхолдер «Формат экспорта истории ({0} тредов)»; сейв-диалог «Сохранить историю проекта», имя файла `vibeide-history-<slug>-<YYYY-MM-DD>.<ext>`; итог: «История экспортирована: {0} тредов → {1}». Пусто: «У текущего проекта нет истории чатов для экспорта.»
  - **«Удалить историю текущего проекта»** (`vibeide.history.clearProject`): warning-диалог «Удалить всю историю чатов текущего проекта ({0} тредов)?», деталь: «Затрагиваются только треды, принадлежащие этому проекту. История без проекта и других проектов не трогается. Действие необратимо — рекомендуется сначала экспортировать.», кнопка «Удалить»; итог: «Удалено тредов текущего проекта: {0}.»
