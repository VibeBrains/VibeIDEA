# Разбор дайджестов 27–30.09.2026

Четыре дайджеста разобраны одним документом: темы повторяются.

Каждая тема сверена с `functional.md`, `roadmap.md`, `decisions.md`, кодом `vibe-agent` и сидами набора.
Из одиннадцати тем шесть уже сделаны или не применимы.

Все три модели при ползунке «выключено» (это умолчание) делают не то, что обещает ползунок.
Документация Anthropic в день разбора сначала не открывалась, и Sonnet 5.5 с диагностикой кэша были сверены по SDK Anthropic на GitHub; позже в тот же день страницы открылись, и всё сверено по ним (копии — `/Volumes/Storage/Caches/anthropic-docs/`).

## 2. Claude Sonnet 5.5

Тема 29.09 №1.

Находки:
- [Анонс Anthropic](https://www.anthropic.com/claude-sonnet-5-5), 28.09.2026: `claude-sonnet-5-5`, $2 / $10 за 1M, запись в кэш $2.50, чтение $0.20; умолчание усилия — `high` на платформе, `medium` в Claude Code; задачи кибербезопасности повышенного риска «visibly fall back to Sonnet 5».
- [Заметки Anthropic](https://platform.claude.com/docs/en/release-notes/overview) в пересказе [releasebot](https://releasebot.io/updates/anthropic): вместо `disabled` — `between_tools`, принудительный вызов инструмента — 400, блоки мышления Sonnet 5.5 работают только в аккаунте, который их получил.
- [ComputingForGeeks](https://computingforgeeks.com/claude-sonnet-5-5-released-features-benchmarks/): мышление адаптивное и включено по умолчанию, самый низкий режим — `between_tools`; `temperature` отвергается, `budget_tokens` тоже.
- [SDK Anthropic для Python](https://github.com/anthropics/anthropic-sdk-python/blob/main/CHANGELOG.md): тип `ThinkingConfigBetweenTools` — `{"type": "between_tools"}` без других полей (коммит `a9a577d`); помощник запасной модели понижает его до `disabled` на других моделях: «the fallback model may not accept `between_tools`» (коммит `a3834d4`).

Что у нас есть: правило `^claude-(opus|sonnet|fable|mythos)-5` уже даёт Sonnet 5.5 адаптивное мышление и снимает выборку.
Чего нет:
- «Выключено» не шлёт ничего: правило `OFF_THINKING_DISABLED` записано для точного `claude-sonnet-5`, а `THINKING_ALWAYS_ON` Sonnet 5.5 не касается. Модель думает на вендорском `high`.
- `NO_FORCED_TOOL_CHOICE` перечисляет Opus 5.5, Fable 5.1 и Mythos 5.1 — Sonnet 5.5 в нём нет.
- В сиде `anthropic.jsonc` модели нет.

[What's new in Sonnet 5.5](https://platform.claude.com/docs/en/models/sonnet-5-5/whats-new-sonnet-5-5) и [страница модели](https://platform.claude.com/docs/en/models/sonnet-5-5/overview): `disabled` — 400 со ссылкой на `between_tools`; `between_tools` принимается при `low`/`medium`/`high`, при `xhigh`/`max` — 400; окно 1M, вывод 128K, часовая запись в кэш $4; системные сообщения посреди разговора и смена инструментов по ходу — поддерживаются.

## 8. Диагностика кэша промпта

Тема 28.09 №5.

Находки:
- [Releasebot](https://releasebot.io/updates/anthropic): диагностика кэша вышла из беты.
- [SDK Anthropic](https://github.com/anthropics/anthropic-sdk-python/blob/main/CHANGELOG.md), коммит `22062b8` «cache diagnostics GA — diagnostics on Message / MessageCreateParams»:
  - запрос: `diagnostics: {"previous_message_id": "msg_…"}` — `id` прошлого ответа; `null` на первом ходе включает диагностику без сравнения;
  - ответ: `diagnostics.cache_miss_reason` с типом `model_changed`, `system_changed`, `tools_changed`, `messages_changed`, `previous_message_not_found` или `unavailable`, у первых четырёх — `cache_missed_input_tokens`;
  - `null` в причине — сравнение ещё не закончено, когда ответ уже отдан.
- Панель кэша у OpenAI — страница консоли, а не поле API: брать нечего.

Что у нас есть: строка «префикс сломан» (`WirePrefix`) и «набор инструментов изменился» — наш взгляд на свой запрос.
Чего нет: взгляда вендора. Наш детектор не видит, что кэш не прочитался по его причине — например, по сроку или другой модели.

→ VibeIDEA: пункт 4 бэклога — фича. Только собственный API Anthropic: у вендоров того же провода поле не обещано.
