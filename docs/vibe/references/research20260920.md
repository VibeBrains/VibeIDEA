## 1. ACP-каталог агентов JetBrains — уже реализовано

Файл — ровно `~/.jetbrains/acp.json`, создаёт его сама IDE («Add Custom Agent»).
Два ключа верхнего уровня: `default_mcp_settings` и `agent_servers`.
Ключ записи в `agent_servers` — **отображаемое имя агента**, не идентификатор; значение несёт `command`, `args`, `env`.
Политика MCP состоит из ТРЁХ ключей, а не двух: `use_custom_mcp` (по умолчанию `true`), `use_idea_mcp` (по умолчанию `false`) и `idea_mcp_allowed_tools` — сужение набора инструментов встроенного сервера.
ACP-агенты **не поддерживаются в WSL**; подписка JetBrains AI не требуется; администратор через IDE Services может урезать реестр.
Источник: www.jetbrains.com/help/ai-assistant/acp.html (страница датирована 22.07.2026, сверена 20.09.2026).

**У нас:** `AcpConfig.configPath()` читает именно этот путь, разбирает `command`/`args`/`env`, применяет `use_custom_mcp`; доктор показывает оба источника агентов.
`use_idea_mcp` не читается осознанно — решение №95: ключ называет ВСТРОЕННЫЙ сервер JetBrains, а не наши инструменты IDE.
`idea_mcp_allowed_tools` не берём **по той же причине**: он сужает инструменты их сервера, и перенос его на наши означал бы, что список, написанный для чужого набора, молча режет наш.

## 2. AGENTS.md как источник правил — взято

Claude Code 2.1.277 (замечен 18.09.2026): «in a project with no CLAUDE.md, Claude Code reads AGENTS.md instead».
Это **фолбэк**, а не слияние: при наличии `CLAUDE.md` файл игнорируется; режим переключается настройкой «Project instructions» с четырьмя значениями.
Ищется в рабочем каталоге и всех каталогах выше; `AGENTS.local.md` и `.agents/` не читаются.
Формальной спеки формата **нет** — соглашение об имени и месте (agents.md); среди читающих заявлены Codex, Cursor, Zed, opencode, goose, Copilot coding agent, Junie.
Источники: releasebot.io/updates/anthropic/claude-code, code.claude.com/docs/en/memory, agents.md.

**Решение: читаем ВСЕГДА, а не как запасной вариант.**
У Claude Code фолбэк осмыслен — там своя `CLAUDE.md` спорит с чужим файлом.
У нас обе границы чужие (`.cursor/rules` и `AGENTS.md`), и выбросить одну значит потерять инструкции, которые человек написал.
Конфликты решает то же правило близости, что и для вложенных правил.

Шаблон `AGENTS.template.md` пришёл в общий набор от соседа (VibeBrains `58b5cfd`), засевается в `.vibe/`.
В корень его переносит действие IDE «Создать AGENTS.md из шаблона»: `AGENTS.md` уезжает в коммит человека, и создавать его сеялкой значит писать в чужой репозиторий.

## 3. Окно контекста у MiniMax — уже реализовано

Отметка «автокомпакт на ~167K» подтверждения не имеет — **слух**.
Официальная дока MiniMax ставит `CLAUDE_CODE_AUTO_COMPACT_WINDOW=1000000` как штатную настройку, а не как обход дефекта.
Anthropic документирует, что для нераспознанного id клиент компактит по ПРЕДПОЛАГАЕМОМУ окну.
Источники: github.com/MiniMax-AI/MiniMax-M2.7/issues/46, platform.minimax.io/docs/token-plan/claude-code, docs.claude.com/en/docs/claude-code/model-config.

Переменную автокомпакта сосед поправил в наборе тем же днём (`58b5cfd`).

## 4. Статические заголовки и forward-proxy — тема сдвинулась, дыра нашлась рядом

`headers:` — ключ **серверного** `gateway.yaml` у Claude apps gateway, а не настройка клиента; требует v2.1.277, имеет список зарезервированных имён и покрывает не все запросы.
`CLAUDE_GATEWAY_PROXY_IS_EGRESS_BOUNDARY=1` — тоже переменная ШЛЮЗА, включается только при трёх условиях разом и намеренно сделана переменной, «so that nothing in the config file can relax the gateway's address check».
На стороне клиента Claude Code читает `HTTPS_PROXY`/`HTTP_PROXY`/`NO_PROXY`, SOCKS не поддерживает и **никогда не гонит loopback через прокси**.
Источники: docs.claude.com/en/docs/claude-code/claude-apps-gateway-config, docs.claude.com/en/docs/claude-code/corporate-proxy.

**У нас заголовки были**, а прокси — нет: один `HttpClient` на все запросы и `ProxySelector.of(...)` без исключений.
Заданный прокси уводил в него и локальные модели — Ollama на `localhost:11434` и локальный muse-glimmer.
Починено: решение об обходе вынесено чистой функцией `ProxySettings.bypasses`, петля мимо всегда, остальное — по `NO_PROXY`.

## 5. Незнакомые дискриминаторы типов — не применимо

Это была регрессия **клиента**: 2.1.275 начал слать всем эндпоинтам серверный инструмент Anthropic `advisor_20260301`, и сторонние шлюзы падали с 400; починено в 2.1.276.
Текст ошибки у прокси точнее: «tools[32]: unknown variant `advisor_20260301`, expected `web_search_20250305`…».
Что именно клиент делает с незнакомым тегом теперь — **не задокументировано**.
Источники: CHANGELOG claude-code, github.com/SaladDay/cc-switch-cli/issues/468, platform.claude.com/docs/en/agents-and-tools/tool-use/advisor-tool.

**У нас взяться неоткуда:** в anthropic-провод уходят только наши собственные инструменты (`ToolCalls.anthropicTools`), серверных инструментов вендора мы не отправляем.
Принцип «возвращать чужое дословно», который Anthropic предписывает для результатов инструментов, у нас уже живёт причудой `ECHO_REASONING`.

## 8. Версия протокола ACP — дыра закрыта, v2 по-прежнему не берём

`protocolVersion` — одно целое, «bumped only for breaking changes»; непрерывное едет через capabilities.
Семантика ответа нормативная: «The client should disconnect, if it doesn't support this version», плюс «Clients and Agents MUST agree on a protocol version».
v2 — **Draft** (объявлен 20.07.2026) с прямой оговоркой «Don't ship it by default in production» и требованием не бросать v1.
**Публичные changelog с датами ЕСТЬ, их три** — посылка дайджеста неверна:
`CHANGELOG.md` в корне (версии крейта), `schema/v1/CHANGELOG.md`, `schema/v2/CHANGELOG.md`, все — Keep a Changelog.
Последние на 18.09.2026: `schema-v1.23.0`, `schema-v2.0.0-alpha.5`, крейт `agent-client-protocol` 2.2.0.
**Версия артефакта ≠ версия провода** — README предупреждает об этом прямо: крейт 2.2.0 говорит на протоколе 1.
Нестабильное помечается отдельным файлом `schema.unstable.json` и префиксом «UNSTABLE» в описании (41 определение); слова `experimental` в схеме нет.
Источники: github.com/agentclientprotocol/agent-client-protocol (README, CHANGELOG, releases), agentclientprotocol.com/protocol/v1/initialization, agentclientprotocol.com/announcements/acp-v2-draft.

**У нас** решение №50 уже зафиксировало v1 и вынесло версию константой; переезд на v2 отклонён — источник это подтверждает.
Дыра была в другом: мы слали `protocolVersion: 1` и не смотрели, что ответил агент.
Теперь ответ сверяется, и при расхождении разговор не начинается с объяснением, а не со странностей.
Молчание агента (поля нет) ошибкой не считается: так отвечали ранние сборки.
