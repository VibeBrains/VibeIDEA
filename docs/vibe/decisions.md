24. **Засев провайдеров** → образец providers.example.jsonc / один жирный providers.json / каталог `.vibe/providers/*.jsonc` → **каталог по файлу на провайдера, авточитаемый, с тумблером `active`** — решение владельца 2026-08-28: у VibeIDE providers.json дополнял вшитых провайдеров, у нас вшитых нет — сеем сразу всё; база активных: OpenCode Go, OpenCode Zen, OpenRouter, MiniMax, Z.AI, Kimi, DeepSeek (+ Claude по ACP, он агент, не провайдер); остальное из каталога VibeIDE переносится выключенным; example-образец удалён из засева. Вшитых списков моделей нет — модели с каталога провайдера (`models.fetch`); кастомная модель в `static` — фича «для гиков»: в UI бейдж «кастом», в доках спека + закомментированный пример в шаблоне. Делегированная развилка (решил Claude): **мержить все, показывать только активные** — фильтр `active` стоит после слияния и `resolveExtends`, поэтому extends/патч по id работают от неактивных записей, а включение делается переопределением `{"id":…,"active":true}` в своём providers.json без правки каталога; контракт №15 не тронут. Порядок наложения — уточнён адверсариальным ревью до коммита: каталог, как «встроенные», лежит в СЛАБЕЙШЕМ слое (глобальный каталог → проектный каталог → глобальный providers.json → проектный providers.json), иначе засеянный в каждый проект файл глушил бы живой глобальный конфиг пользователя. Запись без поля `active` считается активной (осознанно НЕ тристейт: пользовательский providers.json, писанный до каталога, обязан пережить появление одноимённого выключенного сида; патч, не желающий включать, повторяет `"active": false` явно — записано в спеке).

Общий КОД агента невозможен (TS/Electron против Kotlin/JVM) — общим выносится контент. Корень репо VibeBrains = содержимое `.vibe` (README несёт двойную роль: сеемая справка + описание источника); в VibeIDEA submodule = `resources/vibeDefaults` (Bazel-глоб работает, `.git`-gitlink исключён), гейт манифест↔ресурсы ловит дрейф набора. Submodule пинится на коммит — обновление осознанное (`git submodule update --remote`, правило в CLAUDE.md обоих репо: перед работой с сидами — сперва подтянуть). Опубликовано в org: https://github.com/VibeBrains/VibeBrains (пуш из-под аккаунта VibeBrains в gh keyring — у borodatych нет push-прав в org), submodule-URL переключён на GitHub в тот же день. Знания из static-списков VibeIDE сохранены закомментированными кастомными записями в openai/deepseek/kimi.jsonc.

26. **Вотчер providers против кэша последнего набора (п.9 пути переноса)** → перенести у VibeIDE обе части / только вотчер → **только вотчер** (`VibeProvidersWatcher`: VFS-события обоих уровней, `~/.vibe` через явный `addRootToWatch` + принудительный refresh — вне content roots события иначе не приходят; дебаунс 500 мс; публикация в существующий `ProvidersChangeListener.TOPIC`). Кэш последнего рабочего набора НЕ переносим — YAGNI: у VibeIDE он существовал ради синхронной отрисовки на старте рендера, наша панель грузит конфиги off-EDT и локальное чтение занимает миллисекунды.

27. **Авточистка устаревших сидов** → оставить лежать до полного release-обновления / чистить по имени / **чистить по имени + sha256-эталонам исторических версий** — файл, удалённый или переименованный в общем наборе, описывается в `deprecated.json` (VibeBrains, служебный файл набора — не сеется; в гейте манифест↔ресурсы — allowlist SET_METADATA) со ВСЕМИ историческими sha256 (добыты из git-истории `.vibe-defaults` VibeIDE); сеялка удаляет копию только при байт-совпадении с эталоном — правленная остаётся и репортится. Хэш — SHA-256 от LF-нормализованного UTF-8 (контракт набора: Windows-CRLF-чекаут не должен выглядеть «правкой»; наша сторона проверяет raw и LF-вариант, их — normalizeEol). Реализовано в обоих продуктах в одной задаче: VibeIDEA — `VibeDefaults.cleanupDeprecated` + журнал; VibeIDE — генератор эмитит `VIBE_DEPRECATED_MANIFEST` отдельно от сидов, `cleanupDeprecatedVibeDefaults` чистит и `.defaults.lock.json` от фантомных записей. Разовая ручная чистка пяти проектов тем же sha-методом предшествовала механике.

28. **Как понять, старый сид или изменённый (обновление окружения)** → версия формата внутри jsonc / только журнал `.seeded.json` / **реестр ревизий набора с историей sha** — решение владельца 2026-08-28 «продумай до мелочей»: `"version"` внутри providers-файла — версия ФОРМАТА (контракт VibeIDE), её нет у `.md`/`.mdc`/`.py` набора и она путешествует с копией пользователя, поэтому ревизии живут отдельно: `versions.json` (VibeBrains, служебный) = `{path: {version, sha256, history[]}}`, генератор `bump.mjs` (+`--check` как гейт, `--from-git --donor=` для инициализации истории из трёх репозиториев). Матрица вердиктов (`SeedRevisions.verdict`): нет файла → CREATE; sha == релизной → SAME; sha ∈ history → **UPDATE молча**; sha чужая и ревизия выросла → **CONFLICT** (уведомление, файл не трогаем); sha чужая при актуальной ревизии или после «оставить своё» → USER_EDIT (тихо); нетронутая копия при равной ревизии, но контент разошёлся → SET_DRIFT (набор правили без бампа — warning, ловится гейтом). Решение «оставить своё» пишется в журнал как `reconciled: <ревизия>` и снимается только следующим бампом. Авто-мерж предлагается ТОЛЬКО когда единственное отличие — значения `active`, и сохраняется не в пользовательский `providers.json` (переписывая его, потеряли бы поля, которых мы не моделируем), а в собственный `providers/zz-local-toggles.jsonc` — последний по алфавиту в каталоге, поэтому сильнее сидов. Инициализация истории показала: 238 из 248 копий в существующих проектах опознаются нетронутыми; неопознанные — `README.md`/`rules.md`, засеянные старым inline-генератором VibeIDE, они честно остаются «unknown» и не трогаются.

29. **Где живут правила для AI-агентов** → в `docs/vibe/agentsGuide.md`, а не в корневом `AGENTS.md`
    (2026-08-29, ночная работа). Корневой файл принадлежит апстриму: он генерируется их
    `community/.ai/render-guides.mjs`, и последний коммит в нём чужой. Правка означала бы конфликт
    на каждом синке — ровно то, чего запрещает граница форка. Проверять принадлежность файла:
    `git cat-file -e upstream/master:<путь>`.

30. **Что считает храповик локализации** → только ИНТЕРФЕЙСНЫЕ литералы (2026-08-29, ночная
    работа). Довести общее число русских строк до нуля нельзя: часть из них — данные, а не текст
    для человека (регэкспы детекторов ищут русские фразы в чужой странице; преамбулы ролей уходят
    в промпт модели). Такие файлы перечислены в `i18nExclusions.txt` **с причиной**, правило приёма
    строгое: сообщение находки, подпись кнопки и текст ошибки в ленте — интерфейс, сколько бы их
    ни было. Альтернатива «считать всё» отвергнута: она заставляла бы переводить то, что переводом
    ломается.

31. **Мост замера дизайна: JCEF, а не платформенный `ui.webview`** → JCEF (2026-08-29). Платформенный
    WebView служит бандленным ассетам плагина через свои asset-хендлеры, а мерить нужно произвольную
    страницу пользователя (localhost, staging). `JBCefBrowser.loadURL` это умеет, WebView — нет.
    Цена решения: JCEF может отсутствовать в сборке, поэтому панель честно говорит об этом вместо
    пустого экрана.

32. **Бинари `/watch` и голосовой ввод** → берём из системы; своего зеркала не заводим (2026-08-29).
    У VibeIDE для этого есть релиз-зеркало с SHA256, у форка нет ни релизной инфраструктуры, ни
    места для хранения. `yt-dlp`/`ffmpeg` находятся в PATH и типовых каталогах, при отсутствии
    выдаётся точная команда установки. Следствие, названное вслух: локальный STT (пункт 18 roadmap)
    без этой инфраструктуры не реализуем честно, и аудио без субтитров даёт отказ с причиной.

33. **Каталог строк для vibe-server: свой или общий** → ОБЩИЙ, в `vibe-agent` (решение владельца
    30.08.2026). Два каталога означают два места для одной кнопки «Отмена» и неизбежное расхождение
    формулировок. Цена: `vibe-server` получает `<depends>com.vibe.agent</depends>` и зависимость в
    Bazel — оба плагина всегда едут в одном дистрибутиве, поэтому связь ничего не ломает. Следствие,
    которое пришлось чинить сразу: гейт локализации искал использования ключей только в `vibe-agent`
    и объявил строки сервера мёртвыми — теперь он смотрит на все наши модули.

34. **Поставка языковых серверов вместе с IDE** → ПОСТАВЛЯЕМ САМИ СЕРВЕРЫ, РАНТАЙМЫ — НЕТ (решение
    владельца 31.08.2026). Phpactor едет одним phar (4,3 МБ), vtsls/CSS/ESLint — подготовленным
    npm-деревом (56 МБ, из которого выброшена вложенная копия TypeScript на 64 МБ). PHP и Node
    берутся с машины: **ступень «Node в комплекте» признана избыточной** — Node давно ставится
    отдельно по классике, и +110 МБ на платформу плюс второй рантайм, обновляемый при каждой его
    уязвимости, покупали бы предусловие, которое у всех и так выполнено. Во всех случаях **свой
