# Журнал решений VibeIDEA

Формат: дата — развилка → варианты → выбор → почему. Ночные (без владельца) помечены 🌙.

## 2026-08-23 🌙 — ночь основания

1. **Стартовый пак start0** → применять / нет → **нет** → форк готовой JVM-кодовой базы, а не новый веб-проект; пак (Point0+Prisma+better-auth) неприменим по стеку. Осознанное отступление от глобального правила.
2. **Глубина клона** → shallow / полный → **полный** → форку нужна история для merge с апстримом; shallow — полурешение, ломающее будущие синки.
3. **Remotes** → оставить origin=JetBrains / переименовать → **origin → upstream** → защита от случайного push в чужой репозиторий; свой origin появится решением владельца.
4. **Ветки** → master-only / main+next → **master = зеркало `upstream/master` (обновление только ff-merge из него), main = релизная, next = работа** → глобальная дисциплина main/next + явное место для «чистого апстрима» (синк-база).
5. **PHP/TS** → ждать открытых плагинов / LSP-стек → **LSP4IJ (EPL-2.0) + Phpactor (MIT) + vtsls (MIT) + vscode-js-debug/vscode-php-debug (MIT)** → единственный лицензионно чистый путь: плагины PhpStorm/WebStorm закрыты, Intelephense запрещает редистрибуцию (EULA §5c — проверено по тексту), открытых аналогов нет. `platform/lsp` (открыт 2026-06, Apache-2.0) — отслеживать как нативную замену языковых фич; DAP остаётся за LSP4IJ.
6. **Агентская обвязка** → реверс закрытого Claude-плагина / свой ACP-клиент → **свой ACP-клиент на Kotlin SDK `com.agentclientprotocol:acp`** → JetBrains-клиент закрыт (AI Chat), в IC его нет; ACP даёт весь парк агентов сразу; Claude — через официальный адаптер `claude-agent-acp`.
7. **Размещение своего кода** → правки платформы / оверлей → **оверлей: свои модули/плагины `com.vibe.*`**, правки платформы только с записью в FORK_CHANGES.md → урок VibeIDE: merge-налог на каждую правку апстрима вечен.
8. **Имя продукта** → «VibeIDEA» → **рабочее, не окончательное** → сходство с товарным знаком «IntelliJ IDEA»; решение за владельцем (вынесено в утренний отчёт).
9а. **Синк с апстримом** → по HEAD master / по тегам → **по тегам релизов** → master IC движется слишком быстро; теги — стабильные точки, обе стороны (IC и android) чекаутятся на один тег. Формат подтверждён фактом (`git ls-remote --tags`): `idea/2026.2.1`.

10. **Обрыв полного клона (curl 56 на 78%, потеряно ~1.5 ч)** → ретраить монолитный пак / shallow+деепен → **shallow `--depth 1` сразу + фоновая дозакачка истории кусками `--deepen` с ретраями, всё под `caffeinate -i`** → монолитный пак ~6 GB нерезюмируем, каждый обрыв обнуляет загрузку; кусочный деепен ретраится пошагово, а ночная работа не блокируется (рабочее дерево уже есть). Конечное состояние то же — полная история master (уточнение решения №2, не отмена).

11. **Коллизия с docs/ апстрима** → наши доки рядом с чужими в `docs/` / свой неймспейс → **`docs/vibe/`** → у IC уже есть `docs/`, и на case-insensitive APFS наш `README.md` молча перетёр их `readme.md` (восстановлен из git до коммита); оверлей-принцип распространён и на документацию. Грабля записана: [[caseInsensitiveFs]].

12. **Падение search_index (traverseUI) под нашим префиксом** → скипнуть шаг / чинить платформу → **точечная правка платформы** `AppUIUtil.loadConsentsForEditing` (`toMutableList()`) → это латентный баг апстрима на продуктах без бандленных согласий (`removeIf` на иммутабельном списке); скип шага деградировал бы поиск по настройкам. Запись в FORK_CHANGES.md, кандидат на отправку апстриму.
13. **Источник LSP4IJ для бандла** → Marketplace / GitHub releases → **GitHub releases с пином sha256** (`vibe-plugins/deps/download.sh`) → артефакт EPL-2.0 раздаётся самим Red Hat на GitHub; Marketplace-ToS не затрагивается вовсе.

14. **ACP-клиент: официальный Kotlin SDK или свой минимальный** → SDK из Maven Central / свой ndjson JSON-RPC → **свой минимальный (~250 строк)** → затащить внешнюю Maven-зависимость в JPS+Bazel-граф IC — отдельная инженерная задача с рисками, а протокольная поверхность MVP крошечная; kotlinx-serialization уже в платформе (JsonElement-API не требует компилятор-плагина). Миграция на SDK — открытый пункт roadmap, интерфейс клиента изолирован в `acp/`.

15. **Скоуп providers.json первой итерации** → полный паритет VibeIDE / честное подмножество → **подмножество с точным контрактом файла** (схема полей, мерж global/workspace, JSONC, толерантность, extends, ключи вне файла, Guard-правила — дословно; НЕ вошло: встроенные провайдеры, models.fetch, gemini-протокол, FIM-потребитель, кэш+вотчер) → контракт файла — то, что переносится между продуктами и что нельзя менять потом; потребители наращиваются по одному. Границы записаны в спеке. Расхождение спеки VibeIDE с её же примером (`reasoning.field` удалён, но остался в zai.jsonc) — не воспроизводим.

16. **Пилюля «Режим» в композере** → 4 режима VibeIDE (Чат/Обзор/План/Агент) как глобальная настройка / режимы сессии ACP-агента → **режимы ACP (`session/new.modes` + `session/set_mode`), у прямого LLM пилюля скрыта** → у голого LLM нет инструментов, «Обзор»/«Агент» были бы фальшивыми переключателями; режим реально принадлежит агенту (у claude-agent-acp: Auto/Manual/Accept Edits/Plan/Don't Ask). Отклонение от спеки зафиксировано в functional.md.
17. **Очередь инъекций** → IDE-сторонняя (держим до `stopReason`, сливаем в следующий `session/prompt`) / `_session/steering` claude-agent-acp → **IDE-сторонняя** → портируемо на любого ACP-агента; steering — опциональный fast-path, заведётся при живом E2E, если понадобится подмешивать в идущий ход.
18. **Вложения: картинки да, PDF нет (пока)** → тянуть PDFBox ради извлечения текста / отложить → **отложить, пункт roadmap** → новая зависимость в JPS+Bazel-граф — отдельное решение; картинки идут нативными блоками ACP `image` и image-частями трёх LLM-протоколов без зависимостей.
